## 摘要
长周期LLM智能体会积累推理轨迹、动作和工具观测结果，最终可能超出模型的固定上下文窗口。现有压缩方法通过丢弃、总结或检索早期信息来解决这一限制，但可能会移除任务关键细节或无法可靠恢复它们。我们提出ARC（可寻址回忆压缩），一种将存档存储与活动上下文呈现分离的上下文管理框架。ARC将工具观测结果存储在仅追加、ID可寻址的日志中，并在需要压缩时用紧凑的引用替换较旧的观测结果。智能体随后可以使用这些标识符请求存储的内容，而无需重新执行相应工具或仅依赖基于相似性的检索。我们使用具有16k上下文窗口的Qwen3-8B和具有32k上下文窗口的Qwen3-32B评估ARC。在"大海捞针"评估中，ARC实现了99.40%的平均准确答案准确率，而评估中最佳基线为88.12%。在我们的硬件成本模型下，ARC还减少了估计的服务时间和HBM流量。在LongBench-v2 Hard子集上，ARC获得了29.97%的平均准确率，而最佳基线为28.25%。这些结果表明，相对于评估的上下文管理基线，在测试设置下，显式的基于地址的回忆可以提高信息保留和服务效率。

## Abstract
Long-horizon LLM agents accumulate reasoning traces, actions, and tool observations that can eventually exceed a model's fixed context window. Existing compaction methods address this limitation by discarding, summarizing, or retrieving earlier information, but they may remove task-critical details or fail to recover them reliably. We propose ARC (Addressable Recall Compaction), a context-management framework that separates archival storage from active-context presentation. ARC stores tool observations in an append-only, ID-addressable log and replaces older observations with compact citations when compaction is required. The agent can subsequently use these identifiers to request stored content without re-executing the corresponding tools or depending solely on similarity-based retrieval. We evaluate ARC using Qwen3-8B with a 16k context window and Qwen3-32B with a 32k context window. On the Needle-in-a-Haystack evaluation, ARC achieves an average exact-answer accuracy of 99.40%, compared with 88.12% for the best-performing baseline in our evaluation. ARC also reduces estimated serving time and HBM traffic under our hardware-cost model. On the LongBench-v2 Hard subset, ARC obtains an average accuracy of 29.97%, compared with 28.25% for the best-performing baseline. These results indicate that explicit, address-based recall can improve information retention and serving efficiency relative to the evaluated context-management baselines under the tested settings.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大语言模型（LLM）Agent 在长周期任务中，不断累积推理轨迹、动作和工具观测，导致转录本（transcript）无限增长，最终超出模型固定的上下文窗口（context window），引发不可恢复的失败。现有上下文压缩方法（如截断、摘要、结构化状态、检索增强生成）都是“有损”的，可能会丢弃或无法可靠恢复关键细节（如变量名、错误字符串等），导致 Agent 犯错或幻觉。
- **研究动机**：能否实现一种“无损”的压缩，同时保持活动上下文大小受限，且允许 Agent 按需精确恢复历史信息？
- **整体含义**：提出了 ARC（Addressable Recall Compaction），一种将存档存储与活动上下文呈现分离的上下文管理框架，用显式、可寻址的 ID 引用替代旧内容，确保任意历史观测都能精确恢复，从而解决长程 Agent 的上下文管理难题。

### 2. 论文提出的方法论

- **核心思想**：解耦“保留什么”和“当前模型看到什么”。所有工具观测总是原样存储在内容寻址的外部存储中（append-only）；活动上下文（active view）受预算限制，被压缩掉的观测留下一个紧凑的引用（citation），Agent 可通过显式命令 `_recall` 精确恢复完整内容。
- **关键技术细节**：
  - **观测存储与ID生成**：每个观测 `O` 与动作签名一起计算哈希（SHA1），生成稳定、唯一的 8 字符十六进制 ID（必要时扩展）。存储记录包含完整内容、元数据等。存储是追加式的，从不删除。
  - **活动视图构建**：由固定前缀、确定性摘要（由规则生成，不调用LLM）、最近若干条记录（短观测保留原文）、长观测替换为引用 `§id`（含 head/tail 预览及 `_recall §id` 提示）、一个外部目录页（catalog page）、已召回内容缓冲区组成。各部分有固定令牌预算，总和不超过上下文窗口。
  - **召回机制**：`_recall §id` 命令被框架拦截，直接从 ObsStore 中读取完整观测并注入回活动视图。有预算限制（每步最多 2 次，总召回内容大小受限，最大单次召回长度 8000 tokens），LRU 淘汰。还提供 `_recall_meta` 仅恢复元数据。
  - **压缩例程**：当预测或实际发生上下文溢出时触发。采用确定性截断与替换：截断早期思考，短观测保留，长观测替换为引用，最近若干轮保留原文。对已引用条目可进一步从完整 stub 压缩为纯 `§id`。整个过程不调用 LLM，无额外模型延迟。
  - **形式保证**：论文给出了定理：只要满足假设（注入性ID、追加式存储、目录页分页、活动视图预算等），在每个时刻模型输入不超过 K 个 token（独立于轮次），且任意存储的观测可通过 ID 精确重建（分成最多 `ceil(n/q)` 个不重叠的 recall chunk）。这是机制层面的保证，不保证模型会正确使用。

### 3. 实验设计

- **数据集/场景**：
  - **Needle-in-a-Haystack (NIH)**：一个 24 字符随机令牌（needle）被嵌入到带噪文件中，Agent 需要在经历压缩后精确找回该令牌。每任务 1000 个，3 个随机种子（42, 82, 122），共 3000 次尝试。
  - **LongBench-v2 Hard 子集**：包含 311 个任务，涉及单/多文档问答、长上下文学习、结构化数据理解、长对话历史、代码仓库理解等，要求多步推理。同样 3 种子，共 933 次尝试。
- **模型与配置**：Qwen3-8B（16k 上下文窗口）和 Qwen3-32B（32k 上下文窗口），均设 4096 令牌完成容量，使用 vLLM 服务。
- **对比方法**（基线）：
  - Full_context：不压缩，无限追加（直至溢出失败）。
  - Sliding_window：保留最近 N 轮。
  - LLM_summary：定期用 LLM 生成历史摘要。
  - Structured_state：将历史压缩为结构化 JSON 对象。
  - RAG_memory：将历史外存向量化，检索相关片段。
- **评估指标**：准确率（Acc）、未回答率（no-ans）、HBM 带宽/时间（基于 roofline 模型）、McNemar 统计显著性检验。
- **消融实验**：召回预算（4k/2k, 8k/4k, 16k/8k, 32k/16k）、强制压缩调度（不同 call 索引）、噪声行数（fixture size）、在 AMD MI300X 上交叉验证。

### 4. 资源与算力

- **推理平台**：主要实验使用 1 块 NVIDIA H200 143GB GPU（4.8 TB/s HBM 带宽，989 TFLOPS BF16）。附录中使用了 1 块 AMD MI300X 192GB GPU 进行跨平台验证。
- **未提及训练**：论文未涉及模型训练，所有实验基于预训练模型进行推理和压缩。
- **HBM 分析模型**：基于 roofline 模型估计 decode/prefill 时间，考虑模型权重、KV 缓存尺寸、批量大小等，并非实际硬件运行时间。

### 5. 实验数量与充分性

- **实验数量**：
  - NIH：6 种方法 × 2 模型规模 × 3 种子 = 36 组实验（每组 1000 任务），共 36,000 次模型调用（估计）。
  - LongBench：6 种方法 × 2 模型 × 3 种子 = 36 组实验（每组 311 任务），共 ~11,196 次。
  - 消融实验：召回预算（2 模型 × 3 预算 × 多种方法）、强制压缩（多种调度）、fixture size（4 级别）、跨平台（只 NIH）。
- **充分性与公平性**：
  - 所有方法使用相同种子、相同模型、相同环境，结果可配对比较。
  - 使用 McNemar 检验配对差异，报告 p 值和 odds ratio，证明统计显著性。
  - 消融实验全面覆盖了 ARC 的关键参数（召回预算、压缩频率、观测大小），且在不同预算下 ARC 表现稳定最优。

### 6. 论文的主要结论与发现

- **NIH 任务**：ARC 达到 99.40% 平均准确率（Qwen3-8B 99.00%，32B 99.80%），而最佳基线 RAG_memory 仅 88.12%（8B 79.57%，32B 96.67%）。ARC 几乎消除了未回答情况（no-ans 接近 0）。
- **LongBench-v2 Hard**：ARC 在 Qwen3-8B 达 27.47%，32B 达 32.47%，分别超过最佳基线 1.64 和 1.80 个百分点。ARC 的 no-ans 率最低，证明其提升来自减少“未能给出答案”而非仅提升答案随机性。
- **效率**：ARC 在 NIH 上比 Sliding_window 减少 HBM 流量 80.3%（8B）和 82.6%（32B），总时间下降约 5 倍；在 LongBench 上也是 HBM 最低的方法。
- **统计显著性**：所有 ARC vs 基线的 McNemar 检验 p ≪ 0.05，odds ratio 远大于 1（如对 RAG_memory 在 8B 上 OR=23.96）。
- **理论贡献**：形式化证明了 ARC 保证活动视图有界性、观测无损性、可寻址精确恢复，并指出线性外部存储是不可避免的（下界）。这是一种机制级保证。

### 7. 优点

- **方法创新性**：首次提出将“保留”和“呈现”分离，使用显式地址引用实现无损压缩，区别于所有现有有损压缩或隐式检索。
- **理论严谨性**：给出了形式化定义和定理，证明活动视图有界、观测无损、可显式恢复，且外部存储渐近最优。
- **实验全面性**：覆盖了两个标准长上下文基准、两个模型规模、三个随机种子；进行了多种消融（召回预算、压缩频率、观测大小、跨平台），并进行了严格的统计检验。
- **效率与性能兼得**：ARC 在提升准确率的同时显著降低 HBM 流量和服务时间，没有常见的“折衷”。
- **跨平台验证**：在 AMD MI300X 上复现了 NIH 结果，表明不依赖特定 GPU 生态。
- **公开代码与详细附录**：提供了算法细节、形式证明、更多消融和跨平台数据，增强可复现性。

### 8. 不足与局限

- **模型家族局限**：仅测试 Qwen3-8B/32B，未在类似 GPT-4、Llama-3、Claude 等模型上验证，通用性存疑。
- **任务覆盖不全**：LongBench 上 ARC 提升较小，且作者承认在对话历史理解任务上隐式检索（如 RAG）可能更好——ARC 并非在所有场景下优于所有基线。
- **令牌开销未量化**：每个引用 stub 会带来固定令牌开销（head/tail preview + 指令），论文未精确测量对有效上下文预算的影响（仅提到量化在补充中，但补充中未给出具体数值）。
- **端到端任务不保证**：ARC 只保证内容可恢复，但不保证模型会选择正确的 ID 或正确推理——即 perfect recall ≠ perfect task success。
- **仅推理无训练**：未探讨如何将 ARC 机制集成到模型微调中以进一步提升智能体行为（如自动决定何时召回）。
- **上下文的“观察”无损，但不保证“思考”无损**：论文明确限定只保证工具观测无损，丢弃的推理痕迹（thoughts）若未存储同样不可恢复。在需要复现推理路径的场景下仍有损失。
- **依赖确定性摘要**：ARC 的压缩使用截断而非 LLM 总结，可能丢失上下文相关性，但这是为了效率；与 LLM 摘要方法相比在信息保留上可能仍有差距。
