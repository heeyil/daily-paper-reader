## 摘要
长期运行的Web智能体常常在最终失败之前偏离轨道：即使当前状态、复用技能或计划假设不再支持用户指令，轨迹在局部上仍可能看起来合理。现有智能体能够规划、反思或复用经验，但其计划很少指定在何种证据下应该继续信任当前步骤。我们提出了FCPAgent，一个用于鲁棒长期Web智能体的可证伪承诺规划框架。FCPAgent将每个计划步骤表示为一个可证伪承诺单元（FCU）：一个基于可复用技能的子目标，同时包含确认性证据、证伪证据和置信度分数。执行被组织为计划-测试-修复循环。混合承诺测试模块在候选动作修改浏览器之前对其进行检测，并在执行后检查观察结果；为了提高效率，它结合了轻量级的证据匹配与基于LLM的诊断验证。当证据证伪一个承诺时，范围感知修复将矛盾定位到执行、技能或规划层面，并修正最小的适当部分。在WebArena上，FCPAgent在平均成功率上比最强基线相对提升了13.8%，在长期任务上提升尤为显著。

## Abstract
Long-horizon web agents often go off track before final failure: a trajectory can remain locally plausible even after the current state, reused skill, or plan assumption no longer supports the user instruction. Existing agents can plan, reflect, or reuse experience, but their plans rarely specify the evidence under which an active step should still be trusted. We propose FCPAgent, a falsifiable commitment planning framework for robust long-horizon web agents. FCPAgent represents each plan step as a Falsifiable Commitment Unit (FCU): a subgoal grounded in a reusable skill, together with confirming evidence, falsifying evidence, and a confidence score. Execution is organized as a plan-test-repair loop. The hybrid commitment testing module checks candidate actions before they modify the browser and checks observations after execution; for efficiency, it combines lightweight evidence matching with LLM-based diagnostic verification. When evidence falsifies a commitment, scope-aware repair localizes the contradiction to the execution, skill, or planning level and revises the smallest adequate part. On WebArena, FCPAgent achieves a 13.8% relative improvement in average success over the strongest baseline, with especially large gains on long-horizon tasks.

- **研究动机**：长期运行的 Web 智能体在执行多步任务时经常“偏离轨道”——即使当前页面、复用技能或高层假设已不再支持用户指令，后续动作在局部上依然看似合理，导致最终失败。现有智能体的计划缺乏可验证的运行时有效性标准，无法在早期察觉偏差。
- **研究背景**：现有方法如反思、动态重规划、技能复用等改进了鲁棒性，但计划步骤很少附带“什么证据下该步骤仍应被信任”的显式说明。受认知科学中“测试–操作–测试–退出”理论的启发，论文提出将每一步计划视为一个可证伪的承诺，通过运行时测试其有效性来提升长期可靠性。
- **整体含义**：FCPAgent 把 Web 智能体的执行从无条件追随计划转变为在线测试承诺，使智能体能够在本地漂移累积成不可逆错误之前进行自我修正，为稳健的长周期 Web 自动化提供新范式。

## 2. 论文提出的方法论
- **核心思想**：每个计划步骤表示为可证伪承诺单元（FCU），包含子目标、可选链接的技能、确认性证据、证伪证据以及置信度。执行被组织为“计划–测试–修复”循环。
- **关键技术细节**：
  - **可证伪承诺生成**：离线构建技能库（来自成功轨迹）和失败-修复记忆库（来自失败或修复后的轨迹）。在线时根据任务查询检索相关经验和记忆，生成 FCU 序列。
  - **混合承诺测试**：
    - 轻量级测试（快速）：在动作执行前和状态返回后，使用 NLI（nli-deberta-v3-base）和图像-文本匹配（SigLIP2）计算证据匹配分数，并辅以规则检查异常。根据分数阈值路由到“继续”、“完成”、“风险”或“验证”。
    - LLM 诊断验证（慢速）：对完成类、风险类或模糊状态，调用 LLM（Qwen3.5-397B-A17B）分析轨迹、当前证据和分数，返回继续、前进或修复决策，并附带诊断信息（执行级、技能级或规划级违规）。
  - **范围感知修复**：根据诊断的违规范围，选择最小的修复动作：
    - 执行级：保留当前 FCU，修正即时动作或路径。
    - 技能级：保留子目标，替换技能并更新证据。
    - 规划级：重写当前及后续 FCU。
    - 严重偏移时回溯到已知安全状态。
  - **经验蒸馏**：成功轨迹提炼为技能，失败/修复轨迹存储为失败-修复记忆，供未来使用。
- **算法流程（文字说明）**：① 检索相关技能和失败案例 → ② 生成 FCU 计划序列 → ③ 对每个 FCU，执行器提出动作后先经动作级快速测试；若路由到验证则调用 LLM 决定是否修复；通过后执行动作 → ④ 观察新状态后进行状态级快速测试；若发现违规则 LLM 诊断并触发范围感知修复；若确认完成则前进到下一 FCU → ⑤ 循环直至所有 FCU 完成或达到步数上限 → ⑥ 离线更新经验库。

## 7. 优点
- **创新性**：将计划步骤显式定义为可测试的承诺，引入“证据驱动”的执行验证机制，填补了现有方法缺乏运行时有效性检查的空白。
- **实用设计**：混合测试巧妙平衡了效率与准确性，轻量级匹配处理常规情况，LLM 诊断仅用于关键边界，避免每次动作都调用昂贵模型。
- **鲁棒修复**：范围感知修复根据违规粒度选择最小的修正动作，既避免过度重规划，又能应对深层问题，且利用失败记忆引导修复。
- **经验复用**：技能库和失败-修复库从离线轨迹中自动蒸馏，为计划生成和修复提供先验知识，且实验证明两者互补。
- **实验充分**：涵盖了多维度分析，包括消融、效率、长期性能、零样本、行为统计等，结果一致性较好。
