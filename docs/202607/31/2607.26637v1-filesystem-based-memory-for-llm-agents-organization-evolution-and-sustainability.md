## 摘要
部署的LLM智能体越来越倾向于将长期记忆保存为文件系统：一个由markdown文件组成的目录树，智能体自身通过通用文件工具进行读取、写入和重组。然而，研究在很大程度上忽略了这一媒介：先前的系统设计了定制的记忆表示并研究其检索，而未检验默认设置的两个工作假设：智能体能否在记忆积累、冲突和过期时保持不断增长的存储库的有序性，以及这种有序性是否值得。我们首次对LLM智能体的基于文件系统的记忆进行了系统探索。我们将该设置形式化为围绕一个记忆文件系统的三个角色：管理智能体整合和组织传入内容，搜索智能体用引用来源回答问题，执行智能体提供任务轨迹并将其提炼为技能，从而将陈述性记忆和技能统一于一个存储库中。在长对话基准和具身任务中，我们变化了记忆形态（智能体组织的层次结构、逐字转储、分块检索）、流规模、工具集（沙箱shell、记忆工具风格的函数、多种搜索工具）以及管理智能体和搜索智能体的能力，随着记忆的增长跟踪回答质量、成本和存储库健康状况。有序性带来的可靠收益是搜索经济性：在材料规模较大时，有序存储库的检索成本大约减半。然而，当前的智能体未能实现默认设置的承诺：在我们的增长研究中，除了最强的管理智能体之外，所有智能体的有序性都会下降，而且我们测量的智能体都没有将有序性本身转化为更优的答案。而且，模型并非影响存储库形态的唯一杠杆：仅改变工具集就能像更换模型一样显著地重塑存储库。这项研究将文件系统默认设置从一种假设转变为智能体记忆的设计空间。

## Abstract
Deployed LLM agents increasingly keep their long-term memory as a filesystem: a directory tree of markdown files that the agent itself reads, writes, and reorganizes through generic file tools. Yet research has largely passed over this medium: prior systems design bespoke memory representations and study retrieval over them, leaving the default's two working assumptions untested: that an agent can keep a growing store organized as memories accumulate, conflict, and go stale, and that this organization pays. We present the first systematic exploration of filesystem-based memory for LLM agents. We formalize the setting as three roles around one memory filesystem: a management agent integrates and organizes incoming content, a search agent answers queries with cited sources, and an execution agent supplies task trajectories that are distilled into skills, unifying declarative memory and skills in a single store. Across long-conversation benchmarks and embodied tasks, we vary memory shape (agent-organized hierarchy, verbatim dump, chunk retrieval), stream scale, tool harness (sandboxed shell, memory-tool-style functions, varied search tooling), and the strengths of the management and search agents, tracking answer quality, cost, and store health as memory grows. What organization reliably buys is search economy: organized stores roughly halve retrieval cost where material is large. Today's agents, however, fall short of the default's promise: in our growth study, organization erodes for all but the strongest management agent, and no agent we measure converts organization itself into better answers. And the model is not the only lever over a store's shape: changing the tool set alone reshapes the store as strongly as swapping the model. The study turns the filesystem default from an assumption into a design space for agent memory.

## 1. 核心问题与整体含义

- **研究背景**：部署的 LLM 智能体越来越依赖文件系统作为长期记忆，即一个由 Markdown 文件组成的目录树，智能体通过通用文件工具自行读取、写入与重组。工业界已广泛采用这一方案（Anthropic 的 Memory Tool、Claude Code 的自动记忆文件夹、AGENTS.md、Agent Skills 等），但学术界的研究却集中在定制化记忆表示（MemGPT 分页上下文、事实库、时序知识图谱、笔记网络、摘要库、话语单元库、嵌入组织树等）及其检索上，几乎无人系统研究文件系统这种默认媒介本身。
- **两个未经检验的核心假设**：①智能体能否在记忆不断积累、冲突与过期的过程中，维持一个持续增长且有序的记忆库？②这种"组织"是否值得其代价？
- **论文定位**：首次对基于文件系统的 LLM 智能体记忆进行系统性探索，将"文件系统默认配置"从隐含假设转化为可设计的实验空间。

## 2. 方法论

- **形式化框架**：将记忆系统拆解为三个围绕同一存储库的角色：
  - **管理智能体（Management Agent）**：负责整合每个新进入的块（chunk）并维护存储库的组织结构。形式化为 M_t = m_H^π(ι, x_t, M_{t-1})，其中 M_0 = ∅。
  - **搜索智能体（Search Agent）**：在固定存储库上回答查询并给出带引用的答案：(a, Γ) = s_Hr^π′(ι, q, M)。
  - **执行智能体（Execution Agent）**：在技能场景中出现，尝试任务 e(τ, Γ) = (ξ, z)，返回轨迹与成功信号，是"将存储质量转化为任务结果"的探针。
- **存储库定义**：记忆存储 M 是根路径层次结构中的有限文件集合，每个文件 f = (p_f, d_f, c_f)——路径、单行描述、文本内容；文件夹结构、文件名与文件内 Markdown 标题共同构成存储库的"分类树"（taxonomy）。
- **分类契约（Taxonomy Contract）**：五个原则——P1 同级可区分、P2 同级相关、P3 父子覆盖、P4 距离镜像相关性、P5 结构经济性。
- **工具集（Harness）**：智能体不能直接修改 M，所有操作通过工具集 H 完成。实验使用了三种工具集：Center（6 个通用文件操作 + 正则搜索的写工具集，只读文件工具的读工具集）、Center+BM25（增加排序关键词搜索）、Shell（完整的 bash 沙箱）。
- **两个实例化**：①会话记忆（LoCoMo、PersonaMem、REALTALK 长对话）；②程序性记忆（ALFWorld 具身任务，技能蒸馏），统一了陈述性记忆与技能于同一存储库。
- **防泄漏协议**：任务 τ_i 的检索 (Γ_i = s(ι_r, τ_i, M_{i-1}))、执行 ((ξ_i, z_i) = e(τ_i, Γ_i)) 与整合 (M_i = m(ι_c, render(ξ_i), M_{i-1})) 严格顺序执行，第 i 个任务只能使用前 i-1 个任务构建的存储库。

## 3. 实验设计

- **数据集与基准**：
  - **LoCoMo**：长多会话对话基准，1 个测试对话，158 个问题（多跳、时序推理、开放域、单跳四类，排除对抗类；另有 4 个黄金标注缺陷问题被单独编目）。
  - **PersonaMem 32k**：3 个对话、32 个问题（多项选择，精确匹配评分）；**PersonaMem 128k**：1 个对话、42 个问题。
  - **REALTALK**：21 天真实人际对话，1 个测试对话、85 个问题。
  - **ALFWorld**：140 个保留任务，覆盖 6 个目标家族（放置、双物体放置、检查、清洁、加热、冷却），使用三链协议和全链协议两种评测方案。
- **记忆变体（6 种）**：Closed-book（无存储基线）、Chunk retrieval（BM25 分块检索，RAG 标准对照）、Verbatim dump（逐字转储，零整理基线）、Foldered sessions（仅 LLM 设计文件夹分类）、Reorg. (preserve) / Reorg. (condense)（LLM 重组，区分是否保留全部事实）、Agent-curated store（管理智能体从空存储逐步构建）。
- **模型配置**：主实验管理/搜索智能体为 gpt-5.4-mini（高推理强度）；能力梯度为 gpt-5.4-nano → gpt-5.4-mini → gpt-5.4；评分法官为 gpt-5.4-mini（低温、固定提示词，预先校准）；执行智能体分 gpt-4.1 与 gpt-4.1-mini 两档。

## 6. 主要结论与发现

- **RQ1（组织形态）**：管理智能体能生长出主题树，但树的形态更多是模型的"签名"而非对规模的响应——规模增大时存储库趋于整合而非碎片化（层级从文件夹/文件迁入文件内标题）；最明显的退化行为是重组过程会静默压缩内容，除非添加"保留每个事实"规则。
- **RQ2（形状的价值）**：没有任何形状在所有基准上赢得正确性；组织化最明确的收益是搜索成本——在 PersonaMem 大材料上，重组/整理存储将单查询检索成本从 4.0 美分降至约 1.4–1.6 美分（近乎减半）。在技能场景，胜者取决于消费方：强执行智能体下逐字 Episode log 最优（87.1%），弱执行智能体下 Curated skills+mem (GS) 反超 10 个百分点（76.4% vs 66.4%）。
- **RQ3（骨干模型能力）**：在会话场景，管理智能体能力只买来组织风格而非答案质量（三个模型正确率在 66.7–73.8% 的窄带内且非单调），而搜索智能体能力单调转化为收益（62→71→79）；在技能场景，管理能力表现为阈值效应——只有最强模型（gpt-5.4）掌握"蒸馏"质量，超越所有 gpt-4.1 执行智能体的格子。
- **RQ4（增长可持续性）**：在所测范围内存储库越增长越有用，积累的经验可替代执行智能体能力（弱执行智能体的 Episode log 从无存储基线 51.4% 升至末段 91.4%）；早期记忆普遍存活，但分类契约遵循度随增长而侵蚀，仅最强管理智能体能维持；增长的代价是每片段整理工作量不摊销，以及逐字日志"全量检索"的持续负债。
- **RQ5（工具集效应）**：增加工具改变行为但不改变结果；替换工具集则重塑存储库本身——在长对话上 Shell 使存储碎片

化（生成更多更小的文件），但答案正确率与 Center 工具集基本持平；Center+BM25 虽将“正则全扫描”替换为排序检索，显著降低了单查询的检索 token 消耗，却同样未带来准确率的系统提升。这一结论揭示了一个重要事实：**工具集改变的是智能体的工作方式（行为轨迹）而非工作成果（任务指标）**——但“方式”本身有独立价值，它决定了成本曲线、存储形态与可维护性，而这些维度恰恰是长期部署中最关键的实际约束。

- **RQ6（成本与整理的摊销问题）**：整理并非免费午餐。管理智能体每处理一个 chunk 都要重读并重写相关文件，成本随时间线性累积且不随存储规模摊销；检索侧的成本则随存储规模增长，但被组织结构有效抑制（重组存储将 PersonaMem 128k 的单查询检索成本近乎减半）。二者权衡的净效应是：**只要存储库在持续使用，组织化投资的回报就为正；但如果只写不读，任何整理都是纯损耗**。这也解释了为何“逐字转储”在技能场景中对强执行智能体依旧有竞争力——它把成本全部推迟到了检索阶段，而执行智能体恰好有能力消化这种原始信息。

## 7. 设计启示（Design Implications）

论文基于上述发现，为实践者提炼出一组可操作的设计指南：

- **以“文件系统原生”为默认起点**：既然通用文件工具已构成工业级默认配置，且实验结果并未显示任何定制化记忆表示在正确性上全面胜出，那么新系统应优先采用文件系统 + Markdown 的朴素方案，而非过早引入专用记忆架构。
- **区分“整理预算”与“检索预算”**：系统设计者应明确记忆库是“写密集”还是“读密集”。写密集场景（如长期日志流水）应保留逐字记录并依靠检索侧能力；读密集场景（如问答助手）应投资重组与主题分层，以换取检索成本的结构性下降。
- **用“保留每个事实”约束对抗静默压缩**：重组智能体默认倾向压缩与丢细节，这是最隐蔽的退化路径。必须显式添加不可丢弃事实的规则，或在整合流程中加入一致性校验步骤。
- **能力分配的不对称性**：管理智能体的能力提升只换来“更漂亮的组织风格”而非答案质量，搜索智能体的能力提升则直接转化为正确率。预算有限时应优先升级搜索端；仅当需要真正高质量蒸馏（如技能提取）时才值得为管理端付出强模型成本。
- **警惕工具集的隐性偏见**：工具集并非中性接口。Shell 的开放式能力会诱导智能体生成更多碎片文件；BM25 会诱导其依赖关键词搜索而弱化手工导航。设计者应意识到工具选择会塑造记忆库的长期形态。

## 8. 局限性（Limitations）

- **规模有限**：单对话评估（LoCoMo 1 个测试对话、REALTALK 1 个、PersonaMem 128k 1 个）使得部分结论仅为暗示性；32–42 道题的格子对 3–5 个百分点的差异缺乏统计效力。
- **非纯正交的规模对照**：PersonaMem 32k 与 128k 使用不同对话内容，无法将差异纯粹归因于流规模；128k 的构建阶梯仅基于一个对话快照。
- **单次抽取**：记忆构建采用单次运行（主要为控制 API 成本），论文明确披露了相同配置不同运行间存储形态的巨大方差（2 文件 vs 29 文件），这意味着对“形状”的结论应视为趋势而非定律。
- **模型代际约束**：实验基于 gpt-5.4 / gpt-4.1 系列，结论对更强/更弱的模型外推时需谨慎；论文自身也发现管理能力存在阈值效应，提示可能存在模型能力拐点。
- **评测面有限**：未覆盖多智能体共享存储、并发写入冲突、记忆删除与遗忘策略、安全/隐私维度（记忆库中的敏感信息）等现实部署问题。
- **无明确缓存率假设**：成本核算给出了“完美缓存”与“无缓存”的边界，但真实部署的缓存命中率取决于具体流量模式，实际成本落在区间内的位置未知。

## 9. 与相关工作的关系及定位

- **区别于记忆表示研究**：MemGPT 的分页上下文、Mem0 的事实库、Memoro 的时序知识图谱、MemOS 的嵌套记忆、A-MEM 的笔记网络、Zep 的摘要库、Letta 的话语单元库、MemInsight 的嵌入组织树等，均将记忆设计为专门数据结构并配套定制检索器；本文反其道而行，承认工业界默认的“树状文件 + 通用工具”本身就是一种值得系统研究的媒介，且证明其竞争力不逊于定制化方案。
- **区别于 RAG 研究**：分块检索（Chunk retrieval）基线代表标准 RAG 上限，而文件系统记忆是“结构化、可重组、可导航”的检索，论文展示了二者的成本与正确率差异。
- **区别于记忆管理（memory editing）研究**：现有工作关注单次写入的更新策略（如删除、改写冲突信息），本文首次把“持续维护一个存储库的组织结构”当作一个独立智能体任务来形式化，并给出分类契约作为可检验的组织质量指标。

## 10. 核心贡献总结

1. **首次系统性研究文件系统记忆**：将工业界默认配置从背景假设提升为实验变量，填补了学术空白。
2. **形式化框架**：管理/搜索/执行三智能体角色划分 + 分类契约（P1–P5），为后续研究提供了通用分析语言。
3. **大规模多轴实证**：覆盖 4 个会话基准 + 140 个具身技能任务 + 6 种记忆变体 + 4 个对照维度，同时报告质量、成本与存储健康三方指标，并给出带 p 值的配对检验。
4. **反直觉的核心发现**：形状不买正确性但买检索成本；管理能力只买风格不买答案；技能场景存在消费方依赖的胜负反转；工具集改变行为不改变结果。
5. **可操作设计指南**：从整理/检索预算划分到静默压缩防护，直接服务于工程实践。

## 11. 总体评价

这是一篇**面向真实系统、方法严谨、结论诚实的探索性研究**。它的价值更多在于“重新定义了问题空间”而非“给出最终答案”：它证明了文件系统记忆不是工程上的权宜之计，而是一个拥有独特组织动力学的研究对象；同时它以罕见的坦诚披露了自身结论的统计局限与运行方差。对于任何正在构建长期 LLM 智能体记忆层的工程师或研究者，本文的框架（三角色 + 分类契约）、成本分析方法和反直觉结论（如“整理主要为检索买单”“管理能力不买正确率”）都提供了直接可用的参考坐标。其最值得后续跟进的方向包括：更大规模与更多对话下的增长研究、并发多智能体存储、以及把分类契约转化为自动评估指标。
