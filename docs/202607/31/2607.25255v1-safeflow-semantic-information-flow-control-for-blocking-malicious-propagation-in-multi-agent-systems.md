## 摘要
多智能体系统通过任务分解和角色专业化提升了能力，但这些机制也引入了一个重要的安全盲点：一个有害目标可以被分解为局部看似合理的子任务，使恶意意图能够逃避任何单个智能体的检测。这是一个日益严重的社会影响挑战：处理敏感信息或关键工具的系统可能将日常委派转变为未经授权的泄露或不安全行为。我们认为，这种失败模式更适合被理解为语义信息流问题，而非单轮提示分类任务。为解决此问题，我们提出了SafeFlow，一种针对多智能体系统的防御框架，将恶意的跨智能体传播形式化为语义信息流问题。SafeFlow将结构化语义污点附加到根请求上，通过动态协作图传播它们，并在不可逆操作执行前执行工作流级验证以重建全局风险上下文。在涵盖提示注入、越狱式不安全工具使用、危险代码执行和有害Web智能体行为的四个基准测试上，与未防御基线和外部防御相比，SafeFlow降低了攻击成功率，同时保持了高良性任务完成率和高成对安全-有害成功率。我们的研究结果表明，多智能体系统仍然缺乏在委派边界上保留风险语义的机制。这一差距可能将日常委派转变为影响个人和组织的隐私损害或不安全行为。SafeFlow在整个工作流程中保持这种风险可见，直到其造成损害之前。

## Abstract
Multi-agent systems improve capability through task decomposition and role specialization, but these same mechanisms introduce an important safety blind spot: a harmful objective can be fragmented into locally plausible subtasks, allowing malicious intent to evade detection by any single agent. This is a growing social-impact challenge: systems handling sensitive information or consequential tools can turn routine delegation into unauthorized disclosure or unsafe action. We argue that this failure mode is better understood as a semantic information-flow problem than as a single-turn prompt classification task. To address this, we propose SafeFlow, a defense framework for multi-agent systems that formalizes malicious cross-agent propagation as a semantic information-flow problem. SafeFlow attaches structured semantic taints to root requests, propagates them through a dynamic collaboration graph, and performs workflow-level validation to reconstruct the global risk context before irreversible actions are committed. Evaluated on four benchmarks spanning prompt injection, jailbreak-based unsafe tool use, risky code execution, and harmful web-agent behavior, SafeFlow reduces attack success rates compared to undefended baselines and external defenses while retaining high benign task completion and a high paired safe--harm success rate. Our findings show that multi-agent systems still lack mechanisms for preserving risk semantics across delegation boundaries. This gap can turn routine delegation into privacy harms or unsafe actions that affect people and organizations. SafeFlow keeps this risk visible throughout the workflow, before it results in harm.

## 2. 方法论：核心思想、关键技术细节与算法流程

- **核心思想**：SafeFlow 将恶意跨代理传播形式化为语义信息流问题，通过**结构化污点标签**在动态协作图中传播，并在硬性“汇点”（如外部发送、特权执行、破坏性写入）处进行**延迟裁决**，只有全局路径满足安全条件时才放行。
- **系统模型**：运行时定义为 \(M = (A, U, T, O)\)，包括智能体集合、工具接口、规划器、可观测执行通道；攻击者不控制模型权重和源码，只通过恶意指令和检索内容操纵工作流。
- **污点语义与标签体系**：
  - 默认使用 7 个标签：`SENSITIVE_READ`、`CREDENTIAL_ACCESS`（保护源）；`EXTERNAL_SEND`、`PRIVILEGED_EXEC`、`CODE_EXEC`、`DESTRUCTIVE_WRITE`（硬汇点）；`PROMPT_OVERRIDE`（控制面覆盖）。
  - 标签随传播保持单调，直到显式的释放规则在硬汇点被满足；模型生成的解释只能提供证据，不能消除污点。
- **五阶段流水线（SafeFlow Architecture）**：
  1. **意图污点标注**（Intent Taint Annotation）：结合词法匹配、受限LLM分类器和工具启发式，为根请求生成结构化污点标签；LLM只能输出预设 schema 内的标签，不能发明释放条件。
  2. **规划与污点传播**（Planning and Taint Propagation）：规划器生成任务骨架后，`PropagateTaints` 确定性地构造带污点的协作图，并将硬汇点暂存，直到验证通过。
  3. **上下文重建**（Context Reconstruction）：为每个节点用 LLM 聚合上游消息、工具事件和污点继承，生成结构化视图，用于后续规则检查。
  4. **全局验证**（Global Validation）：聚合所有局部结果后，`ValidateWorkflow` 基于图结构、污点传播和暂存汇点，确定性地执行源-汇规则，做出最终的放行/拦截决策。
  5. **归因决策**（Attribution-Aware Decision）：记录关键路径、触发污点、汇点类型和未满足的释放条件，输出可审计的归因报告。
- **释放规则（Declassification）**：硬汇点只有在同时满足“任务必要性”“目标授权”且不匹配任何禁止模式时才会被提交；否则保持拦截。
- **关键设计**：**延迟裁决**——许多攻击只有在多个局部合理动作组合成完整路径后才变得明确，因此 SafeFlow 不依赖单点拒绝，而是保留跨节点风险证据。

## 3. 实验设计：数据集 / 场景、Benchmark 与对比方法

- **数据集与场景**：四个对抗性基准，每个基准使用固定 110 个实例，共 440 个有害工作流：
  - **ASB**（Agent Security Bench）：提示注入；
  - **AgentHarm**：越狱式不安全工具使用；
  - **RedCode**：危险代码执行；
  - **SafeArena**：有害自主 Web 智能体行为。
- **目标模型**：默认防御侧模型为 DeepSeek-V3.2-Exp；模型敏感性实验中额外测试了 o4-mini、MiMo-v2.5、Kimi-K2.6、Claude-3.5-Haiku、GPT-5-mini。
- **对比方法**：
  - 未防御工作流：**SafeAgents**；
  - 外部防御：**GuardAgent**、**AutoDefense**、**AegisLLM**；
  - SafeFlow 与所有基线使用相同的归一化输入和运行时可观测工件，不依赖特权信息。
- **评价指标**：攻击成功率（ASR）、任务完成率（TCR）、误报率（FPR）、配对安全-有害成功率（Paired）。
- **鲁棒性测试**：

## 6. 主要结论与发现

- SafeFlow 在多智能体系统中将恶意传播建模为语义信息流问题，通过结构化污点传播和全局延迟验证，能够有效阻断跨智能体的恶意链。
- 在四个基准上，SafeFlow 将平均 ASR 从未防御的 **69.3%** 降至 **12.7%**，同时保持约 **90% 以上的 TCR** 和最高的配对安全-有害成功率（ASB 81.5%、AgentHarm 78.6%、RedCode 80.8%、SafeArena 75.1%）。
- 在越狱攻击下，SafeFlow 仍保持最低 ASR（JailBroken 下 32.3%，远低于未防御的 85.5%）。
- 防御侧模型敏感性低：不同 LLM 下 ASR 均在 8%–12.7% 范围内，说明主要收益来自工作流级管道而非特定模型。
- 消融结果显示：**污点传播（TP）是最关键组件**，移除后 ASR 显著上升；全局验证和上下文重建也各有不可替代的作用。
- 多智能体系统普遍缺乏跨委派边界保留风险语义的机制，SafeFlow 使风险在造成实际危害前保持可见并可拦截。

## 7. 优点

- **视角新颖**：将多智能体安全从“单点提示分类”提升为“信息流控制”，更贴合真实攻击模式。
- **设计合理**：延迟裁决让系统只在完整源-汇路径成立时才拦截，避免过早误伤；结构化标签和确定性规则保证了可审计性。
- **实用性较强**：不依赖特权信息，只使用共享运行时的工件；新增领域只需扩展标签 schema 和规则即可上线。
- **实验扎实**：涵盖了多类攻击、多个防御模型、消融、策略敏感性、自适应攻击、间接注入和统计检验，验证了方法的鲁棒性和可移植性。
- **性能平衡好**：在显著降低 ASR 的同时，保持了较高的良性任务完成率和较低的误报率，配对成功率领先所有基线。

## 8. 不足与局限

- **实验规模与覆盖**：每个基准仅 110 个实例，样本量较小；未能覆盖真实生产环境中的复杂多智能体任务。
- **可观测性依赖**：SafeFlow 严重依赖运行时事件的可观测性；若存在未记录的消息边、隐藏工具调用或完全未插桩的组件，则可能漏报（论文在边界条件中也承认了这一点）。
- **防御侧 LLM 偏差**：意图标注和上下文重建依赖 LLM，存在标签遗漏或误标的风险；论文虽设定了封闭 schema，但 LLM 本身仍可能被间接注入影响。
- **计算开销**：每工作流额外 3.7 次 LLM 调用和 8.8 秒延迟，在某些实时系统中可能成为瓶颈。
- **误报风险**：标签 schema 扩展虽然降低 ASR，但会推高 FPR；论文报告 FPR 从 5.9% 升至 7.4%，说明存在过度拦截的可能。
- **未提供算力细节**：如 GPU 型号、数量、训练时长等资源信息缺失，影响复现性和能耗评估。
