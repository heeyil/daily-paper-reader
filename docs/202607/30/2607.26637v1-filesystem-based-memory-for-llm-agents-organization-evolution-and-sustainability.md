## 摘要
部署的LLM智能体越来越多地将其长期记忆以文件系统的形式存储：一个由智能体自身通过通用文件工具读取、写入和重组的markdown文件目录树。然而，研究大多忽视了这一介质：先前的系统设计定制化记忆表征并研究其检索，而未测试默认设置的两个工作假设：智能体能否在记忆积累、冲突和过时的情况下保持不断增长的存储有序，以及这种组织是否值得。我们首次对基于文件系统的LLM智能体记忆进行了系统探索。我们将这一设定形式化为围绕一个记忆文件系统的三个角色：管理智能体整合并组织进入的内容，搜索智能体用引用的来源回答查询，执行智能体提供任务轨迹并将其提炼为技能，从而在单一存储中统一陈述性记忆和技能。在长对话基准和具身任务中，我们改变记忆形态（智能体组织的层级结构、逐字转储、块检索）、流规模、工具集（沙盒shell、记忆工具风格函数、多样搜索工具）以及管理和搜索智能体的强度，跟踪随着记忆增长的回答质量、成本和存储健康状态。组织可靠地带来的收益是搜索经济性：在有大量材料时，有组织的存储大约能将检索成本减半。然而，当今的智能体未能达到默认设置的承诺：在我们的增长研究中，除最强的管理智能体外，所有智能体的组织性都在下降，并且我们衡量的任何智能体都未能将组织本身转化为更好的答案。并且，模型并非影响存储形态的唯一杠杆：仅改变工具集就能像更换模型一样显著重塑存储。这项研究将文件系统默认设置从一个假设转变为智能体记忆的设计空间。

## Abstract
Deployed LLM agents increasingly keep their long-term memory as a filesystem: a directory tree of markdown files that the agent itself reads, writes, and reorganizes through generic file tools. Yet research has largely passed over this medium: prior systems design bespoke memory representations and study retrieval over them, leaving the default's two working assumptions untested: that an agent can keep a growing store organized as memories accumulate, conflict, and go stale, and that this organization pays. We present the first systematic exploration of filesystem-based memory for LLM agents. We formalize the setting as three roles around one memory filesystem: a management agent integrates and organizes incoming content, a search agent answers queries with cited sources, and an execution agent supplies task trajectories that are distilled into skills, unifying declarative memory and skills in a single store. Across long-conversation benchmarks and embodied tasks, we vary memory shape (agent-organized hierarchy, verbatim dump, chunk retrieval), stream scale, tool harness (sandboxed shell, memory-tool-style functions, varied search tooling), and the strengths of the management and search agents, tracking answer quality, cost, and store health as memory grows. What organization reliably buys is search economy: organized stores roughly halve retrieval cost where material is large. Today's agents, however, fall short of the default's promise: in our growth study, organization erodes for all but the strongest management agent, and no agent we measure converts organization itself into better answers. And the model is not the only lever over a store's shape: changing the tool set alone reshapes the store as strongly as swapping the model. The study turns the filesystem default from an assumption into a design space for agent memory.

# 基于文件系统的 LLM 智能体记忆：组织、演化与可持续性——中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：部署的 LLM 智能体（如 Claude Code、Anthropic Memory Tool）越来越多地将长期记忆以**文件系统**的形式存储——一个由智能体自身通过通用文件工具读写、重组的 Markdown 目录树。这一做法已成行业默认，但学术界主要研究定制化的记忆表征（如事实库、知识图谱、嵌入树等），而忽略了文件系统这一“默认”介质。
- **核心问题**：两个未经验证的假设：  
  - **组织可持续性**：智能体能否在记忆不断积累、冲突、过时的情况下，保持存储的有序性？  
  - **组织价值**：这种有组织的存储结构是否真正降低了搜索成本或提升了答案质量？
- **研究意义**：将文件系统默认设置从一个“未经检验的假设”转化为一个**可设计、可评估的设计空间**，为更持久、更智能的代理记忆系统提供实证基础。

## 2. 方法论

- **核心思想**：形式化三个角色围绕**同一个文件系统存储**：
  1. **管理代理 (Management Agent)**：负责整合每个输入块（chunk）并持续维护存储的组织结构（创建、编辑、合并、拆分、移动文件）。
  2. **搜索代理 (Search Agent)**：负责回答查询，需提供引文（文件路径+行号），且只能通过文件工具（grep、view、toc、section_read）导航结构。
  3. **执行代理 (Execution Agent)**：在技能设置中出现，接收检索到的技能并执行任务，其轨迹被管理代理提炼为新的技能。
- **关键技术细节**：
  - 存储的“组织契约”定义为五条属性：兄弟区分性、兄弟相关性、父子覆盖性、树距离—内容相关性、结构服务于搜索而非自身。
  - 文件具有 YAML frontmatter（name, description, metadata），描述是检索的表面标识。
  - 实验变化四个维度：**记忆形状**（管理代理构建的层次、逐字转储、块检索）、**流规模**（对话长度/任务数）、**工具集**（内存工具函数、沙盒 shell、BM25 搜索）、**模型强度**（gpt-5.4-nano/mini/full）。
- **成本追踪**：记录每一轮 token（uncached/cached/output）、工具调用次数、存储大小。
- **健康指标**：文件/文件夹/节数、交叉引用数、树形度量（深度、扇出、内容相关性与树距离的 Spearman 相关等）。

## 3. 实验设计

- **数据集与场景**：
  - **对话记忆**：LoCoMo（1个测试对话，158个问题）、PersonaMem（32k 和 128k 层级）、REALTALK（1个对话，85个问题）。
  - **技能记忆**：ALFWorld（140个家务任务，6个目标家族）。
- **对比方法**（六种记忆变体）：
  - **Closed-book**：无存储，纯参数知识。
  - **Chunk retrieval**：对话分块索引（BM25），检索 top-3 块全文。
  - **Verbatim dump**：逐会话原样存储，零组织成本。
  - **Foldered sessions**：将动词转储文件放入 LLM 设计的分类文件夹，文件内容不变。
  - **Reorganized store**：LLM 对动词转储进行重构（分为 condense 和 preserve 两个版本）。
  - **Agent-curated store**：管理代理从空开始逐块构建和组织，是“完整组织”代表。
- **技能设置额外变体**：
  - **Episode log**：逐任务附加原始轨迹。
  - **Curated skills**：管理代理提炼技能文件。
  - **Curated skills+mem**：增加记忆笔记（教训、警告），并设“成功门”（只有成功尝试才能创建正技能）。
  - **Curated skills+mem (GS)**：检索时不再是返回文件，而是搜索代理**撰写任务专用指导**（guidance synthesis）。
- **评估指标**：对话：正确性（裁判模型或精确匹配）与归因（引文支持）。技能：环境报出的任务成功率和部署成本。

## 5. 实验数量与充分性

- **实验数量**：
  - **对话设置**：四个基准上六种变体 → 约 24 个主要细胞（每个包含数十至数百个问题）。
  - **技能设置**：两个执行代理强度 × 五种变体（三链协议）+ 完整链的多种变体（工具集、模型强度）→ 约 15–20 个细胞（每个 140 任务）。
  - **消融与扩展**：
    - 模型强度网格：3×3（3 个管理代理 × 3 个搜索代理）在 PersonaMem 128k。
    - 工具集对比：三种工具集在对话和技能上。
    - 可持续发展：完整链的逐任务快照（140 步，记录存储变化、成本曲线）。
    - 额外审计：错误答案的溯源（PersonaMem 32k 失败分析）、重构稳定性验证（同一配置重跑产生不同形状）。
- **充分性评价**：
  - **优点**：覆盖了不同基准、不同规模、不同模型强度、不同工具集，并提供了增长曲线而非终点单点。实验设计系统且清晰。
  - **局限**：对话基准仅有一个对话长度（时间跨度最多几十轮/几十字节），**远未达到“月级”记忆的考验**。所有实验基于单一 API 模型家族（gpt-5.4），通用性有限。重跑变化表明单次运行结果存在一定噪声（约 ±1–2 题）。质量基准对工具集引起的形状变化**几乎不敏感**，使得关于存储形状的结论受限。PersonaMem 32k 上 curated store 的失败未得到完全解释（假设是管理代理的能力限制，但搜索侧尚未测试）。

## 6. 主要结论与发现

1. **组织可靠地降低搜索成本**：尤其是在材料庞大时，有组织的存储可将检索费用减半。这一收益随材料体积增长而扩大。
2. **组织不直接提升答案质量**：没有任何一种存储形状在所有基准上获胜。Agent-curated 存储仅在 LoCoMo 上领先，在 PersonaMem 32k 上最差（37.5% vs 动词转储的 78.1%）。
3. **管理代理能力与质量解耦（对话）**：在固定搜索代理下，更换管理代理模型（nano/mini/full）几乎不影响正确性（73.8→66.7→71.4），但会极大改变存储形状。
4. **搜索代理能力与质量强相关（对话）**：在相同存储下，搜索代理越强答案越好（约 62→71→79%）。
5. **技能设置中执行代理强度决定记忆**：强执行代理（gpt-4.1）偏好原始轨迹日志（Episode log 87.1%）；弱执行代理（gpt-4.1-mini）则依赖合成指导（GS 76.4%），且记忆对弱执行代理价值更大（提升 23.5% 对 13.5%）。
6. **工具集是非中性杠杆**：仅更换工具集（从文件函数到 shell）可改变存储形状（如 PersonaMem 128k 从 2 个文件变为 147 个），但质量几乎不变或仅在小范围内变动。
7. **增长帮助而非伤害**：在 140 任务完整链中，所有变体的成功率随积累上升；早期记忆几乎全部存活；存储成本随记忆形式分化（日志型线性增长，综合指导型平台化）。
8. **管理代理能力是“组织维持”的瓶颈**：只有最强的管理代理能保持组织契约的遵守；其余代理的组织性随时间侵蚀。

## 7. 优点

- **首次系统研究文件系统记忆**：填补了“默认介质未被探索”的空白，将行业实践转化为可操作的设计空间。
- **形式化角色分解**：管理/搜索/执行的分离简洁且通用，可映射到现有生产系统（如一个模型可充当所有角色）。
- **实验设计多维且系统**：同时变化四个轴（形状、规模、工具集、模型能力），并提供增长曲线而非终点值。
- **跨设置统一验证**：在对话记忆和技能记忆两种场景下使用完全相同的存储类和角色契约，验证结论的普适性。
- **注重成本与健康**：不仅报告成绩，还量化了构建和部署成本（token、美元），以及存储的健康状态（文件存活率、组织属性等），使结论更具工程实践意义。
- **工具集作为设计杠杆的识别**：发现工具集对存储形状和结果有强烈影响，为未来设计提供了调控手段。

## 8. 不足与局限

- **实验规模有限**：对话测试仅为单次对话（最多 113k 词元），不足以评估数月甚至年间的记忆演化。
- **基准对形状不敏感**：在对话任务上，即使存储形状差异巨大（2 文件 vs 147 文件），答案质量几乎相同，限制了关于组织价值的结论。
- **模型家族单一**：所有实验基于一个 API 模型系列（gpt-5.4），不排除其他模型（如 Claude、Gemini）可能表现不同。开放性权重模型未包含。
- **单次运行噪声**：作者明确指出同一配置在不同运行时可能产生完全不同的文件计数（如 Center+BM25 在 LoCoMo 上运行两次产生 2 和 29 个文件），表明部分结论存在随机性。
- **管理代理能力与搜索代理能力的不对称分析不完整**：PersonaMem 32k 上 curation 失败的原因部分归于管理代理，但搜索侧假设未完全验证（仅初步测试了升级管理代理的效果）。
- **未探索长期遗忘与衰减**：虽然测试了 140 任务增长，但未模拟数月后记忆“自然消亡”或“内容腐烂”的情况。组织维护带来持续成本（每块 6–12 轮，不随存储增长而减少）。
- **未涉及记忆隐私、安全性或幻觉管理**：文件系统存储可能被其他进程访问或污染，论文未评估此类风险。
