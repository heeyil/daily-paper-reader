## 摘要
针对不同成本-质量权衡的大语言模型（LLM）进行路由选择已成为企业AI的基本部署特性。现有路由器主要对每次LLM调用做出独立路由决策。然而，智能体应用程序作为长期工作流执行，其质量仅由延迟的任务级结果决定。这种不匹配导致每次调用路由器无法正确地将反馈归因于单个路由决策。为解决此问题，我们提出了TRACE-Router，一种任务级路由框架，使路由与监督单元对齐。TRACE-Router在任务接入时利用上下文赌博机为每个任务分配一次模型，将所有后续LLM调用固定到所选后端，并使用任务的终端奖励更新其策略，同时考虑准确性和延迟。通过利用延迟的任务反馈，TRACE-Router学习适应工作负载的路由策略，同时避免显式任务复杂性估计。在三个智能体基准测试中，TRACE-Router持续改善准确率-延迟权衡，实现非支配的帕累托前沿点。在tau2-Bench上，它比单个模型的延迟匹配插值高出7-8个准确率点，而在Terminal-Bench上，它以36%更低的延迟比最强单模型基线高出7.1个准确率点。

## Abstract
Routing to select large language models (LLMs) with different cost-quality trade-offs has become a fundamental deployment feature of enterprise AI. Existing routers, primarily make independent routing decisions for each LLM call. However, agentic applications execute as long-horizon workflows whose quality is determined only by a delayed, task-level outcome. This mismatch prevents per-call routers from correctly attributing feedback to individual routing decisions. Towards mitigating this, we present TRACE-Router, a task-level routing framework that aligns routing with the unit of supervision. TRACE-Router assigns each task to a model once at admission using a contextual bandit, pins all subsequent LLM calls to the selected backend, and updates its policy using the task's terminal reward, jointly accounting for accuracy and latency. By leveraging delayed task feedback, TRACE-Router learns routing policies that adapt to the workload while avoiding explicit task-complexity estimation. Across three agentic benchmarks, TRACE-Router consistently improves the accuracy-latency trade-off, achieving non-dominated Pareto frontier points. On tau2-Bench, it outperforms latency-matched interpolation between individual models by 7-8 accuracy points, while on Terminal-Bench it achieves 7.1 higher accuracy points than the strongest single model baseline with 36% lower latency.

# TRACE-ROUTER: 面向智能体AI的任务一致性与自适应在线路由 —— 详细总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：现代LLM部署中使用异构模型池，小模型低延迟低成本，大模型高准确率高成本。没有单一模型始终最优。因此，路由（routing）成为LLM部署的核心原语，即对于每个请求动态选择最佳模型。
- **现有方法的局限**：几乎所有现有路由器都基于请求级（request-level）抽象：给定一个提示，选择哪个模型回答。这对于单轮推理是合适的，但对于**智能体工作流（agentic workloads）** 却是错误的粒度。智能体任务是一个有状态的执行轨迹，包含多次LLM调用、工具使用、检索、验证和环境交互。如果每次LLM调用独立路由，可能产生全局次优结果：一个中间简单调用被路由给小模型，可能中断之前大模型积累的状态，而最终任务成败取决于整个轨迹。更根本的问题是，任务成功或失败只在终点观测到，产生单一的延迟结果，需要归因于整个执行过程中的所有路由决策。现有方法缺乏原则性的信用分配机制，无法从任务级反馈中有效学习。
- **核心洞察**：**路由的单位应与反馈的单位匹配**。在智能体工作负载中，反馈本质上是任务级的（程序是否通过测试、环境目标是否达成、裁判给出最终分数），而贯穿整个轨迹的决策是唯一能被该信号明确归因的最细粒度选择。
- **目标**：提出一种任务级路由框架TRACE-Router，通过在线模型选择，使路由决策与任务级反馈对齐，学习准确率-延迟的最佳权衡。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：将整个任务轨迹作为路由和学习的单位。在任务首次出现时做出一次模型选择决策，将该任务的所有后续LLM调用固定到所选后端（任务一致性），并在任务终止时使用最终的准确率和端到端延迟产生的延迟奖励更新做出原始决策的策略。
- **关键技术细节**：
  - **任务一致性路由（Task-Consistent Routing）**：
    - 模型池 \(M = \{1,\dots,K\}\)，任务 \(t\) 产生执行轨迹 \(\Pi_t = (q_{t,1}, q_{t,2}, \dots, q_{t,H_t})\)。
    - 智能体框架为每个请求附加持久任务标识符 \(\kappa_t\)。路由器维护活动任务表 \(A\)，映射 \(\kappa_t\) 到记录 (context= \(c_t\), model= \(m_t\))。
    - 对于每个新任务，路由器选择后端并记录；对于进行中的任务，直接复用存储的后端。这使得整个任务使用同一个模型，防止跨模型状态失效，并提供单一信用分配目标。
  - **上下文条件化模型选择（Context-Conditioned Model Selection）**：
    - 为了处理不同任务可能对模型有不同偏好（有些强调延迟，有些强调准确率），引入离散任务上下文。使用一个上下文函数 \(g\) 将初始任务描述映射到有限上下文集合 \(C\)（如EASY, MEDIUM, HARD）。本文使用精简的基于正则表达式的复杂度分类器，无需模型调用、无需嵌入、无需训练数据。
    - 每个上下文 \(c\) 维护独立的多臂赌博机 \(B_c\)，拥有自己的选择分布 \(\pi_c\)。新任务在上下文 \(c_t\) 下采样 \(m_t \sim \pi_{c_t}(\cdot)\)，且反馈只更新对应的赌博机。
  - **冷启动上下文UCB（Cold-Start Contextual UCB）**：
    - 每个赌博机 \(B_c\) 维护每臂的拉取计数 \(N_{c,m}\) 和奖励和 \(S_{c,m}\)。
    - 冷启动：每个上下文的前 \(k|M|\) 个任务采用轮询方式强制探索（本文 \(k=1\)，即每臂1次强制拉取），然后使用UCB选择：\(m_t = \arg\max_m \left[ \hat{\mu}_{c,m} + \sqrt{\frac{2\log(1/\delta)}{N_{c,m}}} \right]\)，其中 \(\delta\) 是固定置信参数（默认0.1）。
    - 选择UCB而非ε-贪婪或汤普森采样，因其探索强度在多个基准上稳定。
  - **任务级准确率-延迟奖励（Task-Level Accuracy-Latency Reward）**：
    - 任务完成后，获得分级准确率 \(a_{t,m} \in [0,1]\) 和端到端延迟 \(\ell_{t,m}\)。延迟归一化并截断到 \([0,1]\)：\(\tilde{\ell}_{t,m} = \min(\ell_{t,m}/\ell_0, 1)\)。
    - 构造奖励 \(r_{t,m}^{(\alpha)} = (1-\alpha) a_{t,m} - \alpha \tilde{\ell}_{t,m}\)，其中 \(\alpha \in [0,1]\) 是权衡参数。不同\(\alpha\)维护独立的策略状态，观测不共享。
  - **延迟信用分配（Delayed Credit Assignment）**：
    - 任务终止后，根据任务ID查找上下文和后端，仅更新对应上下文-后端对的统计量。任务从活动表移除。对于并发工作负载，进行中的任务保留其到达时选择的后端，更新按照完成顺序进行。

- **算法流程**（文字说明）：
  1. 初始化：每个上下文的每臂计数和奖励和为0。设置\(\delta\)，\(\alpha\)，\(k=1\)，上下文函数\(g\)。
  2. 对于每个新任务\(t\)：
     - 提取初始描述\(x_t\)，计算上下文\(c_t = g(x_t)\)。
     - 如果上下文\(c_t\)的赌博机处于冷启动阶段（总拉取次数小于\(k|M|\)），则按轮询分配臂；否则根据UCB公式选择臂\(m_t\)。
     - 将\((c_t, m_t)\)存入活动任务表\(A\)。
  3. 任务执行过程中，每个请求携带\(\kappa_t\)，路由器从\(A\)读取后端并转发。
  4. 任务完成后，获取准确率\(a_{t,m_t}\)和延迟\(\ell_{t,m_t}\)，计算奖励\(r_{t,m_t}^{(\alpha)}\)。
  5. 从\(A\)恢复上下文\(c_t\)和后端\(m_t\)，更新统计：\(N_{c_t,m_t} \leftarrow N_{c_t,m_t}+1\), \(S_{c_t,m_t} \leftarrow S_{c_t,m_t} + r_{t,m_t}^{(\alpha)}\)。
  6. 从\(A\)中移除该任务。

## 6. 主要结论与发现

- **准确率-延迟前沿显著改善**：
  - τ2-Bench平均：TRACE-Router占据帕累托前沿内部点（55.2%, 57.6%, 61.2%准确率，对应25.4-26.4秒延迟），所有学习和启发式基线被支配。
  - 超过延迟匹配随机混合7-8个准确率点。
  - α=0策略（纯准确率）用67%的延迟差距捕获了90%的准确率差距。
  - 在电信领域，小模型（Qwen3.5-4B）准确率仅10.5%，延迟30.2秒，大模型60.5%准确率，延迟32.7秒，而TRACE-Router α=1（纯延迟）达到39.0%准确率，30.0秒延迟，同时更快更准确。
  - Terminal-Bench：TRACE-Router α=0.75解决46.8%任务，延迟172秒，对普通大模型（39.7%, 270秒）准确率高7.1点且延迟低36%，接近准确率oracle (48.0%)的1.2点内。路由在这里严格优于任一单独模型。
- **上下文条件化并非提高平均太多，但决定哪些点可达**：上下文条件化比上下文无关通常高1-2点，但关键差异在于上下文无关的某些α点被支配，而条件化的点保持前沿。
- **冷启动优于热启动**：热启动（带先验）在准确率上相近，但系统性地选择更慢的模型（因为先验偏好模型被确认后难以被推翻），导致延迟位置更高。冷启动更快适应互补模型，因此默认冷启动。
- **UCB比ε-贪婪和汤普森采样更稳定**：UCB在三个基准上最优参数区间一致（\(\delta \in [0.5,0.8]\)），而ε-贪婪最优参数随基准变化大。默认δ=0.1虽非最优，但性能合理。

## 7. 优点

- **问题定义明确**：指出现有请求级路由与智能体工作流任务级反馈的根本不匹配，提出“路由单位应与反馈单位匹配”的基本原则。
- **方案简洁实用**：TRACE-Router采用上下文赌博机，无需离线训练、无需显式任务复杂度估计、无需额外模型调用。上下文分类器仅用正则表达式，零增加接入延迟。
- **任务一致性机制**：通过持久化任务标识符和活动表，实现全轨迹单模型绑定，使信用分配清晰，同时兼容并发服务栈。
- **灵活的权衡**：通过扫描\(\alpha\)参数产生一组帕累托最优政策，适应不同部署偏好。
- **全面的实验验证**：覆盖多个领域和任务规模，与多种基线对比，消融完整。特别对比了延迟匹配随机混合，展示了适应性带来的额外收益。
- **扩展到多模型**：在四模型场景中依然有效，体现可扩展性。
- **开源友好**：实现基于LiteLLM，易于集成。

## 8. 不足与局限

- **实验规模有限**：主要基准任务数量有限（τ2-Bench 114, Terminal-Bench 48, LiveCodeBench 300）。Terminal-Bench仅48个任务，统计稳定性可能不足（每个点约2.1点准确率波动）。
- **模型池限制**：主实验仅使用两个模型（相同家族的4B/9B或9B/27B），四模型实验仅部分基准。未测试不同家族、更大规模模型（如70B+）或更多类别下的性能。
- **上下文分类器简单**：正则表达式分类器虽然实用且零成本，但可能无法捕捉复杂任务差异。更精细的上下文（如嵌入聚类）可能提升效果，但作者声明结果可视为下界。
- **赌博机假设**：假设任务流内任务独立同分布，实际工作负载可能有时间相关或非平稳特性。未讨论非平稳环境下的适应性。
- **奖励定义局限**：奖励函数仅考虑准确率和延迟的线性组合，可扩展为多目标（如成本、安全性）。延迟归一化系数\(\ell_0\)需要手动设定，且截断可能丢失信息。
