## 摘要
Agent技能如今要么由人工编写，要么通过一次LLM生成过程产生，因此缺乏闭环，无法从它们实际引起的交互失败中改进。近期工作确实关闭了这一闭环，但其反馈来源于单轮问答评估。结果导致显著的不对称性：一旦第一轮修补了单次交互所能揭示的空白，演化梯度便会衰减，仅在多轮中才显现的缺陷仍不可见，演化陷入停滞。这些系统中的治理同样由端到端验证分数驱动，这是一个标量门控，可以拒绝退化的候选者，但既不能定位其结构成因，也不能修复它。我们认为，持续技能演化的约束条件既不是编辑能力，也不是迭代次数，而是评估反馈是否持续提供可信的演化梯度。我们引入了SkillEvo，其中可信反馈生成梯度，可控治理约束其方向。第一个组件将多轮用户模拟从评估端点重塑为反馈生成器：后续问题逐层暴露缺陷，使得每一轮修订既消费反馈又产生新反馈。第二个组件用独立的治理层替代标量门控的被动拒绝，主动修复事实退化和结构膨胀，防止梯度在退化累积时发生漂移。在六类云服务、9个生产技能和98个技能参考文件中，SkillEvo比基于自我反思的演化高出23.0个百分点，比单轮问答驱动的演化高出15.4个百分点。

## Abstract
Agent Skills are today either hand-authored or produced in a single LLM generation pass, and consequently possess no closed loop through which they might improve from the interaction failures they actually cause. Recent work does close this loop, but derives its feedback from single-turn question-answering evaluation. The consequence is a sharp asymmetry: once the first round has patched the gaps that a single exchange can reveal, the evolution gradient decays, the defects that surface only across multiple turns remain invisible, and evolution stalls. Governance in these systems is likewise driven by an end-to-end verification score, a scalar gate that can reject a degraded candidate but can neither localize nor repair its structural cause. We argue that the binding constraint on sustained skill evolution is neither editing capability nor the number of iterations, but whether the evaluation feedback keeps supplying trustworthy evolution gradients. We introduce SkillEvo, in which trustworthy feedback generates the gradient and controllable governance constrains its direction. The first component recasts multi-turn user simulation from an evaluation endpoint into a feedback generator: follow-up questions expose defects layer by layer, so that every round of revision both consumes feedback and produces new feedback. The second replaces the passive rejection of a scalar gate with an independent governance layer that actively repairs factual degradation and structural bloat, preventing the gradient from drifting as degradation accumulates. Across six categories of cloud services, 9 production Skills, and 98 skill-reference files, SkillEvo surpasses self-reflection-based evolution by 23.0 points and single- turn-QA-driven evolution by 15.4 points.

**现有方案的缺陷：**

| 现有方法 | 缺陷 |
|---------|------|
| 人工编写/维护 | 规模受限、延迟高、成本昂贵 |
| 单轮 LLM 生成 | 无闭环，无法从实际交互失败中学习 |
| Self-Refine 式自反思 | 无评估信号，无法区分真实缺陷与模型盲区 |

| 标量分数门控 | 能拒绝退化候选，但无法定位/修复结构性问题 |

**核心不对称性：** 单轮问答只能暴露用户开场白中呈现的缺陷；大量缺陷**仅在多轮交互（追问、澄清、抵抗）中才浮现**。第一轮修补后，单轮反馈梯度即告衰减，多轮才显现的缺陷永远不可见。

**治理层面的缺陷：** 现有系统用标量分数作为门控，但技能是**多文件有向图**（路由表 + 引用关系），损坏以知识膨胀、悬空引用、事实过度泛化等形式出现，**无法在标量分数空间中表达**，更无法针对性修复。

## 2. 方法论：SkillEvo 框架

SkillEvo 建立在两根支柱之上：**可信反馈生成（Trustworthy Feedback Generation）** 与 **可控技能治理（Controllable Skill Governance）**。

### 2.1 总体闭环流程

```
Scenario Synthesizer → User Agent → Verifier → Collective Attribution → Skill Optimizer → Skill Governor
```

七个步骤构成完整演化循环：
1. **场景合成器（Scenario Synthesizer）**：从真实人工处理工单提取意图议程、行为事实、情绪轨迹、人工参考解决方案，构成评估任务
2. **用户智能体（User Agent）**：与加载当前技能 $S_t$ 的服务智能体 $\pi(S_t)$ 进行多轮交互，产生轨迹 $\tau_t$
3. **验证器（Verifier）**：对照人工参考解决方案判定成功/失败，生成反馈 $(r_t, f_t)$
4. **集体归因（Collective Attribution）**：将失败分为三类——知识缺口、能力上限、评估噪声；**仅知识缺口**投影到反馈信号 $L_t$
5. **技能优化器（Skill Optimizer）**：执行**有界更新** $S_{t+1} = \text{Update}(S_t, L_t, S_0)$
6. **技能治理器（Skill Governor）**：独立检测结构退化（知识膨胀、引用断裂、事实过度泛化），发出建议
7. **检查点与版本选择**：在开发集上选择最优版本

### 2.2 可信反馈的三大必要条件

反馈信号 $L_t$ 可信当且仅当三个条件**同时成立**：

| 条件 | 内涵 | 实现机制 |
|------|------|---------|
| **覆盖度（Coverage）** $c_U = 1$ | 所有关键意图均已提出，模拟忠实 | **意图状态机**（Intent State Machine）：跟踪每个意图是否提出、是否实质解决；仅在全部满足时才允许正常终止 |
| **准确度（Accuracy）** | 暴露意图的判定对照人工参考 | **双侧重直评估**（Dual-Sided Orthogonal Evaluation），将责任分离 |
| **可归因性（Attributability）** | 根因可被技能修复 | **集体归因**（Collective Attribution）：知识缺口 vs 能力上限 vs 评估噪声三类分类 |

**关键设计：用户重建（Trustworthy User Reconstruction）**

从真实工单提取三类信息构建"受约束用户"：
- **意图议程**：核心请求与可选追问，标注 关键/次要，固定模拟用户应提出的内容
- **行为事实**：用户已持有的信息、已尝试的操作、可观察的症状——约束回复为真实信息，防止捏造
- **情绪轨迹**：合作程度波动与情绪转折点，使交互节奏真实化

目标是**任务级约束的真实主义**（防止意图遗漏、事实捏造、答案泄漏），而非复制真实用户的完整语言分布。

**双侧重直评估公式：**

模拟器侧：$c_U = |K_{asked}| / |K|$（意图覆盖度）

智能体侧：$s_C = h \cdot \frac{\sum_i w_i a_i}{\sum_i w_i}$，其中 $w_i = \alpha$（关键意图，$\alpha=0.7$）或 $1-\alpha$（次要意图）

$s_C$ 是**意图级**度量（判定已暴露意图的响应可靠性），而非端到端解决率。低 $s_C$ 恰好提供演化反馈。

**集体归因：**
- **知识缺口（Knowledge Gap）**：人工参考中的稳定事实被遗漏或错误作答 → **可修复，投影到反馈**
- **能力上限（Capability Limit）**：权限/工具限制、交付不善、基础设施故障 → **不可修复，隔离出循环**
- **评估噪声（Evaluation Noise）**：假阴性、场景失真 → **隔离出循环**

同一轮中多个失败常指向同一缺口，SkillEvo 通过语义相似度**合并所有知识缺口**为单一信号 $L_t = \text{Merge}(...)$，聚焦跨样本共性而非逐实例噪声。

### 2.3 可控演化的双重一致性

**事实一致性（硬约束）：** 修订后的技能必须保留生产基线的稳定事实：
$$\text{Facts}(S_t) \supseteq \text{Facts}(S_0) \cap S_{stable}$$

**双锚点检测：**
- $S_0$（生产基线）→ 检测跨轮累积的事实丢失
- $S_{t-1}$（上一轮）→ 检测本轮新引入的事实错误

双锚点解决单一锚点无法区分"修复方向"的问题：被删除的 $S_0 \rightarrow S_t$ 行定位应恢复的丢失事实；$S_{t-1} \rightarrow S_t$ 的变化行禁止回退到原始版本。违反即拒绝候选并触发同轮修复。

**结构一致性（软约束）：** 技能构成有向图（路由节点 → 知识节点，节点间交叉引用），连续修订在三个维度侵蚀：

| 退化类型 | 表现 | 标量分数能否感知 |
|---------|------|-----------------|
| 知识膨胀 | 节点内冗余增长，稀释路由精度 | ✗ |
| 引用断裂 | 节点间连接被切断：悬空引用、孤儿文件 | ✗ |
| 事实过度泛化 | 具体值/版本/规则退化为模糊表述 | ✗ |

软约束不丢弃修订，而是将治理建议与归因缺口**合并注入下一轮**，沿迭代序列逐轮消解退化。

## 7. 优点

### 方法层面

- **问题定义精准**：清晰识别"评估反馈质量决定演化天花板"这一核心瓶颈，而非盲目增加迭代次数
- **闭环设计完整**：真实工单 → 模拟用户 → 智能体对话 → 归因 → 信号 → 编辑 → 治理，全自动循环，无需手工构造场景
- **双侧重直评估巧妙**：模拟器与智能体的责任正交分离，防止模拟失真污染评估结论
- **集体归因合理**：仅将"知识缺口"类失败投影到反馈，隔离不可修复的噪声与能力限制
- **双锚点事实一致性**：$S_0$ 检测累积丢失、$S_{t-1}$ 检测新引入错误的双锚点设计，解决了单一锚点的修复方向歧义
- **有界修订**：证据边界（只修补已验证缺口）+ 参照边界（锚定生产基线）防止知识漂移
- **Generator ≠ Evaluator**：避免模型自审的循环依赖，是一个成本低而收益显著的架构决策

### 工程层面

- 已在腾讯云生产环境部署，有真实运营条件验证
- 术语表、提示词约束、超参数配置等完整记录，可复现性良好
- 伦理保障完善：数据去标识化、人工确认门槛、事实一致性硬约束

## 8. 不足与局限

### 实验与评估层面

- **数据集不可公开**：工单源自生产系统，受用户隐私与商业保密约束；虽论证方法可迁移，但无法独立复现验证
- **基线覆盖有限**：仅以 SkillForge 代表整个单轮 QA 范式层，缺乏与更多同类方法的直接横向对比
- **领域局限**：仅在腾讯云客服场景验证，未在非云服务、非客服场景测试方法的普适性
- **缺乏统计严谨性**：未报告多次运行的方差、置信区间或显著性检验
- **超参数均无敏感性扫描**：α=0.7、通过阈值 60、早停条件等均为部署管线既有设置

### 方法本身

- **模拟逼真度存在上限**：尽管保真度达 95.3%，但任务级约束现实不等于语言分布现实，"答案泄漏"与"意图遗漏"等风险仍可能残留
- **归因分类的误差风险**：知识缺口 vs 能力上限的边界在真实案例中可能模糊，错误分类会污染反馈信号
- **治理层的启发式性质**：结构性一致性依赖人工设计的三类退化和判定规则，非学得机制
- **四轮演化的饱和度未知**：TSR 在 R4 为 81.8 且仍在上升，未报告其是否到达新的饱和点

### 应用与部署限制

- **必须有真实工单作为种子**：方法依赖"有真实用户已暴露问题、有人工参考解决方案"的多轮咨询日志——冷启动场景可能不适用
- **人工确认仍是必要门槛**：论文明确承认，任何自动写入知识的框架都存在错误修订被服务给真实用户的风险；人工确认是

## 9. 综合评价与适用场景

### 方法论的最佳匹配场景

- **具备历史人工工单积累的领域**：客服、运维诊断、技术支持等已沉淀大量"问题→人工解决方案"配对日志的场景，可直接复用其提取"意图议程 + 行为事实 + 情绪轨迹"的做法
- **技能结构可显式建模的智能体**：以路由表、知识节点、交叉引用构成的多文件有向图技能，而非隐式参数化知识——只有显式结构才能支撑悬空引用、知识膨胀等治理检测
- **对知识漂移高度敏感的生产系统**：事实一致性硬约束适合知识错误代价高昂的企业环境（云服务、医疗、金融等）

### 需谨慎或不适用的场景

- **冷启动场景**：无真实工单种子则无法构建受约束用户；需先人工积累多轮咨询日志
- **开放式创作/探索型任务**：技能边界模糊，无法定义"人工参考解决方案"与稳定事实集，验证器与归因分类均失去锚点
- **超长生命周期演化**：四轮后的饱和度未知（R4 仍为上升趋势），且治理规则为人工设计的启发式，长尾退化模式可能超出三类预设的覆盖范围

### 总体判断

SkillEvo 的核心贡献不在于提出更强的编辑范式或更强的推理模型，而在于**系统性地重新定义了演化反馈的获取方式**——将多轮交互中才浮现的缺陷转化为可利用的学习梯度，并以治理层约束知识漂移。其核心洞见（评估信号的质量与可归因性决定演化天花板）对智能体持续学习领域具有普适迁移价值，即使具体实现（意图状态机、双侧重直评估、集体归因）与云客服场景深度绑定。

从证据强度看：主实验加双消融干净地分离了两个核心设计决策的各自贡献（多轮反馈 +15.4 分、治理层 −3.2 分防退化），这是论文最扎实的部分；但数据集不可公开、未报告方差与显著性、仅单领域验证，使其结论的普适性仍待外部独立复现。

**一句话总结：** SkillEvo 证明了一个朴素却常被忽视的命题——智能体技能持续演化的瓶颈不在"怎么改"，而在"怎么可信地知道该改什么"；而更真实、更深入的多轮交互评估，正是让演化梯度自我更新的关键。
