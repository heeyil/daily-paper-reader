## 摘要
长周期复杂任务要求智能体在持续变化的环境中反复观察状态、制定计划、调用工具、验证结果并从失败中恢复。然而，这种控制经验往往局限于单一情境或固定提示，难以在历史轨迹中积累和重用。本文提出了OpenLoopEvolve（OLE），一个以循环策略为中心的自进化框架。OLE将智能体的观察、规划、记忆、行动、验证、恢复、停止和预算控制表示为具有版本和谱系的可移植策略资产，并提供在线和离线两种进化模式，可根据实际需求选择：在线模式基于持续运行中的反馈触发候选策略生成，而离线模式则从存档轨迹和失败证据中搜索候选策略。两种模式共享一个进化机制，包括大语言模型的自主提案、冠军-挑战者配对评估和稳健发布。在线发布的策略在后续任务边界激活，使用后续反馈监控，并在满足降级条件时回滚到其父版本。在模拟业务基准YC-Bench上，两种模式相对于固定的初始循环策略都提高了整体任务性能、任务成功率和风险指标。结果表明，将循环策略视为可治理资产可以支持控制经验的积累、比较、发布和重用，并提高智能体在长周期复杂任务上的表现。

## Abstract
Long-horizon complex tasks require agents to repeatedly observe states, formulate plans, invoke tools, verify results, and recover from failures in continuously changing environments. However, such control experience often remains confined to a single context or a fixed prompt, and is difficult to accumulate and reuse across historical traces. This paper presents OpenLoopEvolve (OLE), a self-evolution framework centered on the Loop Policy. OLE represents an agent's observation, planning, memory, action, verification, recovery, stopping, and budget control as portable policy assets with versions and lineages, and provides online and offline evolution modes that can be selected according to practical needs: the online mode triggers candidate generation based on feedback from continuous operation, whereas the offline mode searches for candidate policies from archived traces and failure evidence. Both modes share an evolution mechanism consisting of autonomous proposals by a large language model, Champion--Challenger paired evaluation, and robust release. Policies released online are activated at a subsequent task boundary, monitored using subsequent feedback, and rolled back to their parent versions when degradation conditions are met. On the simulated business benchmark YC-Bench, both modes improve aggregate task performance, task success rate, and risk metrics relative to a fixed initial Loop Policy. The results indicate that treating the Loop Policy as a governable asset can support the accumulation, comparison, release, and reuse of control experience and improve agent performance on long-horizon complex tasks.

## 2. 论文提出的方法论

### 2.1 核心思想

OLE 框架将循环控制逻辑与宿主实现、单次运行上下文解耦，使策略可以独立地被存储、比较、发布和复用。其核心设计包括三个关键概念：

- **Loop Policy（循环策略）**：八元组结构 π = ⟨π_obs, π_plan, π_mem, π_act, π_ver, π_rec, π_stop, π_bud⟩，分别控制观察获取、计划更新、记忆使用、行动选择、结果验证、失败恢复、停止条件与预算分配，以 YAML 风格的外部可读格式表示。
- **Bundle（资产包）**：B_v = ⟨π_v, χ_v, ℓ_v⟩，其中 π_v 是循环策略，χ_v 是适用条件集合，ℓ_v 是版本谱系（含父版本索引与支撑证据）。Bundle 是策略演化的完整候选单元，通过稳定版本索引注册与追踪。
- **Trace（轨迹）与 Evidence（证据）契约**：轨迹 τ_i = (g_i, π_v(i), H_i, y_i) 记录任务、策略版本、交互历史和运行结果，保证绩效可归因；证据 ε_j = (ρ_j, δ_j, u_j, I_j) 进一步将轨迹提炼为带方向（正向/负向）、指标变化、目标组件和支撑轨迹索引的可测试演化依据。

### 2.2 共享演化机制

两种模式共用同一处理链：轨迹 → 证据构建 → LLM 候选生成 → 冠军-挑战者配对评估 → 稳健发布 → 后续任务边界激活。

- **配对评估**：在相同任务 g_i 和受控运行条件 z_i,j（保证落在 Champion 与候选 Bundle 适用条件交集内）下分别执行，计算价值分数差异：

  Δ_i,j = q(π_k,j; g_i, z_i,j) − q(π_c; g_i, z_i,j)

  以及相对变化 r_i,j = Δ_i,j / max{|q(π_c; g_i, z_i,j)|, ε}。

- **稳健发布门控**（Gate）：候选必须同时满足四类约束——收益（benefit）、证据质量（evidence quality）、尾部风险（tail risk）、资源成本（resource cost），即 Gate(P_k,j, Θ) = accept ⟺ ∏ Γ_α(P_k,j, Θ_α) = 1，且配置阈值不得放松任务契约中的验证与资源边界。

### 2.3 在线模式（Algorithm 1）

- 持续接收主机提交的可归因轨迹批次；先经 CANARYMONITOR 监测当前版本是否存在性能退化，若满足回滚条件则回滚至父版本并隔离相关轨迹。
- 满足触发条件（TrIg，可依据反馈量、周期或任务阶段）后，从可用轨迹提取证据 E，由 LLM 生成单个 Challenger Bundle，进行配对评估与门控判断。
- 通过门控的候选被记录为发布资产，**仅在后续任务边界激活**为新的 Champion，确保同一任务全程由同一策略控制、结果可归因。在线模式支持发布后监测与回滚机制。

### 2.4 离线模式（Algorithm 2）

- 以存档轨迹 D_off 和当前 Champion 为输入，先提取统一证据 E。
- LLM 围绕 Champion 自动生成初始候选集 C_1（每次 k=3 个候选），随后进行多代搜索：每代对候选Bundle 逐一执行配对评估，记录评估映射；通过**精英保留（Select）保留非支配候选**与 Champion 共同进入下一代；LLM 基于累积评估反馈对保留策略进行**突变与重组**生成新候选。
- 每代候选均以稳定版本索引注册并记录谱系关系（直接父版本 + 其他供体记入证据）。迭代 K 代（最多 4 轮）后，从通过发布门控的最终保留集中选取聚合价值分数最高的 Bundle 作为继任 Champion；若无合格候选则保持原 Champion。

### 2.5 在线与离线的区别与统一

- **在线模式**：证据来自最近运行反馈，单候选/轮，注重反馈及时性与版本可回滚；更新不中断当前任务，激活发生在任务边界。
- **离线模式**：证据来自存档轨迹，多候选、多代搜索，注重在受控评估环境下的集中探索。
- 两者统一遵循"证据 → 候选 → 配对评估 → 稳健发布 → 任务边界激活"的边界语义，候选生成属于搜索过程，只有通过验证的候选才能发布并进入执行路径。

## 3. 实验设计

- **基准（Benchmark）**：**YC-Bench**——模拟真实业务持续运营一年的长期规划与一致性执行基准，以最终资金衡量序列决策的累积效果（含任务选择、资源分配、风险管理）。
- **对比方法（4 种设置）**：
  - **Baseline（Native agent）**：使用官方 YC-Bench Agent Loop，不集成 OLE，也不加载额外循环策略。
  - **Fixed-π0（固定初始策略）**：加载与 OLE 相同的初始循环策略 π0，但整年保持不变，用于分离"引入策略"与"进化策略"的效应。
  - **OLE-online**：从 π0 出发，执行期间在线进化与更新，共进行 12 次候选更新尝试。
  - **OLE-offline（固定策略）**：实验前通过离线进化得到固定策略，评估期间不更新。
- **统一配置**：全部使用 deepseek-v4-flash 模型，官方 medium 配置，官方种子 seeds 1/2/3，20-turn context，从相同初始状态开始年度评估。
- **评估指标**：平均最终资金、任务成功率、年度生存率（3 个种子中的存活数）、平均最大回撤；另统计 token 用量与每调用平均 token 数。

## 6. 论文的主要结论与发现

- 在 YC-Bench 上，OLE-online 与 OLE-offline 相对于 Fixed-π0 分别将平均最终资金提升 **140.07%** 和 **166.31%**；任务成功率分别提升 **13.98** 和 **17.92 个百分点**（达到 87.87% 和 91.80%）。
- 年度生存率从 Fixed-π0 的 1/3 提升至 OLE-online 的 2/3 和 OLE-offline 的 3/3；平均最大回撤分别降低 **10.77%** 和 **38.30%**。
- 两种模式都优于固定的初始循环策略，且 OLE-offline 的固定策略在整体收益与风险指标上略优于 OLE-online。
- 尽管 OLE 模式的总 token 消耗更高，但每调用平均 token 数更低，且支撑了更长的执行周期（平均生存天数从 207.78 天提升至 294.00 天/365.00 天）；这说明循环策略在扩大持续执行规模的同时控制了单次交互的推理成本。
- 总体结论：将循环策略作为**可治理资产**，可支撑控制经验的积累、比较、发布与复用，显著改善长周期复杂任务上的智能体表现。

- **离线模式评估方式有限**：OLE-offline 以"实验前固定策略"的形态评测，只能证明离线搜索能在某一固定任务分布上找到更好的策略，不能说明离线策略在业务条件动态漂移时的适应能力；而 OLE-online 的 12 次更新尝试仅跨越 3 个种子，更新次数与候选探索规模都比较有限。
- **配对评估成本与公平性未充分讨论**：论文报告了配对评估消耗约 24–30M tokens，但对每次配对评估的候选-场景配对数量、回滚判定阈值（CANARYMONITOR 的具体触发条件）、以及门控各阈值的取值依据未作详细披露；配对评估假设同一 LLM 在相同受控条件下执行的可重复性，但 LLM 采样本身具有随机性，论文未报告多次重复评估的方差。
- **对"策略可迁移性"的验证偏弱**：论文强调 Loop Policy 是可移植、可复用的资产，但实验并未验证同一策略跨任务分布、跨模型或跨领域的迁移效果；发布策略在"后续任务边界激活"的语义也仅在 YC-Bench 的年度模拟中体现，缺少更复杂异构任务序列的验证。
- **理论基础与局限说明不足**：论文未讨论策略搜索空间的表示容量限制（即八元组 YAML 形式能否表达任意需要的循环控制逻辑）、LLM 作为候选生成器的偏差、以及策略版本谱系在长期演化中的膨胀与可维护性问题。
- **缺乏与代表性基线的直接对照**：实验中的对比设置均为"自家框架内部"的变体（Baseline、Fixed-π0、OLE-online、OLE-offline），没有与 Reflexion、ExpeL、Voyager、DSPy、AFlow 等既有方法在同一基准上做直接比较，因此"优于既有方法"这一隐含主张缺少实证支撑。

---

## 9. 总体评价与启示

总体而言，OLE 论文提出了一条有吸引力的技术路线：把智能体的完整"行动-验证-恢复-停止"闭环从运行实例中抽离出来，作为可版本化、可治理的策略资产进行演化与复用。这一视角比"记忆内容更新"或"单步动作优化"更接近长周期任务性能瓶颈的本质——即循环控制层面的系统性问题。在线与离线两种演化模式共享"证据→候选→验证→发布→激活"的同一协议，兼顾了反馈及时性与受控探索密度，设计上具备较好的完整性、可审计性和工程可落地性。

实验结果表明，在该框架下，无论在线演化还是离线预搜索，都能将年度任务的最终资金提升 140%–166%，并显著提高任务成功率与年度生存率，同时降低平均单次调用的 token 成本。这说明循环策略的显式外化和证据驱动的保守发布机制，确实能够把"经验"转化为可复用的控制改进。

然而，论文在实证广度与深度上仍有明显空间：单一基准、单一模型、有限种子、缺乏消融与外部基线对照，使得结论的泛化性尚不能盖棺定论。未来的工作可围绕多任务多模型验证、组件级消融、门控阈值灵敏度分析、策略迁移性测试以及长期演化的版本治理成本展开。

综合来看，该论文在概念建模与系统设计上具有原创性贡献，实验初步验证了其有效性，但作为一篇实证主张，其证据强度属于"方向正确、初步可行"的级别，尚需更多样化的验证来确立其在智能体自动演化研究中的稳固地位。
