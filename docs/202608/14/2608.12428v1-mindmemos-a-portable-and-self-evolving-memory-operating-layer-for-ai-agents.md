## 摘要
记忆是AI智能体的核心组成部分，使其能够积累经验、保持个性化，并在长期交互中适应。然而，现有记忆系统在开发后往往保持不变，限制了其通过持续使用来适应记忆模型、组织策略和程序性知识的能力。我们提出MindMemOS，一个可移植且自我进化的记忆操作层，使用统一的实体-属性-时间结构组织开放世界信息。MindMemOS支持场景自适应记忆建模、高阶模式发现、自主记忆精炼和持续技能进化。其MindMemEvolve算法采用验证驱动的进化搜索来优化目标场景的记忆模式，而dreaming通过合并冗余记录和解决冲突来巩固积累的记忆。此外，隐式纠正反馈作为人在回路信号，用于识别和修正潜在不准确或不对齐的记忆。其MindSkillEvolve算法进一步将智能体执行轨迹转化为可重用且逐步精炼的技能。MindMemOS在LOCOMO上达到94.03%的准确率，在PersonaMem上达到70.63%。MindSkillEvolve将SpreadsheetBench的成功率比初始技能基线提高了9.2个百分点。

## Abstract
Memory is a core component of AI agents, enabling them to accumulate experience, maintain personalization, and adapt over long-term interactions. However, existing memory systems often remain fixed after development, limiting their ability to adapt their memory models, organization strategies, and procedural knowledge through continued use. We present MindMemOS, a portable and self-evolving memory operating layer that organizes open-world information using a unified entity property timestructure. MindMemOS supports scenario-adaptive memory modeling, higher-order pattern discovery, autonomous memory refinement, and continuous skill evolution. Its MindMemEvolve algorithm employs validation-driven evolutionary search to optimize memory schemas for target scenarios, whiledreaming consolidates accumulated memories by merging redundant records and resolving conflicts. In addition, implicit corrective feedback serves as a human-in-the-loop signal for identifying and revising potentially inaccurate or misaligned memories. Its MindSkillEvolve algorithm further transforms agent execution trajectories into reusable and progressively refined skills. MindMemOS achieves 94.03% accuracy on LOCOMO and 70.63% on PersonaMem. MindSkillEvolve improves SpreadsheetBench success by 9.2 percentage points over the initial-skill baseline.

## 1. 核心问题与研究动机

- **背景**：基于LLM的智能体正被广泛用于软件工程、办公自动化、信息处理等知识密集型任务。随着智能体与用户长期交互，它必须保留用户偏好、既有知识、任务相关资源和程序性经验，这些信息远超单个上下文窗口的容量，因此记忆系统是智能体的核心基础设施。
- **现有方法的不足**：已有研究分为"记忆模型"（参数化/潜记忆）和"记忆系统"（外部文本/结构化存储）两条路线，但普遍存在**"开发后固定"**的问题——记忆提取策略、建模结构和组织策略在部署后几乎不再变化。
- **三大挑战**：
  1. **表征与可移植性矛盾**：非结构化记忆可移植但缺乏细粒度组织和时间推理能力；手工设计的模式能捕获场景信息但跨领域适配成本高。
  2. **记忆质量维护缺失**：持续积累的记忆会包含冗余、过时和冲突信息，需要超越在线提取/检索的系统性维护。
  3. **内容与技能割裂**：记忆内容与程序性技能分开管理，难以将执行经验转化为可复用、渐进精炼的智能体能力。

## 2. 方法论

### 2.1 总体架构

采用分层架构，解耦智能体集成、记忆算法和记忆结构（建模与存储）：底层为记忆结构层（建模管理、存储、技能），中层为记忆算法层（生成、检索、质量优化、技能进化），上层为智能体应用层（FastAPI HTTP API、SDK、CLI、OpenClaw插件/Skills）。

### 2.2 三维记忆结构（实体-属性-时间）

- **实体维度**：记忆描述的主体（人、组织、地点、事件、工件），通过关系边连接。
- **属性维度**：实体的特定属性或方面，支持场景自适应定义，可分为一阶属性（单次观察的显式事实）和高阶属性（跨多次观察综合的模式）。
- **时间维度**：记录信息有效、观测或记录的时间；同一实体-属性对的连续记录构成时间线，支持更新和冲突版本而不覆盖历史。

### 2.3 记忆生成算法

- **MindVanilla（无模式）**：按轮次分组输入、召回感知提取（内容哈希匹配+实体重叠+BM25，加权倒数排名融合）、去重与动作规划（Add/Reinforce/Update/Merge/Skip），分配粗粒度语义类型（档案、事实、情景记忆、工具痕迹、经验、技能候选）。
- **MindSchema（模式引导）**：LLM分段器划分话题片段 → 按场景自适应模式提取实体实例与属性值、解析时间表达式 → 实体融合（解析等价、沿时间线更新属性、标记过期）→ 图合并。

### 2.4 紧凑检索

- 外层智能体层负责迭代检索规划（确定时间范围、记忆类型、查询公式、评估证据充分性）。
- 内层工具层采用BM25稀疏匹配+嵌入模型稠密匹配的混合检索，RRF融合；支持前向（实体→属性）和反向（属性→实体）双向图遍历，以及前驱/后继版本的时间扩展和实体关系扩展。
- 检索键增强：将实体描述分解为多个检索字段，取最高字段级得分作为实体得分。

### 2.5 Dreaming（离线巩固）

- 选择回看窗口内未巩固的add记录作为种子，构建实体中心簇；两阶段"检测-行动"：第一轮LLM识别冲突、重复、互补碎片、低价值内容、模糊关系；第二轮LLM生成保守变更计划（创建/更新/合并/归档/添加关系链接）。
- 通过标准写入接口执行，新记忆带来源溯源，时间线边连接版本；处理后标记add记录为已巩固。效果：减少冗余、解决冲突、保留谱系。

### 2.6 Feedback（反馈）

- **显式反馈**：用户用自然语言直接修正存储的记忆，规划器生成add/update/delete/no-op动作；仅当前任务相关的临时修正不会进入长期记忆。
- **隐式反馈**：从用户对任务智能体的纠正中推断信号（异步运行），按持久性分类为任务临时/场景特定/长期；场景特定信号附带适用条件，长期信号捕获可泛化的事实、偏好或行为约束。

### 2.7 MindMemEvolve（记忆模式自进化）

- 目标函数：最大化Judge得分
  S∗ = arg max (1/N) Σ Judge(aᵢ, LLM(qᵢ, MindMemOS search(qᵢ; S) | MindMemOS add(contextᵢ; S)))
- 采用LLM引导的进化算法：初始化（对初始模式S0随机变异生成K个个体）→ 适应度评估（沙盒干净记忆库，按簇摄取上下文，计算QA准确率）→ 繁殖（精英保留 + 锦标赛选择父代 + 诱导变异[基于错误案例提出新实体/属性] + 随机变异[注入合理类型、以概率p_prune剪枝低频实体/属性] + 交叉[插入父代差异显著的实体和属性]）→ 最终在完整训练集上选择最优个体。
- 核心洞察：变异算子并非纯随机，而是LLM信息引导的——诱导变异利用Judge错误信号进行定向模式修复。

### 2.8 MindSkillEvolve（轨迹驱动技能进化）

- 云边协同技能生命周期管理：客户端负责注册、元数据收集、版本同步、回滚；云端集中存储、维护版本链、跨设备同步。
- 流程：收集同一技能版本下未消费的轨迹 → 转换为证据驱动的分析（任务目标、执行过程、关键转折点、技能有效性、工具模式、最终结果）→ 批量生成技能改进计划 → LLM转换为具体编辑操作 → 确定性应用到技能内容，生成新版本。
- 两种变体：**非监督版**仅依赖轨迹分析识别成功策略与失败模式；**监督版**额外使用轨迹得分强化高分段一致行为、抑制低分段错误。

## 3. 实验设计

### 3.1 对话记忆评测（LOCOMO）

- **数据集**：LOCOMO，10个长多会话对话（平均300+轮、最多35个会话），1986个标注问题；聚焦四类推理：单跳、多跳、时间、开放域。
- **对比方法**：Mem0、memU、MemOS、Zep、EverOS（基线结果引用自EverOS论文）。
- **配置**：答案模型gpt-4.1-mini，记忆系统LLM、嵌入/重排模型、Judge模型与EverOS默认实现对齐。
- **结果**：MindSchema总体94.03%（EverOS 93.05、Zep 85.22），单跳96.79、多跳93.97、时间90.34、开放域82.29（所有方法中最高）；MindVanilla 87.60%。

### 3.2 个性化评测（PersonaMem）

- **数据集**：PersonaMem，20个不同人格交替问答，7类查询（Recall Sha.、Recall Mem.、Track Evo.、Revisit、Suggest、Recom.、General.）。
- **对比方法**：Mem0、memU、MemOS、EverOS（本地部署开源代码，相同模型配置）。
- **结果**：MindSchema总体70.63%（EverOS 67.57，+3.06），主要在Recall Sha.（81.40 vs 74.42）和Suggest.（47.31 vs 35.48）；MindVanilla 67.74%。

### 3.3 Dreaming评测（MemoryAgentBench）

- **数据集**：MemoryAgentBench的FactConsolidation子集（选择性遗忘：原事实后被矛盾改写事实替代，以后者为准），单跳与多跳、4种上下文规模（6k/32k/64k/262k）。
- **对比方法**：Mem0、MemoRAG、HippoRAG-v2（引用自MemoryAgentBench）、Infini Memory（gpt-5-mini下）。
- **结果**：gpt-4o-mini下整体精度0.377→0.459，AMCR约20%；gpt-5-mini下整体0.545→0.585，AMCR约22.5%。Dreaming后优于Infini Memory（单跳0.920 vs 0.800）。

### 3.4 技能进化评测（SpreadsheetBench）

- **数据集**：SpreadsheetBench-Verified，400个验证过的表格操作任务（275个单元格级、125个工作表级）。
- **对比设置**：无技能（51.3%）、初始技能Init-skill（48.0%）、MindSkillEvolve-Unsup（55.3%）、MindSkillEvolve-Sup（57.2%，比Init-skill提升9.2个百分点）。
- **配置**：每40个任务触发一轮进化，轨迹按8个任务一批分组；报告成功率、智能体token消耗和进化token消耗。

### 3.5 MindMemEvolve消融（PersonaMem）

- 按语义相似度聚类会话，随机选12簇196个QA为训练集，剩余393个QA为测试集；禁用episodic回退机制以隔离效果。

## 4. 相关工作

### 4.1 智能体记忆系统

- **外部文本存储路线**：Mem0、memU、Zep、EverOS等系统将记忆作为显式文本/结构化记录管理，以支持长时对话和个性化。这类工作与MindMemOS共享"分层记忆管理"的基本思路，但普遍依赖固定的场景模板或浅层更新策略，缺乏跨会话的自主演化能力。
- **参数化记忆路线**：MemGPT、HippoRAG、MemoryBank等研究探索用上下文压缩或图索引将经验编码进模型参数或检索结构中；其优点是检索端到端优化，但难以满足可解释、可审计、跨设备迁移的需求。
- **本工作的定位**：MindMemOS跨越两者——将记忆建模为显式的实体-属性-时间三维结构，同时用离线巩固和模式进化实现类似"记忆重放"的深层整理效果，在透明性和适应性之间取得新平衡。

### 4.2 记忆压缩与巩固

- **睡眠重放**：受认知科学中记忆巩固（consolidation）启发，多个工作尝试在离线阶段对对话摘要或记忆条目做压缩与重写。Dreaming与之不同在于：不是单纯地压缩摘要，而是显式检测冲突、冗余和互补碎片，并产生带时间线谱系的精细图编辑操作。

### 4.3 技能获取与进化

- **Trajectory-based prompting**：许多系统从成功轨迹中提取提示词或few-shot样例来提升智能体表现。MindSkillEvolve进一步将技能视为版本化、可回滚的工件，引入监督信号（轨迹得分）引导技能内容向高分段偏好收敛，从而支持持续的程序性知识积累。

### 4.4 元学习与模式搜索

- **Prompt/结构搜索**：自动搜索检索模式的方法通常依赖贝叶斯优化或进化算法。MindMemEvolve的独特之处在于将进化算子与LLM推理结合，用Judge错误信号指导变异方向，大幅缩小搜索空间，并在真实数据上验证了模式的跨场景泛化能力。

## 5. 局限性

1. **成本与延迟**：Dreaming、MindMemEvolve和MindSkillEvolve均依赖多次LLM调用（检测、规划、评估、变异），在超大规模记忆库或高频交互场景下的经济成本与延迟可能成为部署瓶颈；论文未报告完整的时间/成本预算。
2. **评估范围有限**：对话记忆评测集中于英文、会话式场景；个性化评测规模较小（20个人格）；技能进化仅在表格任务中验证，对软件工程、办公自动化等其他领域的迁移效果尚不明确。
3. **隐式反馈的粒度**：Feedback模块从任务纠正中推断长期信号，依赖任务智能体和记忆系统之间的协作假设；当纠正的意图本身模糊时，信号分类误差可能累积。
4. **模式进化的初始敏感度**：MindMemEvolve从初始模式出发进化，若初始模式的实体/属性定义过于稀疏，或Judge分数在局部极值附近波动，进化可能收敛到次优结构。
5. **分布式一致性未充分验证**：云边协同的技能生命周期管理在论文中主要展示为架构设计与单机实验，跨设备并发写入、版本冲突解决的实际鲁棒性仍需更深入的压力测试。

## 6. 结论

MindMemOS提出了一种将记忆建模、算法与智能体集成解耦的分层架构，通过实体-属性-时间三维结构赋予记忆细粒度组织与时间推理能力；通过Dreaming离线巩固实现记忆质量的持续维护；通过Feedback将用户纠正转化为可执行的记忆编辑；通过MindMemEvolve和MindSkillEvolve分别让记忆模式与程序性技能在部署后持续自我进化。实验在LOCOMO、PersonaMem、MemoryAgentBench和SpreadsheetBench四个基准上分别验证了检索精度、个性化、冲突遗忘下的记忆一致性以及技能习得四方面能力，均达到当前最优或显著优于基线水平。论文的核心主张——记忆系统不应是"开发后固定"的，而应是一个自我进化的操作层——为下一代智能体基础设施的设计提供了有价值的范式参考。

**未来方向**：降低离线巩固与进化的计算开销；探索更细粒度的记忆遗忘与隐私约束；在多智能体协作场景中扩展记忆共享与权限管理；将模式进化与技能进化统一为一个闭环，实现记忆结构与智能体能力的协同增长。
