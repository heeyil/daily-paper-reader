## 摘要
智能体技能越来越多地被用于为大型语言模型（LLM）智能体配备可复用的程序性知识。尽管由于技能库的不断增大，近期工作在技能检索方面取得了显著改进，但检索到合理的技能包并不能保证执行它是有价值的。由于每次技能条件下的展开（rollout）在计算上都很昂贵，决定检索到的技能包是否应该执行已成为一个日益重要的挑战。为此，我们引入了奖励感知动态执行门（RADEG），这是一个轻量级、与检索器无关的决策层，位于技能检索与智能体执行之间。RADEG学习一个低成本的替代模型，在昂贵的展开启动之前预测查询-技能包对的执行效用。为了在控制任务难度的同时获得信息丰富的监督信号，我们通过删除、添加或替换一个技能来局部扰动每个检索到的技能包，产生匹配的同一查询展开，从而隔离技能包组成对验证器奖励的影响。在部署期间，RADEG随着新的验证器反馈可用，仅更新一个热启动的逻辑回归头，从而实现无需重新训练检索器或智能体的廉价执行/跳过边界适应。在288个收集的展开上的查询级留出评估中，RADEG大幅减少了不必要的智能体执行，同时保留了大部分下游验证器奖励。在不同的执行预算下，它始终优于基于相关性和随机门控，表明执行感知的替代建模为技能检索提供了一种实用且经济有效的补充。

## Abstract
Agent skills are increasingly used to equip large language model (LLM) agents with reusable procedural knowledge. Although recent work has substantially improved skill retrieval due to the increasing skill libraries, retrieving a plausible skill bundle does not guarantee that executing it is worthwhile. Since every skill-conditioned rollout is computationally expensive, deciding whether a retrieved bundle should be executed has become an increasingly important challenge. To this end, we introduce the Reward-Aware Dynamic Execution Gate (RADEG), a lightweight, retriever-agnostic decision layer between skill retrieval and agent execution. RADEG learns a low-cost surrogate model that predicts the execution utility of a query--bundle pair before the expensive rollout is launched. To obtain informative supervision while controlling for task difficulty, we locally perturb each retrieved bundle by deleting, adding, or replacing one skill, producing matched same-query rollouts that isolate the effect of bundle composition on verifier reward. During deployment, RADEG updates only a warm-started logistic head as new verifier feedback becomes available, enabling inexpensive adaptation of the execute/skip boundary without retraining either the retriever or the agent. Under a query-level held-out evaluation on 288 collected rollouts, RADEG substantially reduces unnecessary agent executions while preserving a large fraction of the downstream verifier reward. It consistently outperforms relevance-based and random gating across different execution budgets, demonstrating that execution-aware surrogate modeling provides a practical and cost-effective complement to skill retrieval.

## 论文核心问题与整体含义（研究动机和背景）

- **核心痛点**：基于技能的LLM智能体依赖检索系统从大规模技能库中选取“技能包”，但**检索到高相关性的技能包，并不保证执行它就能产生实际效用**。作者将这一现象定义为 **“相关性–效用差距”（relevance–utility gap）**。
- **代价不对称**：技能检索本身相对廉价，而技能条件下的智能体执行（调用API、工具交互、时间开销）代价高昂。若仅凭相关性决定是否执行，可能将大量计算预算浪费在“看似合理但无实际产出”的技能包上。
- **现有评估缺陷**：当前检索器通常以Hit@K、Recall@K、MRR、NDCG等排序指标评估，但这些指标仅衡量“技能是否被正确排到高位”，并不反映“用该技能包执行智能体是否产生有用的下游结果”。
- **已有实证线索**：已有研究报道技能库扩大时的“技能遮蔽”、跨智能体的负迁移、以及即使检索到gold技能也未能正确使用等失败模式，进一步佐证该差距的存在。
- **论文立意**：将“检索决策”与“执行决策”分离——检索器回答“哪些技能相关”，而RADEG回答“这个查询–技能包组合是否值得执行”，从而在启动高成本展开前进行低成本的效用预判。

## 论文提出的方法论

### 核心思想

- 在**技能检索与智能体执行之间**插入一个轻量级、**与检索器无关**的决策层——RADEG（Reward-Aware Dynamic Execution Gate）。
- RADEG学习一个低成本替代模型，预测“若用该技能包执行当前查询，验证器奖励是否非零”，以此决定执行或跳过。

### 关键技术细节

1. **执行门控目标**：
   - 定义查询 q、检索技能包 b = R(q)、下游智能体 A、验证器 V，奖励 r(q,b) ∈ [0,1]。
   - 执行效用标签定义为 y(q,b) = I[r(q,b) > 0]，即奖励是否非零（包括部分奖励）。
   - RADEG学习效用分数 s_θ(q,b) ≈ Pr(r > 0 | q,b)，执行决策为 g = I[s_θ ≥ τ]。

2. **查询–技能包编码**：
   - 使用固定文本编码器 E（实现中为 all-MiniLM-L6-v2）对查询和每个技能文本分别编码。
   - 技能包表示通过对其中所有技能的嵌入做**均值池化**得到，与技能数量和顺序无关。
   - 最终输入为查询嵌入与技能包嵌入的拼接，另加实现特定的辅助特征（四维包条件指示符、四个GoS PPR统计量）。

3. **离线效用学习**：
   - 用MLP编码器 h_ϕ 将输入映射为表示，接一个逻辑回归头预测非零奖励概率。
   - 使用**类加权二元交叉熵损失**训练，正类权重 ω+ = N_neg/N_pos 以缓解正负样本不平衡。

4. **奖励感知的动态门控（在线阶段）**：
   - 部署时**冻结效用编码器，仅更新逻辑回归头**（w, c），保持稳定表示的同时让执行边界在线适应新反馈。
   - 每观察到一次新验证器反馈，对逻辑头做一次在线梯度更新；检索器和智能体完全不动。
   - 这种设计使RADEG可以不重训练地适应新的执行/跳过边界。

5. **受控扰动构造监督数据**：
   - 为控制任务难度、隔离技能包组成对奖励的影响，对每个GoS检索的八技能包进行三种局部扰动：**删除最高PPR技能**、**添加低相似度技能**、**替换为图相似技能**。
   - 每个查询生成4种条件（原始+3种扰动），共72×4=288条(query, bundle, reward)轨迹。

## 实验设计

### 数据集与场景

- **主benchmark**：SkillsBench（Li et al., 2026b），包含72个任务、288条rollout（194条零奖励，94条正奖励）。
- 检索器为Graph-of-Skills (GoS)，执行环境为Docker中配置的Claude-Code风格环境，执行模型为Claude Sonnet 4.6（经第三方API中继）。
- 奖励由确定性的、任务特定的SkillsBench验证器给出，归一化到[0,1]。

### 对比方法

| 方法 | 说明 |
|---|---|
| **Always-Execute** | 始终执行，奖励归一化基准 |
| **Random-Gate** | 随机评分 |
| **PPR-Gate** | 用聚合PPR相关性作为执行评分 |
| **Static Head** | 冻结的离线训练逻辑头，无在线更新 |
| **Memory-Corrected Head** | 静态预测与k=5余弦近邻正标签频率的加权组合 |
| **Oracle** | 用真实标签排序，仅作为不可达到的上界 |

### 其他实验

- **跨智能体适应**：将Sonnet训练的模型迁移到Qwen3.7-Max、DeepSeek-Chat、GLM-5.2等目标智能体。
- **跨检索器泛化**：用混合检索、BM25、嵌入检索、gold-distractor四种检索策略构造技能包，评估不同包大小。
- **选择性反馈与探索**：ε-greedy探索率从0到1的扫描。
- **特征消融**：逐一移除查询嵌入、技能包嵌入、包条件特征、PPR统计量。
- **额外benchmark**：τ-Bench、AgentDojo、ToolSandbox三个工具智能体benchmark，各60条轨迹、三种工具包条件（Gold/Halfmix/Distractor）。

## 论文的主要结论与发现

- **相关性不等于效用**：在72个任务中，22个在至少一种扰动下发生奖励变化；聚合PPR相关性分数与执行奖励的Spearman相关接近于零，AUROC仅为0.435/0.418，无证据表明高检索相关性对应正执行奖励。
- **RADEG的效果**：在默认阈值τ=0.5下，**跳过68%的智能体调用，同时保留61%的总验证器奖励**；执行调用平均奖励从0.309提升到0.483（相对提升约56%），AUROC 0.717、AUPRC 0.570，显著优于随机门控、PPR门控及静态/记忆修正头。
- **预算受限下优势更大**：在20%执行预算时保留40%奖励（PPR门控仅15%、随机19%），在20%/40%/60%/80%各预算下的优势经bootstrap检验p<0.001。
- **跨智能体与跨检索器具备迁移潜力**：AUROC在Qwen3.7-Max为0.733、GLM-5.2为0.752、DeepSeek-Chat为0.628；在三种标准检索器上AUROC范围0.683–0.750，包大小从8降到7仅产生小幅变化。
- **在线头部更新有价值**：RADEG明显优于Static Head和Memory-Corrected Head，说明轻量级参数化在线更新对适应执行边界是有效的。

## 优点

- **问题切中实际痛点**：区分“检索相关性”与“执行效用”这一洞察准确击中了当前技能检索评估和实践中的关键盲点，动机实证扎实。
- **轻量且与检索器无关**：RADEG不修改上游检索器和下游智能体，可即插即用，集成成本低。
- **受控扰动的数据构造策略**：通过删除/添加/替换单个技能生成同查询多条件样本，既隔离了技能包组成对奖励的影响，又控制了任务难度，训练数据构造巧妙。
- **在线学习设计简洁高效**：冻结编码器、仅更新逻辑头，既能自适应漂移又避免灾难性遗忘和重复训练开销。
- **实验分析严谨**：包含bootstrap显著性检验、30-split不确定性分析、阈值敏感性、选择性反馈、跨智能体/跨检索器泛化等，分析角度全面；并附有详细的运行时基准。
- **评估指标切合门控场景**：提出Calls Saved、Reward Retained、Reward per Call等门控专属指标，并做固定预算比较，比单一分类指标更有实践指导意义。

## 不足与局限

- **数据规模有限**：主评估仅288条rollout，正例仅94条，领域和任务覆盖窄，结论外推需审慎。
- **选择性反馈偏差**：部署中跳过未执行的调用无法获得奖励标签，论文虽然用ε-greedy探索做了模拟，但该模拟基于完整信息的replay，与真实在线部署仍存在差距。
- **扰动类型受限**：仅含删除、添加、替换各一种，未覆盖更复杂的技能包组合变形（如重新排序、多技能替换、依赖结构变化等）。
- **部分实验样本量不足**：跨智能体评估中多个目标低于10个正例，论文自认不应作为可靠迁移证据；跨benchmark实验每benchmark仅60条轨迹。
