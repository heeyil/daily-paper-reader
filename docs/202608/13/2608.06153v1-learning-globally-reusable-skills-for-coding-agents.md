## 摘要
自动化技能进化使得大规模语言模型（LLM）智能体能够在无需昂贵重新训练的情况下持续改进。然而，现有方法通常将技能进化视为一系列局部更新，忽略了技能之间的关系，且往往产生过拟合的技能更新，难以跨任务泛化。我们提出了GSE，一个全局化的技能进化框架，联合优化技能兼容性与技能泛化能力。为保持技能库的一致性，GSE维护一个技能关系图（SRG），显式建模并协同演化技能间的关系。为提升泛化能力，GSE采用基于聚类的技能整合，从局部更新中抽象出可复用能力，并采用回放驱动的验证以防止过拟合和行为回退。我们在两个代表性的软件工程任务上评估了GSE：缺陷揭示测试生成与误报缺陷报告过滤。在两种最先进的编码智能体OpenHands和mini-SWE-agent上，GSE始终取得最佳精确率、召回率和F1分数。与现有进化技术相比，GSE在测试生成上将精确率和召回率分别提升了6.1%~34.1%和31.8%~180.0%，在误报过滤上分别提升了15.4%~96.4%和13.1%~19.8%。在内部工业智能体上的部署进一步将F1分数提升了61.4%，证明了GSE在进化有效技能方面的有效性与可泛化性。

## Abstract
Automated skill evolution enables Large Language Model (LLM) agents to continuously improve without expensive retraining. However, existing approaches typically treat skill evolution as a sequence of local updates, overlooking relationships among skills and often producing overfitted skill updates that fail to generalize across tasks. We propose GSE, a globalized skill evolution framework that jointly optimizes skill compatibility and skill generalization. To preserve consistency across the skill bank, GSE maintains a Skill Relation Graph (SRG) that explicitly models and co-evolves inter-skill relationships. To improve generalization, GSE performs cluster-based skill consolidation to abstract reusable capabilities from local updates and employs replay-driven verification to prevent overfitting and behavioral regressions. We evaluate GSE on two representative software engineering tasks: bug-revealing test generation and false-positive bug report filtering. Across two state-of-the-art coding agents, OpenHands and mini-SWE-agent, GSE consistently achieves the best precision, recall, and F1-score. Compared with existing evolution techniques, GSE improves precision and recall by 6.1%~34.1% and 31.8%~180.0% for test generation, and by 15.4%~96.4% and 13.1%~19.8% for false-positive filtering. Deployment on an internal industrial agent further yields a 61.4% improvement in F1-score, demonstrating the effectiveness and generalizability of GSE for evolving effective skills.

## 1. 核心问题与整体含义

- **研究动机**：编码智能体（如基于 LLM 的软件工程智能体）在测试生成、缺陷分析等任务中表现优异，但静态设计（固定提示词、工具策略、手工技能）难以适应多样化项目与失败模式。为在不重新训练模型的前提下持续提升智能体能力，自动化技能进化成为重要途径。
- **现有问题**：已有技能进化方法本质上是一系列“局部更新”（local updates）——从单条执行轨迹提炼技能或修改技能，再直接合并进技能库。这种做法存在两个核心缺陷：
  1. **技能兼容性缺失**：技能之间存在依赖、共现或冲突关系，但现有方法未显式建模；局部更新可能破坏其他技能所依赖的假设，导致技能库内部不一致。
  2. **泛化能力不足**：从单条轨迹生成的更新高度特化，可能过拟合到特定项目、缺陷模式或执行场景；多条轨迹可能反映同一能力缺口却以碎片化形式编码，直接合并会使技能库碎片化、增长后质量退化。
- **整体含义**：技能进化应被建模为**全局优化问题**，而非独立局部更新的序列；需要同时优化技能库的兼容性与可复用性。

## 2. 方法论：GSE 框架

GSE（Globalized Skill Evolution，全局化技能进化）由三个主要阶段组成：

### 2.1 轨迹收集（Trace Collection）
- 对底层智能体进行插桩，记录内部推理、工具调用、命令参数、环境反馈与最终结果。
- 由于原始轨迹冗长，GSE 执行轨迹简化：删除 `find`/`grep` 完整输出、文件原始内容、info 级日志等噪声，保留命令、目标路径、关键错误/警告消息、推理块，以支撑后续因果分析。

### 2.2 进化提案生成（Evolution Proposal Generation）
- **失败诊断（Failure Diagnosis）**：更新智能体对失败进行分层诊断，判断是导航（上下文探索）、推理（代码理解）还是执行（工具行为）缺陷；据此生成**通用能力增强**（如探索、验证策略）或**可复用问题模式**（如库约束、框架特定策略）两类技能。
- **技能关系图（Skill Relation Graph, SRG）**：
  - 有向图 G=(V, E)，V 为技能节点，E 为关系边；
  - 关系类型包括 `dependency`（依赖）、`co-usage`（协同使用）、`conflict`（冲突）；
  - 给定一个更新提案，GSE 通过 SRG 识别受影响的相邻技能，并利用技能元数据检索潜在交互技能，进行语义分析；若更新改变了假设、中间输出、适用条件或交互模式，则生成**辅助进化提案**，实现技能内容与关系的协同演化。
- **DSL 结构化提案**：使用领域特定语言（DSL）规范化提案，字段包括目标技能、操作（如 UPDATE）、具体内容、理由、预期行为、关系更新（增删边、修改关系类型）。例如更新 `ContextExplorer` 技能并新增一条与 `TestRunnerConfig` 的 `dependency` 关系。
- **局部验证**：应用提案后重放原始失败案例，不能解决该案例的提案被丢弃。

### 2.3 技能泛化（Skill Generalization）
- **聚类整合（Skill Consolidation）**：
  - 对修改已有技能的提案，按受影响技能集合聚类；对引入新技能的提案，按理由与预期效果的语义相似度聚类；
  - 合并智能体提取簇内共同模式、移除案例特定细节、解决冗余/冲突，生成高层级技能抽象，构造候选技能库。
- **回放驱动验证（Replay-Driven Validation）**：
  - 对修改已有技能的候选库，回放历史中激活过受影响技能的案例；对新技能，回放产生该簇提案的案例；
  - 只有保持或提升回放性能的候选技能库才被接受并并入技能库。
- **算法流程**（Algorithm 1）：局部验证过的提案 P → 按受影响技能/新技能分组 → 语义聚类 → 对每个簇抽取共性 → 实例化到当前 SRG → 回放历史案例 → 通过则更新技能库。

## 3. 实验设计

### 3.1 数据集 / 场景

  - 通过 AST 解析开发者修复补丁识别 focal methods，人工验证可触发缺陷，随机选择其中一个作为被测方法。
- **任务二：假阳性缺陷报告过滤（False-Positive Bug Report Filtering）**

## 6. 主要结论与发现

- **测试生成**：
  - 在 OpenHands 上 GSE 获 Precision 0.35 / Recall 0.28 / F1 0.31，比最强基线（Human Skills 或 Live-SWE-agent）提升 6.1%、64.7%、40.9%；
  - 在 mini-SWE-agent 上获 0.55 / 0.29 / 0.38，提升 27.9%、31.8%、31.0%；
  - 手工技能提升有限且不稳定，Local 更新的进化方法增益小，GSE 通过全局关系协同与泛化带来显著提升。
- **误报过滤**：
  - OpenHands 上 GSE 取 0.55 / 0.95 / 0.70，远超最强基线（0.29 / 0.84 / 0.43）；mini-SWE-agent 上 0.30 / 0.97 / 0.46；
  - Precision 提升 15.4%~96.4%，Recall 提升 13.1%~19.8%；说明 GSE 在保持高召回的同时显著降低误报。
- **消融**：去掉 SRG 或去掉泛化机制均导致 F1 明显下降（测试生成从 0.31 掉到 0.27；误报过滤从 0.70 掉到 0.59/0.54），证明两个组件均不可或缺。
- **工业部署**：内部智能体 + GSE 将 F1 从 0.43 提升至 0.71（+61.4%），表明对强工业智能体同样有效。
- **成本**：GSE 的进化 token 成本比 Trace2Skill 高约 12%，但执行阶段 token 消耗低于所有带技能方法，说明有效技能减少了无效探索，整体经济性可接受。
- **主要发现总结**：全局化技能进化能够持续、经济地提升编码智能体的任务成功率，优于局部更新方法。

## 7. 优点

- **问题建模新颖**：将技能进化从局部更新提升到全局优化，明确两个关键挑战（兼容性与泛化），系统化设计对应机制。
- **技能关系图（SRG）**：显式建模技能间 dependency / co-usage / conflict，并作为“一等对象”参与进化，协同更新技能内容与关系，有效防止更新传播时破坏一致性。
- **技能泛化机制**：聚类整合 + 回放验证形成闭环，从案例特化技能中抽象出可复用能力，减少碎片化和过拟合，防止行为回归；算法流程清晰、可复现。
- **DSL 结构化提案**：规范进化语言，降低歧义，有利于自动化处理与模块化扩展。
- **实验设计严谨**：
  - 多智能体、多任务、开源+工业数据集；
  - one-project-held-out 协议防止泄漏；
  - 对比多种 SOTA 基线（Live-SWE-agent、Trace2Skill）及手工技能；
  - 温度设零降低随机性；
  - 同时报告 token 成本，兼顾效果与效率；
  - 工业部署增强了外部有效性。
- **性能提升显著**：在精确率、召回率、F1 上全面超越基线，尤其是误报过滤任务中召回率接近 0.95~0.97，同时精度提升数倍。
