## 摘要
现实世界中的数据科学涉及跨数据整理、探索、建模、可视化和验证的长周期工作流，并需要在真实操作环境中协调使用笔记本、IDE、终端、浏览器和数据库等工具。然而，现有基准缺乏真实计算机交互，并且不评估智能体能否在现实计算环境中执行完整的端到端数据科学工作流，未能捕捉数据科学实践的多阶段、多工具特性。我们提出了DSAgentBench，这是第一个在真实计算机环境中评估智能体能否自动化完整数据科学工作流的基准。DSAgentBench包含275个多样化任务，覆盖整个数据科学生命周期，反映了实践中所需的复杂性和工具协调。每个任务要求在中间输出中进行基于事实的决策和协调工具使用，并包含一个确定性评估器，用于验证分析正确性、视觉输出和模型性能，而不仅仅是代码执行。我们使用15个闭源和开源模型进行的广泛实验表明，即使是最强的智能体Claude-4.6-Sonnet，其任务成功率也仅为56.70%，而所有开源智能体的成功率均低于1%，经常在工具编排、操作系统接地和多步推理方面失败。这些结果揭示了当前智能体系统与真实数据科学工作流之间的巨大能力差距，使DSAgentBench成为开发基于事实、可验证、自主数据科学智能体的基础。我们在https://github.com/vis-nlp/DSAgentBench上发布DSAgentBench。

## Abstract
Real-world data science involves long-horizon workflows that span data wrangling, exploration, modeling, visualization, and validation, and require coordinated use of tools such as notebooks, IDEs, terminals, browsers, and databases within real operating environments. Yet existing benchmarks lack real-computer interaction and do not evaluate whether agents can execute complete end-to-end data-science workflows in realistic computing environments, failing to capture the multi-stage, multi-tool nature of data-science practice. We introduce DSAgentBench, the first benchmark to evaluate whether agents can automate full data-science workflows inside real computer environments. DSAgentBench contains 275 diverse tasks covering the entire data-science life-cycle, reflecting the complexity and tool coordination required in practice. Each task requires grounding decisions in intermediate outputs and coordinated tool use, and includes a deterministic evaluator that verifies analytical correctness, visual outputs, and model performance rather than code-only execution. Our extensive experiments with 15 closed- and open-source models show that even the strongest agent, Claude-4.6-Sonnet, achieves only 56.70% task success, while all open-source agents remain below 1%, frequently failing at tool orchestration, OS grounding, and multi-step reasoning. These results reveal a substantial capability gap between current agentic systems and real data-science workflows, positioning DSAgentBench as a foundation for developing grounded, verifiable, autonomous data-science agents. We release DSAgentBench at https://github.com/vis-nlp/DSAgentBench.

- **现有基准的不足**：
  - 通用 GUI 基准（如 OSWorld、WebArena）评估的是计算机操作能力，而非数据科学分析推理能力；

### 2. 论文提出的方法论：核心思想、关键技术细节、流程

- **核心思想**：将数据科学任务建模为真实计算环境中的自主长周期决策问题；智能体需要基于多模态观察（截图 + 可访问性树）执行 GUI 操作，通过中间输出不断调整策略，最终产出满足确定性评估器的分析结果。
- **问题形式化**：基准由三元组集合 \( T = \{(C_i, I_i, V_i)\} \) 组成，其中 \( C_i \) 为系统初始配置（文件系统、数据集、软件环境），\( I_i \) 为自然语言任务指令，\( V_i \) 为确定性 Python 评估器。任务的成败完全由 \( V_i \) 判定，不预设唯一路径。
- **环境架构**：基于 OSWorld 框架扩展，运行 Ubuntu OS，提供：
  - **观察空间**：1920×1080 桌面截图，或截图 + AT-SPI 提取的 A11y（可访问性）树；
  - **动作空间**：统一 GUI 动作空间（鼠标、键盘、WAIT/DONE/FAIL 元动作），所有智能体通过 pyautogui 以坐标方式交互，保证公平比较；
  - **工具支持**：VS Code、Jupyter Notebook、Chrome，以及自动数据获取能力（Kaggle API、OpenML、SQLite、URL）。
- **任务构造流程**（三阶段）：
  1. **数据来源**：从 Kaggle、OpenML、GitHub（Plotly datasets）、SQLite 数据库及 Web API 收集真实异构数据；
  2. **任务与评估器设计**：专家分析 100 个高分 Kaggle notebook，结合 LLM 辅助完善任务分类体系（六大类），四位专家在三个月内（约 400 工作时）人工撰写 275 个任务及配套确定性评估器；LLM 仅用于措辞润色与边缘情况发现，不参与任务逻辑设计；
  3. **双标注者验证**：创建者与验证者独立审查，初始一致率 86%，其余通过迭代讨论修订至全部达成共识。

### 3. 实验设计：数据集、基准、对比方法

- **基准规模**：275 个人工撰写的长周期任务，覆盖数据科学全生命周期。
- **任务分布**：
  - 六个类别：EDA（43.3%，119 个）、建模（41 个）、特征工程（37 个）、可视化与报告（33 个）、数据获取（23 个）、评估与部署（12 个）；
  - 难度分布：Hard 47.6%、Medium 46.9%、Easy 5.5%；
  - 56.7% 为多阶段任务，平均每任务需要 4–5 个分析步骤。
- **数据模态与来源**：表格数据占 95.3%（图像 3.6%、文本 1.1%）；数据来自 GitHub（37.1%）、Kaggle（29.8%）、OpenML（18.9%）、SQLite（7.6%）、Web（6.5%）。
- **评估模型（15 个）**：
  - **闭源**：GPT-4o、GPT-5、GPT-5-mini、O4-mini、Gemini-2.5-Pro、Claude-4/4.5/4.6-Sonnet、OpenAI Computer-Using Agent；
  - **混合**：Jedi-3B/7B（开源定位模型 + GPT-4o 规划）；
  - **开源**：UI-TARS-2B/7B、GUI-OWL-7B、OpenCUA-72B。
- **观察设置**：两种——仅截图、截图 + A11y 树。开源模型因不支持 A11y 输入仅评估截图模式。
- **评估指标**：任务成功率（评估分数 ≥ 0.95 视为成功）和平均评估分数；评估器为确定性 Python 脚本，检查分析数值、可视化文件、模型性能阈值（如 F1/accuracy ≥ 0.7），仅约 10% 任务使用 LLM 视觉裁判（且须先通过确定性门槛，并采用交叉模型判分避免循环）。

### 4. 资源与算力

- **闭源模型**：通过提供商 API 访问，无需本地托管，配备 VMware Ubuntu 虚拟机运行评估框架。
- **开源模型**：自托管于 Google Cloud Platform（GCP），使用 Docker 式虚拟机 + GPU 实例（n1-standard-4 机型 + 200 GB 标准磁盘），vLLM 推理引擎服务并发推理。
- **明确说明有限**：论文**未明确披露**具体的 GPU 型号、GPU 数量、各模型的推理总时长或训练成本。仅提及 GCP n1-standard-4 实例规格。

### 5. 实验数量与充分性

- **主要实验**：在两种观察设置下对 15 个模型进行全量基准评估，共 275 个任务 × 15 个模型 × 2 种设置（开源模型仅 1 种），矩阵规模较大。
- **消融实验**：
  - 动作预算消融（15/30/50 步），结果显示预算增加仅带来边际收益（24.54%→25.81%）；
  - 终端优先（terminal-first）提示消融，性能无明显变化（19.34%→20.73%）；
  - Jupyter 对比 VS Code 工具效果差异分析；
  - 单阶段 vs 多阶段、不同难度层级的表现分析。
- **错误分析**：人工检查 604 条闭源模型轨迹 + 150 条开源模型轨迹，进行根因分类、首次失败步骤（FF）、时序失败结构与恢复能力分析。
- **可重复性验证**：对 GPT-4o 和 Claude-4.5-Sonnet 重复实验，准确率波动在 ±1% 内，说明评测管线稳定可靠。
- **人类参考基线**：3 名参与者（2 名应用科学家 + 1 名硕士毕业生）达到 85.09% 成功率。
- **总体评价**：实验设计较为充分、客观、公平——统一动作空间、统一评估流程、开闭源模型对比、多维度消融和错误分析提供了较完整的证据链。唯一不足是开源模型未参与 A11y 设置对比，且错误分析仅覆盖部分轨迹。

### 6. 论文的主要结论与发现

- **性能差距巨大**：最强智能体 Claude-4.6-Sonnet 在 Screenshot + A11y 设置下仅达 **56.70%** 成功率；GPT-5 次之（29.81%）；其余闭源模型约 20%；**所有开源模型低于 1%**。
- **人类基线**为 85.09%，表明任务可解且区分度良好。
- **A11y 树带来有限增益**：添加可访问性树普遍改善表现，但增益因模型而异，部分模型无法有效利用结构化 UI 信息。
- **失败根因分布**：开源模型几乎完全失败于**接地错误**（97–98%）；闭源较强模型失败模式更多元，包括终端操作、代码逻辑和推理错误。
- **任务类型难度差异**：数据获取、模型验证和评估类任务最难；EDA 相对表现最好。
- **关键瓶颈**：性能受限于接地、规划、多步推理和工具编排能力的综合不足，而非动作预算不足（增加预算几乎无提升）。
- **效率差异**：Gemini-2.5-Pro 成功运行平均仅 6.76 步，而 CUA 平均 15 步（总是耗尽预算），揭示探索深度与执行效率之间的权衡。
