## 摘要
检索可以识别出可能相关的过去轨迹，但它并未说明在用户、实体、约束或环境状态发生变化后，执行代理应如何使用该轨迹。我们将这一检索后复用步骤视为长时程轨迹记忆的一个独立瓶颈，并构建了一个评估框架，该框架在保持候选检索、目标状态、模型、解码和工具预算固定的同时，改变传递给代理的支持信息。我们以查询条件下的复用（QCR）来实例化该框架，这是一种刻意简化的目标绑定笔记，记录了可复用流程、待恢复的绑定、适用条件和验证要求。QCR用于检验复用假设，而非声称某种普遍偏好的记忆格式。在WebArena、WorkArena和AppWorld中的2,391个目标实例上，QCR达到了62.3%的平均成功率，比完整轨迹高出10.7个百分点，同时使用的在线令牌减少了48.9%。摘要重排序为94.8%的目标选择了可复用记忆，使最终任务成功率与神谕可复用选择器相差在1.8个百分点以内。按轨迹长度和源-目标绑定变化进行的分析表明，随着轨迹变长或源特定值改变，直接轨迹注入的效用会大幅下降，而目标绑定支持则保留了更大比例的已测收益。由此产生的框架将检索质量与将检索经验转化为安全、有用支持以用于新任务的问题分离开来。

## Abstract
Retrieval can identify a past trajectory that may matter, yet it does not specify how an acting agent should use that trajectory after users, entities, constraints, or environment state have changed. We identify this post-retrieval reuse step as a distinct bottleneck for long-horizon trajectory memory and formulate an evaluation framework that holds candidate retrieval, target state, model, decoding, and tool budget fixed while varying the support delivered to the agent. We instantiate the framework with query-conditioned reuse (QCR), a deliberately simple target-bound note that records a reusable procedure, bindings to recover, applicability conditions, and verification requirements. QCR serves to test the reuse hypothesis rather than to claim a universally preferred memory format. Across 2,391 target instances in WebArena, WorkArena, and AppWorld, QCR reaches 62.3% average Success, 10.7 points above Full Trajectory, while using 48.9% fewer online tokens. Summary reranking selects a reusable memory for 94.8% of targets, placing end-task Success within 1.8 points of an oracle reusable selector. Analyses by trajectory length and source--target binding shift show that direct trajectory injection loses much of its utility as traces grow longer or source-specific values change, whereas target-bound support preserves a larger share of the measured gain. The resulting framework separates retrieval quality from the problem of turning retrieved experience into safe, useful support for a new task.

## 1. 论文的核心问题与整体含义

### 研究背景
- 智能体记忆系统已在**存储、索引、检索**方面取得长足进步，但大多数记忆评估（如 LongBench、LoCoMo、LongMemEval）都在"访问"层面戛然而止——只检验系统能否留存、排序并回答关于过往交互的问题。
- 对于**短记忆条目**（如事实、局部指令），"检索到"≈"能使用"，检索质量即可代理记忆效用。
- 但对于**长时程任务轨迹**，情况截然不同：轨迹虽编码了宝贵的工具流程、决策规则和验证序列，但也携带大量与源任务绑定的**用户、对象、路径、日期、观测**等过时信息。检索到轨迹**并不等于**代理知道如何使用它。

### 核心问题
> 当用户、实体、约束或环境状态发生变化后，智能体如何将检索到的历史轨迹安全、有效地复用到新任务上？

作者将这一问题定义为**检索后复用瓶颈（post-retrieval reuse bottleneck）**，并指出：
- 该瓶颈不是简单的长上下文问题（模型在长上下文中"迷失在中间"），
- 也不是单纯的检索质量问题（检索已能高覆盖地找到相关轨迹），
- 而是**将历史经验转化为目标专用支持**这一独立环节的缺失。

### 整体研究含义
- 论文将记忆效用从"检索质量"和"源忠实度"中分离出来，主张**记忆应以"是否改善当前查询的求解"为标准**——即更高的验证完成率、更少的无谓探索、更低的在线成本。
- 结论：记忆系统应在**存储层保留丰富完整记录**，但在**执行层向代理提供紧凑、目标绑定的复用说明**。

## 2. 论文提出的方法论

### 核心思想
提出**查询条件复用（QCR, Query-Conditioned Reuse）**——在检索之后、执行之前插入一个**刻意简单的支持转换步骤**，从选定的历史轨迹中提炼出目标专用的复用说明。该设计用于**检验"复用假设"**（即瓶颈在复用而非存储/检索），而非声称某种通用最优记忆格式。

### QCR 支持笔记的四字段结构
| 字段 | 作用 |
|---|---|
| **工作流不变量（Workflow Invariant）** | 保留仍然适用于目标任务的工具顺序、决策规则和前置验证步骤 |
| **需重新获取的绑定（Bindings to Re-obtain）** | 明确指出哪些值（实体、路径、用户、日期、记录ID等）必须从当前目标环境中重新获取，**禁止将源值作为答案** |
| **适用条件（Applicability Conditions）** | 保留源轨迹中暂停、换分支或验证的理由；允许代理在目标状态违反源前置条件时**拒绝复用** |
| **验证护栏（Verification Guardrail）** | 要求代理在完成前对目标端结果进行验证 |

### 关键技术细节
1. **绑定感知的目标构造（Binding-Aware Target Construction）**：从每个验证通过的源轨迹生成最多4个目标变体，按绑定替换数量分为 None / Small / Medium / Large 四个偏移等级。
2. **统一冻结记忆库**：跨环境混合存储 623 条验证通过的历史轨迹，不按任务族或环境分区；排除环境标签和来源信息。
3. **冻结检索边界**：固定嵌入检索器返回 top-5 候选集，轻量级排序器选出一条轨迹后缓存，**所有对比条件共享同一候选集和选中记录**。
4. **在线成本公式**：`Conline = Ibase + Imem + Isyn + Osyn + Oact`，即基础指令 + 记忆注入 + 支持合成输入/输出 + 执行输出（不重复计算 API 输入）。

### 评估框架
- 保持以下要素**完全固定**：候选检索集、目标状态、模型、解码配置、工具预算、验证器；
- 仅改变"同一选中经验"的**表示与使用方式**（原始轨迹 vs 通用摘要 vs QCR 笔记）；
- 指标：成功率、里程碑完成度、API 调用数、非重叠在线 token 数。

## 6. 论文的主要结论与发现

### 主实验结论（端到端性能）
| 方法 | 成功率 | API 调用 | 在线 Token |
|---|---|---|---|
| No Memory | 38.4% | 24.6 | 15.2k |
| Generic Summary | 47.9% | 20.8 | 8.1k |
| Full Trajectory | 51.6% | 21.9 | 18.4k |
| **QCR** | **62.3%** | **16.7** | **9.4k** |

- QCR 比 Full Trajectory 高出 **+10.7 个百分点**，同时在线 token 减少 **48.9%**；
- 在三个环境中均一致：WebArena +10.9、WorkArena +10.8、AppWorld +10.4（相对 Full Trajectory）。

### 检索与选择结论
- top-5 候选覆盖度高（配对轨迹 95.6%，可复用轨迹 97.8%），但 retriever top-1 配对准确率仅 78.9%；
- **摘要重排**将最终可复用记忆准确率提升至 94.8%，端任务成功率达到 62.3%，仅比神谕可复用选择低 **1.8 点**；
- 选择规则对端任务有显著影响：Random top-5 仅 44.8% vs 重排后 62.3%（+17.5 点）。

### 轨迹长度敏感性
- Full Trajectory 的效用随轨迹增长急剧衰减：Short 组 +18.4 → Very Long 组仅 +2.9（保留 15.8%）；
- QCR 在 Very Long 组仍保持 **+13.2** 点效用（保留 60.3%）。

### 绑定偏移敏感性
- 大偏移下 Full Trajectory 效用塌缩至 +2.2（保留 8.2%），QCR 保持 +20.1（保留 67.9%）；
- 大偏移下 Full Trajectory 产生 stale-binding 错误达 46.9%，QCR 仅 10.9%；correct rebinding 从 31.7% 提升至 77.8%。

### 核心发现
> 历史轨迹蕴含的程序性知识是有用的，但**长轨迹和绑定变化会侵蚀直接注入的价值**；目标绑定的定向支持在保留工作流的同时强制代理恢复当前绑定，从而在更低成本下获得更高成功率。**检索与复用是两个独立的瓶颈环节。**

## 8. 不足与局限

### 实验覆盖局限
- **仅限成功轨迹**：未评估部分失败轨迹、失败后恢复轨迹的价值，真实系统中失败经验也可能有用；
- **单条记忆注入**：未测试多条轨迹组合、跨任务的累积记忆复用；
- **人工构造的目标对**：绑定重写由人工生成，不是自然涌现的任务重复模式——可能高估/低估真实场景的复用难度；
- **无真实长期部署**：未涉及开放环境中的记忆获取、更新和遗忘。

### 偏差风险
- 轨迹长度组与任务难度相混淆（No-Memory 成功率随长度组从 55.2% 降至 18.9%），作者承认这是相关性而非因果估计；
- 使用 DeepSeek-V4-Pro 单一模型，无法验证 QCR 对模型类型/规模的泛化；
- QCR 支持笔记的质量依赖 LLM 的理解与提炼能力，模型升级后效果是否保持未知。

### 应用限制
- 框架聚焦于"成功→成功"的迁移，未评估**安全敏感任务**中的不可逆副作用或策略违规风险；
- QCR 笔记可能遗漏关键隐式约束（四字段是作者承认的最小实现选择，非通用最优）；
- 报告 token 节省不意味着所有任务都应最小化 token——安全场景可能需要额外检查；
- 排序器本身依赖 LLM 摘要，引入额外的性能依赖层。

### 信息缺失
- 未提供算力配置、推理时延、经济成本等工程实践所需数据；
- 未提供开源代码与完整提示模板（正文仅展示部分骨架），可复现性有待增强。

## 总结

本论文通过严谨的框架设计（冻结检索边界）、刻意简单的干预方法（QCR 四字段笔记）、跨三环境的充分验证，令人信服地证明了：**长时程轨迹记忆的瓶颈已从"检索可得性"转移到"检索后复用"**。其核心理念——存储层保留丰富记录、执行层提供目标绑定支持——为下一代智能体记忆系统提供了明确的设计原则：**不仅要找到历史经验，更要让历史经验以安全、有效的方式服务于当前任务。**
