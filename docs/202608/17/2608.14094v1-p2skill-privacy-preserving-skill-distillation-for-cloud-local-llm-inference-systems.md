## 摘要
云-本地LLM推理系统有潜力利用大型云模型的推理能力，同时保护个人设备上的敏感用户数据。发往云的请求必须排除个人身份信息（PII）以防止外部数据泄露。现有的隐私保护方法依赖于提示扰动、实体掩码或模型微调，但这些方法可能会扭曲上下文语义或需要额外训练。本文提出了P2Skill，一种基于提示的技能蒸馏方法，其中本地小语言模型（SLM）通过遵循技能提示自主执行分解、PII感知路由、改写和重构。技能由云LLM根据执行失败反复提炼，使本地SLM能够泛化到记住的PII模式之外，因此P2Skill不需要针对隐私的微调或学习辅助检测器。在四领域基准上的评估表明，P2Skill的隐私保护推理质量比之前的基线分别高出1.69倍和3.66倍。

## Abstract
Cloud-local LLM inference systems have the potential to use the reasoning capability of large cloud models while protecting sensitive user data on personal devices. Cloud-bound requests must exclude personally identifiable information (PII) to prevent external data leakage. Existing privacy-preserving methods rely on prompt perturbation, entity masking, or model fine-tuning, but these approaches may distort contextual semantics or require additional training. This paper proposes P2Skill, a prompt-based skill distillation method in which a local small language model (SLM) autonomously performs decomposition, PII-aware routing, paraphrasing, and reconstruction by following the skill prompts. Skills are iteratively refined from execution failures by a cloud LLM, enabling the local SLM to generalize beyond memorized PII patterns, and therefore P2Skill requires no privacy-specific fine-tuning or learned auxiliary detectors. Evaluation on a four-domain benchmark shows that P2Skill achieves $1.69\times$ and $3.66\times$ higher privacy-preserved inference quality than previous baselines.

# P2Skill：隐私保护的技能蒸馏方法——详细中文总结

## 1. 核心问题与研究动机

- **背景**：云-本地LLM推理系统旨在兼顾云大模型（Cloud LLM）的强推理能力与本地设备的数据保护需求。然而，用户发送到云端进行推理的提示词（prompt）中常携带个人身份信息（PII），存在严重的外部数据泄露风险，尤其在医疗、法律、金融等敏感场景中。
- **现有方法的不足**：
  - **密码学推理**：安全性高，但需要专用原语、模型重训练和复杂多方基础设施。
  - **基于NER的去标识化**：能够剥离可识别实体，但会删除任务关键上下文，导致推理质量下降。
  - **本地差分隐私（LDP）扰动**：在传输前扰动令牌，但注入噪声会破坏语言连贯性，隐私-效用权衡固有存在。
  - **云-本地协同系统**（如PRISM、PAPILLON）虽可分区推理，但隐私模块往往需要单独训练或校准，且重构原始语义需要额外的还原模块。
- **核心问题**：如何在最小化PII泄露的同时，维持云端推理质量，且避免对本地模型进行隐私特化微调或引入额外学习模块？
- **P2Skill的答案**：本文提出一种**基于提示词技能蒸馏（Prompt-based Skill Distillation）**的方法，让本地小语言模型（SLM）通过执行可迭代精炼的技能提示，自主完成分解、PII感知路由、改写与重构，从而在不改动SLM权重的前提下实现隐私保护推理。

## 2. 方法论

### 2.1 核心思想
- 将隐私保护流程封装为四种可复用的自然语言**技能（Skill）**提示：
  1. **隐私感知分解（Decomposition）**：将用户提示拆分为子任务，并为每个子任务附加PII标记。
  2. **PII感知路由（PII-aware Routing）**：根据PII标记和确定性子串匹配结果，将子任务路由到本地SLM或云LLM。
  3. **PII改写（Paraphrasing）**：对含PII且计划发送云端的子任务进行重写，移除所有检测到的标识符，同时保留任务语义。
  4. **最终响应重构（Reconstruction）**：将本地和云端结果整合为最终回复，必要时从本地PII映射中还原用户原标识符。
- 整个流程由本地SLM（冻结参数）执行，云端LLM在**技能蒸馏循环**中扮演参考（生成目标答案）、评估者（打分并标记失败阶段）、监督者（重写失败技能）三种角色，逐步改善技能提示。

### 2.2 关键技术细节
- **路由规则**（公式1）：
  - 无PII子任务 → 直接发送云端；
  - 有PII但改写后匹配器判定干净 → 改写后发送云端；
  - 有PII且改写后仍含标识符 → 本地SLM处理。
- **改写约束**（公式2）：改写文本不能包含原PII字串，即所有检测到的标识符必须被移除。
- **技能蒸馏循环**：
  - 每次迭代采样包含含PII和PII-free样本的mini-batch；
  - 本地SLM执行完整流水线并记录各阶段trace；
  - 云LLM参考角色直接回答原提示产生参考回答；评估角色对本地响应打分（1-10分），并返回失败标签；
  - 若得分低于阈值τ，则根据确定性规则将失败归因到唯一阶段（分解/改写/重构，路由不直接更新）；
  - 监督者仅接收聚合的失败统计（不接触具体失败样本），生成候选技能重写；
  - **记忆化检查**：拒绝包含占位符（如`[NAME]`）或长引文片段的候选，防止监督者“背诵”具体样本；通过检查后才替换技能提示。
- **核心优势**：无需微调SLM、无需训练辅助PII检测器；通过提示级闭环提炼使模型能泛化识别PII模式，而非记忆特定示例。

## 7. 优点

- **无需训练**：完全基于提示词操作，不需要微调SLM或训练PII检测器，部署成本低、适应新领域无需重训。
- **避免语义扭曲**：相比LDP噪声扰动，改写方式尽量保留任务上下文，隐私与质量权衡更好。
- **闭环提炼机制**：云LLM作为监督者基于聚合失败统计更新技能，并设置防记忆化检查，避免对样本的硬编码，增强了泛化能力。
- **模块化可解释**：四个技能责任清晰，每个阶段的输出有迹可循，便于调试和审计。
- **跨模型稳定性**：在四种不同规模和系列的SLM上均有效，且在两种云评判模型下趋势一致。

## 8. 不足与局限

- **残留泄漏风险**：PII检测依赖本地SLM的提示式推理，而非专门的学习器，对于复杂或隐蔽的PII仍可能漏检；一旦分解阶段漏标，后续模块无法补救。
- **推理质量上限**：P2Skill的IQ整体低于Cloud Only，尤其在银行业务等需要具体账户信息的场景中，改写会丢失关键数值，导致质量下降。
- **与SOTA的对比不充分**：未与完整版PRISM或PAPILLON等同样面向云-本地推理的隐私方法直接比较，且基线的复现可能削弱了对手实力。
- **LLM评判偏差**：自动评估依赖LLM作为裁判，可能不完全反映人类偏好；作者也承认需要人类研究。
