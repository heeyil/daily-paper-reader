## 摘要
自主LLM代理越来越多地部署在复杂的真实世界工作流程中，但它们仍然容易受到运行时行为漂移的影响，这是一种对原始任务的无声偏离，可能对外部系统造成不可逆的副作用。现有方法在提示级别处理漂移，但缺乏用于步骤级检测、风险评估和恢复决策的结构化机制。由于主任务执行代理通常是一个大型且昂贵的模型，无法在每次部署时重新训练，因此本工作针对即插即用的恢复模块。它引入了一个基于图的框架，其中单个小型语言模型通过强化学习进行训练，以在恢复图的每个节点上专门化，外部于主代理。每个节点都有一个精确的角色：漂移分类、操作检测、风险评估或最终决策，模型学习生成适应该角色的结构化XML格式推理。训练将基于规则的结构奖励与LLM作为评判者的语义质量信号相结合，因此模型既根据其回答方式（模式和长度）也根据其所说内容进行评分。在公开的AppWorld基准上的实验表明，该方法通常利用关于疑似漂移 onset 的信息，使用小型语言模型发出正确的恢复决策。此外，训练后的小型语言模型可靠地遵守规定的输出模式，并根据其分配的节点角色在每个字段中生成语义上适当的内容。

## Abstract
Autonomous LLM agents are increasingly deployed in complex real-world workflows, yet they remain vulnerable to runtime behavioral drift, a silent deviation from the original task that can lead to irreversible side effects on external systems. Existing approaches address drift at the prompt level but lack structured mechanisms for step-level detection, risk assessment, and recovery decision. Because the main task-executing agent is often a large and expensive model that cannot be re-trained on every deployment, this work targets a plug-and-play recovery module instead. It introduces a graph-based framework in which a single small language model is trained via reinforcement learning to specialize at each node of a recovery graph, external to the main agent. Each node has a precise role\,: drift classification, operation detection, risk evaluation, or final decision and the model learns to produce structured XML-formatted reasoning adapted to that role. Training combines rule-based structural rewards with an LLM-as-judge semantic-quality signal, so that the model is graded both on how it answers (schema and length) and on what it says. Experiments on the public AppWorld benchmark show that the method generally exploits information about the suspected drift onset to issue correct recovery decisions using a small language model. In addition, the trained small language model reliably respects the prescribed output schema and produces semantically appropriate content in each field according to its assigned node role.

## 1. 核心问题与研究动机

- **研究背景**：LLM 代理（agent）不再局限于问答，而是能够执行真实操作——调用 API、发送邮件、转账、修改数据库等。随着 ReAct 等框架的流行和 AppWorld 等基准的推出，代理在真实系统上的每一次失误代价都变得更高。
- **核心问题**：代理在执行长轨迹任务时容易出现**运行时行为漂移（behavioral drift）**，即代理在某一时刻开始偏离原始任务目标，却仍自信地继续执行后续步骤。这种漂移可能由网页或邮件中隐藏的恶意指令（提示注入）引发，也可能因代理自行过度扩展模糊子目标而产生。
- **关键难点**：漂移不同于崩溃或简单幻觉——幻觉答案可能触发一系列动作，最终导致漂移；且漂移一旦发生，代理已执行写操作（如转账、删除消息），仅重置模型消息历史**无法回滚环境状态**。
- **现有方法不足**：多数防御集中在输入侧（隔离不可信内容、训练指令层次、代理-工具边界防火墙），属于预防性措施，缺少漂移发生后的**结构化检测与恢复机制**。
- **本文目标**：提出一个**即插即用（plug-and-play）的恢复模块**，主任务代理无需重新训练，由一个外部小型语言模型专门负责漂移后的诊断与恢复决策。

## 2. 方法论

### 2.1 核心思想

将漂移恢复建模为一个小型状态机的路由遍历（routed traversal）：采用一个**五节点恢复图**，图中所有节点由同一个小型语言模型充当策略，但通过**角色条件提示（role-conditioned prompts）** 使模型在每个节点扮演不同专业角色。模型在每个节点输出统一的 `<reasoning>` + `<answer>` XML 格式，其中 `<answer>` 包含节点特定的 JSON 键集。

### 2.2 五节点恢复图

- **n1 – 漂移分类（Classify Drift）**：给定任务、外部漂移检测器提供的疑似漂移起始点和单步内容，判断该步骤是否与任务对齐（Y/N）。不对齐则路由到 n2。
- **n2 – 操作检测（Detect Operations）**：仅当 n1 标记为漂移时触发，枚举该步骤中成功执行的写操作和偏离任务的读操作，排除失败的写入和任务对齐的读取。
- **n3 – 文档搜索（Search Documentation）**：根据检测到的写操作，输出去重后的相关应用程序集合（如 Spotify、Gmail），用于获取 API 文档。
- **n4 – 风险评估（Evaluate Risk）**：结合写操作和 API 文档，将写操作分为 `write_reversible` 和 `write_not_reversible`。
- **n5 – 汇总决策（Aggregate & Decide）**：基于完整的逐步诊断，输出最终动作 `rollback_before_drift`（含目标步骤）或 `escalate_human`（含结构化事件报告）。

### 2.3 向后遍历与对齐连串终止

- 路由控制逻辑实现向后遍历：从疑似漂移起点 k0 开始逐步行进，遇到 Y（对齐）且**连续 K 个 Y** 时终止遍历（K 为对齐连串长度）。
- 单一对齐步骤不足以证明漂移已结束，需要连续 K 个对齐步骤作为稳健的近似信号。

### 2.4 基于 GRPO 的节点专用 RL 训练

采用 **GRPO（组相对策略优化）** 对同一策略在不同节点角色上进行专门化训练，每个节点共享 rollout 流程：

- 每个训练提示 q（带节点标签 ν ∈ {n1…n5}）采样 G 个补全。
- 每个补全需输出完整 XML 响应（1 个 `<reasoning>` 块 + 1 个 `<answer>` JSON 块）。
- **组归一化优势**：$\hat{A}_i = \frac{r_i - \bar{r}}{\text{std}(r) + \varepsilon}$，无需价值网络。
- **目标函数**：GRPO 裁剪目标 + KL 惩罚项，保持策略靠近基座模型（基座模型是 XML 模式可识别性的保障）。

### 2.5 复合奖励函数

奖励 R(o, ν, q) 为 9 个奖励分量加权求和，每个分量 ∈ [0,1]：

| 类型 | 奖励分量 | 作用 |
|------|---------|------|
| 格式类（节点无关） | rxml-count | 统计 4 个预期 XML 标签，惩罚 `</answer>` 后的垃圾文本 |
| | rstrict | 严格标签顺序与间距奖励 |
| | rsoft | 软性标签顺序奖励（训练早期先学会软模式） |
| 长度与风格（节点无关） | rreas-len | 奖励简洁推理块 |
| | rtot-len | 惩罚总输出过长（下游节点需要消费该文本） |
| JSON 与节点模式（节点特定） | rjson-valid | `<answer>` 内容为合法 JSON |
| | rjson-schema | JSON 键与节点期望键集匹配（Jaccard 部分学分） |
| | rjson-sanity | 节点特定值检查（如 is_aligned ∈ {Y,N}、action 合法性） |
| 语义质量（LLM-as-judge） | rjudge | 冻结的更强 LLM 法官根据角色特定评分规则，对推理是否扎根于提示、答案内容是否一致且合理进行打分 |

- 训练中 rjudge 采用 14B 开源推理模型（自托管），评分缓存并并行调用。
- **非负奖励设计**使策略即使在全组都不完美的情况下仍被拉向组内最优。

### 2.6 漂移分类学（重要前提）

- **Type I – 瞬时读漂移**：漂移区内无环境变化、无写入，直接回滚消息历史即可。
- **Type II – 持久读漂移**：无写入但漂移源持续存在（如恶意文档仍在邮箱中），需额外携带漂移感知恢复记忆/警告。
- **Type III – 写入漂移**：漂移区至少有一个写操作，环境已改变，回滚消息历史无济于事；需区分可逆/不可逆写入，不可逆则必须升级给人类。当前框架只做检测，不执行逆操作。

## 6. 主要结论与发现

- **内在奖励全面改善**：Granite 3.3 2B 的复合奖励均值从 3.68 升至 5.15，judge 子分数从 0.71 升至 0.90；Qwen 2.5 1.5B 更显著，从 0.56 升至 4.80（8.6 倍提升），judge 分数从 0.47 升至 0.66。100 个留出提示上的增益全部为正。

- **端到端恢复有效**：Type I 下训练 Granite 达到 27.5% 聚合完成率，是无漂移上界 35.3% 的约 78%，接近 GPT-4o 恢复背骨（32.5%）的表现；Type II 下 GPT-4o 初始代理时达到 35.0%，接近无漂移上界 42.5%。

- **语义质量同步提升**：rjudge 的稳定提升表明 GRPO 不只优化形式检查，也增强了内容扎根性。
- **单一策略多角色可行**：无需为每个节点训练独立策略，通过节点标签条件化 + 复合奖励即可在单模型中完成全部五角色专门化。

## 7. 优点

- **即插即用设计**：恢复模块完全外部于主代理，不要求重训大型昂贵模型，部署成本低。
- **单一小模型 + 多角色共享策略**：避免了 per-node 独立策略的资源开销，GRPO 的组相对信号使训练在单 GPU 上可行。
- **奖励设计的两条腿**：规则化结构奖励 + LLM-as-judge 语义奖励的结合，使模型既学会“怎么说”（模式与长度）又学会“说什么”（内容质量），且非负奖励设计在早期训练阶段保持策略向组内最优收敛。
- **结构化推理（XML+JSON）而非自由 CoT**：每个节点输出成为下一个节点的“类型化消息”，避免了自由文本解析脆弱性问题，这与诊断图的分步路由天然匹配。
- **问题定义严谨**：对理想执行集、漂移定义（非单调性）、三种漂移类型的分类学、可逆/不可逆操作的定义都很清晰，为后续研究建立了形式化基础。
- **端到端验证合理**：既有内在指标（奖励分解）又有外在指标（AppWorld 任务完成率），并包含上界/下界对比，能有效区分恢复模块自身能力和任务执行代理能力的局限。

## 8. 不足与局限

- **Type III（写漂移）未闭环**：框架目前只检测和分类写操作，不执行逆 API 调用；对可逆写入的实际修复、对不可逆写入的自动处理均留给未来工作。n4 的可逆性分类只有 judge 分数支撑，未在真实环境中验证。
- **n4（evaluate_risk）是薄弱环节**：Granite 上 judge 子分数仅从 0.72 提升至 0.78，低于其他节点。可逆性判断依赖 API 逆操作的事实知识，通用 judge 可能无法检测编造的逆端点。
- **对疑似漂移起点 k0 的质量高度依赖**：外部漂移检测器提供的 onset 质量直接影响恢复效果，论文未对 k0 的鲁棒性做专门实验。
- **奖励黑客风险**：小模型可能学会 judge 过度评价的“看似合理但空洞”的风格化推理（如冗长的因果连接词），GRPO 的组归一化能吸收单调平移但不能消除系统性偏向。
- **长度奖励轻微回退**：Granite 的 tot_len 从 0.14 降至 0.08，因为训练后模型产出的 `<reasoning>` 变长（judge 奖励更丰富推理），需要在未来工作中重新调整长度奖励权重。
- **实验覆盖面有限**：端到端评估仅覆盖单一漂移模式（注入恶意指令），没有覆盖代理自身过度扩展子目标导致的自然漂移；Type II 中较弱初始代理（GPT-4o-mini）恢复效果明显受限（7.5% vs 12.5% 恢复背骨），说明恢复模块效果部分受制于主代理在回滚后能否正确使用警告。
- **与基础模型的对比基线薄弱**：端到端实验缺少与现有替代恢复策略的系统对比（如提示级一次性修复、自由 CoT 修复等），未证明图结构相对非结构化提示在恢复成功率上有显著优势。
