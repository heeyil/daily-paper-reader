## 摘要
许多现实世界任务要求LLM智能体在较长的执行时程中与环境交互。早期执行中发生的错误可能会通过智能体上下文和环境状态传播，且其影响可能难以通过后续行动逆转。现有方法主要旨在通过计划细化和安全检查减少此类错误，但在错误发生后提供的支持甚少。为实现长时程执行中的恢复，我们提出AgentRewind，一种运行时恢复框架，记录智能体上下文与受控环境的对齐检查点，使智能体能够返回早期状态并利用先前尝试的信息恢复执行。我们还构建了MettleBench，一个用于评估包含一系列相关需求的长时程工程任务完成情况与部分进展的基准。跨任务、多模型、执行策略和智能体框架的实验表明，AgentRewind在任务成功率和平均检查表进展方面优于所对比的基线。

## Abstract
Many real-world tasks require LLM agents to interact with their environments over long execution horizons. Errors that occur early in execution may propagate through both the agent context and environment state, and their effects may be difficult to reverse through subsequent actions. Existing methods mainly seek to reduce such errors through plan refinement and safety checks but provide little support after errors occur. To enable recovery during long-horizon execution, we present AgentRewind, a runtime recovery framework that records aligned checkpoints of the agent context and controlled environment, allowing agents to return to an earlier state and resume execution with information from previous attempts. We also construct MettleBench, a benchmark for evaluating task completion and partial progress on long-horizon engineering assignments containing a series of related requirements. Experiments across tasks, multiple models, execution strategies, and agent harnesses show that AgentRewind improves task success rate and average checklist progress over the compared baselines.

## 1. 核心问题与研究动机

- **问题背景**：LLM智能体在解决现实任务时，需要与环境进行长时程交互。这类任务涉及大量执行步骤，智能体在早期执行中容易犯错，错误会通过智能体上下文（context）和环境状态（environment state）双向传播，且影响往往难以通过后续操作逆转。
- **现有方法的不足**：已有工作主要聚焦于**预防错误**——通过计划细化（如LATS、Plan-and-Act）和安全检查（如AgentDoG、GuardAgent）来降低错误率。但即使单步错误率极低，累积失败风险也会随轨迹长度迅速上升；一旦错误实际发生并破坏执行，现有方法缺乏有效的**事后恢复（recovery）**能力。
- **核心研究问题**：如何让长时程智能体在执行过程中“纠正历史错误”——即回到之前的某个正确状态，并带着前次失败的经验重新出发？

## 2. 方法论：AgentRewind 框架

### 2.1 核心思想

AgentRewind 是一个**运行时恢复层**（runtime recovery layer），位于智能体与受控外部环境之间。它通过记录**对齐的检查点（aligned checkpoints）**，使智能体在发现当前轨迹无法继续推进时，可以主动回退到历史检查点，保留此前尝试的信息继续执行。

### 2.2 关键形式化

- **标准前向执行**：智能体在步骤 t 生成决策 uₜ，环境更新状态 sₜ → sₜ₊₁ 并返回观察 oₜ₊₁，上下文更新为 cₜ₊₁。轨迹只能**向前增长**。
- **可恢复执行**：在每次 LLM 决策边界，记录可恢复检查点 dₜ = (cₜ, sₜ)，并构造描述该段执行元信息的元数据 ηₜ。当智能体判断当前轨迹无法继续时：
  1. 选择历史检查点 dₖ（k ≤ T）；
  2. 从当前轨迹生成**回退记忆** m（如被证伪的假设、替代策略）；
  3. AgentRewind 将环境恢复至 sₖ、上下文恢复至 cₖ，并将累积的回退记忆集合 M 注入 cₖ，形成新上下文 c′ₖ；
  4. 智能体从 (c′ₖ, s′ₖ) 继续生成新的后缀轨迹。

### 2.3 运行时恢复层的实现机制

- **记录机制**：AgentRewind 透明记录轨迹（LLM输入输出、工具调用与结果、任务指令），不改变智能体与环境的正常交互方式。利用 `llm` 记录和 `tool` 记录两种节点类型，逐条保存执行记录。
- **回退机制**：向智能体暴露 `backtrack_candidates`（列出可回退的检查点候选）和 `backtrack_commit`（提交回退并携带记忆说明）两个控制工具，由智能体自主决定是否和如何回退。
- **环境恢复边界**：可恢复范围为**工作区目录树**（workspace directory tree）。通过维护工作区外部的裸 Git 仓库记录文件系统快照，恢复时对比当前树与目标树：删除新增文件、还原修改、恢复已删文件。`.git` 目录内部、网络请求、外部服务调用等影响不可撤销；但保留前缀是按执行日志复现的，不会二次触发外部副作用。

### 2.4 MettleBench 基准

- **任务形式**：每个任务是一个包含**一系列有序、相互依赖的验收标准**的工程作业 T = (x, s₀, U, G)，其中 G = (g₁, ..., gₙ) 是有序验收标准列表，每个 gᵢ 是对环境状态的二元判定函数。
- **评估指标**：任务成功 = 所有验收标准满足；部分进展 = 满足的最长前缀长度 ℓ / n，即 **检查表前缀进度 ρ(s_T) = ℓ/n**。
- **构建来源**：从 5 个现有基准（Terminal-Bench 2.0、ProgramBench、SWE-bench、ProjectEval、GitTaskBench）衍生 82 个任务、640 个验收标准，并验证每个任务都有前向参考解（无回滚机制也能完成）、评估器确定性、工作区初始失败。

## 3. 实验设计

### 3.1 基准与数据

### 3.2 对比方法与策略

- **Continue**：验证反馈后从当前上下文和环境直接继续。
- **Restart with Experiences**：失败后重置环境与上下文，将此前累积的失败经验文件带入新一轮尝试。
- **Safety Review**：同 Continue，但每个工具调用前经 AgentDoG 安全监控审查，不安全动作被拦截。
- **AgentRewind**：可回退执行，使用 `backtrack_candidates` 和 `backtrack_commit`。

### 3.3 评估变量与配置

- **7 个基础模型**：GPT-5.4、GPT-5.4 mini、Qwen3.7-Max、Qwen3.5-27B、Kimi K2.5、DeepSeek-V4-Flash、GLM-5.1。

- **主要配置**：温度 0.0（贪心解码，Kimi K2.5 例外为厂商规定的 0.6）、无步数/时间限制、连续 5 次相同首个失败即终止。每个配置独立重复 3 次。

## 6. 主要结论与发现

1. **AgentRewind 在全部设置下均优于基线**：在 MettleBench 上（GPT-5.4），任务成功率从 Continue 的 62.2% 提升至 87.8%（+25.6 个百分点）；平均检查表进度从 81.4% 提升至 94.3%。GPT-5.4 mini 下也从 33.7% 提升至 51.2%。
2. **回退在长时程任务中尤为重要**：按轨迹长度分组后，AgentRewind 在中、长时程组中的增益远大于短时程组。
3. **安全审查并非总有效**：Safety Review 在 GPT-5.4 下甚至显著劣于 Continue（34.1% vs 62.2%），说明过度拦截可能打断有效推理。
4. **组件消融揭示了各环节的重要性**：去掉环境回退降幅最大（87.8% → 43.9%），其次是去掉回退记忆（→ 51.2%），去掉上下文回退（→ 65.9%）。三者相互补充。
5. **配对的失败恢复实验证实恢复能力提升**：从相同失败端点出发，AgentRewind 恢复率为 30.0%，Continue 仅 8.0%。
6. **泛化性良好**：跨 3 种智能体框架均有效，且在 Terminal-Bench 2.0 上也优于基线和 Restart with Experiences。

## 7. 优点

- **弥补了现有研究的关键断层**：当前领域聚焦预防性措施，AgentRewind 率先系统性地支持事后恢复，与预防方法正交可结合。
- **对齐检查点设计巧妙**：上下文与环境状态在同一决策边界对齐记录，回退时恢复同一时间点的全部状态，而非孤立的上下文或环境恢复。
- **回退记忆机制**：不是简单“回到过去”，而是带着失败经验继续，避免重蹈覆辙，这一设计将回退从“重来”升级为“更聪明的重来”。
- **MettleBench 基准设计精细**：有序、隐藏、相互依赖的验收标准真实地刻画了长时程工程任务的特性（后续步骤可能破坏之前满足的标准）；“前向参考解”验证保证基准不强制需要回退机制；部分进度指标（前缀进度）比二值成功度量信息更丰富。
- **对执行策略的公平比较**：所有策略共享相同环境、工具、终止条件，仅差异在失败后处理，对比清晰可控。
- **工程实现成熟**：论文详细说明了与 3 个智能体框架的适配方法、记录格式、恢复的精确边界和限制，可复现性强。

## 8. 不足与局限

- **恢复边界有限**：只能恢复受控环境中的工作区文件系统，无法撤销网络请求、外部服务调用、进程运行时状态等外部副作用。论文承认了这一限制，但未讨论在需要与外部系统持续交互的任务中该方法的退化程度。
- **依赖外部验证器识别停滞**：AgentRewind 依赖环境返回“连续 5 次相同失败”的外部信号来判定停滞。若验证反馈本身不准确或延迟，回退决策可能被误导。论文将其列为未来方向，未做深入处理。
- **无内置进度评估能力**：智能体何时回退、回退到哪个检查点，完全取决于智能体自身判断，缺乏更系统化的回退策略（如自动选择最优回退点）。
- **每配置仅 3 次重复**：考虑到 LLM 采样的随机性，3 次重复的均值和标准差估计精度有限，对差异较小的比较（如 GPT-5.4 mini 下 AgentRewind vs Restart 的任务成功率差异）置信度受限。
- **模型版本与时代**：论文中的模型名称（GPT-5.4、Qwen3.7、GLM-5.1 等）和日期（2026年）具有时效性，方法在更早或更新的模型家族上的表现未验证。
- **未披露算力成本**：没有报告回退机制带来的额外推理开销（额外的 `backtrack_candidates` / `backtrack_commit` 调用、元数据生成等），使实际部署成本评估困难。
