## 摘要
现代LLM智能体通常通过手动修改提示、工具或工作流来改进，而模型周围的可执行脚手架——即“外壳”（harness）——在部署后通常被视为固定工件。本研究探讨了一种替代方案，其中外壳是任务特定且可持续演进的：每个任务族维护自己的外壳，通过固定的任务注入接缝在迭代中热切换，并利用环境反馈进行重写。我们提出了层次化自我改进（HSI），该框架中，一个冻结的LLM M在三个层次范围内运作：执行任务的任务外壳H、重写H的进化器，以及在冻结外部锚定下重写进化器策略代码的元进化器。一种思考开/关设计通过在执行任务时禁用推理，而在自我修改时启用推理，来隔离外壳演进的贡献。HSI受两个因素限制：反馈保真度界限，因为演进需要信息丰富的奖励信号来引导选择；以及骨干能力界限，因为外壳重新设计无法克服冻结模型的局限。在BALROG上使用DeepSeek-V4-Flash-Preview作为冻结骨干，HSI在中等难度任务上相比初始外壳取得了持续改进（BabyAI上+39.3，Crafter上+33.0，TextWorld上+25.0，MiniHack上+15.0，均为原始百分比进度），同时在BabaIsAI子套件上获得了强大的保留泛化能力（在20%未见分割中，BreakStop上最佳测试0.98，GoTo上1.00）。在超出骨干能力的任务（NLE）上，外壳演进没有带来改进。这些结果表明，在明确的经验限制下，任务特定的外壳演进是改进冻结LLM智能体的一个可行方向。代码可在 https://github.com/TailinZhou/hsi 获取。

## Abstract
Modern LLM agents are often improved by modifying prompts, tools, or workflows manually, while the executable scaffold surrounding the model---the \emph{harness}---is typically treated as a fixed artifact after deployment. This work studies an alternative where the harness is \emph{task-specific and continuously evolvable}: each task family maintains its own harness, which is hot-swapped across iterations through a fixed task-injection seam and rewritten using environment feedback. We introduce \textbf{Hierarchical Self-Improvement (HSI)}, a framework in which a single frozen LLM $M$ operates across three hierarchical scopes: a task harness $H$ that executes tasks, an evolver that rewrites $H$, and a meta-evolver that rewrites the evolver's strategy code under a frozen outer anchor. A thinking-on/off design isolates the contribution of harness evolution by disabling reasoning during task execution while enabling it during self-modification. HSI is bounded by two factors: a \emph{feedback-fidelity bound}, since evolution requires informative reward signals to guide selection, and a \emph{backbone capability bound}, since harness redesign cannot overcome limitations of the frozen model. On BALROG with DeepSeek-V4-Flash-Preview as the frozen backbone, HSI achieves consistent gains over the initial harness on moderate-difficulty tasks ($+39.3$ on BabyAI, $+33.0$ on Crafter, $+25.0$ on TextWorld, and $+15.0$ on MiniHack, all in raw \% Progress), while obtaining strong held-out generalization on BabaIsAI sub-suites ($0.98$ best-test on BreakStop and $1.00$ on GoTo from a $20\%$ unseen split). On tasks beyond the backbone's capability (NLE), harness evolution provides no improvement. These results demonstrate task-specific harness evolution as a viable axis for improving frozen LLM agents under clear empirical limits. Code is available at https://github.com/TailinZhou/hsi.

## 1. 核心问题与研究动机

- **背景**：现代 LLM 智能体的性能高度依赖其外围可执行脚手架（即 harness），包括提示词、工具编排、记忆、状态管理和验证逻辑等。研究发现，即使使用相同的模型骨干，不同的 harness 设计也会造成显著的性能差距。
- **核心问题**：当底层模型被冻结时，智能体能否**内生地（endogenously）演化自己的 harness** 来提升任务性能？这种提升的**根本限制**是什么？
- **现存挑战**：
  - 现有自我改进方法（如 Gödel Machine 风格的系统）主要进化的是智能体的逐步骤决策代码，尚未充分触及 harness 层；
  - 针对 harness 层的工程优化往往依赖外部更强的模型作为提议者，而非同一模型内生完成；
  - 近年评估发现，harness 进化可能只是"测试时搜索"的假象，存在严重的过拟合和泛化不足问题。
- **核心主张**：HSI 提出"任务特定、可持续演进"的 harness 范式——每个任务族维护自己的 harness，通过固定接口热切换，并依据环境反馈持续重写，从而在冻结骨干模型下实现系统性的性能提升。

## 2. 方法论：Hierarchical Self-Improvement (HSI)

### 2.1 核心设计思想

- **单一冻结模型，三个层次范围**：同一个冻结 LLM M 同时在三个层次运作：
  - **任务 harness 层**：M 执行任务 harness H 与环境交互；
  - **进化器层（Evolver）**：M 重写 H，包括种子选择、主进化、提交选择；
  - **元进化器层（Meta-Evolver）**：M 重写进化器的策略代码 Σ。
- **冻结外部锚点**：元进化器自身的执行逻辑不可编辑，由不可变初始化模板加载，从而防止无限制的自我指涉，将自我修改限制在分层且经验验证的编辑范围内。
- **思考开/关设计**：任务执行时禁用推理（固定模型能力上限），自我修改时启用推理（最大化修改成功概率），从而隔离 harness 进化的真实贡献。

### 2.2 五阶段进化循环

1. **种子选择（Seed Selection）**：从累积进化图 Gt 中选择祖先版本，生成结构化假设（包括锚定版本、选择动机、预期改进方向、可证伪标准），将进化从无约束变异转化为目标导向搜索。
2. **主进化（Main Evolution）**：基于种子和假设生成候选 harness 版本，可编辑面覆盖提示、工具、内存、状态管理、钩子和执行策略；通过环境评估获得奖励反馈。
3. **提交选择（Commit Selection）**：不只看最高奖励，而是维护多样化的提交池（多提交池），保留多个进化方向及语义理由。
4. **元进化（Meta-Evolution）**：修改进化策略 Σ（种子策略、进化策略、提交策略、最终版本选择策略），使搜索策略本身也可适应。
5. **最佳版本选择（Best-Version Selection）**：优先考虑泛化性，在验证集上评估候选版本，导出最终部署的 harness。

### 2.3 关键公式

- 种子选择：$(H_t, h_t) = \text{seed\_selection}(G_t, M)$
- 主进化：$\{V_t^{(k)}\}_{k=1}^{K_t} = \text{main\_evolution}(\hat{H}_t, h_t; M)$
- 提交选择：$C_t = \text{commit\_selection}(\{V_t^{(k)}\}, G_t; M)$
- 元进化：$\Sigma_{t+1} = \text{meta\_evolution}(G_t \cup C_t, \Sigma_t; M)$
- 候选评估使用随机下置信界奖励：$r = \mu - z\frac{\sigma}{\sqrt{n}}$，其中 z=0.5

### 2.4 理论边界

- **反馈保真度界限**：进化需要信息丰富的奖励信号来引导选择；奖励稀疏时进化无效。
- **骨干能力界限**：harness 重设计无法克服冻结模型自身的推理能力局限。

## 3. 实验设计

### 3.1 Benchmark 与数据集

- **BALROG**：长视界文本交互游戏基准，包含 6 个环境，覆盖不同能力需求：
  - **BabyAI**（指令跟随/导航）、**BabaIsAI**（导航/推箱）、**Crafter**（长视界规划/资源管理）、**TextWorld**（多步推理/对象操作）、**MiniHack**（高难度 roguelike）、**NLE**（NetHack，超高难度/稀疏奖励）
- **指标**：episode 级 % Progress（0-100 标度，进化时缩放到 [0,1]）

### 3.2 骨干模型与配置

- 所有实验使用 **DeepSeek-V4-Flash-Preview** 作为冻结骨干 M（任务执行、进化器、元进化器三层次共享同一模型）
- 每轮进化 T=5 次外迭代，每次迭代最多 80 个 react() 步
- 任务执行时温度 0、禁用思考；进化和元进化时启用思考、推理强度最大

### 3.3 两种评估协议

- **Setup A（分布内进化）**：进化与评估使用同一任务集，但每次评估重新采样环境种子。应用于 TextWorld、BabyAI、Crafter、MiniHack、NLE。
- **Setup B（保留泛化）**：对 BabaIsAI 按子套件（BreakStop、GoTo、Make）划分开发/验证/测试集，测试集在进化过程中完全不可见，评估 20% 未见任务的泛化能力。

### 3.4 对比方法

- **Init Harness**：手写原始 harness 在相同骨干和评估协议下的表现（主要受控基线）
- **BALROG 排行榜公开结果**：Gemini-3-Pro、Grok-4、Claude-Opus-4.5、GPT-4o、DeepSeek-R1 等前沿模型原生配置下的结果（仅作上下文参考）
- **Meta-off 消融**：关闭元进化器，隔离进化策略自身演进的贡献

## 6. 主要结论与发现

1. **内生 harness 进化有效**：冻结的 DeepSeek-V4-Flash 通过 HSI 在中等难度任务上大幅提升——BabyAI +39.3、Crafter +33.0、TextWorld +25.0、MiniHack +15.0（均为原始 % Progress）。
2. **元进化贡献显著**：关闭元进化器后所有套件性能下降，TextWorld 下降 19.0、MiniHack 下降 10.0，说明进化策略自身的适应能力在高复杂度搜索空间中尤为重要。
3. **保留泛化可行**：BabaIsAI 导航类子套件（BreakStop、GoTo）获得接近完美的保留测试表现（0.98 和 1.00），说明进化发现的交互模式可迁移至未见任务。
4. **反馈质量决定进化成效**：NLE 上由于骨干初始能力和奖励信号都极低，harness 进化无实质改进（0.2% Progress），验证了反馈保真度界限。
5. **骨干能力是最终约束**：BabaIsAI-Make 等需要多步合成的任务，即便 harness 进化有提升（0 → 0.36），仍受限于冻结模型的推理能力上界。
6. **进化动态特征**：最大改进通常出现在第一轮迭代，后期迭代趋于精细化；进化过程非单调，后期修改可能出现性能回退。

## 7. 优点与亮点

- **概念创新**：将"进化者自身也可被进化"的元层次思想引入 harness 工程，同时通过冻结外部锚点避免了无限制自我指涉的理论风险。
- **实验归因清晰**：思考开/关设计巧妙地将 harness 进化的贡献与推理时计算量分离，这是同类工作中少见的严谨设计。
- **任务特定范式的提出**：区别于"一个通用 harness 走天下"的思路，HSI 强调每个任务族维护专属 harness，并通过保留集评估泛化，回应了近期关于 harness 进化过拟合的批评。
- **理论边界刻画**：通过跨难度环境的系统实验，清晰地刻画了反馈保真度界限和骨干能力界限两个实用边界。
- **开源性**：代码已公开，便于社区复现和扩展。

## 8. 不足与局限

- **骨干单一性**：仅使用一个 API 模型（DeepSeek-V4-Flash），无法判断结论是否适用于其他模型族、不同规模模型或开源模型。
- **进化轮次有限**：T=5 轮进化相对较浅，未探索更长进化时间下的收益曲线是否趋于饱和或继续增长。
- **NLE 负结果的解释力有限**：无法区分是反馈稀疏导致的进化失败，还是骨干能力不足导致的根本失效。
- **计算成本未报告**：未量化进化过程的 API 调用次数、总 token 消耗或经济成本，限制了实际部署可行性的判断。
- **统计稳健性存疑**：进化多次运行的标准差、显著性检验等信息缺失，单次运行结果可能受随机性影响。
- **BabaIsAI-Make 泛化差距**：进化提升了开发集性能，但保留测试集表现仍大幅落后（0.36 vs 0.56 dev），说明进化策略可能仍存在一定程度的开发集过拟合。
- **无跨任务迁移验证**：论文明确说明"任务特定进化"，但未测试同一任务族内不同子套件之间的迁移效果。
