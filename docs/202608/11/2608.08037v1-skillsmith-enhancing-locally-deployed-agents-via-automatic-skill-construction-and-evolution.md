## 摘要
基于大语言模型的智能体框架现已成为处理多步任务的个人助理。现有框架（如OpenClaw）通常采用云智能体部署模式，以闭源云大语言模型（LLM）作为骨干模型，这可能暴露用户隐私信息并产生重复的LLM调用成本。本地智能体通过在用户控制的设备上部署前沿开源小语言模型（SLM）来解决上述部署问题，但其任务效果仍远逊于云智能体。通过诊断分析，我们发现，采用前沿SLM骨干的本地智能体效果有限，主要源于骨干模型规模有限导致的环境知识缺失，包括环境规则与操作流程。为了以非参数化、上下文高效且无需专家编写的方式补充此类知识，我们提出了SkillSmith——一种云-本地智能体协作框架，将技能（Skill）作为上下文高效的知识载体，从云智能体任务探索中自动构建技能，并利用本地智能体执行反馈进化技能，以增强冻结的本地智能体。在每日智能体任务数据集AppWorld和WorkBench上的实验表明，自动生成的技能使配备Qwen3.6-27B（SLM）的本地智能体达到了与使用前沿LLM的云智能体相当的任务效果，超越了最强的非参数基线，将AppWorld-Normal上的每任务平均动作数从36.1降至9.9，并且无需重新运行技能构建即可泛化到其他SLM骨干模型。

## Abstract
LLM-based agent frameworks now act as personal assistants for multi-step tasks. Existing agent frameworks such as OpenClaw commonly follow the Cloud Agent depolyment mode using closed-source cloud LLMs as backbone model, which may expose private user information and incur repeated LLM-calling costs. Local Agents address these deployment concerns by depolying frontier open-source SLMs on user-controlled devices, but their task effectiveness still lags far behind Cloud Agents. Through diagnostic analysis, we reveal that the limited effectiveness of Local Agents with frontier SLM backbones mainly comes from missing environment knowledge caused by limited backbone model scale including environment rules and operation procedures. To supply such knowledge non-parametrically, context-efficiently, and without expert authoring, we present SkillSmith, a Cloud--Local Agent collaboration framework that uses Skill as a context-efficient knowledge carrier, automatic constructs Skill from Cloud Agent task exploration and evolves Skill using Local Agent execution feedback to enhance a frozen Local Agent. Experiments on daily agent task datasets AppWorld and WorkBench show that the automatically generated Skill enables the Local Agent with Qwen3.6-27B(SLM) to achieve task effectiveness comparable to Cloud Agents with frontier LLMs, outperform the strongest non-parametric baselines, reduce average actions per task from 36.1 to 9.9 on AppWorld-Normal, and generalize to other SLM backbone models without rerunning Skill construction.

- **本地部署优势与挑战**：本地智能体（Local Agent）在用户设备上部署开源小语言模型（SLM），可避免隐私泄露和云端调用成本，但任务通过率显著低于云端智能体（如 Qwen3.6-27B 在 AppWorld-Normal 上仅 36.3%，vs Claude Opus 4.7 的 94.0%）。

- **整体意义**：论文提出以“技能”（Skill）作为非参数化、上下文高效的知识载体，通过云-本地智能体协作自动构建并演进技能，在不微调骨干模型的前提下增强冻结的本地 SLM，可兼顾隐私、成本与任务效果。

## 2. 方法论：SkillSmith 框架

- **核心思想**：采用“技能”（Skill）作为环境知识载体，定义为三元组 $S=(M,R,C)$：
  - $M$：主 Markdown 文件（SKILL.md），包含元数据、通用指令和引用索引；
  - $R$：参考文件集合，存环境规则与操作过程；
  - $C$：加载条件，决定何时加载对应参考文件。
  这种设计支持渐进披露，只将当前任务相关的知识放入上下文，避免上下文膨胀。
- **优化框架**：将技能学习建模为黑盒优化——在长度预算 $L_{max}$ 下，寻找使冻结本地智能体在目标任务分布上期望通过率最大的技能 $S^*$。由于技能空间是离散自然语言文档，无梯度可用，论文借鉴 TextGrad 思路，将云端 LLM 作为文本优化器，本地执行反馈作为类梯度信号。
- **两阶段流程**：
  1. **技能创建（Skill Creation）**：
     - 云智能体执行代表性训练任务，结合评估器反馈，将每条轨迹反思压缩为 Reflection Report（包含任务、轨迹摘要、更优路径、陷阱、工具等）。
     - 随后通过多角色智能体协作创建初始技能：Cluster Agent 对报告聚类；Distill SubAgent 从每个聚类中提炼可复用信号（步骤模板、陷阱与补救、规则、触发关键词、跨聚类通用性）；Merge Agent 将聚类洞察合并为长度受限的初始技能 $S_0$——跨聚类通用知识进入主手册，特定领域知识放入参考文件并附加载条件。
  2. **技能进化（Skill Evolution）**（多轮迭代）：
     - 本地智能体携带当前技能 $S_{i-1}$ 执行训练任务，将失败轨迹与评估反馈压缩成 Failure Report；
     - 云智能体对这些报告聚类，由 Analyze SubAgent 将失败归因于：技能/参考未加载、技能内容不完整或错误、接近通过的粗心错误、非技能可修复原因，并按失败频率给出修改优先级；
     - Merge Agent 将修改意见合并为新的受限技能 $S_i$，解决冲突、按优先级修改、超预算时压缩；
     - 多次迭代后选取训练集上经验通过率最高的技能版本作为最终部署技能 $S^*$。
- **算法流程**（Algorithm 1）可概括为：执行反思 → 聚类 → 提炼 → 合并创建初始技能 → 本地执行压缩 → 反复聚类分析合并进化。

## 6. 主要结论与发现

- **诊断结论**：本地 SLM 与云 LLM 的核心智能体能力相当；效果差距主要由环境知识缺失造成；非参数注入环境知识可有效修复大部分失败。
- **方法效果**：
  - SkillSmith 在 AppWorld-Normal、AppWorld-Challenge、WorkBench 上分别达到 78.6%、74.9%、89.0% PR，超越最强非参数基线 11.3–26.2 个百分点；

  - 离线性价比高：在线服务足够多任务后，总成本优于持续调用云 LLM 的智能体。

## 8. 不足与局限
