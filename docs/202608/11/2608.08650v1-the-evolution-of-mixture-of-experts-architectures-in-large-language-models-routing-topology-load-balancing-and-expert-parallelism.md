## 摘要
混合专家模型在保持每个令牌激活的计算量受限的同时增加了参数容量，但其架构演变无法仅通过按时间顺序列出的模型发布来解释。本技术综述综合了原始论文、官方技术报告和先前综述，从五个耦合维度组织现代混合专家系统：专家粒度、专家拓扑、路由自由度、负载均衡范围和执行结构。我们将八个架构里程碑描述为一个依赖图，包含六条主线发展和两条正交分支，而非八代连续演进。随后，我们通过四个控制面对各个系统进行分析：专家拓扑、路由、均衡和专家并行。这些控制面规定了存在哪些专家、每个令牌由哪些专家处理、如何控制总体负载以及如何将选中的计算映射到物理设备上。该框架将诸如Top-k路由、共享专家、细粒度专家和动态专家组合等算法选择与令牌调度、设备放置、全对全通信和通信-计算重叠等系统问题联系起来。最后，我们以等预算预训练实验、质量和系统指标以及开放研究问题作为结论。主要趋势是从单纯激活更多稀疏参数转向解耦语义路由、计算预算和物理执行。

## Abstract
Mixture-of-Experts models increase parameter capacity while keeping the computation activated by each token bounded, but their architectural evolution cannot be explained by a chronological list of model releases alone. This technical survey synthesizes primary papers, official technical reports, and prior surveys to organize modern Mixture-of-Experts systems along five coupled dimensions: expert granularity, expert topology, routing freedom, the scope of load balancing, and execution structure. We describe eight architectural milestones as a dependency graph with six mainline developments and two orthogonal branches, rather than as eight successive generations. We then analyze individual systems through four control planes: Expert Topology, Routing, Balance, and Expert Parallelism. These planes specify which experts exist, which experts process each token, how aggregate load is controlled, and how selected computation is mapped onto physical devices. The framework connects algorithmic choices such as Top-k routing, shared experts, fine-grained experts, and dynamic expert composition with systems concerns including token dispatch, device placement, all-to-all communication, and communication-computation overlap. We conclude with equal-budget pretraining experiments, quality and systems metrics, and open research questions. The main trend is a shift from merely activating more sparse parameters toward decoupling semantic routing, computational budgets, and physical execution.

## 2. 论文提出的方法论

### 2.1 核心思想

论文提出一个**双视角互补分析框架**：
- **时间轴视角**：八个演进里程碑，按“主导瓶颈迁移”划分，由六条主干节点 + 两条正交分支构成依赖图；
- **系统剖面视角**：四控制平面（Topology → Routing → Balance → Expert Parallel）构成闭环，分析单个 MoE 系统的内部工作机制。

### 2.2 关键技术细节

#### 形式化定义（Token-choice MoE）
- 路由器计算专家亲和度：`sᵢ,ₜ = φ(xₜ, eᵢ)`，通过 `TopK` 选出候选集 Kₜ；
- 输出为加权组合：`yₜ = xₜ + Σᵢ∈Kₜ gᵢ,ₜ Eᵢ(xₜ)`，其中权重 `gᵢ,ₜ` 为 softmax 归一化。
- 若存在共享专家，则增加常开路径项。

#### 三目标优化
- MoE 同时优化：**总容量最大化**、**单 token 激活量控制**、**系统效率（低负载变异系数 CV）**；
- 公式：总容量近似为 `P_active ≈ P_dense + (k/N)·P_routed + P_shared`；
- 负载变异系数 `CV_expert` 用于衡量负载均衡程度——低 CV 有利于 EP 吞吐，但不必然代表知识专门化。

#### 四控制平面闭环
- **Topology（对象层）**：定义专家集合、粒度、共享关系，属于慢变量；
- **Routing（决策层）**：逐 token 生成专家子集 Kₜ，优化局部语义匹配；
- **Balance（控制层）**：统计聚合负载 {nᵢ}，通过 loss、bias、capacity 反馈；
- **Expert Parallel（执行层）**：按放置 π 和调度 σ 执行 dispatch/combine。
- 存在两类反向依赖：物理拓扑约束语义路由；运时复制/放置可在不改变 Kₜ 情况下改善物理负载。

#### 八个演进里程碑
1. **Dense/Soft MoE（1991）**：建立 gating + experts + weighted combination 三角色，但计算随专家数线性增长；
2. **Sparse Top-k（2017）**：噪声 Top-k 路由实现“参数容量与单 token 计算解耦”，建立容量杠杆；
3. **Transformer MoE + EP（GShard）**：固定执行链 Attention→Router→Dispatch→Expert FFN→Combine，引入 All-to-All、capacity、token drop 等配套机制；
4. **开放权重粗粒度 MoE（Mixtral）**：打通预训练→指令微调→推理部署→社区复现的完整闭环；
5. **Shared + Fine-grained experts（DeepSeekMoE/V2）**：提高组合分辨率、隔离公共知识、device-limited routing 控制 fan-out；
6. **Ultra-sparse scaling（PEER、Kimi K2）**：固定 active budget 下继续扩总专家数，验证 scaling 收益；
7. **动态计算（LongCat-Flash）**：zero-computation experts、adaptive-k，实现 token 级可变计算预算；
8. **语义路由与物理解耦（ScMoE、MoHGE、GMoE、Head Parallel）**：四条前沿分支分别优化时间重叠、计算形态、参数复用、数据移动。

#### 关键平衡机制
- 经典辅助损失：`L_bal = (α/N)·Σ fᵢ·Pᵢ`，同时承担防 collapse 与防 straggler 双重职责，但二者不等价；
- **Auxiliary-Loss-Free（ALF）策略**：引入非梯度路由 bias `bᵢ ← bᵢ + η·sign(n̄ − nᵢ)`，避免均衡目标直接干扰 LM 梯度（DeepSeek-V3 采用 batch-wise ALF + 弱 sequence-wise loss）。

## 6. 论文的主要结论与发现

1. **主干结论**：MoE 架构史不是“专家越来越多”的单线扩张，而是**五条路线的共同演化**——专家粒度、拓扑、路由、均衡、执行结构各自演变且相互耦合。
2. **趋势判断**：竞争焦点已从“稀疏激活更多参数”转向**语义路由、计算预算与物理执行的解耦**。
3. **四控制平面闭环**：拓扑、路由、均衡、EP 两个方向的依赖（物理约束语义、运行时均衡反馈）必须同时考虑，不能把负载均衡仅理解为辅助损失，也不能把 EP 看作后置实现。
4. **主流主干识别**：截至 2026 年，大规模 decoder MoE 的主流组合为：**Token-choice Top-k + 细粒度专家 + 可选共享路径 + 全局/batch-wise 均衡或 ALF + 拓扑受限路由 + dropless kernels/通信重叠 + 运行时专家放置**。
5. **未来方向**：ScMoE 之后没有唯一“下一代结构”，更可信的是四者组合——**更自由的语义路由、显式平均计算预算控制、拓扑感知或确定性通信、运行时专家放置**。
6. **评估方式**：架构评估应从单一 validation loss 扩展为**质量、专业化、active budget、暴露通信和尾延迟的联合分析**。

## 7. 优点

- **框架创新**：提出“时间轴瓶颈迁移 + 系统四控制平面”的双视角框架，避免单纯按年份切分模型，也避免“控制面”与“发展阶段”混淆。
- **算法与系统结合**：将路由算法（Top-k、共享专家、动态预算）与系统实现（token dispatch、device placement、All-to-All、通信隐藏）统一在一个框架中分析。
- **概念澄清细致**：
  - 区分 z-loss（数值稳定）与 balance loss（负载均衡）；
  - 区分“总 All-to-All 时间”与“暴露通信时间”；
  - 区分“逻辑专家均衡”与“物理设备/网络均衡”；
  - 指出 shared expert 不是 fine-grained MoE 的必要条件；
  - 澄清“DeepSeek-V3 完全无平衡损失”的说法不准确。
- **实验设计建议实用**：给出可操作的等预算消融矩阵、系统指标列表（CV/Gini、暴露通信、P99 等）以及代码预训练场景的分桶统计建议，为后续研究提供了清晰的实验蓝图。
- **开放问题提炼**：从专业化分析单位、高稀疏系统最优点、运行时均衡边界、动态计算尾延迟、后训练路由稳定性五个方面指出未来研究方向。

## 8. 不足与局限

- **缺乏原创实验验证**：作为综述，未亲自验证所提出框架的实证有效性；消融矩阵、指标建议均停留在“建议”层面。
- **部分前沿分支证据不足**：
  - 结构化通信（Head Parallel）缺少 trillion-parameter 万卡级公开验证；
  - 跨层全局专家（GMoE）缺少大规模训练证据；
  - MoHGE 异构专家的物理放置与尾延迟问题尚未证明可解；
  - Soft MoE / Lory 等连续路由方案在超大规模 decoder 与低延迟 EP 上的系统优势尚未证明。
- **动态计算的闭环控制问题未解决**：若 Router 同时决定语义专家和计算预算，balance bias 会同时影响 specialization 和吞吐；若只约束长期均值，则短时 burst 可能出现——论文指出了问题但没有给出解决方案。
- **平衡下沉到 runtime 的边界未定**：训练弱约束与运行时强均衡之间的最优划分点、参数副本显存与缓存一致性代价均未定量分析。
- **后训练稳定性问题悬置**：SFT/RL 阶段路由漂移、Router 是否冻结、是否 routing replay 等问题没有实证结论。
- **可能的时效性限制**：文中引用了若干标注为 2026 年的工作（如 MoHGE、GMoE、Head Parallel、LongCat 2.0 等），这些分支尚未经受更长时间的大规模独立复现检验，其结论可能随后续研究修订。
