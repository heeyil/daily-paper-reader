## 摘要
我们引入状态转换预训练（STP）作为GUI智能体的新扩展轴。在STP阶段，我们通过联合优化逆动力学（从状态变化预测动作）和正动力学（从当前状态和动作预测下一状态），在视觉状态转换上持续预训练一个统一的多模态模型。这种优化使模型具备更好的动作接地视觉表示和GUI动态的内部世界模型。当随后针对带有任务指令的轨迹进行微调时，我们在桌面和移动GUI场景（AgentNetBench、AndroidControl和GUIOdyssey）的智能体基准测试中，STP训练的模型始终优于仅通过直接轨迹微调训练的基线。进一步的实证研究表明，联合动力学优化相对于单目标训练能产生稳定的改进，且下游性能随转换数据量的增加而稳步提升。

## Abstract
We introduce State Transition Pretraining (STP) as a new scaling axis for GUI agents. During the STP stage, we continually pretrain a unified multimodal model on visual state transitions by jointly optimizing inverse dynamics (predicting actions from state changes) and forward dynamics (predicting next states from current states and actions). This optimization equips the model with better action-grounded visual representations and an internal world model of GUI dynamics. When subsequently fine-tuned on trajectories with task instructions, our STP-trained models consistently outperform baselines trained solely via direct trajectory fine-tuning across agent benchmarks in both desktop and mobile GUI scenarios (AgentNetBench, AndroidControl, and GUIOdyssey). Further empirical studies show that joint dynamics optimization yields stable improvements over single-objective training, and downstream performance scales steadily with the volume of transition data.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：GUI 智能体（GUI Agent）通过理解任务指令和界面截图来预测并执行操作，已成为自动化数字工作流的关键技术。然而，高效训练和扩展 GUI 智能体仍面临挑战。
- **现有方法的问题**：
  - **轨迹微调（Trajectory Fine-tuning）**：需要大量人工标注的多步骤轨迹数据，成本高、难扩展。
  - **强化学习（RL）**：依赖复杂交互环境，工程实施困难。
  - **目标耦合**：直接轨迹微调隐式混杂了视觉定位、动力学建模和任务规划，导致优化困难、数据效率低。
- **核心洞察**：轨迹数据可以分解为**无标注的步骤级状态转换元组** (状态, 动作, 下一状态)，这些元组天然丰富且廉价。
- **论文目标**：提出 **状态转换预训练（State Transition Pretraining, STP）**，将其作为一种新的扩展轴（scaling axis），通过预训练让模型学习动作相关的视觉表征和 GUI 动力学，从而为后续轨迹微调提供更好的初始化。

## 2. 方法论（核心思想、关键技术细节）

- **核心思想**：在统一的**多模态模型（UMM）** 上，联合优化两个互补的预训练目标：
  - **逆动力学（Inverse Dynamics）**：从连续截图 (状态, 下一状态) 预测动作，即 (st, s_{t+1}) → at。该目标促使模型定位交互位置、提取与动作相关的细粒度视觉特征。
  - **正动力学（Forward Dynamics）**：从当前状态和动作预测下一状态，即 (st, a_t) → s_{t+1}。该目标采用生成式建模（如流匹配），使模型内化“动作如何改变界面状态”，形成 GUI 动力学世界模型。
- **形式化定义**：
  - L_inv = − log p_θ(a_t | s_t, s_{t+1})
  - L_fwd = L_gen(s_{t+1}; s_t, a_t, θ)（具体为 BAGEL 中的流匹配生成损失）
  - 联合目标：L_pre = L_fwd + λ L_inv，其中 λ 在 AgentNet/GUIOdyssey 上为 0.25，在 AndroidControl 上为 0.5。
- **数据构造**：从现有轨迹数据集中分解出转换元组，无需任务指令标注。论文从 AgentNet 提取 320K 转换（Win&Mac）、AndroidControl 提取 67K、GUIOdyssey 提取 95K。
- **训练流程**：
  1. **STP 阶段**：在转换元组上预训练骨干模型（一个 epoch）。
  2. **轨迹微调阶段**：在带任务指令的轨迹上，以逐步方式优化条件动作分布 p_θ(a_t | u, s_t, h_t)，其中 h_t 是不含历史截图的文本化动作历史。
- **骨干模型**：采用 **BAGEL**，一种 MoT 架构的统一多模态模型（约 7B 激活参数 / 14B 总参数），原生支持图像理解和生成，天然适配逆（图像+图像→文本）与正（图像+文本→图像）两个目标。

## 6. 主要结论与发现

- **STP 一致提升下游性能**：
  - AgentNetBench（2K 轨迹）：平均 SR 从 64.9% 提升至 67.2%（+2.3%）。
  - AgentNetBench（5K Ubuntu 域偏移）：平均 SR 从 56.9% 提升至 63.1%（+6.2%），增益最大。
  - AgentNetBench（18K 轨迹）：平均 SR 从 67.1% 提升至 69.5%（+2.4%）。
  - AndroidControl：步骤 SR 从 71.1% 提升至 72.0%（+0.9%），坐标准确率 +1.3%。
  - GUIOdyssey：步骤 SR 从 76.8% 提升至 77.4%（+0.6%），坐标准确率 +1.6%。
- **收益来源不只是额外数据**：即使在 STP 数据完全来自微调轨迹（Group 1c）的情况下，STP 仍提升 +2.4%，说明结构化学习信号（逆/正动态）本身有效。
- **联合目标优于单一目标**：逆+正动态联合预训练在所有设置下均优于仅逆动态或仅正动态；个别设置下单目标甚至低于基线。
- **正动态优于重建**：逆+正动态持续优于逆+重建，说明重建缺乏动作感知监督。
- **仅改进视觉编码器不足**：只更新 ViT 的预训练收益会快速衰减；必须联合优化语言组件才能充分利用状态转换信号。
- **扩展性**：转换数据量从 48K 增至 320K，平均成功率稳步上升；同时 STP 优势在微调轨迹从 2K 增至 18K 时依然保持。
- **采样粒度影响甚微**：轨迹级与步骤级采样在同样 192K 预算下效果接近（66.85% vs 66.45%），支持未来自动化收集步骤级数据的可行性。

## 9. 未来工作与开放问题

- **自动化数据收集**：目前转换数据主要源于现有轨迹库，未来方向是在真实或模拟交互环境中闭环自动收集步骤级转换元组，从而大幅扩充预训练数据规模。
- **与强化学习结合**：STP 可作为 RL 的初始化或辅助奖励信号，帮助智能体在稀疏奖励环境中更快探索；该方向论文仅提及但未展开实验。
- **任务条件化预训练**：当前预训练信号完全与任务指令解耦，若在预训练阶段引入条件化指令或目标描述，可能使世界模型更具任务感知能力。
- **跨平台统一扩展**：验证 STP 在更多平台（如网页、命令行、跨应用工作流）上的适用性，探索“通用界面世界模型”的可能性。
- **计算效率优化**：正动力学目标引入图像生成开销，未来可探索更轻量的生成损失设计、蒸馏或稀疏训练策略，以降低 STP 的部署门槛。

## 10. 总结

论文提出了一种新颖、低成本且可扩展的 GUI 智能体预训练范式——状态转换预训练（STP）。其核心贡献在于：将轨迹数据解构为无标注的步骤级状态转换元组，并利用统一多模态模型原生支持图像生成与理解的能力，联合优化逆动力学与正动力学目标，使模型在接触任务级指令之前即获得扎实的界面定位能力与 GUI 动力学知识。通过大量控制变量实验，论文证明了 STP 在桌面与移动环境、不同数据规模、域偏移条件下的一致增益，其收益不仅来自额外数据暴露，更来自结构化学习信号本身，且该增益可随预训练数据规模的增长而持续放大。尽管在移动场景中的提升幅度有限、正动力学目标的训练成本也较高，但 STP 为 GUI 智能体研究提供了一个正交于轨迹微调、可与强化学习互补的重要扩展轴，为未来构建可泛化的通用 GUI 智能体奠定了坚实基础。
