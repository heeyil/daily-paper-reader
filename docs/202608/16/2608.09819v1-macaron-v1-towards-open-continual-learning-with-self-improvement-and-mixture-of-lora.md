## 摘要
Macaron-V1 是一个面向经验智能的开放智能体-模型家族：在真实环境中从经验中学习，并在部署后持续学习。它围绕两个系统目标进行组织。适应性是通过对版本化模型-测试框架对进行递归改进来实现的，其中来自某一配置的经验在外部契约下进行评估，并用于构建其后续版本。协作是通过 LoRA 混合（MoL）架构实现的，该架构冻结基础模型，组合专家 LoRA 适配器，并在每轮用户交互中选择一个 LoRA。旗舰型号 Macaron-V1-Venti 将 744B 的 GLM-5.2 基础模型与四个 LoRA（分别用于聊天、智能体、编码和 GenUI）相结合；基于 Qwen3.6 的 Macaron-V1-Tall（50B）采用相同的设计，用于本地部署。本报告将 Macaron-V1 展示为一个跨架构、算法和基础设施的协同设计系统。MoL 架构通过可扩展的 LoRA 专家支持持续学习。该算法结合了模型-测试框架协同设计和递归自我改进循环，包括 UI4A 组件原生 GenUI 测试框架、有状态动作基础、版本化 HCP 契约以及智能体强化学习框架 MindForge。支持基础设施包括后训练平台 MinT、长上下文强化学习方法 LongStraw，以及用于稀疏 MoE 和 DSA 基础模型的稳定性技术。我们在个人智能、GenUI 和通用能力基准上，与前沿基线进行对比，评估了 Macaron-V1。我们的结果验证了当前系统，而持续学习和集体智能带来的复合增益仍是未解决的问题。

## Abstract
Macaron-V1 is an open agent-model family for experiential intelligence: learning from experience in real environments and continuing to learn after deployment. It is organized around two system goals. Adaptation is pursued through recursive improvement of versioned model-harness pairs, where experience from one configuration is evaluated under an external contract and used to construct its successor. Collaboration is pursued via the Mixture-of-LoRA (MoL) architecture that freezes a base model, composes specialist LoRA adapters, and selects one LoRA per user turn. The flagship Macaron-V1-Venti combines a 744B GLM-5.2 base with four LoRAs for chat, agent, coding, and GenUI; the Qwen3.6-based Macaron-V1-Tall (50B) uses the same design for local deployment. This report presents Macaron-V1 as a co-designed system spanning architecture, algorithms, and infrastructure. The MoL architecture supports continual learning through extensible LoRA specialists. The algorithm combines Model-Harness Co-design and recursive self-improvement loop, including the UI4A component-native GenUI harness, a stateful action substrate, versioned HCP contract, and the agentic RL framework MindForge. The supporting infrastructure includes the post-training platform MinT, the long-context RL method LongStraw, and stability techniques for sparse MoE and DSA base models. We evaluate Macaron-V1 on Personal Intelligence, GenUI, and general capability benchmarks against frontier baselines. Our results validate the current system, while compounding gains from continual learning and collective intelligence remain open questions.

### 方法论

#### 核心思想
- 采用 **Mixture-of-LoRA（MoL）架构**：冻结大型基础模型，在其上叠加多个专家 LoRA 适配器，每次用户交互选择一个 LoRA 处理，避免多任务联合训练带来的跨任务干扰。
- 将 **测试框架（Harness）作为一等的训练目标**：模型和其运行环境（工具、提示词、执行协议）共同进化，而非仅更新模型权重。
- 构建 **递归自我改进循环（RSI）**：基于版本化模型-测试框架对，从经验中生成更困难的任务，评估轨迹，进行配置搜索和参数更新，形成持续学习的反馈回路。

#### 关键技术细节
- **MoL 架构**：
  - 基座模型 + 四个 LoRA 专家：L0（聊天/路由）、L1（智能体）、L2（编码）、L3（GenUI）。
  - 路由循环：L0 以受限解码输出当前轮次的适配器标签；所选专家基于自身“会话视图”回答，并在结束时生成 192 token 摘要供其他适配器跨轮次继承。
  - 每个适配器拥有独立的会话视图：只保留自己历史的原始轨迹，对其他适配器仅保留摘要，保证隐私和连续性。
  - 两级 KV 缓存复用：生产路径利用稳定自身视图触发原生前缀缓存；实验性路径通过路由-解码覆盖层复用连续前缀。
- **模型-测试框架协同设计**：
  - **UI4A**：组件原生 GenUI 测试框架，模型编写普通前端代码（import + component + state + Action），运行时强制边界，可扩展 Flutter/native 等渲染目标。
  - **REPL 智能体测试框架**：状态化 Python 命名空间，实现可执行组合（中间值留在运行时中，无需重复文本化）和验证后复用（save_tool/promote_tool 避免未验证工具进入生产）。
  - **HCP**：版本化 TOML 格式的运行时契约，标准化模型选择、工具策略、提示词、会话状态等配置，使配置可移植、可审计。
- **递归自我改进循环（MindForge）**：
  - **发现（Discovery）**：基于种子库生成更难的变体任务，需满足质量与学习价值标准。
  - **扩展（Expansion）**：在当前固定模型-测试框架配置下执行任务，评估轨迹，进行语言空间配置搜索（修改 HCP 中提示词、技能等）。
  - **更新（Update）**：选择有效轨迹训练 LoRA 适配器，同时注册新 HCP 配置，形成下一代模型-配置对。
  - 策略表达：`π_φ(a_t | o_≤t; θ, c)`，其中 θ 为冻结基座参数，φ 为可训练 LoRA 参数，c 为版本化测试框架配置；用 GRPO 更新适配器。

#### 基础设施
- **MinT**：模型状态谱系管理平台，支持适配器修订（revision）与策略记录分离，可管理大规模适配器目录（测量百万级）。
- **LongStraw**：响应式长上下文 RL 执行栈，仅对响应部分进行反向传播，支持超过 200 万 token 的上下文训练（固定 GPU 预算内）。
- **稀疏基座稳定性控制**：R3 路由重放、DSA 实现对齐、IcePop 式余数过滤，以减少训练与 rollout 分布不一致。

- **基础设施完备**：MinT、LongStraw、稀疏基座对齐控制等支撑了长上下文 RL、大规模适配器管理和训练/部署一致性，工程实现扎实。
- **开放与诚实**：公开发布模型权重和 MoL 测试框架，明确说明证据边界（哪些是复现、哪些是外部值、哪些是设计动机而非实证）。
- **评测设计有创新**：动态宪法式评判（六条公理 + 人物/场景条件化）、多智能体沙盘模拟（LivingBench）、确定性视觉评估流程（UI4A-Bench）均针对个性化/交互式智能的评测难点。

### 不足与局限

- **实验规模与独立性**：内部基准规模小，且与训练数据同分布，因而不是独立的泛化测试；缺乏区间估计和统计检验。
- **持续学习未闭环验证**：只进行了配置搜索阶段（Expansion），未执行参数更新（Update），因此没有跨代持续学习的定量证据。
- **组件贡献不清晰**：没有消融实验说明增益来自基座、LoRA、路由、测试框架还是它们的综合作用。
- **比较公平性局限**：部分基准使用外部公开值作为对比，这些值采用各自不同的评估协议，不能直接视为同等条件下的比较；内部基准的裁判模型（GLM-5.2）可能与测试模型同族从而带来偏差。
- **多模态能力保持存疑**：Tall 的适配器仅用文本训练，多模态评测显示 MME 感知下降 52.99 分，说明视觉能力有所损害，且未做重复/方差分析。
- **安全与治理缺失**：未披露数据收集的同意、去标识化审计、安全红队评估等环节；作者也承认这不能支持高风险个人助理场景的部署。
- **部署成本**：MoL 路由和摘要增加了约 32% 的总时延（1.51 秒/请求）在 Venti 上，对实时交互可能构成挑战（尽管有 KV 复用措施）。
- **尚未实现集体智能**：仅验证了四个内部专家的组合，未测试多团队/多用户适配器的联合能力，也没有评估第三方适配器的兼容性、信任与安全机制。
