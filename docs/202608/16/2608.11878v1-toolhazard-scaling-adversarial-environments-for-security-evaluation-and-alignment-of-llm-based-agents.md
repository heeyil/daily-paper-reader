## 摘要
集成外部工具的大型语言模型（LLM）代理容易受到嵌入在环境状态中的间接提示注入攻击。然而，现有研究大多依赖于手动实现或复用的环境、基于LLM的随机工具模拟以及预定义的注入位置，限制了在更广泛领域中进行可扩展的安全研究。为弥合这一差距，我们提出了**ToolHazard**，一种可扩展的对抗性环境合成框架，可减少人工工程，并支持通过额外种子域和计算进行扩展。通过环境模拟器、攻击者代理和用户模拟器，ToolHazard合成可执行的有状态环境，发现可行的注入点并生成特定于环境的载荷，并构建基于状态的长时程任务。基于ToolHazard，我们构建了**ToolHazard-Bench**，用于在复杂工作流和多样化环境攻击下对代理进行压力测试。实验揭示了代理的实质性漏洞，并表明注入时机和位置会影响攻击有效性。此外，ToolHazard生成的对齐数据提高了在ToolHazard-Bench和AgentDojo上的安全性，同时保持了良性任务的实用性。

## Abstract
Large language model (LLM) agents integrated with external tools are vulnerable to indirect prompt injections embedded in environmental states. However, existing studies largely rely on manually implemented or reused environments, stochastic LLM-based tool simulation, and predefined injection locations, limiting scalable security research across broader domains. To bridge this gap, we propose **ToolHazard**, a scalable adversarial environment synthesis framework that reduces human engineering and supports expansion with additional seed domains and compute. Through an Environment Simulator, an Attacker Agent, and a User Simulator, ToolHazard synthesizes executable stateful environments, discovers viable injection points and generates environment-specific payloads, and constructs state-grounded long-horizon tasks. Based on ToolHazard, we build **ToolHazard-Bench** for stress-testing agents under complex workflows and diverse environmental attacks. Experiments reveal substantial agent vulnerabilities and show that injection timing and placement affect attack effectiveness. Moreover, ToolHazard-generated alignment data improves security on both ToolHazard-Bench and AgentDojo while preserving benign task utility.

## 2. 方法论

### 2.1 核心思想

ToolHazard通过三个模块实现自动化管线，将环境合成、攻击注入、任务生成和验证函数生成全流程自动化：

- **环境模拟器（Environment Simulator）**：LLM驱动的环境生成器，自动抽象并合成可执行的有状态工具交互环境；
- **攻击者代理（Attacker Agent）**：自动发现可行注入点并生成环境专属的攻击载荷，规划并执行攻击；
- **用户模拟器（User Simulator）**：生成基于环境状态的长时程任务，使任务集随环境池扩展而扩展。

### 2.2 关键技术细节

**环境模拟器三阶段管线：**
1. **环境蓝图规划**：从种子任务数据集推断环境类型、状态表示、实体模式、转换规则和操作约束，形式化为 B = f_ops(f_state(f_env(D)))；
2. **可执行程序构建**：将蓝图翻译为面向对象Python程序，环境实现为类、实体为类属性、工具为可调用方法，并生成标准化API文档；
3. **自动化质量检查**：采用双代理验证管线（测试代理+检查代理），环境质量评分 score_env = (1/N)Σ Judge(ai)，低于阈值的环境被丢弃。

**用户模拟器两步生成：**
1. 基于环境骨架和约束初始化环境状态：S_init = f_init(E, R, T)；
2. 基于初始化状态合成长期任务：q = f_task(S_init, E, R, T)。

**攻击者代理：**
- **攻击点发现**三阶段：可注入属性识别（区分自由文本字段与受限字段）→ 操作读写依赖分析（构建操作-状态依赖图）→ 攻击点匹配（保留兼具写路径和读路径的属性）；
- **对抗注入管线**：轨迹对齐的攻击点过滤（按良性执行轨迹中读路径激活顺序排序）→ 计划-执行式对抗注入（LLM选择攻击点、构建攻击计划、使用六种预定义注入策略封装载荷）。

**验证函数生成：** 将任务分解为可验证条件 {c_k}，为每个条件生成验证函数 f_ck，最终得分 Score = (1/K)Σ 𝟙[f_ck(S_final)=1]，仅依赖终态S_final，与轨迹无关，支持多解路径。

## 3. 实验设计

### 3.1 数据集与Benchmark

- **种子数据**：从ToolACE和API-Bank采样任务查询；
- **环境生成**：环境模拟器生成191个有效环境，分为140个训练候选和51个测试候选；经注入点可达性过滤后，保留60个训练环境（ToolHazard-Align）和28个不相交测试环境（ToolHazard-Bench）；
- **ToolHazard-Bench**：87个长时程任务、28个有状态环境、512个工具，平均执行步骤15.56步，平均每任务候选工具18.75个；
- **ToolHazard-Align**：60个训练环境，每个环境5个初始状态和良性任务（300个实例），经6种攻击策略扩展后保留1,040个有效样本（329个用于RL，711个用于SFT）。

### 3.2 评测模型与基线

- **目标代理**：7个模型，包括4个闭源（GPT-5、GPT-4.1、Gemini-3.1-Pro、Gemini-2.5-Pro）和3个开源（DeepSeek-V3.2、Qwen3-8B、Qwen3-4B），均以ReAct框架实例化；
- **攻击策略**：6种提示注入封装——basic combined、important-template、multi-turn、decision hijacking、reasoning-criteria、tool-selection；
- **对齐对比方法**：仅SFT、SFT+RL、ToolHazard-Align（SFT+RL综合方法），并在ToolHazard-Bench和AgentDojo两个基准上评估。

### 3.3 主要指标

- **BR（良性任务完成率）**：在对抗扰动下完成用户原始任务的比例；
- **ASR（攻击成功率）**：代理执行注入恶意任务的比例；
- 两者均由验证函数基于终态程序化计算，不使用LLM裁判。

## 4. 资源与算力

## 6. 主要结论与发现

1. **LLM代理对环境注入高度脆弱**：几乎所有模型都呈现高ASR，四个攻击策略在GPT-5上超过40%，三个在Gemini-3.1-Pro上超过30%。DeepSeek-V3.2的BR最高但最易受攻击，而Qwen3-4B因指令跟随能力较弱反而受影响较小——更强模型可能更易被环境注入操纵；
2. **新兴攻击策略威胁更大**：decision hijacking、tool-selection、reasoning-criteria在三类模型中持续达到高ASR，而现有防御较有效的基本联合攻击已不足以代表威胁前沿；
3. **注入时机影响攻击效果**：越早被代理遇到的注入指令攻击成功率越高（67.2% vs 45.7%），提示需在初始执行步骤强化防护；
4. **注入位置影响攻击效果**：注入内容越靠近工具响应末尾，攻击成功率越高（67.4% vs 44.2%），反映LLM代理对尾端内容的位置偏差；
5. **输出格式影响攻击成功率**：自由文本输出（最高80.4% ASR）显著比结构化格式（JSON/YAML，最低1.2%~5.9% ASR）更易受攻击，结构化格式通过显式语法提供部分语义隔离；
6. **攻击同时损害良性任务能力**：攻击不仅诱导不安全行为，还一致性地降低代理完成原任务的能力（如GPT-4.1 multi-turn攻击下BR从78.6%降至41.3%）；
7. **对齐有效且具有泛化性**：ToolHazard-Align在ToolHazard-Bench上同时提升BR（Qwen3-8B：67.64%→75.94%）和降低ASR（36.10%→18.06%），并在AgentDojo上跨环境泛化（BR 43.05%→52.08%，ASR 29.16%→18.34%），且不诱发过度拒答；
8. **跨攻击策略泛化**：仅在3种攻击上训练可将未见3种攻击的ASR从37.19%降至26.92%，接近全部6种攻击训练的25.45%，说明模型学到的是鲁棒性而非记忆特定攻击。

## 7. 优点

- **可扩展性范式**：以LLM驱动的环境合成为核心，显著减少人工工程，支持通过新种子域和算力持续扩展；种子数据不限于ToolACE/API-Bank，可迁移到其他数据源；
- **可执行有状态环境**：与LLM模拟环境不同，ToolHazard生成的环境是真正可执行、有状态的，支持确定性验证和可靠训练，避免随机反馈；
- **自动攻击点发现**：超越预定义注入位置，通过读写依赖分析和轨迹对齐过滤，发现任务执行中真实可达的注入点；
- **验证函数机制**：基于终态的程序化验证不依赖LLM裁判，简化评分过程且与执行轨迹无关，支持多解路径，可复现性强；
- **评估与对齐一体**：同时支持基准评测（ToolHazard-Bench）和对抗训练（ToolHazard-Align），兼顾SFT与RL，且奖励设计避免平凡拒绝（不做任何操作会失败良性任务）；
- **成本可控**：平均每环境$0.59的合成成本使大规模扩展成为可能；
- **多维度洞察**：对注入时机、位置、输出格式等因素的系统分析为防御设计提供具体方向。

## 8. 不足与局限

- **合成环境的真实性差距**：论文自身承认，合成环境与真实企业系统之间存在差距，无法完全捕捉专有实现、部署特定交互或生产环境的长尾故障模式；应视为可复现压力测试而非生产风险的直接估计；
- **攻击策略覆盖有限**：仅考虑6种预定义注入策略封装，不自动发现新攻击策略；主要聚焦对抗环境构建的规模化而非新攻击策略的发现；
- **范围限定**：仅覆盖API型工具代理，浏览器Web代理和网页级注入不在范围内；
- **对齐实验的模型规模受限**：SFT+RL对齐仅在Qwen3-4B/8B两个中小型开源模型上完成，受算力限制未覆盖更大模型，泛化结论有待扩展验证；
- **种子数据依赖**：环境领域覆盖受限于ToolACE和API-Bank所代表的领域，不一定覆盖所有真实生产场景；
- **人类验证规模有限**：虽然进行了人工质量验证（3名硕士生、28个环境），但未报告更大规模众包验证或独立第三方评估。
