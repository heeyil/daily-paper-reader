## 摘要
理解大型代码库对于大语言模型（LLM）智能体而言是一项长程任务：回答单个问题可能需要构建并运行软件、跨文件跟踪执行过程，并在数十分钟内综合证据。在 SWE-Atlas QnA（一个针对生产仓库长程问题的基准测试）上，单个 Claude Code 智能体（Opus 4.6）仅解决了 32.3% 的任务。在智能体之间以清晰上下文分工可缓解这一限制。然而，代码理解的子任务相互依赖。一个智能体的发现可能改写另一个智能体的任务，因此智能体必须在执行期间协调，而不仅仅在阶段边界。现有的多智能体系统仅支持阶段之间的此类交换，通过分阶段交接或同步轮次。通信与工作仍然互斥。执行中途的发现只能等到下一个边界才能共享。我们提出 AgentRadio，一个异步消息传递层，为编码智能体框架提供三种原语：线程、消息和等待被提及。最后一种作为后台任务运行，在不中断前台工作的情况下呈现队友的消息，因此每个智能体都能被动感知同伴并将新发现纳入其进行中的任务。在五阶段分工与协商协议下，由 AgentRadio 组织的四个智能体解决了 62.1% 的任务，比单个智能体高出 29.8 个百分点，且高于使用更新 Opus 4.8 的 Claude Code（57.2%）。按评分标准分析显示，增益随任务难度增加而增长，与作为潜在机制的途中修正一致。我们的代码可在 https://github.com/Coral-Protocol/AgentRadio 获取。

## Abstract
Understanding large codebases is a long-horizon task for Large Language Model (LLM) agents: answering a single question can require building and running the software, tracing execution across files, and synthesizing evidence over tens of minutes. On SWE-Atlas QnA, a benchmark of long-horizon questions over production repositories, a single Claude Code agent (Opus 4.6) resolves only 32.3% of tasks. Dividing the work among agents with clean contexts mitigates this limitation. However, the subtasks of code comprehension are interdependent. One agent's findings can rewrite another's task, so agents must coordinate during execution, not only at phase boundaries. Existing multi-agent systems support such exchange only between phases, through staged handoffs or synchronized rounds. Communication and work remain mutually exclusive. A discovery made mid-execution cannot be shared until the next boundary. We present AgentRadio, an asynchronous message-passing layer that equips coding-agent harnesses with three primitives: threads, messages, and waiting for mentions. The last runs as a background task, surfacing teammates' messages without interrupting foreground work, so each agent remains passively aware of its peers and folds new findings into its ongoing task. Under a five-phase protocol of division of labor and negotiation, four agents organized by AgentRadio resolve 62.1% of tasks, 29.8 points above a single agent and above Claude Code with the newer Opus 4.8 (57.2%). Rubric-level analysis shows the gain growing with task difficulty, consistent with mid-course correction as the underlying mechanism. Our code is available at https://github.com/Coral-Protocol/AgentRadio.

## 一、论文的核心问题与整体含义（研究动机和背景）

大型代码库的理解任务是对 LLM 智能体的长程挑战：回答一个问题可能需要构建并运行软件、跨文件追踪执行流程、并在数十分钟内综合证据。在 SWE-Atlas QnA 基准上，单个 Claude Code 智能体（Opus 4.6）仅能解决 32.3% 的任务。将工作分派给多个拥有干净上下文的智能体可缓解此限制，但代码理解子任务之间存在高度相互依赖——一个智能体的发现可能重新定义另一智能体的任务，因此智能体必须在执行过程中实时协调，而非仅在阶段边界同步。

论文指出现有多智能体系统存在一个根本缺口：**通信与工作互斥**。现有系统（如 Anthropic 的多代理研究系统、MPAS、HyperAgent、DynTaskMAS 等）要么并行但彼此隔离，要么在轮次间同步，要么仅支持异步调度而无横向通信。一个执行中途的发现，必须等待下一阶段边界才能被共享。AgentRadio 试图填补这一空白：让正在工作的智能体能够同时“倾听”队友，实现真正的被动感知。

## 二、论文提出的方法论

**核心思想**：为编码智能体框架提供一个异步消息传递层，使智能体可以像司机听收音机一样，在不中断前台工作的情况下感知队友的发现。

**三原语**（AgentRadio 暴露的操作）：

- `create_thread(name, participants)`：在消息服务器上开启命名会话，返回线程标识符。
- `send_message(thread, content, mentions)`：向线程追加消息并立即返回（非阻塞），可在消息中被 @提及 特定智能体。
- `wait_for_mention(timeout)`：阻塞直至收到提及调用者的消息，返回该消息及全线程快照。

**关键设计——被动感知**：`wait_for_mention` 在前台运行即为阻塞接收（智能体停止工作以监听）；作为后台任务运行时则成为被动感知，智能体持续工作，提及消息在步骤边界浮现，不会打断正在运行的命令。形式化地说：阻塞接收中，消息的可见性增长需要花费一步工作；被动感知中，智能体在步骤 t 时可见所有在 t 前发送的消息，无需花费任何步骤监听。这一单比特差异就是实验所隔离的变量。

**五阶段协议**（分工与协商）：

- **P1 探索**：每个智能体启动后台 watcher，独立探索仓库并草拟子问题，不发送任何消息。
- **P2 分工**：装配者（agent-1）开启规划线程，智能体汇总 P1 发现，协商子问题划分并修订直至全员批准。
- **P3 执行**：各智能体处理自己的子问题；在被动感知下，发现与队友相关的事实、与计划矛盾之处、障碍或死胡同时，立即发布到工作日志。
- **P4 审查**：各智能体在结果线程发布带证据的发现，审查者报告事实冲突、证据不足或遗漏观察，可将会问题退回 P3。
- **P5 提交**：装配者综合获批结果，起草最终答案，经全体批准后提交。

**实现**：消息服务器是独立进程，智能体通过三个 shell 脚本访问原语。切换阻塞到被动模式不增加任何 LLM 调用，因为 watcher 是操作系统进程而非智能体步骤。

## 三、实验设计

**基准与数据**：SWE-Atlas QnA，124 道专家撰写的关于 11 个生产代码库（4 种语言）的长程问题，共 1,306 条 rubric（每条任务平均 12.3 条）。任务类别包括：架构与系统设计（44）、根因分析（37）、代码入门（28）、安全（11）、API 与库集成（4）。评测规则严格：rubric 需三专家多数表决通过、修改源文件自动失败、任务须全部 rubric 通过才算解决。

**对比配置（梯子式消融）**：

- B0：单个 Claude Code 智能体
- B1：六个独立单智能体运行取最优（计算匹配基线，费用约等于全栈）
- L1：四个智能体 + 仅分工
- L2：四个智能体 + 分工 + 协商（五阶段协议在阻塞接收下运行）
- L3：四个智能体 + 被动感知（完整 AgentRadio 配置）

**模型**：Claude Opus 4.6 和开源模型 DeepSeek V4 Pro，同一 harness、思维程度高、温度 0，每配置每任务运行一次以进行配对比较。另与单智能体 Claude Code（Opus 4.8，公共排行榜最强单智能体条目）进行比较。

实验较为充分：

## 六、论文的主要结论与发现

1. **AgentRadio 显著提升长程多代理协作性能**：四代理组织下，Opus 4.6 从单代理 32.3% 提升至 62.1%（相对提升 92%），DeepSeek V4 Pro 从 29.0% 提升至 50.8%。
2. **超越更强模型**：四 Opus 4.6 代理（62.1%）超过单 Opus 4.8 代理（57.2%），即被动感知的一个自由度比一代模型更强。
3. **每层都有贡献**：分工 +7.2 点、协商 +12.1 点、被动感知 +10.5 点（Opus 4.6）；DeepSeek 上分别为 +2.4、+8.1、+11.3。
4. **被动感知增益随任务难度增长**：L2 缺失 1-3 条 rubrics 的任务上每任务仅增 0.3-0.5 条，缺失 5 条的任务上每任务增 2.0 条——困难任务需要执行中纠正，这正是被动感知的机制优势。
5. **结构优于算力**：全栈在相同成本下远超 best-of-6 采样。
6. **被动感知的机制本质**：它能把智能体已经做出但会吞没的发现转化为全队证据（MinIO 案例），但不能提供任何智能体都未形成的概念（Grafana 案例）。

## 七、优点

- **清晰的单自由度隔离**：L2→L3 仅改变通信模式（阻塞 vs 后台），不改变模型、harness、协议或提示词中的任务定义，实验归因干净。
- **被动感知的设计精巧性**：无需额外 LLM 调用，只是将 watcher 作为操作系统后台进程，低成本获得高收益。
- **成本与收益并报**：透明披露每任务 API 成本，并以计算匹配基线（B1）排除预算效应的混淆。
- **rubric 级归因**：不只看总分，而是逐条 rubric 追踪收益和损失，分析细致。
- **方差控制**：三重复实验验证了单次运行协议的稳健性。
- **案例研究的双面性**：既展示了成功案例，也展示了失败边界，避免了过度声称。
- **对现有工作有清晰定位**：通过 1,400 篇论文的综述说明异步性缺失，并系统分类了三种现有模式。

## 八、不足与局限

- **基准覆盖单一**：仅在 SWE-Atlas QnA 上验证，未在 SWE-bench、WebArena 等其他多方代理基准上测试，外部效度有限。
- **模型生态局限**：两个模型（Opus 4.6 和 DeepSeek V4 Pro）差距大，但均未覆盖更多样化模型家族；且未能确认方法在 GPT、Gemini 等模型上的可迁移性。
- **无独立第三方复现**：论文为预印本（arXiv:2607.28430v1），代码虽已公开链接，但结果尚未经同行评审和独立验证。
- **潜在利益冲突**：SWE-Atlas 作者与本文作者有重叠（Zekun Guo 为通讯作者且出现在 SWE-Atlas 作者列表中），评判使用同一家族模型（Claude Opus 4.5），可能存在无意识偏倚。
- **成本门槛较高**：全栈每任务 19.45 美元（Opus 4.6），约为单代理的 6 倍，对预算有限的研究团队不友好。
- **协议需要人工设计**：五阶段协议及消息触发条件依赖人工设定，未涉及智能体自主学习沟通策略；方法的普适性受协议工程的限制。
- **被动感知的能力边界明确**：无法催生任何智能体未形成的概念（Grafana 案例说明），并非通用解法。
- **长程极端情形未探索**：未测试更长任务（如数天级）、更多代理数（如 8-16 个）或消息风暴时的扩展性。
