## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题的解决能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出了MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自主进化。在执行前，MANTA从先前的结构经验中初始化一个任务条件下的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界的结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在五个基准上评估了MANTA与代表性单智能体和多智能体基线的性能，涵盖信息检索、工具使用、规划、工作流执行和数学推理。MANTA取得了74.0的最高平均分，比最强基线高出5.8个百分点，并在PlanCraft上获得最佳结果。这些结果表明，推理时的自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

### 1. 核心问题与研究动机

- **背景**：基于大语言模型（LLM）的多智能体系统通过任务分解、专业化分工、信息交换与中间验证来提升复杂问题解决能力。现有系统取得了显著成效，但普遍存在一个关键局限：**通信拓扑（communication topology）被视为静态的设计选择或离线优化的产物**，一旦系统投入运行，其协作结构便不再改变。
- **核心问题**：多智能体系统的通信拓扑能否像生物系统一样，在**任务执行过程中自我进化**？具体来说：系统能否在解决每项任务时，根据任务特征规划初始结构，在协作过程中根据实时信号发现结构缺陷，并执行本地化的结构修复？
- **研究意义**：该问题将"自我改进"的范畴从输出、提示词、推理轨迹、记忆、智能体角色等层面，拓展到**协作架构本身**（作者称之为"拓扑级自我改进"，即图1中的 L6 层级），填补了该层级在推理时自适应方向上的空白。

### 2. 方法论：MANTA 框架

#### 核心思想
MANTA（Multi-Agent Network Topology Adaptation）采用**双层嵌套架构**：底层为目标多智能体系统（执行任务），上层为编排层（负责规划、监控与修复）。系统在推理时能够对通信拓扑施加**有界（bounded）的结构更新**，无需更新模型权重或进行离线搜索。

#### 技术细节

**拓扑表示**：每个智能体拥有结构性角色（如协调者、工作者、验证者、辩论者、投票者）和阶段角色（工作者或评论者）。智能体按预定义交互模式分组（可嵌套），并受上下文策略控制信息可见性。所有拓扑经确定性代码校验后才可执行。

**三层 LLM 组件 + 确定性控制**：

1. **Topology Planner（拓扑规划器）**：执行前依据任务与长期经验规划初始拓扑（模式、智能体数量、可选验证者等），以紧凑 JSON 输出，由确定性代码扩展和验证。
2. **Trace Auditor（轨迹审计器）**：每轮协作后扫描结构化协作轨迹（工具记录、中继包、置信度、未解决问题、证据可见性），检测过程异常。它**不判断答案正确性**，只报告过程风险（如工具错误级联、分支崩溃、过早共识、重复状态变更、缺失验证等）。
3. **Skill Reflector（技能反思器）**：每 N 次运行后基于过程信号（非基准真值）重写长期剧本中的经验教训。

**两时间尺度记忆**：
- **短期剧本**：记录当前运行每一轮拓扑、审计发现、修复建议与决策。
- **长期剧本**：跨运行积累"任务特征→拓扑选择"的可迁移经验教训。

**修复机制**：
- 每次运行最多允许**一次拓扑突变**，每次突变最多 **3 个操作**（如添加智能体、将智能体扩展为子群组、更改群组模式、增删通信边、调整上下文可见性）。
- 修复由审计门控触发（存在中/高严重度可修复标志），确定性代码应用操作并全面验证结构合法性。
- 智能体为无状态设计，共享运行状态（中继包存储、证据账本、候选列表），拓扑突变后只需重新指向新规格，无需迁移或丢失状态。

### 6. 主要结论与发现

- **性能领先**：MANTA 在五个基准上平均 **74.0 分**，超过最强基线 **5.8 个百分点**（第二名 ADAS 为 68.2），并在 PlanCraft 上取得最佳结果。相比 Single Agent 在全部基准上均有提升。
- **消融结论**：初始拓扑规划贡献最大（移除后从 71.7 降至 57.5）；执行时拓扑修复次之（降至 60.8）；长期剧本的跨运行学习提供额外增益。
- **突变预算收益递减**：首次突变带来最大增益，后续突变仅小幅提升——表明**少量有界修复**即可覆盖大多数可修复失败。
- **经验可迁移**：MANTA 的长期剧本在同领域迁移（+3.3 点）和跨领域迁移（+3.3 点）均为正收益；对比方法均表现为负迁移（MASS 甚至 −58.3 点），说明 MANTA 学到的是**可继承的结构性知识**而非任务绑定的工作流。
- **拓扑修复的本质**：修复不一定是"加智能体"——在 162 次操作中，只有 9.3% 是新增智能体。更常见的修复是改变执行顺序（串行化）、重连通信边、增加验证角色。
- **审计是有效的过程信号**：无修复标志的运行正确率 83.2%，有标志的仅 62.5%，两者相差 20.7 点；审计能识别出 117 个错误运行中的 75 个。但"干净轨迹"不等于正确答案，误报仍存在。
- **Token 效率**：MANTA 在所有多智能体系统中 token 消耗最低，说明**有目标的自适应优于盲目扩大协作规模**。

### 7. 优点与亮点

- **问题创新性**：首次系统性地提出"拓扑级推理时自我改进"这一新问题层级，并给出完整的形式化定义与解决方案。
- **方法论优雅**：将在线自适应转化为"过程监控 + 有界突变"问题，避免全搜索空间的暴力优化；通过确定性代码保障结构合法性，兼具 LLM 的灵活性与代码的可靠性。
- **过程信号与正确答案隔离**：审计器、反思器、长期剧本均不接触基准真值，保证学习循环的方法论纯净性。
- **记忆机制设计精巧**：短期/长期双层剧本有效支持同运行修复与跨运行迁移；无状态智能体 + 共享存储的设计使拓扑突变"廉价且无损"。
- **丰富的案例分析**：展示了 5 类具体修复场景（分支扩展、验证插入、串行化、通信重连、评论者插入），直观证明拓扑修复的多样性。
- **多维度实验验证**：不仅报告性能，还系统验证了组件贡献、修复预算曲线、经验可迁移性、token 效率以及审计机制自身的可靠性。
- **公平对比意识**：所有方法统一骨干模型、统一推理预算，静态工作流使用与 MANTA 相同的角色集合。

### 8. 不足与局限

- **实验规模有限**：每个基准仅 30 题、3 次运行，统计功效有限；标准偏差在部分基准上较大（如 MATH 上 ±5.7），部分差异可能未达统计显著性。
- **单模型验证**：仅使用 Gemma 4 31B 一个骨干模型，未验证方法在不同规模/不同厂商模型上的鲁棒性。
- **审计机制局限**：
  - 精度仅为 37.5%，大量"误报"（标记但答案正确）——如 BrowseComp 中 FPR 高达 90%，说明审计信号虽有用但噪声大。
  - 部分过程标志（如信息压缩丢失、工具错误级联）与正确率无相关甚至负相关，表明标志设计仍有改进空间。
  - 错误中 35.9% 完全无过程异常（如 PlanCraft 和 MATH 中大量错误推理无可观察的协调症状），这类错误无法通过拓扑修复解决。
- **修复有效性证据不足**：论文自身承认，清除率仅表示"下一个审计中该模式消失"，无法证明是修复的因果效应；缺乏与"同等计算量继续运行"的反事实对照实验。
- **跨域迁移测度单一**：仅在同一数据集族（规划↔工作流）内验证迁移性，未涉及跨能力类别（如推理→检索）的迁移。
- **应用限制**：过程审计依赖预定义故障模式集合，面对新型或未定义的协作失败可能失明；修复效果受限于单次突变预算。论文未讨论真实场景中的延迟开销、外部 API 成本等落地问题。
- **公平性存疑**：对自适应基线（如 AFlow、MASS）的复现是否完全忠实原始配置、是否为每个基线做了针对 Gemma 4 的超参数调优，论文未充分说明；且静态多智能体基线未获得与 MANTA 同等的"经验积累"机会。
