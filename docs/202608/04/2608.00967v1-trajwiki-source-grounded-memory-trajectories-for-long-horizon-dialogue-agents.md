## 摘要
大型语言模型智能体在生成连贯且上下文恰当的响应方面表现出强大能力，但稳健的长时程对话仍受限于缺乏可追踪、可更新且诊断透明的外部记忆。现有的记忆增强智能体通常将记忆存储为孤立记录或可覆写状态，难以保留信息如何起源、演化、冲突或随时间过时。我们提出TrajWiki，一种面向长时程对话智能体的基于轨迹的记忆框架。TrajWiki不将记忆视为静态条目，而是将每条记忆表示为源接地的演化轨迹，通过不可变的片段快照和主张级操作（如ADD、REVISE和DEPRECATE）加以维护。为减少碎片化和检索成本，TrajWiki进一步引入记忆维基（Memory Wiki），一个持久化的中间层，将对话历史增量编译为结构化且相互关联的维基页面，捕获显著实体、事件、数量、主题和冲突。在推理时，查询从相关维基页面层级路由到链接的记忆轨迹，再到对应的快照和源消息，以进行基于证据的答案合成。在LoCoMo和MedMT上的实验表明，TrajWiki在开源和闭源LLM骨干上均提升了长时程对话性能，同时为记忆演化、检索失败和答案生成提供了更强的可解释性和诊断可见性。

## Abstract
Large language model agents have shown strong capabilities in generating coherent and contextually appropriate responses, yet robust long-horizon dialogue remains limited by the lack of external memory that is traceable, updatable, and diagnostically transparent. Existing memory-augmented agents often store memories as isolated records or overwritable states, making it difficult to preserve how information originates, evolves, conflicts, or becomes obsolete over time. We propose TrajWiki, a trajectory-based memory framework for long-horizon conversational agents. Instead of treating memory as static entries, TrajWiki represents each memory as a source-grounded evolution trajectory, maintained through immutable episodic snapshots and claim-level operations such as ADD, REVISE, and DEPRECATE. To reduce fragmentation and retrieval cost, TrajWiki further introduces Memory Wiki, a persistent intermediate layer that incrementally compiles dialogue history into structured and interlinked wiki pages capturing salient entities, events, quantities, topics, and conflicts. At inference time, queries are routed hierarchically from relevant wiki pages to linked memory trajectories, then to corresponding snapshots and source messages for evidence-grounded answer synthesis. Experiments on LoCoMo and MedMT show that TrajWiki improves long-horizon dialogue performance across both open-source and closed-source LLM backbones, while providing greater interpretability and diagnostic visibility into memory evolution, retrieval failures, and answer generation.

## 1. 核心问题与研究动机

- **核心问题**：大型语言模型（LLM）智能体在长时程对话中缺乏**可追溯（traceable）、可更新（updatable）、诊断透明（diagnostically transparent）**的外部记忆机制。现有记忆系统通常将记忆存储为孤立记录或可覆写状态，难以保留信息如何**起源、演化、冲突或过时**的完整路径。
- **两大未充分解决的挑战**：
  1. **来源历史缺失**：现有系统仅保留"当前信念"，不保留信念如何形成——哪些主张被修订或废弃、哪些源话语支撑了每次更新；
  2. **扁平检索碎片化**：细粒度记忆累积后，对时间敏感、多跳或更新敏感问题的扁平检索日益碎片化，缺乏对事实间演化、冲突和关联关系的建模。
- **整体意义**：论文主张将记忆视为"演化的、源接地的结构"而非"扁平检索池"，为构建更可靠的长时程对话智能体提供了新范式。

## 2. 方法论

### 2.1 核心思想
TrajWiki 将对话历史转化为**源接地的记忆轨迹（source-grounded memory trajectories）**，并编译为持久的**记忆维基（Memory Wiki）**，通过分层检索实现证据接地的答案生成。

整体流水线：`对话历史 D → 情景快照 Σ → 记忆轨迹 T → 记忆维基 W → 检索证据 Eq → 最终答案 aq`

### 2.2 关键技术细节

**（1）溯源感知的记忆轨迹（Provenance-Aware Memory Trajectories）**
- 每轮对话转换为**不可变的情景快照**（含提取的主张、说话者与时间上下文、原始源消息链接）
- 轨迹为**仅追加的有序序列**：`Tj = (σj,1, σj,2, ..., σj,nj)`
- 新快照通过兼容性函数 `g(σ, Tj)` 被分配到最匹配的轨迹或新建轨迹（考虑实体连续性、侧面重叠、词汇证据、时间兼容性和语义漂移）
- 主张级编辑操作：**ADD、REVISE、DEPRECATE**——修订或废弃的主张不删除，保留原始快照和源引用

**（2）持久记忆维基（Memory Wiki）**
- 作为原始记忆与查询时检索之间的**可读、可路由组织层**
- 四种页面类型：`index`（全局目录）、`entity`（实体页）、`topic`（主题页）、`inventory`（清单页）
- 页面内包含：概览、关键事实、项目/计数、链接轨迹、冲突/不确定性
- 维基不替代源证据，而是保留到轨迹和原始消息的链接；通过非索引页面覆盖审计确保轨迹可达

**（3）分层检索与证据接地生成（Hierarchical Retrieval & Evidence-Grounded Generation）**
- **第一层**：查询路由到相关维基页面（融合语义+词汇+实体+侧面+时间信号）
- **第二层**：从页面链接构造候选轨迹集，通过相关性+覆盖度目标选择互补轨迹
- **第三层**：展开为带溯源链接的证据（轨迹、快照、主张、源引用、时间戳）
- 最终答案受**源支持约束**：`refs(aq) ⊆ refs(Eq)`；证据不足时**弃答（abstain）**或受控重试
- 所有答案需经结构化证据合成（含可回答性决策、支持事实、源引用、时间锚点、不确定性）

## 7. 优点

- **创新的记忆建模**：将记忆表示为"源接地演化轨迹"，通过不可变快照和ADD/REVISE/DEPRECATE操作保留完整演化历史，解决了现有系统"只存当前状态"的根本缺陷。
- **分层组织架构**：Memory Wiki作为持久中间层，将原始记忆、轨迹组织、查询路由解耦，兼顾可读性与可扩展性。
- **端到端溯源链**：从原始消息→快照→轨迹→维基页→检索证据→最终答案，全链路保留来源引用，支持证据约束生成与弃答机制。
- **诊断可见性**：提供失败定位（页面路由失误、轨迹选择遗漏、答案合成错误、接地失败）、语义漂移度量、审计包压缩（从594.7→195.1源数量，20.33K→11.34K tokens）等多维诊断。
- **计算效率洞察**：通过离线覆盖分析（无需重跑生成）进行超参数选择，并给出预算控制下的消融比较，方法论上高效严谨。
- **领域迁移验证**：在开放的LoCoMo与专业医疗MedMT-Bench上均验证，证明框架通用性。
- **可复现性**：附录提供确定性评分特征、结构化输出schema、超参数、验证规则、回退/修复程序等完整实现细节。

## 8. 不足与局限

- **结构化输出依赖**：系统严重依赖LLM的结构化输出用于提取、记忆更新、维基构建、答案合成和验证；格式错误输出会触发高昂的回退/修复路径（在GPT-4o-mini上仍记录约2,562次额外调用、26.93M额外token），对较弱或非指令微调模型更严重。
- **摘要介导的显著性漂移**：重复抽象可能改变特定事实的显著性，导致答案生成依赖压缩记忆而非最相关的原始证据；案例研究表明相关证据存在但"陶艺"事实通过快照→轨迹→维基层级的抽象后显著性被削弱。
- **诊断指标为代理而非事实**：不支持答案风险、失败定位、冲突暴露率等均为离线代理指标，未经人工验证的审计准确性。
- **消融未重跑生成**：反事实消融仅报告检索/上下文指标，无法确认这些变体对最终答案质量的真实影响。
- **高成本**：当前实现是"计算密集型、溯源导向"系统而非token最小化基线；记忆构建占主导成本，未来需缓存、批处理、蒸馏替代方案。
- **未明确报告硬件资源**：缺乏GPU型号/数量等算力细节，可能影响复现成本评估。
- **LoCoMo排除了对抗性类别**：遵循Mem0惯例但限制了对其对抗场景鲁棒性的评估。
- **F1/BLEU-1为规范化的语义匹配**：软匹配策略可能引入评估偏差，需结合LLM裁判结果综合解读。
