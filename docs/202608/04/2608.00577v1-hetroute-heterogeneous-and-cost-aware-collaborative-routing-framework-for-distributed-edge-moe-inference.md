## 摘要
混合专家（MoE）模型已成为大规模AI服务的主流架构，但在地理分布的异构边缘服务器上部署它们仍具挑战。当一个令牌的Top-k激活专家分布在多个服务器上时，最优路由取决于跨服务器链路带宽、异构GPU计算能力、GPU-CPU专家加载延迟、瞬时队列积压以及副本级量化质量损失。现有的分布式推理和MoE服务方法分别处理这些因素，并未提供统一的在线多服务器协同路由框架。本文提出HetRoute，一种面向分布式边缘MoE推理的异构成本感知协同路由框架。HetRoute引入一个统一的每分配成本模型，明确捕获四个成本组件：跨服务器传输、GPU-CPU卸载、带队列的GPU计算以及量化引起的质量惩罚。在该模型引导下，离线阶段通过路由成本耦合的部署算法确定专家服务器放置、GPU-CPU驻留和副本精度，而在线阶段则将Top-k激活专家集作为整体路由，通过精确枚举或束搜索最小化瓶颈层成本。理论分析建立了回退可行性、参与服务器数量的界限、小候选域上的逐层最优性以及在线计算复杂度。在异构10服务器边缘测试平台上对三个MoE模型的轨迹驱动评估表明，与代表性基线相比，HetRoute将平均推理延迟降低最高59.0%，P99延迟降低最高58.0%，跨服务器流量减少最高72.1%，吞吐量提升2.13倍，同时将质量退化控制在配置预算内。

## Abstract
Mixture-of-Experts (MoE) models have become a dominant architecture for large-scale AI services, yet deploying them over geo-distributed heterogeneous edge servers remains challenging. When the Top-k activated experts of a token are spread across multiple servers, the optimal routing depends jointly on cross-server link bandwidth, heterogeneous GPU computing capability, GPU-CPU expert loading delay, instantaneous queueing backlog, and replica-level quantization quality loss. Existing distributed inference and MoE serving methods address these factors separately and do not provide a unified framework for online multi-server collaborative routing. In this paper, we propose HetRoute, a heterogeneous-cost-aware collaborative routing framework for distributed edge MoE inference. HetRoute introduces a unified per-assignment cost model that explicitly captures four cost components: cross-server transmission, GPU-CPU offloading, GPU computation with queueing, and quantization-induced quality penalty. Guided by this model, the offline stage determines expert server placement, GPU-CPU residency, and replica precision through a routing-cost-coupled deployment algorithm, while the online stage routes the Top-k activated expert set as a whole by minimizing the bottleneck layer cost via exact enumeration or beam search. Theoretical analysis establishes fallback feasibility, a bound on the number of participating servers, per-layer optimality for small candidate domains, and online computational complexity. Trace-driven evaluation on three MoE models over a heterogeneous 10-server edge testbed shows that HetRoute reduces average inference latency by up to 59.0% and P99 latency by up to 58.0%, cuts cross-server traffic by up to 72.1%, and achieves 2.13x throughput improvement compared with representative baselines, while keeping quality degradation within the configured budget.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：混合专家（MoE）模型已成为大规模 AI 服务的主流架构，其稀疏激活特性天然适合资源受限的边缘环境。但将 MoE 模型部署在地理分布、资源异构的边缘服务器上进行协同推理时，面临一系列新的挑战。
- **核心问题**：一个 token 在某层的 Top-k 激活专家可能分布在多个服务器上，最优路由策略**不能只看专家位置或单因素指标**，而必须联合考虑以下四类异构成本：
  1. 跨服务器链路带宽（边缘网络为普通互联网链路，带宽差异大、不稳定）；
  2. 异构 GPU 计算能力与瞬时队列积压；
  3. GPU-CPU 间专家加载（卸载）延迟——本地 CPU 中的冷专家可能比远端 GPU 中的热专家更慢；
  4. 副本级量化精度不同导致的质量损失差异。
- **现有方法的不足**：分布式推理工作（如 EdgeShard、Petals）主要针对稠密模型的分割；MoE 服务系统（如 MoE-Infinity、Prism）分别优化专家缓存、放置或卸载；模型分块/卸载方法（如 FlexGen）多在单一节点内存层次上优化。它们**均缺乏一个统一框架来联合建模上述全部因素**，也没有解决在线多服务器协同路由问题。
- **本文解决方案**：提出 **HetRoute**——一个面向分布式边缘 MoE 推理的异构成本感知协同路由框架，通过"离线部署优化 + 在线集合级路由"的两阶段协同设计解决该问题。

## 2. 方法论：核心思想、关键技术细节

### 2.1 统一异构成本模型

- 定义了**每分配成本**（公式 9），将一次专家执行分配的综合代价显式建模为四项之和：
  - **跨服务器传输项**：如果目标副本不在当前驻留服务器上，需传输隐藏状态；
  - **GPU-CPU 卸载项**：若副本驻留在 CPU 内存，需先加载入 GPU；
  - **计算排队项**：GPU 计算时间 + 当前积压负载造成的排队延迟；
  - **质量惩罚项**：量化损失与替换执行损失之和（以权重系数 λ 纳入）。链路带宽、GPU 算力（FLOPs）、PCIe 带宽；传输、计算并行执行，层延迟取所有分支的**瓶颈（最大值）**，而非求和。

### 2.2 问题建模与分解

- 构建联合优化问题 **P0**：同时优化离线部署（专家放置 X、GPU/CPU 驻留 Y、副本量化精度），以及在线路由决策 Z，目标为延迟与质量退化之和最小。
- 约束条件包括：GPU/CPU 内存容量约束、(c.4) **全精度精确副本不变式**（每个专家至少在一个服务器上保有全精度精确副本）、每个目标专家恰好执行一次、(c.9) 每 token 质量预算硬约束、(c.10) 调度窗口稳定性约束。
- 由于 P0 联合耦合离线与在线决策且状态在线才揭示，将其分解为两阶段：离线算法固定 (X, Y)，在线算法求解 Z。

### 2.3 离线部署算法（Algorithm 1）：路由成本耦合的三阶段启发式

- **Stage 1（路由概率加权 GPU 驻留）**：模拟在线路由器，估计每个副本的实际被选概率，以其为权重乘以卸载延迟节省量来计算 **GPU 驻留收益**；按收益从大到小贪心分配 GPU 内存，而非仅按原始激活频率。
- **Stage 2（统一成本驱动冗余复制）**：对每个候选 (专家, 服务器, 精度) 计算**冗余收益** = 期望在线路由成本降低值 − 内存价格 μ；反复插入收益最大的副本，直到预算耗尽。
- **Stage 3（驻留重优化）**：在扩大的副本集合上全局重新分配 GPU 驻留，并加入"边际收益递减"保护，防止同一专家的多个 GPU 副本挤占其他高价值专家资源。
- 设计核心：所有离线收益项均使用**与在线阶段完全相同的统一成本函数**进行评估，实现离线-在线的闭环协同。

### 2.4 在线协同路由算法（Algorithm 2）

- **精确优先候选构造**：优先使用目标专家自身的精确副本（经质量与稳定性守卫筛选）；仅当所有精确候选均不可行时，才启用相似性驱动的替换副本；依次：**候选集构造 → 守卫剪枝（质量 + 稳定性）→ 集合级选择（枚举/束搜索）→ 应急回退**。
- **集合级瓶颈成本优化**：将每个 token 的 k 个激活专家作为一个整体进行路由（以瓶颈层延迟最小化为目标），而非逐专家贪心选择；小候选域用精确枚举，大候选域用束搜索 + 1-交换局部搜索；采用**支配快速路径**（全部本地且 GPU 驻留且队列轻且本地延迟优于远端）以降低开销，但并非无条件本地优先。
- **双守卫机制**：硬性质量守卫（可验证/可评估 token 质量预算）**永不放松**；正常稳定性守卫（服务器窗口容量）在**应急回退**模式下可放松，超载转化为排队延迟而非路由不可行。
- **自适应反馈**：通过投影反馈规则在线调整传输/卸载/计算/质量四项成本的单位权重 α，动态惩罚正在成为系统瓶颈的成本组件。

### 2.5 理论性质

- **Property 1（回退可行性）**：基于 (c.4) 不变式，应急回退始终可找到全精度精确副本，质量增量恒为 0，算法必然终止于完整且质量可行的路由。
- **Property 2（参与服务器数上界）**：任何 token-层对的实际参与服务器数 ≤ k，与候选域大小无关。
- **Property 3（小候选域逐层最优性）**：候选域规模 ≤ 阈值 R 时，精确枚举返回当前积压状态下的逐层全局最优解。
- **Property 4（交换精炼局部最优性）**：束搜索 + 1-交换在有限步内终止于单目标重分配意义下的局部最优。
- **Property 5（在线复杂度）**：束搜索变体 O(LkRB)，精确变体 O(LR^k)，只依赖平均副本数 R 而非服务器数 N，适合实际边缘部署。

## 6. 主要结论与发现

- **性能收益**（Mixtral-8x7B 上 vs. 代表性基线）：
  - 平均延迟降低最高达 **59.0%**（156 ms vs. EdgeShard）；
  - P99 延迟降低最高达 **58.0%**（286 ms，比 Prism 低 33.2%）；
  - 跨服务器流量减少最高达 **72.1%**（每千 token 1.24 GB）；
  - 吞吐量提升 **2.13 倍**（1490 token/s，v.s. EdgeShard）。
- **质量保持**：质量退化始终在预算内；在 2% 预算下，WikiText 困惑度仅从 5.32 上升到 5.39，SQuAD F1 仅从 86.7 降到 86.1，GSM8K 准确率仅从 56.8% 降到 56.0%；质量-延迟曲线平滑单调，在约 2% 预算处出现拐点。
- **集合级路由的必要性**：Top-k 越大（如 k=4 时提升 29.8%），集合级路由相对于逐专家贪心的优势越明显，因为扇出/扇入耦合更强。
- **冗余部署的边际效应**：内存预算比从 1.0 增至 2.0 时效果显著，超过 2.0 后趋于饱和。
- **负载鲁棒性**：80 req/s 重负载下，HetRoute 的 SLA 满足率（73%）明显优于 Prism（51%）和 EdgeShard（21%）。

## 7. 优点

- **实验维度丰富**：跨模型、跨负载、组件消融、质量-延迟权衡等多角度验证，结论有交叉印证。

- **算力与平台细节不透明**：未报告测试服务器的 GPU 具体型号、训练/校准耗时、内存带宽细节，无法复现精确实验环境。
- **实验场景局限**：仅基于模拟的 10 服务器追踪驱动平台，无真实广域网/互联网部署验证；未考虑移动设备、车辆、无人机等更受限的边缘终端。
- **最优性局限**：逐层路由只能保证小候选域下的局部最优，跨层整体非最优；束搜索（大候选域）没有近似比保证，论文仅报告实验性表现。
- **未报告统计不确定性**：缺少区间估计与种子方差分析，无法判断改进差异的统计显著性。
- **模型覆盖有限**：仅覆盖 3 个 MoE 模型（最大为 8x7B），缺少更大规模（如 70B+）或稀疏度更高的模型验证；Top-k 仅覆盖 2 与 4，未覆盖更大 k。
- **设计参数敏感性**：权重 ω₁/ω₂、束宽度 B、枚举阈值 R、内存价格 μ 等超参数的选择对性能影响有待更系统的敏感性分析。
- **适用性限制**：质量预算采用加性代理与 KL 散度标定，与真实任务指标（准确率/F1）之间的关系仅在三个数据集上验证

- **适用性限制（续）**：质量预算采用加性代理与 KL 散度标定，与真实任务指标（准确率/F1）之间的关系仅在三个数据集上验证，缺乏对翻译、代码生成、多轮对话等更多任务类型的检验；此外，质量退化预算的设定需要人工指定，不同任务对质量损失的容忍度差异较大，实际部署中如何自适应设定预算仍是一个开放问题。
- **在线学习能力有限**：自适应反馈仅通过投影规则调整四项成本权重，本质上是单步启发式更新，缺乏对网络波动、负载漂移等非平稳环境的形式化在线学习保证（如遗憾界）。
- **调度窗口假设较强**：(c.10) 稳定性约束假设未来一个窗口内的请求分布可预测，若突发流量远超窗口预测，路由稳定性可能被破坏，导致频繁重路由。
- **同类系统对比不足**：未与最新的大模型推理框架（如 vLLM、SGLang 的 MoE 分支）或商用边缘推理平台对比，实际部署中的工程竞争力有待验证。

## 9. 未来工作

论文在"结束语"中简要提及，但结合其设计思路可总结出以下有价值的未来方向：

- **跨层联合路由优化**：将多层的 Top-k 选择作为一个整体进行端到端优化，或采用深度强化学习学习跨层路由策略，以突破逐层最优的局限。
- **更细粒度的缓存与预取协同**：将 GPU-CPU 驻留决策与在线热点预测结合，利用请求到达模式提前预取专家，进一步降低冷专家加载延迟。
- **异构设备扩展**：将框架推广到 CPU-only 节点、NPU/TPU 等异构加速器，以及移动端、车端等更受限环境，扩展统一成本模型的适用范围。
- **自适应质量预算机制**：基于任务级反馈（如置信度、下游任务指标）自动调整质量预算，而非依赖静态人工设定。
- **联邦与隐私增强**：在协同推理中引入隐私保护机制（如隐藏状态加密、安全聚合），使框架适用于跨机构、跨信任域的边缘部署。
- **实际部署验证**：在真实广域网或云边协同环境（如 AWS Wavelength、Azure Edge Zone）中进行大规模验证，补充统计显著性分析。

## 10. 总体评价

HetRoute 是分布式 MoE 推理领域一项系统性强、设计完整的代表性工作：

- **从研究问题角度**，它精准定位了边缘 MoE 协同推理中"异构成本交织"这一被忽视的核心挑战，打破了"本地优先"的朴素直觉，论证了统一成本感知的必要性。
- **从方法论角度**，其"统一成本模型 + 离线/在线两阶段协同 + 安全回退保证"的设计框架兼具理论严谨性与工程可行性，特别是全精度精确副本不变式与双守卫机制，在保证质量安全的同时间接降低了在线决策的复杂度。
- **从实验角度**，多模型、多负载、多指标的验证体系较为扎实，量化结果（最高 59% 延迟降低、72% 流量减少、2.13 倍吞吐提升）足以证明其在目标场景下的有效性。

尽管在真实环境验证、统计严谨性与更大规模模型覆盖方面存在一定不足，但该工作为边缘 AI 推理的资源管理与调度提供了一个高质量的统一框架，对该方向后续研究具有重要的启发意义。
