## 摘要
Harness设计通过塑造大型语言模型（LLM）在可执行环境中感知、推理和行动的方式，对Agent性能起着关键作用。近期工作提出了自动harness演化，即通过Agent与环境的交互迭代改进harness。然而，现有方法往往过拟合于演化任务，仅依赖轨迹衍生的信号，并联合优化harness组件，导致组件间相互干扰。我们提出HarnessCompass，一种新颖的自动harness演化框架，其核心是受约束的演化、主动反馈和组件级优化。HarnessCompass首先对演化施加全局约束，将修改限制在任务无关的harness变化上，使其能够泛化到演化任务之外。随后，它用Agent关于harness使用情况的主动第一人称反馈来增强轨迹派生证据，从而为演化提供更丰富的信号。最后，它解耦不同harness组件的优化，再将它们整合成统一的harness，在减少组件间干扰的同时保持组件协同。在SWE-bench Verified上使用GPT-5.4，HarnessCompass仅通过5次演化迭代就将Pass@1从54\%提升至66\%，在有效性和演化效率上均优于AHE。此外，演化得到的harness能有效迁移到保留任务和其他模型上，展现出比先前自动harness演化方法更强的泛化能力。

## Abstract
Harness design plays a critical role in agent performance by shaping how large language models (LLMs) perceive, reason over, and act within executable environments. Recent work has proposed automatic harness evolution, which iteratively improves the harness from agent--environment interactions. However, existing methods often overfit to the evolution tasks, rely exclusively on trajectory-derived signals, and optimize harness components jointly, causing interference across components. We propose HarnessCompass, a novel automatic harness evolution framework built around constrained evolution, proactive feedback, and component-wise optimization. HarnessCompass first enforces global constraints on evolution, restricting modifications to task-agnostic harness changes that generalize beyond the evolution tasks. It then augments trajectory-derived evidence with proactive first-person feedback from the agent about harness usage, yielding richer signals for evolution. Finally, it decouples the optimization of different harness components before consolidating them into a unified harness, reducing cross-component interference while preserving component synergy. On SWE-bench Verified with GPT-5.4, HarnessCompass improves Pass@1 from 54\% to 66\% in only 5 evolution iterations, outperforming AHE in both effectiveness and evolution efficiency. In addition, the evolved harness transfers effectively to held-out tasks and other models, demonstrating substantially stronger generalization than prior automatic harness evolution methods.

## 论文核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM 智能体的性能不仅取决于基础模型，还高度依赖 **harness**——即协调模型与环境交互的软件层，包括提示词、工具、中间件、记忆和验证例程等。尽管自动 harness 演化（automatic harness evolution）已被提出并能在基准上带来显著收益，但现有方法存在三大限制，导致其可靠性和泛化性不足：
  1. **过拟合演化任务**：元智能体可在固定任务集上自由修改 harness，容易把任务特定的捷径编码进去，使分数上升却无法迁移到未见任务；
  2. **仅依赖轨迹外部信号**：元智能体只能从外部看到"任务失败、失败在哪"，却不知道"智能体为什么觉得 harness 难用"，容易产生归因错误；
  3. **联合优化所有组件**：提示词、工具、中间件、记忆等在同一轮中一起修改，编辑之间相互干扰，孤立修改的收益无法复合。
- **论文主张**：问题不在于 harness 演化本身，而在于演化过程缺乏结构和纪律。一个有效的 harness 应该从受约束的、证据更丰富的、按组件解耦的演化过程中涌现。

## 方法论

### 核心思想
HarnessCompass 围绕三个原则构建，对应解决上述三个限制：

### 1. 约束演化（Constrained Evolution）
- 设置**全局泛化门**（Generalization Gate），所有候选修改必须通过后才能应用，覆盖全部七类组件。
- **内容要求**：禁止提及具体任务实例、测试函数、私有符号、任务专属关键字匹配等；只允许可复用的决策准则，并附带适用性条件（applicability criterion），使准则在未见任务上也可被评估。
- **位置要求**：将修改分为两类——
  - **能力编辑（capability edits）**：新增可执行功能（如运行测试、安装缺失依赖），必须放在中间件、工具或子智能体的可执行代码中；
  - **引导编辑（guidance edits）**：仅提供行为指导，必须放在系统提示词或记忆中，禁止编码成可执行逻辑。

### 2. 主动反馈（Proactive Feedback）
- 在验证器评分后，让**同一基础模型**以第一人称报告使用 harness 的体验：
  - **盲报告（blind report）**：不透露 verdict，避免事后归因偏差；
  - **后见报告（hindsight report）**：透露 verdict，并要求将失败归因到 harness、自身推理、任务歧义或环境四类之一。
- 将两份报告调和后，**对照轨迹进行 grounded 验证**：对现有组件的抱怨必须被轨迹直接支持；对缺失能力的请求必须对应轨迹中真实存在的缺口。不支持的报告被丢弃。
- 幸存反馈按组件分组，以置信度评分（考虑报告一致度、影响任务数、盲/后见一致性）作为补充证据注入元智能体的演化查询。

### 3. 组件级优化（Component-wise Optimization）
- 每一轮并行演化两个变体，分别限于**结构组件**（中间件、工具实现、子智能体）和**引导组件**（系统提示词、技能、工具描述、记忆），互不干扰。
- 评估后选择 Pass@1 更高的变体作为胜者，再通过 **R³ 合并**（Revision → Recombination → Refinement）将败者的有效修改整合进来：
  - **Revision**：逐条审查败者修改，仅保留独立有益、不重复不冲突的项；
  - **Recombination**：把保留项应用到胜者基础上，文件级冲突以胜者优先；
  - **Refinement**：删除实现重叠功能的冗余修改，优先保留更确定性的实现。

### 算法流程（文字说明）
从最小 harness H0（仅含一个 shell 命令工具和简短系统提示词，无中间件/技能/子智能体）出发，每轮：① 用当前 harness 对演化集做 k 次 rollout；② 从轨迹中提取证据；③ 获取 grounded 的第一人称反馈；④ 并行演化结构和引导两个变体并分别评估；⑤ 选出胜者，用 R³ 将败者贡献整合；⑥ 若整合后优于当前 harness 则接受，否则保持。

## 主要结论与发现

- **有效性**：在 GPT-5.4 上，HarnessCompass 将 Pass@1 从 seed 的 54.0% 提升至 66.0%（50 任务演化集），仅需 **5 轮**迭代；AHE 达到 63.0% 需要 **20 轮**。在 450 个未见任务上，HarnessCompass 达到 60.4%，优于 AHE 的 54.7%；500 任务加权总量为 61.0%，优于 AHE 的 55.5%。
- **泛化性**：冻结 harness 迁移到 Claude-Sonnet-4.6 后，Total 从 70.0% 提升至 73.8%，说明学到的改进是跨任务、跨模型可复用的工程原则，而非任务或模型特化的补丁。
- **各原则的互补作用**：泛化门促进迁移（单加后 Held-Out 从 51.6% 升至 58.4%）；主动反馈扩大优化信号（Sample 升至 66.0%）；R³ 合并恢复泛化并大幅减少轮数（Held-Out 恢复至 60.4%，Turns 从 12 降至 5）。
- **收益分布**：提升广泛分布于大仓库且集中在 harness 敏感场景（如 sphinx +22.8、pytest +15.8）；在 seed 已很强的仓库（如 scikit-learn）几乎不变。
- **机制洞察**：有门演化储存"带适用性条件的跨任务决策准则"，无门演化储存"任务专属配方"（如针对 django-13158 的具体改法），后者在演化集上可充当"答案书"但无法迁移。

## 总体评价

HarnessCompass 是一篇方法设计严谨、评估架构清晰、论证链完整的实证论文。其对 AHE 三个结构性缺陷的诊断切中要害，三个设计原则与缺陷一一对应，且每一条都能通过消融实验获得直接的性能解释。从最小 harness 出发、以共享同一基础模型的设定排除干扰，使得最终的每个百分点的提升都可归因于 harness 工程而非模型能力——这种"干净"的实验归因在 LLM 智能体研究领域并不多见。论文在泛化评估上的投入（未见任务 + 跨模型迁移 + 按仓库细分）显著超出目前同类工作的平均水平，值得作为方法论范本。

同时，其局限也真实存在：单一基准、50 任务演化集、k=2 的统计精度、单模型迁移验证，决定了本文的结论更准确的理解是"在 SWE-bench Verified 范围内，受约束的 harness 演化优于自由演化"，而非放之四海而皆准的普遍规律。但作为第一篇系统性地回答"如何让 harness 演化不靠过拟合任务集而靠学习工程原则"的工作，它在问题定位、方法构造、实验验证三个层面都为后续研究提供了坚实起点。
