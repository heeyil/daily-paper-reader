## 摘要
现代智能体框架通过外部技能库装备大型语言模型，以解决复杂任务。然而，尚不清楚这些系统能否有效进化其技能，以及由此产生的技能是否真的能提升任务解决能力。为弥补这一缺口，我们提出了ContinualSkillBench，一个用于上下文持续技能学习的动态评估框架。它涵盖五个代表性领域，每个领域包含100个相互关联的子任务，按难度递增排列，并提供了跨任务技能复用的机会。我们的实验表明，顺序执行通常能提升性能，但提升幅度在不同模型和领域间差异显著。此外，上下文学习在平均表现上与显式技能维护相当，这表明性能提升很大程度上源于对先前上下文和反馈的适应，而非单纯的技能抽象复用。然而，显式技能对于需要可复用流程或精确输出的任务仍具有选择性优势。我们进一步发现，能力较弱的模型倾向于积累更大、更碎片化的任务特定技能集合。这些发现表明，当前的上下文技能进化机制能够支持持续适应，但仍难以稳定地将经验整合为稳健且可迁移的技能。

## Abstract
Modern agent frameworks equip large language models with external skill libraries to solve complex tasks. However, it remains unclear whether these systems can effectively evolve their skills and whether the resulting skills improve task-solving capabilities. To bridge this gap, we introduce ContinualSkillBench, a dynamic evaluation framework for in-context continual skill learning. It covers five representative domains, each containing 100 interconnected subtasks ordered by increasing difficulty and opportunities for cross-task skill reuse. Our experiments show that sequential execution generally improves performance, but the gains vary substantially across models and domains. Moreover, in-context learning performs comparably to explicit skill maintenance on average, suggesting that much of the improvement arises from adaptation to prior context and feedback rather than reusable skill abstraction alone. Explicit skills nevertheless provide selective benefits for tasks requiring reusable procedures or precise outputs. We further find that less capable models tend to accumulate larger, more fragmented collections of task-specific skills. These findings show that current in-context skill evolution mechanisms can support continual adaptation, but still struggle to consistently consolidate experience into robust and transferable skills.

## 2. 论文提出的方法论

**核心思想：**
构建一个动态评估框架 ContinualSkillBench，以“技能链”为组织逻辑，将同一领域内 100 个互连子任务按难度递增和跨任务技能依赖关系排序，测试智能体是否能在顺序执行中不断沉淀和复用技能。

**关键技术细节与流程：**

1. **领域选择**：覆盖五个代表性领域——医疗保健、法律、数学、金融、办公，均为实际应用价值高、需复杂推理和精细评估的领域。

2. **三阶任务池构建**：
   - 基础层：经典标准化数据集（如 OlympiadBench、LawBench、TAT-QA）测试核心知识处理；
   - 中间层：开放式智能体数据集（如 GAIA、ClawBench、MedAgentsBench、MathCoder）测试多步推理和工具使用；
   - 高级层：复杂人工评估基准（如 OneMillionBench）测试高层战略决策。
   - 共收集约 30,000 个原始任务，每领域最终筛选出 100 个。

3. **技能标注与过滤**：使用 LLM 标注每个任务所需的核心技能，按目标领域相关性过滤任务，并给出初始难度评分。

4. **依赖评估与图排序**：
   - 每域采样 200 对任务，LLM 判断双向技能迁移关系（YES/PARTIAL/NO），共产生 400 个方向性判断；
   - 将 YES 判断转换为有向依赖图 G=(V,E)，边 A→B 表示任务 A 的技能有助于任务 B；
   - 按课程约束排序：先按难度分层、从易到难，在每层内使用 Kahn 拓扑排序的贪心变体——优先处理出度最大的零入度节点（即对更多后续任务有技能支持的任务），环时打破选择最大出度剩余节点。

5. **人工审查**：人工复核每领域 100 个任务序列的质量、难度递进合理性、技能迁移关系的真实性。

6. **三回合交互协议**（基于 Harbor 框架）：
   - **回合1 任务引入**：智能体接收子任务指令和当前技能库；
   - **回合2 任务执行**：智能体利用技能、工具完成任务，记录执行过程和输出；
   - **回合3 反馈反射与技能更新**：智能体接收评估器反馈，使用 `Create Skill` 和 `Modify Skill` 元技能创建或修改技能，更新后的库从下一任务开始可用。

7. **评估指标**（四类评估器）：
   - **精确匹配（EM）**：短确定性答案的精确匹配；
   - **F1**：长答案的 token 级部分重叠；
   - **数值精度**：按任务容忍度（通常 ε ≤ 10⁻⁴）比较数值答案；

## 3. 实验设计

**Benchmark 结构：**
- 五个领域（Law、Finance、Healthcare、Office、Math），每个领域 100 个相互关联的子任务，按难度和技能依赖递进排列。
- 每个领域围绕三条宏观能力轨迹组织（如 Finance 从财务计算→财务分析→财务决策；Math 从代数计算→数学代码生成→研究级数学）。

**评估模型：**
- GPT-4o、GPT-5.3-Codex、Claude 4.7 Opus，共三个代表性前沿模型，使用 Codex CLI 和 Claude Code 两种智能体序列化工具。

**对比设置：**
- **独立执行（Independent，基线）**：每任务重置交互历史和技能库，从零开始。
- **顺序执行（Sequential）**：保留上下文和技能库，在 100 任务序列上持续进行技能维护。
- **纯上下文学习（ICL）**：有顺序和反馈但禁止创建/修改技能，仅在 GPT-5.3-Codex 上对 Law、Finance、Healthcare 三个领域评测。
- **RAG 消融（附录F）**：检索先前轨迹片段而非维护显式技能，仅在 Opus 4.7 上的 Healthcare 评测。

**数据源统计：**

## 6. 论文的主要结论与发现

1. **顺序执行普遍提升性能**：15 个模型-领域组合中 13 个提升原始奖励、14 个提升归一化奖励；宏平均绝对提升 +0.071（原始）和 +0.078（归一化），相对提升 16.2% 和 16.9%。但提升幅度并非普适，存在模型和领域差异。

2. **提升幅度与基础能力不对应**：GPT-5.3-Codex 获得最大平均归一化提升（+0.098），但 Opus 4.7 拥有最强独立基线却不拥有最大提升。基础任务求解能力不能单独决定持续学习收益。

3. **领域依赖显著**：Healthcare 平均提升最大（+0.149），其次是 Finance（+0.076）、Law（+0.058）、Office（+0.054）、Math（+0.052）。唯一归一化奖励下降发生在 Opus 4.7 的 Math 领域（−0.008）。

4. **评估器类型影响增益分布**：结构化任务（EM、Numeric）通常受益更多；但非普适——Opus 4.7 在 Healthcare 的 Rubric 提升 +0.234，但其 Math Rubric 反而下降 −0.192。

5. **显式技能维护并不总是优于纯 ICL**：GPT-5.3-Codex 上三个领域的平均归一化奖励：Independent 0.466, ICL 0.605, Sequential 0.602。顺序略胜 ICL 于 Law 和 Finance，但Healthcare反超 ICL 表现更好。说明 Sequential 的大部分增益其实来自保留上下文和反馈，而非技能抽象本身。

6. **显式技能具有选择性优势**：在需要严格输出约束或可复用流程的任务上（如 Law/Finance 的 EM、Healthcare 的 Programmatic 0.250→0.500）表现更好；但在开放式 Rubric 任务上容易过度特化到早期评估标准。

7. **弱模型技能库碎片化更严重**：GPT-4o 累积 384 个技能，平均质量分 5.68；GPT-5.3-Codex 仅 205 个技能，平均质量分 7.94。弱模型技能更少被重用，形成“库越大、利用率越低”的碎片化模式，说明其难以将经验合并为泛化过程。

8. **当前技能进化机制的瓶颈**：能支持持续适应，但难以将经验**持续巩固为稳健且可迁移的技能**——这是当前所有模型面临的共同局限。

## 7. 优点

- **任务序列的结构化设计**：通过技能链、难度梯度和依赖图排序，创造“后续任务依赖前序技能”的真实持续学习环境，而非简单随机堆叠任务。结构验证（69.5%任务复用已学技能、置换检验显示局部技能连续性显著优于随机序）有力支撑了这一设计决策。
- **多基线系统对比**：Independent / ICL / RAG / Sequential 四层设计巧妙分离了“上下文适应”与“显式技能维护”的贡献，使“技能是否真正有用”这一问题得到公平检验。
- **多维度评估体系**：整合精确匹配、F1、数值宽容差、Rubric 和程序化测试五类评估器，能够细致捕捉不同任务类型上的性能差异，避免单一指标带来的偏差。
- **技能库动态行为分析**：不仅看最终任务分数，还分析技能调用频率、技能库规模、内容质量和碎片化程度，提供了技能维护行为的全貌。
- **跨领域设计和公开资源**：五个实用领域、多来源基准池、代码开源，为社区后续扩展提供基础。

## 8. 不足与局限

- **任务来源受限**：各领域任务仍取自固定来源集合；真实部署场景的长尾分布、数据偏移、非基准格式的指令未覆盖。
