## 摘要
最近的文本到SQL系统越来越依赖多轮交互、执行反馈和强化学习。然而，大多数现有方法仅将执行正确性作为轨迹级奖励，这为识别导致成功或失败的SQL决策提供了有限的指导。我们提出了SERL-SQL，一种用于多轮文本到SQL智能体的选择性执行接地强化学习框架。SERL-SQL采样在策略SQL交互轨迹，并使用仅训练用的教师模型通过执行反馈对学生动作进行重新评分。由此产生的师生似然差距被转换为有界、掩蔽的权重，这些权重仅在SQL和工具动作标记上重新加权GRPO优势。通过这种方式，任务奖励保持了优化方向，而执行事后反馈提供了局部信用分配。在BIRD、Spider和跨域基准上的实验表明，SERL-SQL达到了竞争性能，在BIRD-Dev上达到了76.56%的执行准确率，在Spider-Test上达到了89.92%。此外，我们基于奖励的选择策略紧密接近oracle Best-of-N上限，并且始终优于基于一致性的选择，表明SERL-SQL产生了高质量候选，这些候选可以通过轻量级执行接地奖励可靠地识别。我们的代码将在https://github.com/Ffunkytao/SERL-SQL发布。

## Abstract
Recent Text-to-SQL systems increasingly rely on multi-turn interaction, execution feedback, and reinforcement learning. However, most existing methods use execution correctness only as a trajectory-level reward, which provides limited guidance for identifying the SQL decisions responsible for success or failure. We propose SERL-SQL, a selective execution-grounded reinforcement learning framework for multi-turn Text-to-SQL agents. SERL-SQL samples on-policy SQL interaction trajectories and uses a training-only teacher to re-score student actions with execution feedback. The resulting teacher--student likelihood gap is converted into bounded, masked weights that reweight GRPO advantages only on SQL and tool-action tokens. In this way, task rewards preserve the optimization direction, while execution hindsight provides localized credit assignment. Experiments on BIRD, Spider, and cross-domain benchmarks show that SERL-SQL achieves competitive performance, reaching 76.56% execution accuracy on BIRD-Dev and 89.92% on Spider-Test. Moreover, our reward-based selection strategy closely approaches the oracle Best-of-N upper bound and consistently outperforms consistency-based selection, showing that SERL-SQL produces high-quality candidates that can be reliably identified by lightweight execution-grounded rewards. Our code will be released at https://github.com/Ffunkytao/SERL-SQL.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：Text-to-SQL 任务旨在将自然语言问题转化为可执行的 SQL 查询。近年研究已从单次生成范式转向智能体式多轮数据库交互，模型需完成模式链接、SQL 生成、执行验证、错误修正与候选选择等系列决策，代表性系统如 Agentar-Scale-SQL、Arctic-Text2SQL-R1、MARS-SQL 已验证智能体交互与强化学习在 Text-to-SQL 中的有效性。
- **核心问题**：现有方法通常仅将执行正确性作为**轨迹级（trajectory-level）奖励**，即同一条轨迹中的所有 token 获得相同的优势值。这种粗粒度信用分配无法定位导致成败的具体 SQL 决策——推理 token、格式化 token 与决定性 SQL token 被不加区分地更新，使得反馈信号在长轨迹中扩散稀释，优化效率低下。
- **关键洞察**：执行反馈（如运行时错误、空结果、结果表）本质上是**训练时可用的特权证据**（privileged evidence），能够揭示哪些 SQL 决策可能对失败负责。但已有工作未充分利用这一信号进行细粒度信用分配：要么仅用作结果奖励，要么不加区分地整体蒸馏。
- **论文含义**：SERL-SQL 提出将执行反馈作为**训练时的事后视角（hindsight）**，通过训练专用的教师模型对学生动作进行重评分，将师生似然差距转化为有界、掩蔽的权重，仅作用于 SQL 与工具动作 token，从而在不改变任务奖励所确定的优化方向的前提下，实现局部化、精确化的信用分配。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 总体框架

SERL-SQL 由四个阶段组成，核心是：**任务奖励决定更新方向，执行事后反馈决定更新的强度与局部性**。训练结束后教师模型被移除，学生策略作为独立的多轮 SQL 智能体部署。

### 阶段一：模式接地（Schema Grounding）

- 目标：将完整数据库模式压缩为与问题相关的紧凑子集 S′ ⊆ S。
- 流程包含三个部分：
  - **离线值索引**：用嵌入模型 Eη 对每列的代表性取值编码，构建列感知向量索引 I。
  - **问题感知值检索**：从问题中提取关键词与实体提及 Kq，与向量索引做相似度匹配，取 Top-K 相关值作为值证据 Vq。
  - **混合模式链接**：结合推理式链接（根据问题语义结构识别投影列、过滤条件、连接键、聚合属性）与基于值的链接（由检索到的数据库值支撑的列），最终生成接地模式 S′。

### 阶段二：多轮 SQL 智能体轨迹采样

- 定义多轮交互过程 M = (S_int, A, P, R)：状态包含任务输入与完整交互历史；动作包含推理片段与中间 SQL 动作或终结解决方案。
- 每轮策略生成 SQL 后由数据库执行，返回观察（结果表、运行时错误、解析器错误或空结果），智能体可据此修订之前的 SQL 决策。
- 每个输入采样 N 条 on-policy 轨迹，使用分层验证器计算轨迹级奖励：
  - +1：轨迹有效且最终 SQL 执行结果正确；
  - 0：轨迹有效但结果错误；
  - −1：轨迹格式无效。
- 该稀疏奖励用于 GRPO 的组相对优势计算：

  \[
  A_n = \frac{R_n - \text{mean}_m(R_m)}{\text{std}_m(R_m) + \epsilon_A}
  \]

### 阶段三：选择性执行事后教师（Selective Execution-Hindsight Teacher）

- 对每个 SQL 动作构造事后上下文 c_ex_t = H_ex(o_t)，包含执行结果、错误信息、空结果反馈等诊断信息——该上下文仅训练时对教师可见。
- 教师策略 πT（与学生定期同步、stop-gradient）在事后上下文下重新评估学生生成的 token：

  \[
  \log \pi_T(y_{t,i} | h_t, y_{t,<i}, c^{ex}_t)
  \]

  而学生仅使用行动前的信息：

  \[
  \log \pi_\theta(y_{t,i} | h_t, y_{t,<i})
  \]

- 定义**选择性动作掩码** m_{t,i} ∈ {0,1}：仅对可执行 SQL 与工具动作 token（SQL 提交与修订动作）设为 1，推理、格式化等 token 设为 0。

### 阶段四：事后引导的优势重加权（Hindsight-Guided Advantage Reweighting）

- 计算师生对数似然差距：

  \[
  \Delta_{t,i} = \log \pi_T(y_{t,i} | h_t, y_{t,<i}, c^{ex}_t) - \log \pi_\theta(y_{t,i} | h_t, y_{t,<i})
  \]

- 将 Δ 转换为有界、符号感知的权重：

  \[
  w_{t,i} = \text{clip}(\exp(\text{sgn}(A_n) \cdot \text{sg}[\Delta_{t,i}]), w_{\min}, w_{\max})
  \]

  其中 w_min = 1 − ε_w，w_max = 1 + ε_w。正优势轨迹中受事后支持（Δ > 0）的 token 获得更强强化；负优势轨迹中受事后否定（Δ < 0）的 token 获得更强抑制。

- 结合掩码得到有效 token 权重：

  \[
  \bar{w}_{t,i} = (1 - m_{t,i}) + m_{t,i} w_{t,i}
  \]

  非动作 token 保留原始 GRPO 权重。

- 引入训练步数依赖的衰减系数 α_k ∈ [0,1]，最终 token 级优势为：

  \[
  \tilde{A}_{t,i} = A_n [(1 - \alpha_k) + \alpha_k \bar{w}_{t,i}]
  \]

  训练早期充分利用事后反馈改善信用分配，后期逐渐回归纯奖励驱动的 GRPO，降低对特权信息的依赖。

- 最终目标函数使用裁剪代理目标：

  \[
  \mathcal{L}_{\text{SERL-SQL}}(\theta) = -\mathbb{E}_\tau \left[ \sum_{t,i} \ell_{\text{GRPO}}(\theta; \tilde{A}_{t,i}) \right] + \beta \text{KL}(\pi_\theta \| \pi_{\text{ref}})
  \]

## 6. 主要结论与发现

- **核心结论**：SERL-SQL 通过将执行反馈转化为训练时的选择性事后蒸馏信号，实现 token 级的局部信用分配，显著优于仅使用轨迹级奖励的 GRPO 基线，在 BIRD-Dev 上从 71.94%（无执行事后）提升至 74.95%（14B）。
- **模式接地至关重要**：移除模式接地导致最大性能下降（BIRD-Dev 下降 8.53 个百分点），说明信用分配的有效性依赖紧凑且语义对齐的模式上下文。
- **事后信息需要精心控制**：执行事后反馈必须经过有界裁剪、选择性掩码、符号感知和逐步衰减等多重约束，才能稳定提升性能；直接不加约束地使用反而会引入噪声。
- **选择策略优于生成策略**：reward_max 选择策略紧密逼近 oracle Best-of-N 上界，且优于 greedy 和 consistency 选择——说明 SERL-SQL 不仅提升了单条轨迹质量，更提升了生成高质量候选的整体概率分布。
- **事后信息应局部化**：即时观察（immediate observation）作为事后来源效果最佳，全长观察反而带来性能回退，验证了"事后应局部化、与动作因果对齐、而非越丰富越好"的设计哲学。
- **剩余瓶颈**：连接构建（29.1%）和语义理解（24.6%）是最大的错误来源，多表推理和细粒度值接地仍是未来改进重点。

## 9. 对未来研究的启示

- **更细粒度的信用分配机制**：SERL-SQL 的 token 级重加权验证了"局部化事后信号"的有效性，未来可进一步探索将执行反馈映射到更细的子结构（如 WHERE 子句、JOIN 条件、聚合函数）或语义角色层面，实现结构化信用分配。
- **事后信息的自适应调度**：当前衰减系数 α_k 依赖训练步数做线性调度，未来可探索基于教师置信度、轨迹难度或验证器不确定性的自适应权重策略，使事后信号的注入强度随训练进程动态变化。
- **多源特权的融合**：执行反馈之外还存在其他训练时可用的特权信号，如数据库内容统计信息、错误信息的语义类别、问题与模式的注意力热力图等，如何以统一框架融合多重事后证据值得探索。
- **跨引擎与真实环境验证**：将训练策略迁移至 PostgreSQL、MySQL 等不同方言环境，并探索无金标条件下的近似奖励（如基于数据分布统计的启发式验证），是通往实际部署的关键一步。
- **奖励模型与教师模型的协同**：SERL-SQL 中的教师仅作为事后重评分器；未来可考虑让教师同时担任生成建议器（生成修正后的 SQL 片段），与策略形成更紧密的"批评-建议"闭环，但需谨慎处理由此引入的 off-policy 偏差。
- **更全面的事后来源设计**：论文发现"即时观察"优于"全长观察"，说明事后信息并非越多越好；未来可从信息论角度研究如何度量事后上下文与动作之间的互信息，指导事后来源的自动选择与压缩。

## 10. 综合评价

SERL-SQL 是 Text-to-SQL 强化学习领域一篇方法设计扎实、实验分析系统的工作。其核心贡献不在于提出新的训练范式，而在于精准诊断了轨迹级奖励下的信用分配问题，并给出了一套工程上可行、理论上可解释的解决方案——以执行反馈为事后证据，以师生差距为信号源，以裁剪、掩码、衰减三重约束保证稳定性。从结果看，该方法在 BIRD、Spider 系列基准上均取得了有竞争力的表现，且跨 7B 至 32B 多规模验证使结论具有较强的说服力。

然而，论文的局限同样明显：训练数据单一、与最强基线（MARS-SQL）的对比公平性存疑、缺少统计显著性报告、资源开销披露不足，这些都在一定程度上削弱了结论的完备性。尤其是"无金标即无法计算奖励"这一根本假设，限制了方法向真实生产环境的迁移。

总体而言，该论文达到了领域内较高水平——问题选得好、解法想得巧、实验做得全，作为 Text-to-SQL 智能体强化学习方向的重要参考工作，其启发价值大于其直接可复用的工程价值。若后续能在多数据集训练、跨引擎鲁棒性与无金标奖励设计上加以完善，该方法的成熟度将更进一步。
