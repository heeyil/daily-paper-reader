## 摘要
基于大型语言模型的图形用户界面（GUI）智能体正越来越多地部署在移动、网页和桌面环境中。然而，现有的智能体通常是特定于领域的，限制了部署和用户体验。这促使将专门模型整合为单一的跨环境策略。权重合并直接合并领域专家，但在专家意见不一致时可能破坏可执行动作，而在线策略蒸馏（OPD）避免了冲突的教师监督，但在蒸馏过程中仍将所有响应令牌平等对待，忽略了动作令牌是环境与智能体之间唯一接口的事实。为解决这一问题，我们引入了MAGA，它根据结构化动作重新分配训练信号。基于生成动作的正确性，它抑制不必要或无效的蒸馏信号，并专注于错误动作的学习。此外，一种仅训练时的提示优化了领域专家提供的监督信号，而无需改变学生输入。在两种模型规模下，MAGA取得了最高的平均成功率，在8B规模下优于最强基线2.0%，并与教师的平均性能几乎持平。

## Abstract
Graphical user interface (GUI) agents based on large language models are increasingly deployed across mobile, web, and desktop environments. However, existing agents are typically domain-specific, limiting the deployment and user experience. This motivates the consolidation of specialized models into a single cross-environment policy. Weight merging directly merges domain-specific experts but can corrupt executable actions under expert disagreement, while on-policy distillation (OPD) avoids conflicting teacher supervision yet still treats all response tokens equally during distillation, ignoring that action tokens are the only interface between the environment and the agent. To address this, We introduce MAGA that re-allocates training signal according to the structured action. Based on the correctness of the generated action, it suppresses unnecessary or invalid distillation signals and focuses learning on erroneous actions. Besides, a training-only hint optimizes the supervision signal provided by domain-specific teachers without changing the student input. Across two model scales, MAGA achieves the highest mean success rate, outperforming the strongest baseline by 2.0% at 8B and achieves almost the same average performance with teachers.

- **核心问题**：如何将多个领域特定的GUI教师模型整合为一个统一的跨环境学生模型，同时尽最大可能保留各领域教师的能力？

### 现有方案的局限
| 方法类别 | 代表方法 | 核心缺陷 |
|---|---|---|
| 权重合并 | Weight Soup、TIES | 专家在动作决策上存在分歧时，合并参数会破坏可执行动作的准确性（在高分歧样本上成功率下降10%–24%）|
| 在线策略蒸馏（OPD） | UI-MOPD | 将回复视为平坦的令牌序列，对所有token等权训练，忽略了动作令牌是智能体与环境交互的**唯一接口**这一关键事实 |

### 核心洞察
- GUI动作仅占回复token的约4%–7%（推理token占93%–96%），动作信号在常规蒸馏中被严重稀释；
- 动作直接影响环境状态，错误动作会造成不可逆的状态偏移，需要专门的结构化监督。

## 2. 论文提出的方法论

### 核心思想
MAGA（Multi-plAtform self-fusion of GUI aGents via structured Action distillation）根据**结构化动作的正确性**重新分配蒸馏信号：抑制完全正确样本的无效监督，聚焦错误动作，并对动作类型和参数进行差异化处理，同时通过教师侧Hint优化监督质量。

### 关键技术细节

**（1）GUI动作的结构化表示**
- 动作表示为 `a = (z, p_z)`，其中 `z` 为离散动作类型，`p_z` 为类型对应的参数（如坐标、文本、URL、按键等）；
- 回复分为三段：推理token（I_reason）、动作类型token（I_type）、参数token（I_param）。

**（2）学生侧：条件训练信号再分配（三条规则）**

| 规则 | 条件 | 处理方式 |
|---|---|---|
| 规则1 | 动作类型和参数**全部正确** | 整个轨迹的蒸馏优势置零（`w=0`），跳过已正确的动作 |
| 规则2 | 类型正确但**参数错误** | 推理token保持权重1，完整动作跨度（类型+参数）放大为 `1+β` |
| 规则3 | **动作类型错误** | 推理token保持权重1，仅类型token放大为 `1+β`，参数token置零（因参数schema不兼容，监督信号无效） |

**（3）教师侧：训练专用Hint**
- 在教师输入中追加仅含**真实动作类型**的提示 `h(z*)`（如 "Hint: the correct action for this step is a {HINT} action"）；
- 学生输入不变，推理时无需Hint，实现训练与推理的解耦；
- Hint中不含坐标、文本等具体参数，仅为教师提供类型信号，提升评分可靠性。

**（4）蒸馏目标**
最终训练目标为：
```
L_MAGA(θ) = -E[ (1/|y|) Σ w_t · A_hint_t · log π_θ(y_t|x, y<t) ]
```
其中 `w_t` 为上述规则分配的token权重，`A_hint_t` 为基于Hint后的教师与学生的对数概率差（梯度停止）。

## 6. 论文的主要结论与发现

1. **MAGA显著优于所有统一方法**：8B规模下平均成功率51.2%，超过最强基线UI-MOPD约2.0个百分点；TNS达99.9%，几乎与各领域教师的平均性能持平。
2. **MAGA超越教师个体**：在OSWorld（45.3% vs 42.8%）和WebVoyager（74.3% vs 72.1%）上甚至超过了对应领域教师，仅MobileWorld略低3.4个百分点。
3. **权重合并的高分歧退化问题可被MAGA修复**：在66个高分歧样本上，MAGA纠正了Weight Soup的10个错误，仅引入1个新错误（准确率从71.2%提升至84.8%）。
4. **结构化信号分配有效提升了动作正确性**：训练后完全正确动作比例从42.2%升至63.2%，其中类型错误减少16.3%，参数错误减少4.7%。
5. **动作类型是错误的主要来源，也是最有效的纠错切入点**：仅纠正类型即可恢复68.4%的类型错误响应，说明许多参数错误是类型错误的下游结果。
6. **学生比教师更一致地模仿路由教师**：61.5%的动作与对应教师匹配，仅14.8%与跨领域教师匹配；同时发现了3.0%的"正确且不匹配任何教师"的创新动作。
7. **推理token稀释是学生未能全面超越教师的主要原因**：动作仅占响应token的3.9%–7.1%，且MAGA仅用单步数据训练，而真实任务需要多步执行。

## 8. 不足与局限

### 实验覆盖
- **WebVoyager只是子集**（140/基准全量），代表性可能打折；
- **训练与评估数据均为内部工业数据**，外部研究者无法复现或扩展比较；
- 仅在Qwen3-VL系列上验证，**未测试其他VLM架构**（如GPT-4V、LLaVA类），模型族内的结论泛化到其他架构的效果未知。

### 偏差风险
- Web领域训练数据占58%（200k/343k），可能导致领域间数据不平衡偏差；
- URL参数类别的评测样本极少（仅5个），对相关结论的置信度低；
- 坐标类动作占主导（678/841），其他参数类型的分析统计功效不足。

### 方法局限
- **单步训练与多步推理错配**：MAGA基于单步动作正确性做蒸馏，而真实GUI任务是多步执行链，长序列错误传播问题未被直接优化（论文第4.9节自认）；
- **规则依赖动作解析**：三类规则依赖对动作类型的可靠解析和精确评估器，参数语义不兼容时规则3保守掩码可能丢失部分有效监督；
- **Hint仅含动作类型**：论文表明类型错误是主要错误源，但参数错误同样占22.2%，类型Hint无法直接帮助参数级教师对齐。

### 实际部署
- 需要维护多个冻结教师模型并在线评分，**内存/计算开销较大**；
- 高分歧样本上的收益以单个样本的正确性评估为主，**尚未在多步交互终点成功率上独立验证**。
