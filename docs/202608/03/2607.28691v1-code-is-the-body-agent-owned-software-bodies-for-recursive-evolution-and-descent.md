## 摘要
个性化AI智能体通常可配置，但用户无法控制决定其未来行为的工件。我们提出OurArk，一种以智能体自有软件身体为核心的持久化个人智能体架构：该身体是一种承载身份、可检查、可版本化的工件，由人类保管。身体包含行为定义代码、提示词、工具、技能、策略、测试和进化机制。记忆与凭据保持为私有实例状态，而模型推理则被视为可替换的外部服务。OurArk在同一身体上定义了受治理的自我进化与递归衍生。自我进化产生孤立的候选变更，在人类控制下经过验证、审查和合并，从而实现人与智能体对其软件身体的协同开发。衍生创建一个具有独立身份、使命、历史和全新私有状态边界的独立版本化后代；兼容的后代自身可进一步衍生。分化后，可直接父代变更与同伴技能可以被检查以进行选择性局部适配。我们在开源Genesis创建引擎和Enoch参考智能体中实现了该架构。一个四智能体、三次衍生的线性谱系及可执行回归测试展示了递归创建、继承的验证契约、隔离的身体变更、人类控制的审查以及失败更新的恢复。OurArk为个人智能体提供了一个具体基础，使人们能够拥有、治理、专业化并随时间演进这些智能体。

## Abstract
Personalized AI agents are often configurable without giving users control over the artifacts that determine their future behavior. We present OurArk, an architecture for persistent personal agents centered on an agent-owned software body: an identity-bearing, inspectable, and versioned artifact under human custody. The body contains behavior-defining code, prompts, tools, skills, policies, tests, and evolution mechanisms. Memories and credentials remain private instance state, while model inference is treated as a replaceable external service. OurArk defines governed self-evolution and recursive descent over the same body. Self-evolution produces isolated candidate changes that are validated, reviewed, and merged under human control, enabling human-agent co-development of the agent's software body. Descent creates an independently versioned descendant with a distinct identity, mission, history, and fresh private-state boundary; compatible descendants can themselves source further descent. After divergence, direct-parent changes and peer skills can be inspected for selective local adaptation. We implement the architecture in the open-source Genesis creation engine and Enoch reference agent. A four-agent, three-descent linear lineage and executable regression tests demonstrate recursive creation, inherited validation contracts, isolated body changes, human-controlled review, and failed-update recovery. OurArk provides a concrete substrate for personal agents that people can possess, govern, specialize, and evolve over time.

## 1. 核心问题与研究动机

- **背景**：个人电脑使计算变得个人化，智能手机使其持续可用，而作者认为 AI 的下一个类似转折点是：每个人都拥有一个或多个真正属于自己的持久化智能体（persistent agent）。这些智能体应围绕用户的价值观、习惯、反馈与经验，逐步专业化于工作、生活、研究等场景。
- **核心问题**：当前 AI 智能体的"个性化"并不充分——智能体的组件（代码、提示词、工具、技能等）往往由平台组装和控制，用户虽然可以自定义行为，却无法真正"拥有"决定智能体未来行为的工件（artifacts）。用户没有对智能体演化方向的实际掌控权。
- **设计论点**：一个长期存在的个人智能体应该拥有一个**承载身份的软件身体（identity-bearing software body）**——用户能够拥有、检查、治理这个身体，并且智能体与用户能持续共同修改它。
- **整体含义**：论文提出 OurArk 架构，将"智能体自有软件身体"作为连续性、演化、派生、专业化、转移和治理的具体承载单位，使个人智能体可以被用户真正拥有、治理、专业化和长期演化。

## 2. 方法论

### 2.1 核心思想与架构边界

OurArk 将智能体实例定义为四元组：**𝐴 = (𝐵, 𝑆, 𝑅)**，处于人类保管人（custodian）𝐻 之下：

- **身体（Body, 𝐵）**：包含承载身份的、可版本化的工件——行为定义代码、提示词、工具、技能、策略、测试、进化机制等。这是可继承、可演化的持久载体。
- **私有状态（Private State, 𝑆）**：凭据、记忆、日志、队列等，属于单一存活实例，不可继承。
- **外部推理器（External Reasoner, 𝑅）**：提供模型推理服务，但**不是**身份与延续性的持久载体，可随时替换。
- **人类保管人（Custodian, 𝐻）**：拥有身体与私有状态，控制对权威身体的晋升（promotion）决定。

> 核心原则："智能体自有"（agent-owned）指的是身体的生命周期角色，人类保管人保留占有权与最终权威。

### 2.2 三种核心操作

1. **演化（evolve）**：`evolve(𝐵, 𝑐) → 𝐵'` —— 从上下文或压力 𝑐 产生候选身体变更；必须经过配置的验证（validation）和晋升流程后，𝐵' 才成为权威版本。
2. **派生（descend）**：`descend(𝐵, 𝑚) → (𝐵𝑑, 𝑆𝑑)` —— 创建具有独立身份、使命 𝑚、版本历史和全新私有状态边界 𝑆𝑑 的后代身体。
3. **转移（transfer）**：`transfer(𝐵𝑝, 𝐵𝑑, Δ) → 𝐵'𝑑` —— 后代在保持独立历史的前提下，检查并局部适配来自父代或同伴的选定变更 Δ。

### 2.3 六个设计原则

1. **保管与连续性**：用户可占有和迁移身体与状态，身份不绑定于某个模型调用或提供商。
2. **身体级个性化**：代码、提示词、工具、技能、策略、测试和演化机制皆可变，而非仅记忆层面。
3. **可复现的派生**：具名源生成可运行后代，具有明确的身份、谱系和继承的回归测试契约。
4. **独立专业化**：后代演化不强制与父代或中央模板同步。
5. **可问责的变更**：每个候选变更记录请求、差异（diff）、验证结果、版本和晋升决定。
6. **人类治理**：使命、秘密、外部权限、部署和晋升均受人类策略与授权约束。

### 2.4 实现机制

**仓库即身体**：智能体身体由独立的版本化仓库（repository）表示，包含机器可读身份与使命、运行时与通信接口、模型推理与记忆适配器、技能与策略、配置模式（不含私密值）、测试与诊断检查、以及更新/继承/学习/演化代码。

**Genesis 创建引擎**的派生流程（6 步）：
1. 验证干净的已跟踪祖先，记录完整提交标识符，解析清单与锁定依赖；
2. 复制身份特定工件，同时转换包路径和身份相关文本，保留不可变依赖引用；
3. 写入新身份、使命、世代和不可变的直接父代来源信息；
4. 初始化并暂存独立仓库；
5. 解析依赖、运行继承的测试套件，失败或脏验证则拒绝出生；
6. 验证通过后才创建出生提交，并在元数据提交中记录完整标识符。

**受治理的自我演化**：Enoch 支持六种演化来源——用户显式请求、人类反馈、协同工作经验、直接父代继承、跨智能体学习、LLM 头脑风暴。生命周期通过 Git 分支、提交、GitHub Pull Request 和独立工作树（worktree）实现：隔离工作 → 修改身体 → 运行验证 → 发布供审查 → 人类决定是否合并。失败或拒绝的变更不改变权威身体；若更新后健康检查失败则回滚到前一版本。

**继承 vs. 学习**：继承（inheritance）是选择性拉取式的——后代主动询问直接父代的近期变更候选，通过自己的分支、测试和审查进行适配，父代不推送变更；学习（learning）是从任意可信智能体导入已发布的技能，但明确是横向适配而非祖先关系。

## 6. 主要结论与发现

1. **智能体自有软件身体是可行的连续性载体**：通过 Genesis 创建引擎和 Enoch 参考智能体，证明了身份承载、可检查、可版本化的身体可以作为个人智能体的具体延续单位。
2. **递归派生可复现**：兼容后代可以继续产生后代（三次派生验证），使一个种子智能体成为专业化家族的根，而非每次从中央模板重新生成。
3. **受治理的自我演化可执行**：Enoch 展示了六源演化输入、隔离工作树、验证门、可审查变更记录、人类控制合并和失败更新回滚的完整生命周期。
4. **身体/状态/推理器分离有效**：记忆与凭据维持为私有状态、模型推理保持可替换，身份由身体承载而非模型绑定。
5. **后分化选择性转移可行但未完全验证**：直接父代继承与同伴学习的概念区分已实现，但完整的端到端适配流程"部分完成"（partial），尚未进行受控实验。
6. **长期方向**：个人智能体生态系统——一个人拥有多个不同使命、技能、权限和私有状态边界的身体，共享祖先降低创建成本，独立历史保留专业化。

## 7. 优点

- **概念清晰、边界严谨**：身体（可继承）/私有状态（不可继承）/外部推理器（可替换）/人类保管人（最高权威）的四元划分干净利落，避免了常见智能体系统中"记忆即身份"或"模型即身份"的混淆。
- **将"拥有"落到实处**：身体以真实 Git 仓库实现，用户可占有、检查、移动、分支、合并，将抽象的"拥有智能体"转化为具体的版本控制操作。
- **单一体上的演化和派生统一**：同一身体既支持演化（自我修改）又支持派生（产生后代），机制简洁而统一。
- **人类治理嵌入架构**：晋升（merge）权限始终由人类控制，候选变更全流程可审计（请求→diff→验证→版本→决定），而非让智能体自行修改生产代码。
- **区分继承与学习的语义**：继承按谱系拉取父代变更，学习从任意同伴导入技能，两种机制均需经接收方自身验证，避免了无差异的代码合并和"类继承式"的强耦合。
- **可复现的证据**：论文提供冻结版本、不可变提交标识符、可重跑的命令行验证流程，体现了良好的工程严谨性。
- **诚实的局限声明**：明确区分"已证明"与"部分完成"，不夸大数据支撑范围。

## 8. 不足与局限

- **谱系规模有限**：仅一条线性谱系（4 智能体、3 次派生），无兄弟分支、无群体规模演化、无多样开发团队参与，无法证明架构在更复杂谱系树下的可扩展性。
- **测试环境真实性不足**：大多使用 mock 服务，未验证长期运行的可靠性、真实外部服务接入的稳定性、提案质量、专业化质量的优劣或人类审查负担的合理性。
- **语义安全未验证**：没有评估智能体演化后的行为安全性和语义正确性；Genesis 使用边界感知的字符串替换而非语言特定解析器，无法保证每个转换后的文件语义正确。
- **后分化转移未完整验证**：从发现到适配再到采纳的完整后分化转移流程标记为"部分完成"，无受控端到端实验。
- **推理器替换的行为连续性未测量**：替换模型后，智能体行为是否保持一致缺乏实证。
- **安全边界薄弱**：可写执行器具有比生产环境突变沙箱更广泛的文件系统权限；任务、演化和谱系记录不具备防篡改（tamper-evident）特性；受保护范围检查是程序性而非语义性保证。
- **平台依赖假设**：谱系发现和跨智能体技能查找依赖 GitHub 托管仓库和 OurArk 命名约定；Git 本身并非架构必需，但当前实现绑定了 Forge 生态。
