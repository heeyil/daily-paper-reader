## 摘要
长时程工具使用智能体必须对用户目标、领域策略、工具调用、模拟器状态以及延迟的可验证奖励进行推理。强化学习（RL）天然适合这种场景，但多轮在线策略展开会形成长上下文，而特定于模型的注意力层可能需要自定义掩码和学习的汇聚归一化。我们提出了SINKFLEX-RL，一个用于双控制工具使用环境中强化学习的模块化训练系统。该系统结合了兼容Gymnasium的环境包装器、VERL风格的数据流展开、无需单独价值模型的组相对策略优化，以及一个汇聚感知的FlexAttention路径，旨在在因果和滑动窗口掩码下保持模型特定的汇聚缩放。在初步的Tau2Bench零售实验中，验证奖励（mean@1）从训练早期的0.25上升到观测训练窗口后期的0.44，同时训练分数和轨迹奖励代理指标也呈上升趋势。在固定配置的内存基准测试中，优化后的注意力路径在4096个token时将峰值VRAM从28.06GB降至22.52GB，减少了19.7%，并且以25.53GB运行了测量到的8192个token配置，而急切基线则内存不足。这些结果说明了整合环境接口、RL数据流和注意力内核设计对于内存可行的长时程智能体训练的价值。

## Abstract
Long-horizon tool-using agents must reason over user goals, domain policies, tool calls, simulator state, and delayed verifiable rewards. Reinforcement learning (RL) is a natural fit for this setting, but multi-turn on-policy rollouts create long contexts, while model-specific attention layers may require custom masks and learned sink normalization. We present SINKFLEX-RL, a modular training system for RL in dual-control tool-use environments. The system combines a Gymnasium-compatible environment wrapper, a VERL-style rollout dataflow, group-relative policy optimization without a separate value model, and a sink-aware FlexAttention path designed to preserve model-specific sink scaling under causal and sliding-window masks. In a preliminary Tau2Bench retail run, validation reward (mean@1) rises from 0.25 early in training to $0.44$ later in the observed training window, while training-score and trajectory-reward proxies also trend upward. In a fixed-configuration memory benchmark, the optimized attention path reduces peak VRAM from 28.06GB to 22.52GB at 4096 tokens, a $19.7\%$ reduction, and runs the measured 8192-token configuration using $25.53$~GB where the eager baseline runs out of memory. These results illustrate the value of integrating environment interfaces, RL dataflow, and attention-kernel design for memory-feasible long-horizon agent training.

## 2. 方法论：核心思想、关键技术细节与流程
论文提出了 **SINKFLEX-RL** 模块化训练系统，包含四个核心组件：

### 2.1 环境包装器（Environment Wrapper）
- 将双控制（dual-control）工具使用环境封装为 **Gymnasium 兼容的 reset/step 接口**。
- 每次 reset 采样任务并初始化共享状态；每次 step 将模型输出路由到三类处理程序：自然语言回复、工具调用、终止信号。
- 环境包装器同时推进用户模拟器与状态后端，返回下一观测和奖励元数据，使训练器与基准特定的实现细节解耦。

### 2.2 Rollout 数据流（VERL 风格）
- rollout worker 负责智能体循环：格式化观测 → 从当前策略 πθ 采样 → 解析动作 → 将转移追加到轨迹缓冲 → 直到终止或达到最大回合数。
- 训练器接收 token 级对数概率、动作掩码、轨迹奖励和回合元数据，不直接依赖基准解析逻辑。

### 2.3 策略更新：GRPO（无独立价值模型）
- 采用 **组相对策略优化（GRPO）**，避免训练单独的价值/评论家网络，节省内存和计算。
- 对每个采样组 G 个轨迹，计算组归一化优势：
  \[
  \hat{A}_i = \frac{R_i - \mu(R_{1:G})}{\sigma(R_{1:G}) + \epsilon_A}
  \]
- 对每个 token 计算重要性采样比率并做裁剪：
  \[
  \rho_{i,t}(\theta) = \frac{\pi_\theta(y_{i,t} \mid x, y_{i,<t})}{\pi_{\theta_{\text{old}}}(y_{i,t} \mid x, y_{i,<t})}
  \]
  \[
  \bar{\rho}_{i,t}(\theta) = \operatorname{clip}(\rho_{i,t}(\theta), 1-\epsilon_c, 1+\epsilon_c)
  \]
- 损失函数为：
  \[
  J_{i,t}(\theta) = \min\left(\rho_{i,t}(\theta)\hat{A}_i,\ \bar{\rho}_{i,t}(\theta)\hat{A}_i\right)
  \]
  \[
  \mathcal{L}_{\text{GRPO}}(\theta) = -\frac{1}{\sum_i T_i} \sum_{i=1}^{G} \sum_{t=1}^{T_i} J_{i,t}(\theta) + \beta D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})
  \]

### 2.4 汇聚感知的 FlexAttention 路径（Sink-Aware FlexAttention）
- **动机**：模型可能使用学习到的 attention sink 机制，但显式物化 sink token 会额外消耗内存。论文证明**零值 sink 的代数等价性**：
  - 设 sink 的 value 向量为 0，则显式 sink 的注意力输出等价于标准注意力输出乘以一个缩放因子：
  \[
  O_{\text{sink}} = \alpha_{\text{sink}} O_{\text{std}}, \quad \alpha_{\text{sink}} = \sigma(\ell - s_\eta)
  \]
  其中 \(\ell = \log\sum_i \exp(q \cdot k_i)\)（log-sum-exp），\(s_\eta\) 为学习到的 sink logit。
- **实现方式**：
  - 使用 PyTorch FlexAttention 作为可编程注意力底层，掩码函数组合因果掩码、滑动窗口掩码和始终可见的前缀：
    \[
    M_{b,h,q,k} = 1[k \le q] \land 1[q - k \le w \lor k < p]
    \]
  - 注意力调用返回输出 \(z\) 和辅助统计量 log-sum-exp \(\ell\)，然后应用 sink 缩放：
    \[
    z' = z \odot f_\eta(\ell), \quad f_\eta(\ell) = \sigma(\ell - s_\eta)
    \]
  - 通过 `torch.compile` + AOTAutograd 实现端到端的前向/反向编译，避免物化 O(n²) Jacobian。
- **内存优化**：
  - 使用 `torch.compile` 融合点运算，减少中间张量。
  - 掩码元数据在 batch 和 head 维度上广播，避免重复存储块稀疏掩码。
