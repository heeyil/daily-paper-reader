## 摘要
基于大型语言模型（LLM）的搜索智能体通过与外部环境的多轮交互来回答问题。然而，将完整的执行轨迹提供给LLM会导致上下文无界增长并引入噪声。现有压缩方法在减少上下文时会丢失重要细节，且常常在没有修复由错误事实衍生的下游推理的情况下替换错误事实。为解决这一问题，我们提出ReTree，一种用于搜索智能体的自我修正树状存储机制。ReTree构建有界的单步推理上下文，同时保留来源链接的证据。它将搜索建模为证据树，其节点存储有界摘要、证据和修正历史。当新检索到的证据与较早的声明矛盾时，ReTree回退到引入该声明的节点，替换过时证据，重新生成摘要，修剪受影响的枝干，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并确保最终声明可追溯至检索到的段落。在四个公开的问答和搜索基准上的实验表明，ReTree始终优于完整轨迹ReAct，将答案准确率提升高达25.6个百分点（pp）；完整轨迹ReAct的平均最大单步推理上下文是ReTree的$1.27$--$1.51$倍。这些结果确立了ReTree作为长时程搜索的一种有效自我修正存储抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

### 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：基于大型语言模型（LLM）的搜索智能体需要通过多步与外部环境的交互来回答复杂问题，但存在两个相互交织的严重缺陷：
  - **上下文无界增长**：将完整执行轨迹全部输入给 LLM，会导致每一步的推理上下文随搜索深度无限膨胀，既消耗大量 token，又引入噪声干扰。
  - **错误级联传播**：一次检索可能引入错误或过时信息，后续查询与中间结论都基于当前状态，导致错误沿着搜索轨迹逐级放大，形成“错误级联”。
- **现有方法不足**：已有的压缩方法（如滚动摘要、报告式压缩）虽然能控制上下文长度，但会丢失关键细节，尤其无法保留事实与来源之间的关联；更关键的是，它们只替换错误事实本身，却不会修复由该错误事实推导出的下游结论。
- **整体含义**：可靠的搜索记忆不仅需要有界上下文，还必须具备**证据可溯源**（claim-to-source provenance）和**依赖一致性修正**（dependency-consistent revision）的能力，即当证据改变时，能够识别并修复所有依赖该证据的下游状态。

### 2. 方法论：核心思想、关键技术细节、公式或算法流程
- **核心思想**：将搜索过程建模为一棵**证据树**（evidence tree），通过树形结构的记忆存储来同时满足三个需求：有界上下文、证据溯源、依赖一致的修正。借鉴了真值维护系统（Truth Maintenance System）中“改变依据应使依赖结论失效”的原则。
- **证据树结构**：每个节点 n = (sₙ, Eₙ, Hₙ, pₙ)，其中：
  - sₙ：紧凑的任务状态摘要（≤140词），记录已解决/待解决的槽位。
  - Eₙ：该节点本地引入的原子证据，每条证据包含可稳定 ID 和来源 URL。
  - Hₙ：修订历史记录。
  - pₙ：指向父节点的指针。
  - 节点路径上的证据联合构成该节点的累积证据 A(n)。
- **有界上下文构造**：策略每步只看当前节点的摘要 + 与问题和摘要最相关的 top-k（k=5）条证据，即 Cₖ(Mₜ, q) = sₙₜ ∥ TopKₖ(A(nₜ), q ∥ sₙₜ)。这使得每步推理上下文为 O(1)，不随轨迹长度增长。
- **证据提取与来源绑定**：每次检索返回最多5个段落，提取器输出最多6条原子事实，通过**段落索引**而非让模型复述 URL 来绑定来源，避免引用不可验证的问题。
- **冲突触发的回溯修正**（核心机制）：
  1. **冲突检测**：新证据与现存的 top-k 最相关证据比较，仅在“同一实体、同一属性、同一范围、同一时间”下出现不兼容值时才提出冲突。
  2. **修订确认**：第二次调用综合分支摘要、目标证据的变更历史等，防止在先前被拒绝的值之间反复震荡。
  3. **依赖修正**：确认冲突后，定位引入被反驳证据的节点 ι(j)，替换证据文本和来源，追加修订记录，仅从修正后的累积证据重新生成该节点摘要，**剪除该节点的所有后代**，然后从该修复节点恢复搜索。
- **关键公式**：
  - 问题形式化：aₜ ∼ π_θ(· | q, Cₖ(Mₜ₋₁, q))，新的证据集 ΔEₜ = {eⱼ = (j, xⱼ, uⱼ)}，记忆更新 Mₜ = U(Mₜ₋₁, ΔEₜ)。
  - 依赖一致性条件：Depₜ₋₁(j) ⊆ Iₜ ∪ Gₜ(e′ⱼ)，即所有依赖被修订证据的状态必须被失效或重新生成。
- **最终回答生成**：生成器将推理拆分为原子声明，每个声明分配一个或多个证据 ID，通过“声明 → 证据ID → 当前证据文本/URL → 原始段落”的解析链实现真正的段落级归因。

### 6. 主要结论与发现
- **准确率显著提升**：ReTree 在全部 4 个数据集上优于 Full-Trajectory ReAct，Judge Accuracy 提升 8.3–25.6 pp；综合 2,149 问，整体准确率 44.0%，较 Full-Trajectory ReAct 高 13.9 pp，EM 高 7.4 pp。
- **优于所有有界基线**：ReTree 在每个数据集上比 FlatUpdate 高 2.2–4.7 pp；除 2Wiki 上差 0.3 pp 外，其余数据集上均优于 ReportMemory（高 1.7–7.2 pp）；总体上比最强聚合基线 ReportMemory 高 3.0 pp。
- **上下文长度大幅下降**：Full-Trajectory ReAct 的平均最大每步上下文是 ReTree 的 **1.27–1.51 倍**；Full-Trajectory ReAct 呈现无界增长，而 ReTree 保持稳定有界。
- **归因质量领先**：ReTree 在 Citation Precision/Recall 上为 44.5/41.3，显著高于 Full ReAct（37.7/27.1）和 ReportMemory（16.8/21.4）。ReportMemory 的 Uncited Rate 最低（5.9%），但其引用段落对声明的支撑率很差——这揭示出“看似大量引用但实际不可靠”的缺陷。
- **自然回溯确实发生**：9.6%–17.5% 的 ReTree 运行中触发了回溯修正，说明真实搜索确实会引入冲突证据，验证了状态修复机制的必要性。
- **代价可控**：ReTree 相比 FlatUpdate 仅多出 7–11% 的模型调用和 10–13% 的 token 消耗。

### 7. 优点
- **问题建模精准**：将检索错误传播形式化为“结构化状态修复问题”，并给出精确的数学定义（依赖一致性条件），理论框架清晰。
- **机制设计精妙**：结合真值维护系统思想，利用祖先关系作为依赖的保守近似实现子树剪枝，在修复安全性和实现复杂度之间取得务实平衡。
- **来源绑定可靠**：通过段落索引绑定来源，而非让模型生成 URL，有效避免了引文不可验证的常见陷阱；最终的“声明→证据ID→URL→原始段落”解析链实现了真正的段落级归因。
- **冲突判定审慎**：仅在“同实体、同属性、同范围、同时间”下判定冲突，并提供修订历史确认机制防止振荡，降低了误判风险。
- **评估全面且公平**：设置 FlatUpdate 作为机制匹配的消融对照，精确隔离了树形依赖修正的贡献；同时从答案质量、归因质量、上下文消耗、计算开销四个维度评估，视角完整。

### 8. 不足与局限
- **硬剪枝过度失效**：将节点的所有后代都视为依赖者，实际可能包含与修正前提无关的有效状态，导致有用状态被过度失效，需要额外检索来弥补。
- **冲突裁判是瓶颈**：修正质量受限于冲突检测器，假阴性保留污染，假阳性过度剪枝，虽有同范围和历史确认规则抑制，但无法消除。
- **外部存储持续增长**：有界的是单步推理上下文，而非总记忆量；证据存储和线性检索在大规模长时程搜索中仍会变慢。
- **计算开销**：结构修复涉及多次额外 LLM 调用（冲突确认、摘要重建、搜索恢复），token 和调用数相对 FlatUpdate 增加约 10%。
- **应用边界**：ReTree 是搜索工作记忆，不适用于需要无限制回忆所有历史陈述的任务。
- **评估局限**：仅使用单一骨干模型（Qwen3-8B），缺乏多模型泛化；归因诊断仅在一个 FRAMES 子集上进行；缺少与向量索引、缓存等技术结合后的性能分析；冲突检测器、修订确认机制的单独消融实验不足。
