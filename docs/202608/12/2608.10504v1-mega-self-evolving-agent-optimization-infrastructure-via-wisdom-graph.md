## 摘要
随着编码智能体日益承担实现任务，核心挑战从构建单个智能体转向构建能够系统化改进它们的基础设施。现有方法要么在不积累可迁移知识的情况下优化智能体系统，要么积累知识但缺乏对其的组合推理，并且缺少让这些知识通过运行证据自我进化的机制。MEGA（元评估接地适应）作为一种自进化基础设施填补了这些空白：每个优化周期都会产生持久资产，对这些资产的组合推理指导后续优化，运行证据则同时改进积累的智慧及其治理推理。第一层通过行为模式聚类和经验性A/B验证从智能体会话中提炼可复用智慧，将每个过程转化为持久资产。第二层将这些资产分解为类型化智慧图内的原子PCR（主因-上下文-结果）单元，并进行演绎、溯因和归纳推理以扩展隐式关系；随后通过组合检索组装上下文特定的执行计划，这种检索能浮现仅靠嵌入相似性无法触及的桥接知识。第三层在异构智能体工作流（代码节点、LLM调用和使用工具的智能体）上执行多智能体协作优化，通过消除数据方差的受控评估将改进效果归因于具体的策略变更。来自第三层的反馈证据驱动治理智慧组合的策展策略以及跨运行积累的优化轨迹的自我进化。结果是，在该基础设施中，优化智能体系统与进化指导优化的知识是同一个过程。

## Abstract
As coding agents increasingly handle implementation, the central challenge shifts from building individual agents to building an infrastructure that systematically improves them. Current approaches optimize agent systems without accumulating transferable knowledge, accumulate knowledge without compositional reasoning over it, and lack a mechanism for that knowledge to self-evolve through operational evidence. MEGA (Meta Evaluation-Grounded Adaptation) addresses these gaps as a self-evolving infrastructure: each optimization cycle produces durable assets, compositional reasoning over those assets guides subsequent optimization, and operational evidence refines both the accumulated wisdom and the reasoning that governs it. Layer 1 distills reusable wisdom from agent sessions through behavioral-pattern clustering and empirical A/B validation, transforming each process into a durable asset. Layer 2 decomposes these assets into atomic PCR (Primary-Context-Resultant) units within a typed Wisdom Graph and performs deductive, abductive, and inductive reasoning to expand implicit relations; it then assembles context-specific execution plans through compositional retrieval that surfaces bridging knowledge unreachable by embedding similarity alone. Layer 3 performs multi-agent collaborative optimization over heterogeneous agent workflows (code nodes, LLM calls, and tool-using agents), attributing improvement effects to specific strategy changes through controlled evaluation that eliminates data variance. Evidence fed back from Layer 3 drives the self-evolution of both the curation strategies that govern wisdom composition and the optimization trajectories accumulated across runs. The result is an infrastructure in which optimizing an agent system and evolving the knowledge that guides optimization are one and the same process.

## 1. 核心问题与整体含义（研究动机和背景）

随着编码智能体日益承担实际的软件实现任务，研究界的核心挑战已从"能否构建一个会编码的智能体"转向"是否存在一套能系统化、可重复地改进智能体系统的**基础设施**"。作者指出，当前智能体开发自动化领域存在三个结构性的根本缺陷，且从未被统一到单一基础设施中：

1. **优化不积累知识，存储也不等于推理**：现有优化工具（如 GEPA、DSPy、AFlow、Flow）能在单项目内显著提升系统性能，但成功的优化背后"何种策略在何种条件下有效"这一关键理性认知（rationale）未被结构化、不可跨项目迁移。新项目开始时，策略搜索完全从零重启。即使加入内存层（如 Reflexion、ACE、ReasoningBank）也无法解决，因为问题不在于缺乏存储，而在于**缺乏对存储内容的组合推理**。

2. **存储的知识缺乏组合推理能力**：技能库（Voyager、Memento-Skills）存储程序性知识，却无法推理"该组合哪些技能、以什么顺序、在什么条件下使用"。现有的技能编排框架（AgentSkillOS、SkillNet）通过层级树和类型化关系图部分解决了这个问题，但**组合单元仍是完整的技能块**——不将复合技能分解为原子子单元，也不通过逻辑推理发现隐式关系。Press 等人形式化了这一"组合性鸿沟"（compositionality gap）：模型能解决子问题却无法组合它们，且此鸿沟不随模型规模扩大而缩小。

3. **未经运行验证的知识无法自我改进**：即使实现了组合推理，未经实际操作结果检验的知识仍是悬空的。缺乏反馈闭环的话，未经验证和过时的知识会与有效知识混杂积累，检索质量逐步退化。

MEGA 的核心理念是：构建一种**自进化基础设施**，使每条优化周期都产生可迁移的持久资产，对这些资产的组合推理指导后续优化，而运行证据又反过来精炼知识库和治理推理的策略本身。最终图景是：**优化智能体系统与进化指导优化的知识成为同一个过程**，跨项目积累使新项目从历史验证过的基线出发，而非从零开始。

## 2. 方法论：核心思想、关键技术细节与算法流程

MEGA 采用三层闭环架构，其整体循环可形式化为：

```
W(t) = L1(T(t) ∪ T3(t−1)),  Π(t) = L2(W(t), E(t−1)),  E(t), T3(t) = L3(Π(t))
```

其中 t 为外循环索引，E(0)=∅，T3(0)=∅。三层分别如下。

### 2.1 第 1 层：基于会话的智慧生成（Session-based Wisdom Generation）

- **隐私保护过滤**：在客户端侧完成敏感信息掩码与路径匿名化，确保进入管线的数据已净化。
- **两阶段聚类**：
  - 阶段 1（领域预聚类）：基于嵌入相似度的贪心分配，领域从数据中自动涌现而非预定义；
  - 阶段 2（行为模式发现）：在各领域簇内应用 **BIRCH** 算法，以 CF 聚类特征元组 `CF=(N, LS, SS)` 表示子簇，利用其可加性实现单遍 O(n) 处理。通过半径阈值 T 判断新样本归入现有子簇或创建新子簇（簇数自适应，无需预设 k）。
- **LLM 合成与结构化**：将行为模式合成为结构化智慧（技能/策略），提取通用模式并明确异常条件。
- **多级质量门控**：
  - *结构过滤*：哈希去重（O(n)）、LLM 冲突检测与消解、跨轮嵌入相似度去重；
  - *自评估打分*：对文档事实性、可计数性质（如命令/代码示例支撑的规则比例）加权调和平均，防止自评膨胀；
  - *行为 A/B 验证*：对每个候选智慧生成测试用例，在"注入智慧"（处理组）与"基线"（对照组）条件下并行执行，测量**性能提升**与**token 效率**两个 ROI 轴——验证标准是可观察的行为变化而非主观质量判断。

### 2.2 第 2 层：智慧推理与策展（Wisdom Reasoning and Curation）

- **安全网关**：所有资产进入图前，筛查指令级威胁（prompt 注入、工作流劫持）和执行级威胁（数据外泄、破坏性命令）。
- **PCR 原子分解**：每个智慧资产被分解为原子三元组 `ω=(vP, vC, vR, m)`——Primary（核心动作）/Context（适用条件）/Resultant（预期结果）/Method（实现细节）。子技能间的前置依赖、互斥、条件分支、回退等逻辑关系被编码为类型化边。
- **角色流畅节点池**：同一节点可在不同三元组中充当不同角色（如在 A 中是 P，在 B 中是 C），使"Git 分支策略"这类概念既可作为动作也可作为前置条件，天然生成跨技能连接。
- **边评分**：每条边携带源自 Pearl 因果演算的**充分性/必要性双轴分数** `σ(e)=(S(e), N(e))∈[0,1]²`。
- **三种逻辑推理模式**（边集单调扩展，达不动点终止）：
  - *演绎*（传递因果推断）：由 P→C 且 C→R 推断 P→R，每跳乘性衰减分数，长链推断更保守；
  - *溯因*（反向因果推断）：P→R 与 C→R 同时存在且 C→R 必要性高时，推断隐式 P→C 关系，用贝叶斯后验估计置信度；
  - *归纳*（统计模式发现）：多个 Pₙ 同时连接同一 C 与 R 时，用**超几何检验**判断共现是否显著，仅通过则推断 C→R。
- **PCST 组合检索**：将查询相关的子图检索形式化为**带奖励收集的斯坦纳树（PCST)**问题：
  ```
  T* = argmax [Σ π(v;q) − Σ c(e)]
  ```
  奖励 π 与查询相关度成正比，成本 c 与因果弱度成正比。解中的非种子节点即为"桥接知识"——相似度低但连接多个种子节点的必要知识，这是嵌入检索无法发现的。由于所有智慧类型共存于同一图，PCST 执行异质类型的子图组装。
- **执行计划组装**：将推理子图转换为带执行序的计划 Π(q)——技能节点成为执行候选，策略节点成为门控规则，策展模式提供拓扑约束，轨迹提供探索/保守偏置。输出是角色分化的计划图而非 top-k 列表。
- **ROI 驱动的自我进化**：预测效用 `pi = τ(sim_i, stage_i) × η(ω_i)`（历史迁移率 × 饱和式证据置信度）；自适应门控（冷启动宽松、温启动 LCB 约束）；四轴复合评分（相似度、证据强度、阶段适配、基准）；组合级强化（高频高质量组合被提升为策展策略）；内容级进化（修订建议累积超阈值触发更新）；离线模式合并（批量压缩为最佳实践模板）。
- **图形维护**：PCR 级去重、矛盾消解（极性分析→保留强证据变体或转为上下文受限判断）、证据触发的内容更新（过期接口检测、定向补丁）。

### 2.3 第 3 层：评估驱动的多智能体优化

- **优化范围**：与仅优化 prompt 的传统方法不同，Layer 3 将工作流建模为异构图 `A=(N,E)`，节点类型包括：确定性代码节点、单一 LLM 调用、使用工具的智能体节点（多轮推理+工具调用+上下文管理）。优化目标是完整元组（prompt、工具配置、代码逻辑、编排结构）。
- **Adapt 管线**：资产扫描 → 自适应入口 → 条件式研究智能体（缺评估数据/代码时调用）→ 反向 PRD 重建 + 数据合成（分类-难度矩阵、种子场景人工审批、并行生成分层训练/验证集）→ 共享优化循环 → 元学习智能体（提取优化轨迹写入 Layer 2）。
- **多智能体协作**：十多种专业智能体，核心原则是"集中式决策 + 专业化执行"——中央优化智能体直接诊断、假设、执行、测量，科学家/代码审查者/重构智能体负责有界任务。代码审查者执行静态分析和试运行验证（dry-run），防止运行时错误浪费评估预算。
- **数据感知优化**：基线评估后，按评估结构分类（离散检查器/规则评分/连续指标），对每个维度评估密度-多样性-基线性能三维，区分"数据缺口"与"工作流问题"——后者无法通过增广解决。仅针对真实缺口生成目标合成数据（上限 50% 混合比例）。
- **Seed-Epoch 归因纪律**：同一 epoch 内所有迭代在固定种子 ξₑ 确定的同一评估集上评估：
  ```
  ∆i = Acc(De, v_i) − Acc(De, v_{i−1})
  ```
  由于数据不变，∆ 归因于策略变更而非数据采样方差。连续 m 次 |∆|<ε 判定饱和，换新种子推进 epoch——新数据天然验证策略是否过拟合旧 epoch。验证调度采用动量触发策略（基线点、epoch 边界、回归恢复/新最佳时刻）。
- **三类过拟合防护**：反启发式强制（仅允许结构化转换如 JSON 解析、编码规范化，禁止内容感知正则和查找表）；过拟合检测（训练-验证差距超过阈值时限制仅 prompt 优化）；基于可修复性分布的目标校准（prompt 可修复高估、代码可修复中估、架构级缺陷设硬上限）。
- **跨层反馈**：每次优化产生"判定"（verdict）三元组(Δacc, Δlat, Δtok)回喂 Layer 2，更新智慧证据置信度 η(ω) 和迁移率 τ(·)——不将"好智慧"视为绝对类别，而是累积**依上下文条件验证的智慧**。

## 5. 实验数量与充分性

**实验数量**：两大实验（策展质量、优化性能），共 5 个 benchmark（SkillsBench + 4 个优化基准）。无显式消融实验（如仅去 PCST、仅去 Seed-Epoch、仅去行为 A/B 验证的逐级消融）。

**充分性与客观性评估**：

- **正面**：实验一控制严格——同一智能体/技能池/任务/验证器/LLM，唯一变量是策展方法，结果反映端到端管线（检索+策展联合测量），且公开了代码仓库（github.com/mega-edo/mega_benchmark）便于复现。
- **局限**：
  1. 优化性能实验的基线分数**直接引自原文**而非本地复现，不同论文的实验环境、验证集大小和随机种子可能存在差异，对比的严格性存疑；
