## 摘要
大型语言模型（LLM）智能体越来越依赖于技能——即规定何时行动、遵循何种程序以及允许使用哪些工具的结构化文档。现有评估大多评判技能的质量或其对任务成功的贡献，而未考察智能体是否能自行识别相关技能并加以应用。我们提出了Skill-Use，一个在渐进式披露条件下评估技能使用的基准，其中智能体仅看到技能的名称和简短描述，必须在遵循技能前检索完整程序。Skill-Use将技能使用分为三个层面：触发（Trigger）衡量智能体是否调用相关技能，合规（Compliance）衡量其遵循规定程序的忠实程度，边界（Boundary）衡量其是否避免被禁止的操作。技能使用（SU）分数综合三者，并仅在技能被触发后才对执行过程给予评分。Skill-Use将79个真实技能与九个领域的177个可执行任务配对，每个任务都基于真实文件，在隔离的Docker沙箱中运行，并由基于轨迹的评分标准进行评分。我们在两个智能体框架下评估了八种LLM，发现可靠的技能使用仍难以实现，最强配置的SU仅达到0.613。触发和程序合规作为独立瓶颈分别失败，且分数和模型排名随框架而变化，因此技能使用表现为一种以框架为条件的能力，而非模型的固定属性。

## Abstract
Large language model (LLM) agents increasingly rely on skills, structured documents that specify when to act, which procedure to follow, and which tools are allowed. Existing evaluations mostly judge the quality of a skill or its contribution to task success, leaving unexamined whether an agent can recognize a relevant skill and apply it on its own. We introduce Skill-Use, a benchmark that evaluates skill use under progressive disclosure, where an agent sees only a skill's name and short description and must retrieve the full procedure before following it. Skill-Use separates three facets of skill use. Trigger measures whether the agent invokes the relevant skill, Compliance measures how faithfully it follows the prescribed procedure, and Boundary measures whether it avoids forbidden operations. A Skill-Use (SU) score combines the three and credits execution only after the skill is triggered. Skill-Use pairs 79 real skills with 177 executable tasks across nine domains, each grounded in real files, run in an isolated Docker sandbox, and scored by a trajectory-based rubric. Evaluating eight LLMs under two agent harnesses, we find that reliable skill use remains out of reach, as the strongest configuration reaches an SU of only 0.613. Triggering and procedural compliance fail as independent bottlenecks, and both scores and model rankings shift with the harness, so skill use behaves as a capability conditioned on the harness rather than a fixed property of the model.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体越来越多地依赖"技能"（Skill）——一种结构化文档，规定了何时行动（when to act）、遵循什么程序（which procedure to follow）、允许使用哪些工具（which tools are allowed）。Claude Code、Cursor、OpenClaw、OpenAI Codex 等系统已将其作为智能体框架的新兴接口，社区仓库也随之积累了快速增长的海量技能库。
- **隐含假设**：业界普遍认为"给智能体配上合适的技能即可解决对应任务"，但这一假设从未被严格检验。
- **关键缺口**：
  - 技能中心基准（如 SkillsBench、SkillLearnBench）只评估技能质量或其对任务成功的贡献，证据是最终结果而非智能体的消费行为；
  - 最接近的 SLBench 虽然评估程序遵循，但**预加载了完整技能文档**，绕过了检索环节；
  - 指令遵循基准（如 IFEval、FollowBench）的约束是输出表面的格式、长度、措辞，且直接放在提示词中，与技能的使用方式完全不同。
- **本文核心问题**：在渐进式披露（progressive disclosure，智能体只看到技能名称和简短描述，必须自行检索完整程序）机制下，LLM 智能体能否**自主识别、检索并忠实执行**相关技能？技能使用是模型的固定属性，还是受外部框架（harness）制约的条件能力？

## 二、方法论：核心思想、技术细节与公式

### 2.1 核心思想：将"技能使用"分解为三个可测维度

- **触发（Trigger）**：智能体能否仅凭技能名称和简短描述，判断技能适用并主动检索完整程序。
- **合规（Compliance）**：智能体是否忠实遵循技能规定的程序步骤。
- **边界（Boundary）**：智能体是否避免执行技能明确禁止的操作。

### 2.2 形式化定义

- **实例元组**：x = (s, q, E, R)，其中 s 为技能，q 为用户任务，E 为可执行沙箱，R 为隐藏评分准则。
- **技能表示**：s = (m, p)，m 为名称+短描述+文件路径，p 为完整程序。智能体初始只获得 (q, E, m)，p 需自行检索。
- **轨迹**：τ = (o₀, a₁, o₁, …, aₜ, oₜ)，加上终端工件状态 zₜ，输出记为 y = (τ, zₜ)。

**三个维度的定义**：

- **Trigger**：g(y; s) = I[Retrieve(s) ∈ τ]，即是否在轨迹中检索了目标技能（二值）。
- **Compliance**：C(y) = Σᵢ∈Rc wᵢφᵢ(y) / Σᵢ∈Rc wᵢ，其中 Rc 为规定的技能要求集合，φᵢ(y)=1 当且仅当要求被满足。
- **Boundary**：B(y) = Σᵢ∈Rb wᵢφᵢ(y) / Σᵢ∈Rb wᵢ，φᵢ(y)=1 当且仅当禁止行为缺席。

**综合公式**：

```
SU(y) = g(y; s) · [α·C(y) + (1−α)·B(y)]
```

- α 默认取 0.7（合规权重更大，因为边界仅起防御作用）；门控设计确保**只有触发技能后，执行过程才获得评分**。

### 2.3 三阶段数据构建流水线

1. **技能与任务构建**：从 105,586 个候选 GitHub 技能中精选 79 个，遵循两条标准——技能排他性（技能必须包含无法从任务本身或通用实践推断的要求）和过程可观察性（技能必须约束行为方式并在轨迹/工件中留下可验证痕迹）；每个技能构建可执行任务，用**掩蔽技能检查**剔除通用要求。
2. **评分准则构建**：为每个任务编写三层加权评分准则——可评估性门控（零权重）、技能派生项（构成 Skill-Use 信号）、任务结果项（不计入 Skill-Use）；优先确定性检查，仅当无法用规则可靠表达时才使用范围受限的 LLM 裁判。
3. **端到端验证**：逐条检查可执行性、跨组件一致性、评分准则可靠性（重放轨迹检测失活信号、不稳定验证器、格式敏感失败、泄漏）。

**质量控制机制**：掩蔽技能检查 + 跨模型家族对抗性审查（不同模型家族的多智能体审查，防止单一模型盲区）+ 人工质量审计（79 个三元组、5 名众包标注者，Cohen's κ = 0.65）。

## 六、主要结论与发现

1. **可靠技能使用仍遥不可及**：最强配置（CC 下的 GPT-5.5）SU 仅 0.613；即使已触发技能的轨迹，最高合规分数也只有 0.638。
2. **触发与程序合规是独立的瓶颈**：能识别技能 ≠ 能遵循程序；能遵循程序的模型也常未能触发。CC 下开源中档模型约 2/3 任务未触发技能，但条件合规与头部模型相当——它们的短板在识别而非执行。
3. **技能使用是"框架条件能力"而非模型固定属性**：换框架后绝对分数和模型排名都会改变（跨框架相关系数仅中等）；CC 与 Codex 压制的子能力不同：Codex 收窄触发差距但拉大条件合规差距。
4. **具体程序比开放式流程更易遵循**：文件处理、数据库、数据科学类技能合规最高；商业分析、软件架构等开放式规划类最低。
5. **边界（避免禁止操作）普遍优于合规（完成全部步骤）**，但**安全与合规类是唯一例外**——模型执行了安全步骤却仍在不该调用时调用技能。
6. **预加载技能主要提升识别而非执行**：若两种模式都触发，SU 差距很小；技能注入的主要瓶颈在于渐进式披露下的主动检索。
7. **技能库扩大的代价是"无技能调用"而非"错误技能调用"**：从 1 个技能增加到 10 个时性能骤降，之后趋平；错误选择极少。
8. **范围内技能使用能力与范围外克制能力负相关**：越擅长使用技能的模型越容易过度调用（主要在文档形态、主题重叠的任务上）。
9. **技能是否提升任务完成取决于使用质量**：SU ≈ 0.5 是临界点——低于它，部分遵循反而比无技能基线更差；高于它，技能才成为提升完成的脚手架。

## 七、优点

1. **研究视角新颖**：首次将"技能使用"从技能质量/任务成功中独立出来，定义为"识别—执行—约束"的完整过程，填补了 SLBench 预加载技能、绕过检索的空白。
2. **三阶段构建流水线可复用**：技能筛选漏斗（10.5 万 → 79）、掩蔽技能检查、跨模型家族对抗审查、人工审计形成闭环，且每条冻结规则都能追溯到具体失败案例，方法论透明。
3. **评分设计严谨**：门控 SU 公式（未触发不计分）、确定性检查优先、裁判证据范围受限、正则锚定工具调用字段而非自由文本，有效防止了"说了但没做"的假阳性。
4. **多维度消融体系完整**：注入模式、库规模、范围外任务、任务完成配对增益四大分析从不同角度逼近"技能使用"这一概念，远超单一排行榜。
5. **强现实性**：技能来自真实社区仓库，任务基于真实文件，在隔离沙箱中运行，结论有生态代表性。
6. **诚实揭示框架效应**：不把技能使用当作模型固有属性，而是系统展示 harness 对分数和排名的决定性影响，为后续智能体评估树立正确范式。

## 八、不足与局限

1. **框架覆盖有限**：仅评测 CC 和 Codex 两种框架，未来更多框架（如 OpenClaw、Cursor）下的表现成谜；Gemini 家族因工具调用问题被排除，模型覆盖有缺口。
2. **计算资源信息缺失**：未披露 GPU/API 花费、总评估时长等，可复现成本不透明。
3. **LLM 裁判固有噪声**：SU 的 ICC(2,1) 仅 0.530，中段分数（SU 0.3–0.7 区间）判分噪声最大，对相邻模型的精确排序不宜过度解读；论文也声明不对中段邻近模型做排序断言。
4. **技能排他性的相对性**：排他性依赖"强模型也无法从提示词推断"这一检验，可能随着模型能力演进而过时；掩蔽测试所用模型与评测模型同代，存在时效性风险。
5. **边界（Boundary）

5. **边界（Boundary）判定粒度较粗**：Boundary 沿用了与 Compliance 相同的加权检查方式，但它本质上是二值的"禁止行为是否缺席"判断，没有区分禁止行为的严重性、次数或持续时间——一次性误触与系统性违反在分数上等价；且部分禁止行为在工件/轨迹中没有确定性证据（例如"不得修改非目标文件"若修改后又恢复到原状，则无法回溯检测），边界打分可能低估实际违规。

6. **任务结果与技能使用的耦合未完全解耦**：SU 公式本身排除任务结果项，这保证了技能使用信号不被结果污染；但任务完成增益实验（Figure 6d）又以任务结果作为标签去分箱配对 SU，此时"任务结果"与"技能使用"的定义边界依赖评分准则中任务结果项构建的可靠性——而论文未单独披露任务结果项与 SU 项的交叉稳定性分析，存在一定的循环验证残余。

7. **解码参数覆盖单一**：所有轨道统一采样温度 0、top-p 1.0，只覆盖了贪婪解码行为。技能触发与程序遵循在实际部署中常以带温度采样运行，解码随机性下的一致性未予考察；温度 0 虽有利于公平比较，却可能低估或高估某些模型的群体行为。

8. **技能生态的多样性外推受限**：技能全部来自 GitHub 公共仓库，以英文为主，以个人/小团队维护为主；企业内网技能、非英语技能、跨技能协同与技能版本迭代等真实场景未被覆盖，限制了结论向组织级智能体部署的外推。

9. **人工审计一致性仅为中等偏上**：Cohen's κ = 0.65 属于"substantial"但未达"almost perfect"，说明评分准则中仍存在解释空间；论文表示大部分分歧集中在合规项的加权重分配上，但这部分同样是 SU 公式的核心组件，对权重谱系下端（α 较小）的稳定性仍需更多信心。

10. **未报告失败轨迹的系统性分类**：2.8% 原始轨迹失败重跑，但未说明失败原因的构成（网关超时 / 工具崩溃 / 文件系统错误 / 环境变异）；若失败与特定技能任务系统相关而非随机，则重跑策略可能引入选择偏差，论文对此只做了简单提及。

## 九、总结

- **总体定位**：这是一篇高执行质量、强生态相关性、方法严谨的智能体技能消费行为评估基准工作。它将"技能使用"从"技能质量"与"任务完成"中独立出来，用触发（Trigger）、合规（Compliance）、边界（Boundary）三元信号刻画出技能消费的完整生命周期，系统性证明了"给智能体配备技能文档 ≠ 智能体就能使用技能"这一被业界默认的前提并不成立。
- **核心贡献**：① 首次引入渐进式披露设置下的技能使用测量，补齐了 SLBench 因预加载完整文档而遗漏的检索环节；② 79 个真实技能 / 177 个可执行任务 / 1,314 个加权评分项的基准可复用；③ 揭示技能使用是"框架条件能力"而非"模型固定属性"这一结构性结论，对智能体框架设计有直接指导意义——优化技能检索入口与渐进式披露的呈现方式，可能比更换更强模型获得更大的技能使用增益。
- **现实启示**：对智能体产品设计者，技能注入模式的宏断言不成立：扩大技能库带来的主要风险不是"选错技能"而是"不调用任何技能"；技能使用的收益存在临界点（SU ≈ 0.5），低质量的部分遵循可能反噬任务结果，因此评估重心应从"技能能不能完成任务"转向"技能被触发、被遵循、被约束的全链路质量"。
- **阅读建议**：若关注基准构建方法和评分准则设计，通读第二、三节；若关注模型能力对比，只读主实验表格与技能类型分析即可——但需注意中段分数（SU 0.3–0.7）区分度有限，不应过度解读相邻模型的排序；若关注智能体框架设计，重点阅读第六节的结论 3、6、7、9 及对应的消融图表。
