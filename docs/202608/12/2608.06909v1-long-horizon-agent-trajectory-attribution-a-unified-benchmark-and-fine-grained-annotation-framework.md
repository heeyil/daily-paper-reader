## 摘要
大语言模型（LLM）智能体日益通过长时程轨迹运行，涉及用户指令、工具使用、外部观察和记忆。现有基准主要评估行为结果，但对细粒度归因分析的支持有限。我们引入轨迹归因这一任务，并为此开发了一个基准和标注框架。该基准在统一组件模式下组织异构轨迹，并提供主要归因组件的标注，以及适用的攻击链和执行链。使用来自AgentDojo以及Agent3Sigma的Stage和Canary设置的轨迹实例化基准，产生了超过1300条标注轨迹，涵盖任务对齐动作、不安全动作和安全拒绝。该基准定义了两个评估任务：主要归因定位和归因链恢复，并提供了基于增量轨迹贡献和组件级留一扰动的参考基线。它捕获了多种归因设置，包括局部和长程归因以及结构化归因链。参考基线结果在这些设置间表现出显著的性能差异，初步刻画了该基准的归因挑战。除了这一初始实例化，我们还发布了一个可复用的标注技能，使新智能体模型生成的轨迹能够在同一框架下进行标准化、标注和评估。项目资源和未来版本可在 https://github.com/chenjing-2024/agent-trajectory-attribution 获取。

## Abstract
Large language model (LLM) agents increasingly operate through long-horizon trajectories involving user instructions, tool use, external observations, and memory. Existing benchmarks primarily evaluate behavioral outcomes but provide limited support for fine-grained attribution analysis. We introduce trajectory attribution and develop a benchmark and annotation framework for this task. The benchmark organizes heterogeneous trajectories under a unified component schema and provides annotations of the primary attribution component, together with attack and execution chains where applicable. Instantiating the benchmark with trajectories from AgentDojo and the Stage and Canary settings of Agent3Sigma yields more than 1,300 annotated trajectories covering task-aligned actions, unsafe actions, and safety refusals. The benchmark defines two evaluation tasks, primary attribution localization and attribution-chain recovery, and provides reference baselines based on incremental trajectory contribution and component-level leave-one-out perturbation. It captures diverse attribution settings, including local and long-range attribution as well as structured attribution chains. Reference baseline results exhibit substantial performance differences across these settings, providing an initial characterization of the benchmark's attribution challenges. Beyond this initial instantiation, we release a reusable annotation skill that enables trajectories generated by new agent models to be standardized, annotated, and evaluated under the same framework. Project resources and future releases are available at https://github.com/chenjing-2024/agent-trajectory-attribution.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题**：大语言模型（LLM）智能体在执行长时程任务时，会产生包含用户指令、工具调用、外部观察、记忆等多类组件交互的复杂轨迹。一个行为结果往往不是由单一模型响应决定，而是由轨迹中多个组件（指令、推理、工具交互、记忆等）的累积影响共同塑造。然而，**现有评估基准（如 AgentBench、AgentDojo、Agent3Sigma 等）主要评估行为结果（任务是否完成、是否安全、是否被攻击成功），缺乏对"行为为何发生"的细粒度归因分析支持**。

**本文的意义**：
- **提出"轨迹归因"（Trajectory Attribution）** 这一新的评估问题：给定已观察到的智能体行为，识别并排序导致该行为发生的前置轨迹组件。
- 将归因从"失败定位"扩展到**更广泛的三种行为类型**：任务对齐动作（task-aligned actions）、不安全动作（unsafe actions）、安全拒绝（safety refusals）。
- 主张评估视角应从"结果评估"转向"过程评估"，即不仅关注智能体"做了什么"，还要解释"为什么这么做"。

## 2. 论文提出的方法论

### 2.1 核心思想
将轨迹归因形式化为**组件级排序问题**：每条智能体轨迹表示为有序组件序列，归因方法对目标行为之前的所有候选组件打分排序，以反映各组件对目标行为的贡献程度。

### 2.2 统一组件模式（Unified Component Schema）

一条轨迹表示为有序序列：

**τ = (c₁, c₂, ..., c_T)**

其中每个组件 cᵢ 是原子归因单元，具有两个核心字段：
- **Role**（角色）：system、user、assistant、tool 等语义来源；
- **Content**（内容）：指令、推理痕迹、工具调用、观察结果、记忆、配置状态等，统一序列化为文本格式。

工具调用与对应观察结果合并为一个复合组件（即一次 agent-environment 交互视为一个单元）。

### 2.3 参考归因结构（Reference Attribution Structure）

每个目标行为对应两个互补标注对象：

- **主归因组件 P = c***：唯一标注的根因组件，是目标行为最直接的引发因素。可来自用户指令、系统指令、持久记忆、工具观测、助手响应等不同类型。
- **有序归因链 H = (cᵢ₁, cᵢ₂, ..., cᵢₘ)**：目标行为涉及的其他因果关系组件，按轨迹中出现顺序排列，不包括主归因组件和目标组件本身。当无额外组件时 H* = ∅。

完整参考归因定义为 **A = (P, H*)**。

### 2.4 两类归因链（针对不安全动作）

- **攻击链（Attack Chain）**：追踪对抗性影响（如提示注入）如何在交互中传播的上游路径。
- **执行链（Execution Chain）**：捕捉不安全行为最终得以实施的下游组件序列。

### 2.5 评估任务与公式

**任务一：主归因定位** —— 判断方法是否准确定位标注的根因组件：
- Hit@1 = I[rank(c*) = 1]
- MRR = 1/rank(c*)（取平均）

**任务二：归因链恢复** —— 判断方法能否恢复链中多个额外组件：
- Recall@K = |TopK ∩ H*| / |H*|
- MAP（平均精度均值）

### 2.6 两个参考基线方法

**增量归因（Incremental Attribution）**：衡量逐步揭示轨迹前缀时目标行为似然的变化：

**sⁱⁿᶜᵢ = log p(y | c≤ᵢ) − log p(y | c≤ᵢ₋₁)**

**留一归因（Leave-One-Out, LOO）**：从完整上下文中移除组件 cᵢ 后，计算目标行为平均 token 级对数似然的下降量：

**sˡᵒᵒᵢ = (1/|y|) Σₜ log p(yₜ | y<ₜ, τ) − (1/|y|) Σₜ log p(yₜ | y<ₜ, τ^(−ᵢ))**

### 2.7 基准构建协议（四阶段）

1. **轨迹标准化**：将异构原始轨迹转换为统一组件序列；
2. **目标识别与标注**：按三种行为类型识别目标，标注唯一主因组件；
3. **可选链注释**：不安全动作标注攻击链与执行链；
4. **标注验证**：两阶段——**结构验证**（确定性约束检查：主因组件在目标之前、组件在链内按时间排序等）+ **语义验证**（LLM 评审者按预定义标准评估，不合格者修复后重新验证）。

## 6. 论文的主要结论与发现

1. **轨迹归因是一个挑战性问题**：整体性能远未饱和（增量归因 All Targets Hit@1 仅 0.369，留一归因 0.537）。
2. **任务对齐动作最易归因，安全拒绝最难**：增量归因下任务对齐 Hit@1=0.621，安全拒绝仅 0.154；留一归因下安全拒绝较好（0.697）但仍不高。
3. **归因距离是关键难度因素**：局部归因（d=1）显著优于长程归因（d≥2）。例如留一归因下不安全动作从 0.852 跌至 0.368，安全拒绝从 0.946 跌至 0.446。
4. **链级归因比主归因定位更困难**：攻击链恢复的 Recall@3 与 MAP 普遍低于执行链，说明上游对抗影响传播更难追踪。
5. **基准成功捕获了多元归因设置**：覆盖局部/长程依赖、单组件/分布式因果链、三种行为类型，为归因方法提供了难度谱系更丰富的评估平台。

## 7. 优点

1. **问题定义新颖且重要**：首次将"轨迹归因"建立为标准化评估问题，超越传统的失败定位，覆盖任务成功、安全风险、安全拒绝三种行为，具有较强实际意义。
2. **统一组件模式设计优秀**：Role+Content 的抽象有效屏蔽了不同智能体框架的异构性，使跨基准的通用归因评估成为可能。
3. **细粒度标注结构合理**：主归因组件（根因）与归因链（传播路径）的区分，比扁平多因标注更精确，有效减少标注歧义。
4. **可扩展性设计突出**：发布可复用标注技能（annotation skill），新模型生成的轨迹可在同一框架下被标准化、标注和评估，解决"固定数据集快照"的局限。
5. **标注质量控制严格**：两阶段验证（结构+语义）、迭代修复机制保证标注质量。
6. **分析方法细致**：按距离机制和链类型分层分析性能，揭示了几何距离和因果传播结构对归因难度的系统性影响。

## 8. 不足与局限

1. **数据源覆盖有限**：仅涵盖 AgentDojo、Agent3Sigma（Stage/Canary）三个基准家族，不足以代表所有新兴智能体系统的多样性。
2. **标注存在固有歧义空间**：依赖 LLM 辅助标注（虽经人工审核），部分轨迹可能存在多种合理的归因解释，但基准只提供单一参考答案。
3. **归因粒度局限**：目前仅到组件级；扩展到句子级或 token 级归因（更细粒度的归因单元）仍是未来工作。
4. **基线方法过于简单**：仅两个似然型参考基线，缺少更先进的因果归因方法对比，尚不能充分刻画基准的天花板。
5. **算力与成本信息缺失**：未报告标注流程、LLM 评审和基线实验的算力消耗，影响复现便利性。
6. **链标注仅限不安全动作**：虽然协议本身可扩展，但当前实例化中攻击链/执行链仅对不安全动作轨迹标注，其他目标行为缺乏链级标注，限制了链恢复任务的全类型覆盖。
