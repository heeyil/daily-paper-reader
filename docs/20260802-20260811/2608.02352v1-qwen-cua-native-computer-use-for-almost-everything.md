## 摘要
原生计算机使用为智能体提供了一个通用接口，使其能够操作人类可用的几乎任何软件，但这需要长程状态跟踪、大规模交互式体验以及从稀疏但可验证的结果中学习。我们推出了Qwen-CUA，一个具有397B-A17B Qwen混合专家骨干网络的原生计算机使用智能体。它仅通过截图观察，并通过键盘和鼠标事件行动，无需DOM树、无障碍元数据或特定任务的API。其脚手架保持多达20个活动截图，并将较旧的视觉历史折叠为固定大小的块，以保留最近的证据，同时保持可重用的提示前缀。在训练方面，我们构建了一个云部署舰队，可访问近10万个vCPU和数万个并发环境，构建了约4万个可验证任务，并在日常和专业软件中收集个性化的长程工作流。我们通过可验证奖励和轨迹切片来优化完整轨迹，同时迭代训练运行刷新监督数据并重新校准强化学习任务。在八个基准测试中，Qwen-CUA优于Qwen3.7，并与领先的专有系统保持竞争力，在OSWorld-Verified上达到86.2，在OSWorld 2.0上达到18.5/48.4的二元/部分完成度。将相同的方案扩展到超过一万亿参数的模型，得到Qwen-CUA-Max，将这些分数提升至87.6和21.2/53.3。Qwen-CUA还将RedTeamCUA的攻击成功率从36.6降至16.4（相对于Qwen3.7）。效率分析、浏览器部署以及增强Bash的实验进一步刻画了实际行为。这些结果确立了原生计算机使用作为广泛能力的智能体基础，并突出可扩展的可验证交互和混合工具使用作为关键方向。

## Abstract
Native computer use offers a general interface for agents to operate almost any software available to people, but requires long-horizon state tracking, large-scale interactive experience, and learning from sparse yet verifiable outcomes. We introduce Qwen-CUA, a native computer-use agent with a 397B-A17B Qwen mixture-of-experts backbone. It observes only screenshots and acts through keyboard and mouse events, without DOM trees, accessibility metadata, or task-specific APIs. Its scaffold maintains up to 20 active screenshots and folds older visual history in fixed-size blocks to retain recent evidence while preserving reusable prompt prefixes. For training, we build a cloud rollout fleet with access to nearly 100,000 vCPUs and tens of thousands of concurrent environments, construct approximately 40,000 verifiable tasks, and collect personalized long-horizon workflows across everyday and professional software. We optimize complete trajectories with verifiable rewards and trajectory slicing, while iterative training runs refresh supervised data and recalibrate reinforcement-learning tasks. Across eight benchmarks, Qwen-CUA outperforms Qwen3.7 and remains competitive with leading proprietary systems, reaching 86.2 on OSWorld-Verified and 18.5/48.4 binary/partial completion on OSWorld 2.0. Scaling the same recipe to a model with over one trillion parameters yields Qwen-CUA-Max, improving these scores to 87.6 and 21.2/53.3. Qwen-CUA also reduces RedTeamCUA attack success from 36.6 to 16.4 relative to Qwen3.7. Efficiency analyses, a browser deployment, and Bash-augmented experiments further characterize practical behavior. These results establish native computer use as a broadly capable agent foundation and highlight scalable verifiable interaction and hybrid tool use as key directions.

- 该方向存在三类核心挑战：
  - **部分可观测性与长程状态跟踪**：GUI 状态难以从单帧截图完全推断，证据分散在历史截图中；
  - **交互经验获取成本高**：一次 rollout 需要完整的有状态环境；
  - **奖励稀疏且难以验证**：可靠监督通常只来自最终环境状态，而非中间步骤。
- 论文提出的核心问题：能否通过大规模可验证交互训练，使原生计算机使用成为“几乎一切软件”的通用智能体基础？

## 2. 方法论

### 2.1 模型与接口

- 骨干网络：**397B-A17B Qwen 混合专家（MoE）模型**；另外扩展到超过 1T 总参数的 Qwen-CUA-Max。
- 观察：仅输入截图；动作空间：原生鼠标（点击、拖动、滚动）与键盘（按键、输入），外加少量控制动作（截图、等待、终止、询问用户）。
- 不做 DOM/无障碍树/Shell/API 访问，保证接口跨应用、跨环境通用。

### 2.2 长程上下文管理

- 每轮保留**最多 20 张活动截图**，较旧截图按 **10 步为一块**折叠为固定文本占位符。
- 块式折叠（chunked folding）能保持 21–30 步共享同一前缀，避免每步重写历史，进而提升 KV-cache 复用。
- 训练时使用相同的折叠算子：完整轨迹被切分为多个上下文有界的切片，每个切片继承整个 episode 的终局奖励，且只对模型生成的活动 token 计算损失。
- 优点：视觉 token 增长受控，同时保留最近像素和较早的推理/动作记录；训练与推理表示一致。

### 2.3 训练数据与基础设施

- 训练基础设施：基于阿里云 ECS 的 rollout 集群，约 **10 万 vCPU**、**数万并发环境**；支持环境重置、任务调度、结果验证和轨迹记录。
- 任务规模：约 **4 万个可验证任务**，分三类：
  1. 环境操作任务：在可控 Web 模拟服务和桌面软件（含专业/长尾应用）上验证环境状态；
  2. 用户交互任务：模拟用户仅在智能体询问澄清时提供信息，训练模型识别缺失证据；
  3. 长程任务：通过可验证的阶段状态串联（phase-state chaining）构建多阶段工作流。
- 个性化数据：收集真实人类在个性化桌面和专业软件中的长程轨迹，并用模型辅助生成逐步推理，经过过滤后作为额外监督。

### 2.4 强化学习

- 优化目标：可验证奖励的强化学习（RLVR），每个任务包含自然语言指令、可复现初始状态、可执行奖励函数；奖励由最终环境状态计算，不依赖动作序列。
- 优化算法：**软自适应策略优化（SAPO）**，对每个轨迹组进行奖励归一化得到优势：
  \[
  \hat{A}_i = \frac{r_i - \bar{r}}{\sigma_r + \delta}
  \]
  每个 token 有重要性比率 \(\rho_{i,u}\)，通过温度可控的平滑门控限制离策略更新：
  - 正优势温度 \(\tau_{pos}=1.0\)，非正优势温度 \(\tau_{neg}=1.05\)，负优势衰减更快以稳定训练。
- 轨迹切片：在 144K token 上下文限制内枚举多个切片，每个切片继承完整 episode 的终局奖励，不进行人工步骤级奖励分解。

### 2.5 迭代式智能体训练

- 每一轮训练后，用当前模型分析失败 SFT 查询和弱领域，更新教师策略重新生成示范、补充人工轨迹、校准 RL 任务池。
- RL 任务校准：每个候选任务运行 8 次 trial；仅保留至少成功 1 次但不是全部成功（\(0<c(q)<8\)）的任务，聚焦于当前策略“够得着但未饱和”的任务。
- 每轮 SFT 从同一中间 checkpoint 初始化，避免优化漂移。

## 6. 主要结论

- 原生计算机使用可以作为**通用智能体基础**：仅凭截图和键盘鼠标即可覆盖网页、桌面、专业软件、科研、个人化工作流，并达到与领先专有系统相当的水平。
- **可扩展可验证交互**是关键：约 4 万可验证任务 + 大规模 rollout + RLVR + 轨迹切片，能显著提升长程、稀疏奖励下的任务完成能力。
- **混合工具使用**是重要未来方向：Bash 可缩短轨迹长度，但当前切换策略会损失任务质量；若能可靠路由工具，可兼顾通用性和效率。
- 安全方面：相比 Qwen3.7，RedTeamCUA 攻击成功率从 36.6 降至 16.4，但残余风险仍不可忽视。

## 7. 优点

- 接口极简且通用：不依赖 DOM/API/可访问性树，真正以与人类相同的方式操作计算机。
- 长上下文管理设计巧妙：块状折叠 + 稳定前缀 + 训练/推理一致，兼顾视觉历史保留和 KV-cache 复用。
- 训练体系完整：从环境合成、任务构建、SFT 数据刷新、RL 任务校准到迭代训练，形成闭环。
- 奖励利用充分：通过终局奖励 + 轨迹切片使稀疏信号覆盖长轨迹的不同阶段，避免人工步骤级奖励设计。
- 评估维度丰富：除标准基准外还考虑了 token 效率、交互轮次、真实部署、安全对抗和混合工具，分析较为立体。
- 模型容量扩展验证：Qwen-CUA-Max 证明相同训练方案可随参数规模继续提升性能。

## 8. 不足与局限

- **任务完成率仍偏低**：OSWorld 2.0 二元完成率仅 21.2%（Max 版），长程端到端任务仍是较大瓶颈。
- **交互成本高**：每轮一次原生动作导致大量模型推断和延迟，实际使用成本高。
- **混合工具能力不成熟**：Bash 虽能缩短轨迹，但任务成功率下降，说明工具路由、切换时机和模态选择尚未学好。
- **安全风险残留**：RedTeamCUA 综合 ASR 仍有 16.4%，且 Rocket.Chat 上的低 ASR 可能部分由任务失败造成，不能视为稳健拒敌。
- **评估覆盖不完整**：Gym-Anything 有大量环境缺失；部分基准分数来源与复现配置不一致；轮次效率等指标受接口定义影响，不能直接横向比较。
- **可复现性门槛高**：近 100k vCPU、512 张 H200 的算力投入远超一般研究团队；论文未给出完整训练数据和代码细节的开放计划。
- **应用边界**：真实世界动态网站、失败恢复、个性化偏好等仍可能超出基准覆盖，需要进一步部署验证。
