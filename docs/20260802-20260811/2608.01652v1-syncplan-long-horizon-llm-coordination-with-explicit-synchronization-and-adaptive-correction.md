## 摘要
基于LLM的多智能体协调在动态环境中面临效率与自适应性之间的根本权衡。现有方法通常依赖重复的LLM调用或多轮通信来在执行过程中调整决策，这会引入大量延迟，并使协调容易受到异步进度和环境变化的影响。相反，一次性规划降低了协调开销，但产生的开环计划可能迅速过时，或在动作依赖于其他智能体和环境时失效。我们提出SyncPlan，一种通过显式同步和自适应修正实现长时程协调的计划-执行-修正框架。给定状态和团队级任务，集中式LLM协调器在单次规划调用中生成每个智能体的动作链。在执行过程中，显式等待原语和死锁检测强制执行智能体间及智能体-环境依赖关系，而轻量级计划过时检测器持续评估剩余计划，并在环境变化使其假设失效时触发重新规划。我们进一步通过SFT和面向规划的RL，结合密集任务进展和结果级执行反馈来优化协调器。在公共Overcooked基准和复杂的《王者荣耀》环境上的实验表明，与现有的基于LLM的协调器相比，SyncPlan在取得最先进任务成功率的同时，使用的墙钟运行时间不足其0.05%。代码和数据集将公开提供。

## Abstract
LLM-based multi-agent coordination faces a fundamental trade-off between efficiency and adaptivity in dynamic environments. Existing approaches typically rely on repeated LLM invocations or multi-round communication to adapt decisions during execution, introducing substantial latency and making coordination vulnerable to asynchronous progress and environmental changes. Conversely, one-shot planning reduces coordination overhead but produces open-loop plans that can quickly become stale or fail when actions depend on other agents and the environment. We introduce SyncPlan, a plan-execute-correct framework for long-horizon coordination through explicit synchronization and adaptive correction. Given the state and team-level task, a centralized LLM coordinator generates per-agent action chains in a single planning call. During execution, explicit wait primitives and deadlock detection enforce inter-agent and agent-environment dependencies, while a lightweight Plan Staleness Detector continuously assesses the remaining plan and triggers replanning when environmental changes invalidate its assumptions. We further optimize the coordinator through SFT and planning-oriented RL with dense task progress and outcome-level execution feedback. Experiments on the public Overcooked benchmark and the complex Honor of Kings environment show that SyncPlan achieves state-of-the-art task success rates while using less than 0.05% of the wall-clock runtime compared with existing LLM-based coordinators. Code and datasets will be made publicly available.

# SyncPlan 论文总结

## 1. 核心问题与整体含义

- **核心矛盾**：基于LLM的多智能体协调在动态环境中面临**效率与自适应性**之间的根本权衡。
  - 现有方法（如多轮通信、重复LLM调用）虽然能适应环境变化，但引入高延迟，难以满足实时性要求。
  - 一次性规划方案虽然开销低，但生成的是开环计划，在动作依赖其他智能体和环境状态时容易迅速失效。
- **三大挑战**：
  - **实时性约束**：环境以帧级速度演化，频繁调用LLM导致计算开销不可接受。
  - **计划过时**：环境变化会使联合计划失效，延迟重新规划会让智能体继续执行陈旧动作，而周期性重规划又浪费计算。
  - **协调冲突**：异步执行带来时间与条件依赖，但LLM计划通常以自由文本表达依赖，低级执行器无法可靠验证和强制实施。
- **整体含义**：需要一种既能保持高效（避免频繁LLM调用）又能自适应环境变化（及时修正计划）且能显式处理智能体间同步的协调框架，以支撑长时程多智能体任务。

## 2. 方法论

- **SyncPlan 总体框架**：一种“计划-执行-修正”（plan-execute-correct）流程，包含三个核心模块：
  1. **协作规划（Collaborative Planning）**：集中式LLM协调器在单次调用中为每个智能体生成一条长时程低层动作链。
  2. **运行时执行（Runtime Execution）**：执行器推进动作链，并强制执行同步约束，同时检测死锁。
  3. **自适应修正（Adaptive Correction）**：轻量级计划过时检测器（PSD）持续监控计划有效性，仅在必要时触发重规划。
- **关键设计：显式同步原语**
  - 借鉴操作系统中的进程同步思想，引入两种可执行的原语：
    - `Wait_agents`：智能体等待另一智能体达到指定里程碑（开始/完成）。
    - `Wait_entity`：智能体等待环境实体满足特定条件。
  - 等待步骤将跨智能体依赖转化为显式、机器可检查的约束，避免自由文本依赖无法验证的问题。
- **运行时执行与死锁检测**：
  - 每个智能体维护指向当前执行步骤的指针；可执行动作直接派发，同步原语则作为阻塞谓词。
  - 维护有向等待图 `G=(V,E)`，每帧检测有向环；若新增等待边会导致环，则判定死锁并触发重规划。
- **自适应修正：Plan Staleness Detector (PSD)**：
  - 输入三个张量：
    - 链-实体关联矩阵 `C_t`（剩余计划中动作链引用的实体）；
    - 当前实体状态矩阵 `X_t`；
    - 状态差异矩阵 `Δ_t`（状态变化）。
  - 通过两条双线性路径（chain pathway 和 state pathway）融合特征，经 MLP 和 sigmoid 输出重新规划概率，超过阈值 η 时触发重规划。
  - PSD 是轻量级二分类器，采用规则化构建训练标签（Overcooked 用事件帧，HoK 用合成扰动）。
- **训练优化**：
  - **SFT 热身**：从专家轨迹与蒸馏数据构建指令-响应对，让协调器学习结构化动作链和同步原语的生成。
  - **面向规划的强化学习（GRPO）**：设计复合奖励函数 `R(A) = R_prog(A) + α·1[成功] − P(A)`，其中：
    - `R_prog` 包含动作链完成占比、效率、长度正则；
    - 惩罚项覆盖四种失败模式：语法错误、语义错误、死锁、超时，并按严重程度赋予不同系数。
- **完整算法（Algorithm 1）**：
  1. 初始状态生成初始联合计划并初始化指针和等待图；
  2. 每帧执行当前计划步骤并检测死锁；
  3. 若任务完成则返回成功；
  4. 否则由 PSD 评估计划过时概率，若死锁或概率超过阈值则重新调用协调器生成新计划并重置跟踪器；否则更新指针。

## 6. 主要结论与发现

- **性能与效率兼得**：SyncPlan 在 Overcooked 上相对于最强 LLM 基线的 TAR 平均提升 **12.2 个百分点**，而墙钟运行时间不足基线的 **0.05%**；在 HoK 上 TAR 达 **86.3%**，比 DPT-Agent 高 **17.6 个百分点**，实时比率相对运行时间缩短 **超过 26 倍**。
- **组件必要性**：
  - PSD 提供“按需重规划”能力，比周期性重规划更高效、提升更明显；决定“何时修正”比“修正多频繁”更重要。
  - RL 是关键的闭环优化，弥补 SFT 仅模仿静态数据、未考虑执行时序与碰撞约束的不足。
  - 显式同步原语有效降低死锁率，SFT 与 RL 共同促进死锁抑制。
- **模型规模阈值**：在 1B 至 1.5B 之间存在关键能力阈值，低于 1B 的模型无法稳定生成语法有效的动作链；高于 3B 后，由于结构化模式约束了输出空间，收益趋缓。

## 7. 优点

- **创新性**：将操作系统中的同步机制引入 LLM 多智能体协调，使跨智能体依赖成为可执行、可验证的显式约束。
- **高效性**：单次规划 + 轻量级 PSD 按需修正，有效平衡长期规划的开销与环境适应性，显著降低墙钟延迟。
- **训练设计合理**：SFT + 面向规划的 RL 复合奖励，综合考虑任务效果、执行正确性和运行效率；奖励设计区分失败模式严重程度，利于长时程信用分配。
- **实验扎实**：公共基准与复杂真实游戏环境相结合，多个动态场景、系统消融、模型规模/骨干模型探索、统计检验等增强了说服力。
- **可扩展性**：PSD 的链-实体关联矩阵采用规则化构建，易于迁移到新环境；训练流程使用 LoRA，适配成本较低。

## 8. 不足与局限

- **实验覆盖有限**：仅在 Overcooked 和 HoK 两个环境上验证，任务类型相对单一，对更广泛多智能体场景的泛化能力未充分证明。
- **动态事件设计存在偏差风险**：Overcooked 的扰动是脚本化、有限的，难以覆盖真实世界开放式的环境变化；HoK 的内生动态虽自然，但任务固定，难以横向比较不同

不同任务目标下的系统泛化能力；Overcooked 动态事件由规则脚本注入，与 HoK 的自然动态在复杂度上差异较大，二者在扰动强度与分布上不可直接对比，削弱了跨环境结论的一致性。
- **训练成本与评估细节缺失**：论文未报告 SFT 与 RL 阶段的具体 GPU 训练时长、总 token 消耗和峰值显存占用，难以评估训练开销的可复现性；同时，PSD 的置信度阈值 η 未说明是否在评估集上做过调优，存在潜在的选择偏差风险。
- **同步原语表达力上限**：`Wait_agents` 与 `Wait_entity` 仅支持“等待特定智能体/实体”这类单跳条件，对更复杂的时序逻辑（如超时回退、条件分支、资源抢占）支持有限，在面对高动态、强对抗的开放世界任务时可能仍不够灵活。
- **LLM 规划能力的隐性依赖**：SyncPlan 假设协调器能够稳定输出结构化动作链，但其在 1B 以下小模型上出现系统性语法失效，说明方法对骨干模型的基础生成能力存在较强依赖，限制了在轻量级设备端的部署潜力。

## 9. 总体评价

SyncPlan 的核心贡献在于将“系统级同步机制”引入 LLM 多智能体协调，以显式同步原语和轻量级过时检测器化解效率-自适应性矛盾，在设计上具有较强的系统感和工程可落地性。其“少调用 LLM、多依赖结构化执行”的思路，也为后续实时多智能体协调研究提供了一条值得借鉴的技术路径。

然而，该工作的说服力仍受限于实验环境种类较少、动态扰动覆盖有限、训练成本不透明等现实约束。未来可沿两条方向深化：一是将同步原语扩展为更丰富的时序依赖表达，并引入在线学习机制适应开放式环境变化；二是在更多异构环境（如物流调度、机器人协同、仿真城市管理）中检验框架的通用性，并补充训练阶段的详细成本报告。

总体而言，SyncPlan 在方法创新与实验系统度上均有亮点，在“效率优先 + 按需修正”这一设计哲学下取得了令人信服的初步成效，但其长期价值仍取决于在更广泛真实任务中的验证与扩展。
