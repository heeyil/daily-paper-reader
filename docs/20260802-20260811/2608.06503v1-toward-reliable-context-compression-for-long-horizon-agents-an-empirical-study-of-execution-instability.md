## 摘要
循环上下文压缩可控制长程智能体中的上下文增长，但其行为影响仍知之甚少。在这项初步实证研究中，我们表明压缩可能削弱近期交互的影响，导致阻塞动作增加、重复探索增多以及跨运行的不稳定性。受这些观察启发，我们提出了TRACE，一种验证器引导的框架，通过从相同环境状态进行的配对闭环延续来评估每个压缩事件，并利用摘要偏好优化自然语言压缩提示，同时保持所有模型冻结。在AppWorld上的初步结果显示，在任务性能、多运行可靠性和上下文-执行效率方面优于现有压缩基线。这些发现为边界局部评估作为可靠智能体上下文压缩的有前景方向提供了早期证据。

## Abstract
Recurrent context compression controls context growth in long-horizon agents, but its behavioral effects remain poorly understood. In this preliminary empirical study, we show that compression can weaken the influence of recent interactions, increasing blocked actions, repeated exploration, and instability across runs. Motivated by these observations, we introduce TRACE, a verifier-guided framework that evaluates individual compaction events through paired closed-loop continuations from the same environment state and uses summary preferences to optimize a natural-language compression prompt while keeping all models frozen. Initial results on AppWorld show improvements over existing compression baselines in task performance, multi-run reliability, and context--execution efficiency. These findings provide early evidence for boundary-local evaluation as a promising direction for reliable agent context compression.

## 论文核心问题与整体含义

**研究动机与背景**

- 大语言模型（LLM）越来越多地应用于长程、动态演化的交互场景（如智能体 Agent），在这些场景中，上下文随着推理、行动、观察和计划修订不断增长。若不加以控制，完整历史会带来高昂的推理成本和峰值上下文压力。
- 上下文压缩（Context Compression）因此成为长程 LLM 系统可扩展性的关键。早期工作从文档级提示压缩发展到轨迹感知的上下文管理，如 ReSum、SUPO、ACON 等。
- 现有压缩方法普遍隐含一个**替换假设**：只要更短的检查点保留了任务相关内容，它就可以替代原始交互历史。然而论文指出，该假设忽略了历史在长程执行中的**方向性作用**：原始轨迹中"行动-观察"的有序序列锚定了已完成事项、当前执行位置以及任务是否可终止。压缩为陈述性摘要后，冻结的智能体可能丢失局部轨迹位置，重放已完成动作，或在终止边界之后继续行动。

**核心问题**

> 如何在压缩历史的同时，保留一个使冻结智能体能够可靠识别当前执行状态的表示？

论文通过实证研究发现：循环上下文压缩会削弱近期交互的影响，导致阻塞动作（blocked actions）、重复探索（repeated exploration）和跨运行不稳定性（instability across runs），并据此提出 TRACE（Trajectory-Relative Agent Context Compression）框架。

## 方法论

**核心思想**

TRACE 是一种验证器引导（verifier-guided）的框架，核心在于**边界局部评估（boundary-local evaluation）**：不依赖终端任务结果推断压缩质量，而是在每个压缩边界处，从相同环境状态出发，对压缩前后的上下文分别执行成对的闭环延续（paired closed-loop continuations），度量压缩引入的额外执行负担（阻塞或重复动作），并据此优化压缩器的自然语言提示模板。所有模型参数（压缩器、下游智能体、工具、解码配置）保持冻结，仅优化压缩提示词。

**关键技术细节**

1. **边界局部执行验证器（Boundary-Local Execution Verifier）**
   - 在压缩边界 b，记压缩前的上下文为 x⁻_b（前一个循环摘要 + 新累积的原始交互），压缩后的上下文为 x⁺_b(s)（候选摘要 s + 保留的近期原始轮次）。
   - 从相同环境状态出发，分别对 x⁻_b 和 x⁺_b(s) 进行 K 步闭环 rollout（动作真实执行、观察真实返回）。PRE 作为配对局部对照，用于控制冻结智能体自身的随机性和固有执行错误。
   - 定义执行负担：G(τ) = Σ_{j=1}^{K} z_j(τ)，其中 z_j 指示第 j 个动作是否为阻塞动作（触发 AppWorld 原生错误契约）或重复动作（规范化后的工具调用签名与压缩边界前或本 rollout 中早前执行的相同；两种条件并集只计一次）。
   - 压缩引入的负担：ΔG_b(s) = E[G(τ⁺_b(s))] − E[G(τ⁻_b)]；验证器分数 Q_b(s) = −ΔG_b(s)。分数越高，表示候选摘要引入的额外执行回归越少。

2. **验证器引导的提示优化（Verifier-Guided Prompt Optimization）**
   - **训练边界选择**：使用冻结的基础压缩器在 AppWorld 训练集上收集 PRE 和 POST 延续；识别出现阻塞动作的边界，按 AppWorld 原生执行错误类型分层抽样，选出 12 个边界作为优化样本。
   - **候选生成与边界局部评分**：基础压缩器对每个边界独立生成 3 个候选摘要（s_{b,1}, s_{b,2}, s_{b,3}），每个候选生成对应的 POST 延续；PRE 延续跨候选复用。每个摘要按公式 Q_b(s) 评分，每个边界保留最高分和最低分候选，形成 12 个边界匹配的对比样本 D_pref = {(I_b, s⁺_b, s⁻_b)}_{b=1}^{12}。
   - **系统感知的提示提议**：将冻结下游系统提示（H_sys）与当前压缩模板和偏好示例一并提供给冻结的 LLM proposer，防止推导出的指导原则与系统提示矛盾。proposer 只能观察到压缩机输入和"更好/更差"摘要对，看不到后续动作、观察、错误信号或验证器分解。每个提议任务生成 5 个完整候选模板 {P_1, ..., P_5}，仅修改自然语言压缩指令（保留摘要 schema、章节结构、占位符、渲染器、预算和下游接口）。
   - **端到端开发集选择**：每个候选模板在 AppWorld 开发集上运行完整压缩-执行流水线两次，计算 Pass 2（两次运行均成功的任务比例），选择 Pass 2 最高的模板 P*。终端结果不参与构建摘要偏好，仅在最终模型选择阶段使用；选定的 P* 冻结后在测试集上评估，不再修订。

**公式与流程小结**

- 递归上下文更新：z_{t+1} = z̄_{t+1}（若 |z̄_{t+1}| ≤ B），否则 z_{t+1} = C(z̄_{t+1}; B)。
- 验证器信号：G(τ) = Σ_{j=1}^{K} z_j(τ)；ΔG_b(s) = E[G(τ⁺_b(s))] − E[G(τ⁻_b)]；Q_b(s) = −ΔG_b(s)。
- 偏好构建：s⁺_b = arg max_{s_{b,n}} Q_b(s_{b,n})，s⁻_b = arg min_{s_{b,n}} Q_b(s_{b,n})。
- 模板选择：P* = arg max_{P_m} Pass2(P_m)，其中 Pass2 在开发集上计算。

## 主要结论与发现

1. **循环压缩会退化智能体行为**：随着上下文预算缩小，平均通过率下降；P@2 与 P2 之间的差距扩大，说明压缩将原本可靠解决的任务变成间歇性解决的任务，降低多运行稳定性。长程任务退化更严重。
2. **退化不只是信息丢失**：AppWorld 中旧观察可重新查询，FIFO 在中度预算下与摘要压缩相当，说明问题还在于智能体的**执行状态定位（execution-state mislocalization）**。压缩破坏了智能体对"已完成什么、当前在哪、是否该终止"的识别能力。
3. **压缩削弱近期交互的更新效应**：最近交互原样保留时行为发散最小（0.149），被压缩后发散增大（0.233），完全省略时最大（0.289）。压缩保留了部分行为效应但系统性衰减。
4. **压缩诱导回归性探索**：压缩立即增加阻塞/错误动作（第一个动作边际效应 +0.108）和重复探索（后期持续为正），说明已建立的状态变得不那么直接可操作。
5. **TRACE 优于现有压缩基线**：在 AppWorld 测试集上，TRACE 在平均准确率（77.1 vs. 71.4）、Pass 2（67.3 vs. 59.5）和 Pass@2（86.9 vs. 83.3）上均超过最强压缩基线 Prompting-O；在困难任务上全部指标领先。
6. **效率优势**：TRACE 平均步数接近全上下文参考，同时大幅降低峰值 tokens；在困难任务上使用不到一半峰值上下文却几乎保持全上下文的执行长度。
7. **跨模型迁移**：用 MiniMax-M3 优化的压缩模板直接迁移到 Kimi-K2.7-Code，整体准确率 84.5 超过无压缩的 82.7，Pass 2 达 79.2（无压缩为 73.8），在中度困难任务上全面超过无压缩参考。

## 优点

- **问题定位深刻**：论文超越"压缩损失信息"的表层解释，揭示压缩对执行状态定位、终止识别和动作承诺等动态行为的破坏，概念上有明显推进。
- **验证器设计精妙**：通过同一环境状态下的成对闭环延续（PRE 对照 vs. POST 处理）分离压缩引入的执行退化与智能体固有随机性；边界局部评估取代终端结果归因，避免终端成功/失败对每个中间摘要的错误归因。
- **模型完全冻结**：只优化自然语言压缩提示，不更新任何模型参数，具有实际部署价值（无需训练）；跨模型迁移实验进一步证明该方法学到的策略具有一定通用性。
- **信号选取可解释**：以阻塞动作和重复调用作为可观察的执行回归信号，定义清晰、可复现，不依赖黑盒奖励模型。
- **实验设计严谨**：共享评估协议、冻结提示模板并哈希记录、ACON 直接从原始仓库加载、对比多运行稳定性与效率等多个维度；诊断实验（终端完成率、最近交互衰减）提供了机制层面的证据链。
- **系统感知的优化约束**：将下游系统提示提供给 proposer，防止优化出的压缩规则与智能体的操作指令矛盾，这是实践中非常实用的细节。

## 不足与局限

- **基准覆盖过窄**：仅在 AppWorld 上评估。AppWorld 是 API 调用型、信息可重取的环境，结论能否推广到知识密集型任务、浏览器操作（WebArena）、办公自动化（OfficeBench）等场景尚未验证。论文自己也承认跨基准结果留待未来工作。
- **跨模型迁移证据有限**：只验证了 MiniMax-M3 → Kimi-K2.7-Code 单向迁移，且目标模型为同一类（编码/Agent 能力较强模型），不同规模、不同系列模型之间的迁移性未知。
- **验证器信号覆盖不全**：当前验证器只捕捉阻塞和重复动作两类可观察执行回归，可能遗漏"静默状态损坏"（silent state corruption）——摘要中虽无阻塞或重复，但语义被破坏、引导未来决策出错的情况。论文对此有明确承认。
- **rollout 短视性**：边界局部验证使用固定短视界（K 步，上限 5 步）的 rollout，可能无法捕捉延迟出现的执行回归；长视界影响评估未充分覆盖。
- **统计功效有限**：Pass 2 / Pass@2 均基于两次独立运行，运行次数较少；部分实验（如终端完成率）每次条件只采样 10 个动作，置信区间可能较宽。论文虽报告了 bootstrap 置信区间，但整体样本量仍有限。
- **提炼过程的透明度有限**：proposer 只看到偏好，不看到 rollout 细节，虽然是防止过拟合的合理设计，但也使"为什么某些摘要更优"的中间推理不可追踪，压缩模板的改进方向依赖 proposer 的内部推断。
- **应用限制**：优化过程需要运行闭环 rollout（每边界多采样）和开发集端到端选择，计算开销较高；在真实生产环境中，可能需要频繁的边界验证，成本可能成为部署障碍。
