## 摘要
LLM智能体的能力不仅取决于其模型，还取决于其工具链：即用于构建上下文、调用工具、验证结果以及从失败中恢复的可执行程序。近期研究表明，在不更新模型权重的情况下，进化工具链能够带来持续的改进。然而，现有方法假设所有执行经验都可以路由到一个单一的优化器，该优化器沿一条顺序轨迹进化一个工具链。真实的智能体生态系统违背了这一假设：用户、组织和环境产生彼此隔离的经验流，这些经验无法汇总，因此最值得学习的经验恰恰是无法直接集中的经验。我们提出EvolveNet，一种协作式工具链进化范式，将经验提取迁移到数据端。共享工具链被广播到数据本地的智能体部署中，每个部署都在自身工作负载上进化该工具链。只有最终的程序适配结果被合成为更新后的共享工具链并重新分发，从而使每个参与的智能体都能继承其他智能体发现的操作经验。通过将聚合边界从原始工作负载转移到学习到的适配结果，EvolveNet保持工作负载的本地性，并允许多个进化搜索以更浅的串行深度并发进行。由于独立修改的程序不能像模型参数那样取平均，且在组合时可能发生冲突，EvolveNet引入了作用域类型化的、证据引导的程序聚合。在涵盖文本到SQL、数据科学编码、竞争性编程、软件工程和智能体工作流的五个设置中，EvolveNet在所有五项中都改进了共享工具链，其中在异构工作负载下收益最大，而消融实验表明改进来自不同智能体的适配组合，而非从中选择。这些改进归因于不同智能体适配的组合，而非选择其中某一个。

## Abstract
The capabilities of an LLM agent depend not only on its model but on the harness: the executable program that constructs context, invokes tools, verifies results, and recovers from failure. Recent work shows that evolving the harness yields persistent improvements without updating model weights. Existing approaches, however, assume that all execution experience can be routed to a single optimizer, which evolves one harness along a sequential trajectory. Real agent ecosystems violate that assumption: users, organizations, and environments generate isolated streams of experience that cannot be pooled, so the experience most worth learning from is exactly the experience that cannot be directly centralized. We introduce EvolveNet, a paradigm of collaborative harness evolution that moves experience extraction to the data. A shared harness is broadcast to data-local agent deployments, each of which evolves it on its own workload. Only the resulting program adaptations are composed into an updated shared harness and redistributed, so that every participating agent inherits operational experience discovered by the others. By shifting the aggregation boundary from raw workloads to learned adaptations, EvolveNet keeps workloads local and allows multiple evolutionary searches to proceed concurrently with reduced serial depth. Because independently modified programs cannot be averaged like model parameters and may conflict when composed, EvolveNet introduces scope-typed, evidence-guided program aggregation. Across five settings spanning text-to-SQL, data-science coding, competitive programming, software engineering, and agentic workflows, EvolveNet improves the shared harness in all five, with the largest gains under heterogeneous workloads, and ablations attribute the improvement to composition of adaptations from different agents rather than to selecting among them.

# EvolveNet：面向智能体自我改进的协作式工具链进化

## 1. 核心问题与整体含义

**研究动机**：LLM智能体的能力不仅取决于其模型本身，还取决于其"工具链"（harness）——即构建上下文、调用工具、验证中间结果、处理失败恢复的可执行程序。两个使用相同冻结模型的智能体，会因工具链的不同而展现出迥异的能力。近期研究（如TTHE）表明，进化工具链可以在不更新模型权重的情况下获得持久的行为改进。

**核心问题**：现有工具链进化方法遵循**中心化范式**，即假设所有执行经验可以被汇总到单一优化器，沿一条顺序轨迹进化一个工具链。然而，真实智能体生态系统的经验流是**彼此隔离的**：用户、组织、环境和数据库各自产生无法汇总的本地经验，最有价值的经验恰恰无法被集中处理。由此产生的问题是：当经验不能离开本地时，如何让多个智能体部署共同改进一个共享工具链？

**范式创新**：EvolveNet逆转了传统"先聚合数据、再集中进化"的顺序，改为"本地进化、再聚合适配"，将经验提取过程从中心优化器下沉到数据本地的各个部署，从而在不集中原始工作负载的前提下实现协作式的智能体自我改进。

## 2. 方法论

### 2.1 核心思想

EvolveNet 采用**广播—本地进化—聚合—再分发**的循环：

- 服务器将共享工具链 \( h^{(t)} \) 广播给 \( K \) 个数据本地客户端；
- 客户端在自身工作负载 \( D_k^{tr} \) 上独立进化该工具链，得到本地特化程序 \( h_k^{(t)} \)；
- 客户端返回**程序差异（delta）** 及**行为证据（behavioral evidence）**，而非原始数据；
- 服务器聚合这些程序适配，生成候选共享工具链 \( \tilde{h}^{(t+1)} \)；
- 通过**行为验证门控**后，提交为新的共享工具链 \( h^{(t+1)} \) 并重新分发。

### 2.2 关键技术细节

1. **共同基线的程序差异表示**：所有客户端从同一 \( h^{(t)} \) 出发，因此可以用 \( \Delta_k^{(t)} = \text{diff}(h^{(t)}, h_k^{(t)}) \) 表示每个客户端的贡献；服务器逐字节编辑 \( h^{(t)} \) 的副本，而非拼接完整程序文件。

2. **行为证据**：客户端在本地比较进化后的程序与广播程序，记录两类行为变化的集合：
   - \( F_k^{(t)} \)：新解决的测试项（从错误变为正确）；
   - \( B_k^{(t)} \)：新引入的失败项（从正确变为错误）。
   
   这些逐项判定随程序差异一并上传，约束服务器对差异的解释。

3. **作用域类型化程序聚合（scope-typed aggregation）**：每个候选机制被分配作用域：
   - **GLOBAL**：证据跨越两个及以上领域，或属于领域无关的失败模式（如格式错误、执行失败）；
   - **HOME(\( d_k \))**：证据仅来自单一领域，按域条件激活（代码中由 guards 保护）；
   - **⊥（拒绝）**：证据仅为单个测试项（过度拟合）。

4. **程序化采纳**：聚合器一次性启发式地生成采纳方案（因为穷举 \( 2^{|M|} \) 个子集不可行），随后由接受门精确验证可行性约束：\( |F_{val}| \geq |B_{val}| \)，不满足则允许修订一次，再失败则回滚到上一共享工具链。

### 2.3 理论支撑

论文提出两条命题：

- **命题1（作用域隔离）**：HOME作用域的机制在自身域外不可达且不写入跨域读的状态时，不改变域外执行轨迹；
- **命题2（互斥作用域下的冲突消解）**：两个证据分属不同域的机制，即使修改同一行为，也可同时保留而无需仲裁。

这两条命题使得许多程序冲突从"赢家通吃"变为"条件组合"。

### 3.2 对比方法

- **Unevolved harness**：未进化的初始共享工具链；
- **Select-best**：无聚合，直接保留服务器验证分数最高的客户端程序；

- **GLOBAL-only**：禁止域条件化的聚合（只允许全局机制）；
- **Centralized evolution**：中心化优化器，分别在相等串行深度和相等总预算两种预算下对比；
- **EvolveNet（完整版）**：作用域类型化聚合。

### 3.3 关键实验设计细节

- 每基准 \( T=3 \) 轮，每轮每个客户端1次本地生成、1个提议分支（\( E=G=1 \)）；
- 保持集规模：BIRD 150项、DS-1000 200项、SWE-bench 40项、ClawEval 30项、LiveCodeBench 30项；

## 6. 主要结论与发现

1. **共享工具链在全部五个基准上均有提升**：BIRD +13.4点、DS-1000 +13.0点、LiveCodeBench +33.4点、SWE-bench +20.0点、ClawEval +8.3点（均为与未进化工具链的配对显著性比较）；
2. **协作进化优于保留最强客户端**：在所有五设置中，EvolveNet均超过Select-best基线，且收益随客户端工作负载的异质性增大而扩大（BIRD仅+1.4点，LiveCodeBench达+23.4点）；
3. **组合优于路由**：在DS-1000上，组合各客户端机制（68.5%）优于按库分派（Delegation 64.0%）；被禁止域条件化的聚合器（GLOBAL-only 66.5%）已优于Delegation，表明增益主要来自被提升为全局行为的机制，域条件化额外贡献2.0点；
4. **经验确实跨智能体积累**：5个客户端发现的新解决项并集中20项，合并工具链保留了18项（90.0%），且存在2项仅由合并程序解决而没有任何单一客户端达到的行为（即真正的新兴组合能力）；
5. **并行搜索降低串行深度**：\( K=5 \)时客户端阶段的并行加速比达3.96×，\( K=7 \)为5.37×；增加部署不增加轮数，串行深度受最慢分支控制；
6. **门控保证提交轨迹单调不减**：被拒绝的合并导致曲线保持平坦而非下降；平局接受规则在DS-1000（+7.0点）和LiveCodeBench（+16.7点）上优于严格改进规则。

## 7. 优点

### 方法层面

- **问题定位精准**：识别出真实智能体生态的核心约束——经验不可集中，并为此设计了"适配跨边界传输而非数据跨边界传输"的范式；
- **程序聚合理论的创新**：将"作用域类型化"引入程序聚合，将许多看似不可调和的程序冲突转化为可并存的域条件组合，并给出明确的隔离前提（命题1、2），使假设可检验；
- **证据引导而非参数平均**：明确处理了源码程序没有算术平均这一本质差异，用逐项行为判定作为聚合依据；
- **保留共享基线的不可侵犯性**：保留已有提示规则、以局部化扩展方式整合新机制，控制工具链生长。

### 实验层面

- **配对比较协议隔离随机性**：将聚合规则的贡献从本地进化的随机性中分离出来，这是现有工作较少做到的严格设计；
- **直接从机制层面验证"经验积累"**：不只看总分数，而是追踪每个客户端新解决的项目是否保留在合并程序中，提供了更强的科学证据；
- **跨模型堆栈验证鲁棒性**：将整个管线更换为不同提供商的模型后关键行为复制，排除了对单模型栈的依赖；
- **多基准多维度证据链**：从主结果、消融、跨域泛化、并行效率、门控策略多个角度交叉印证结论；
- **诚实报告噪声水平**：先量化运行间波动再定分辨率，避免在噪声带内过度解读微小差异。

## 8. 不足与局限

### 实验覆盖局限

- **数据局部性 ≠ 数据隐私**：论文明确指出，程序编辑本身可能编码客户端信息（如硬编码的schema探针），量化此类泄漏需要威胁模型，作者留待未来工作；
- **轮数与规模有限**：仅 \( T \leq 3 \) 轮、\( K \leq 7 \) 客户端；长时积累（长期运行中机制过时与废弃）的结论尚不能可靠外推；
- **单一种子**：聚合规则对比（表3）仅基于单一快照；作者承认该排序虽被逐库分解和保留率分析佐证，但无独立重复；
- **配对比较是反事实**：表3中各聚合规则共享同一客户端群体，不建模在后续轮次中由于不同聚合导致的分歧演化；
- **LiveCodeBench作为多客户端测试床有局限**：其难度分箱依赖基准测试的元数据，而非自然的域边界。

### 方法本身局限

- **需要带标签的验证数据**：服务器侧需要有代表性的验证切片，这比参数空间聚合（联邦学习）的要求更强；
- **需要推理时可观测的域键**：HOME作用域机制需要能在推理时判断输入所属域，并非所有场景都具备此条件；
- **监督式而非无标签**：标签在本地训练分片（客户端候选选择）和验证切片（服务器门控）两处进入循环，因此是有监督的协作适应，不适用于无标签测试时场景；其结果与先前的无标签工具链进化工作不可直接比较；
- **人工制品单调增长**：作用域类型化采纳在门控持续通过时单调增加代码（BIRD从14行增长到253行，DS-1000从17到409行）；严格的平局拒绝门控并不是正确答案（会牺牲DS-1000上14项和LiveCodeBench上5项），但仍需大小/延迟感知门控和机制退役机制；
- **gold数据的模糊性**：BIRD硬切片中9/40项gold并非唯一确定，封顶了可达分数，可能给结果带来一定系统性偏差。

## 9. 总结性评价

EvolveNet 提出了一种有实质意义的新范式：**将智能体自我改进的聚合单元从"产生经验的数据"转变为"编码经验的可执行程序"**。其作用域类型化聚合机制为"不可平均的源码程序如何协作积累"提供了首个系统性的解决方案。实验证据链完整且可信度高，在异构分布式场景下组合多智能体发现带来了一致的显著改进。尽管存在覆盖深度（轮数、种子数）、隐私建模缺失和人工制品增长等局限，其核心洞见——程序可以携带跨组织边界的操作经验、且可通过证据门控的作用域组合完成积累——对LLM智能体生态的长期演化具有明确价值。
