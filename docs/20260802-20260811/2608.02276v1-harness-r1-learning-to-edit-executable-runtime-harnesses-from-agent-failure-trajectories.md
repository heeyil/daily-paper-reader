## 摘要
基于大语言模型的智能体在部署过程中会不断积累交互轨迹，但其行为通常保持固定不变。除了更新模型权重外，这些轨迹还可用于改进智能体的工具集——即构建上下文、协调工具、验证操作并恢复执行的组件。我们提出Harness-R1，据我们所知，这是首个将对现有可执行运行时的失败条件化、全生命周期编辑转化为一种可学习能力的方法。该方法利用在线强化学习对专用工具集工程师进行后训练，使其所做的编辑能够针对实际任务成功率进行优化，而非由固定编辑器提出。一个独立的9B工程师将一批目标智能体的失败案例转换为经过验证的可执行补丁；对冻结的目标智能体在同一批次中的重新运行提供结果奖励，因此训练仅更新工程师。冷启动监督微调初始化该编辑策略，随后通过组相对策略优化进行在线训练。在WebShop、ALFWorld和DBBench上，Harness-R1将原生Qwen3.5-9B的成功率从44.3%提升至53.6%（+9.3个百分点）。在对目标智能体进行直接微调后，专用目标工程师将平均成功率从59.2%进一步提升至64.2%（+5.0个百分点）；由于这些增益在目标智能体微调前后均能保持，Harness-R1指向了工具集工程师与目标智能体的协同进化方向。

## Abstract
Agents built around large language models continually accumulate interaction trajectories during deployment, yet their behavior typically remains fixed. Beyond updating model weights, these trajectories can improve the agent harness that constructs context, mediates tools, validates actions, and recovers execution. We introduce Harness-R1, the first method, to our knowledge, that makes failure-conditioned, lifecycle-wide editing of an existing executable runtime a learned capability. It post-trains a dedicated harness engineer with online reinforcement learning so that its edits are optimized for the realized task success they produce, rather than proposed by a fixed editor. A separate 9B engineer converts batches of target-agent failures into validated executable patches; fresh same-batch reruns of the frozen target provide outcome rewards, so training updates only the engineer. Cold-start supervised fine-tuning initializes this editing policy, which is then trained online with group-relative policy optimization. Across WebShop, ALFWorld, and DBBench, Harness-R1 raises vanilla Qwen3.5-9B success from 44.3% to 53.6% (+9.3 percentage points). After direct target-agent fine-tuning, a target-specific engineer raises the average further from 59.2% to 64.2% (+5.0 points); because these gains hold both before and after fine-tuning the target, Harness-R1 points toward co-evolving the harness engineer and the target agent.

## 2. 论文提出的方法论

### 2.1 核心思想

- 训练一个独立的 **9B harness 工程师模型**，以一批目标智能体的失败轨迹为输入，生成一个**可执行、可验证的运行时补丁**。
- 补丁安装后，**冻结的目标智能体**在同一批任务上重新运行（rerun），以**实际任务成功率的提升**作为工程师的奖励信号。
- 工程师与目标智能体严格分离：**只更新工程师参数，目标智能体权重保持不变**。

### 2.2 问题形式化

- 设目标智能体为 A（含模型与基础运行时），任务批次为 B = {x₁,...,xₙ}：
  - 基线运行得到轨迹 τ⁰ᵢ 和奖励 R⁰ᵢ；
  - 失败轨迹经确定性提取器压缩为**失败包（failure packet）** s_B；
  - 工程师 H_θ 读取 s_B，生成补丁 P（即可执行覆盖层）；
  - 补丁安装后，冻结目标重跑整个批次，得到新奖励 Rᴾᵢ。
- **奖励定义**：
  - Δ_B(P) = (1/n) Σ (Rᴾᵢ − R⁰ᵢ)
  - r(B, P) = Δ_B(P)（若补丁有效且完整），否则为 0。
- 该奖励**非可微**、只能在编辑改变目标行为后观测到，因此无法直接优化，需要强化学习。

### 2.3 四个生命周期钩子（Action Space）

补丁通过四个可执行钩子介入目标智能体的执行生命周期（仅触碰冻结策略的输入/输出，不触碰策略本身）：

| 钩子 | 调用时机 | 功能 |
|------|---------|------|
| `on_init` | 回合初始化时 | 设置起始上下文、技能/工具提示 |

| `on_before_action` | 动作提交环境前 | 中止并重新提示、改写或强制动作（守卫） |
| `on_post_step` | 环境反馈后 | 注入恢复指导或调度下一步动作 |

- **阶段一：冷启动 SFT**

## 6. 论文的主要结论与发现

1. **在线结果驱动的 harness 编辑显著提升冻结目标**：Harness-R1 将 Qwen3.5-9B 的平均成功率从 44.3% 提升至 53.6%（+9.3 个百分点），三个基准全部正向提升，最大增益在 ALFWorld（40.6%→53.2%）。
2. **训练专用工程师优于提示大型固定模型**：最强的固定前沿编辑者 GLM-5.2 平均 48.8%，低于 Harness-R1 的 53.6%；Self-Refine 在所有基准上降低奖励（−2.6 点），提示式编辑不稳定。
3. **在线 RL 优于纯监督**：Harness-R1 比仅监督式工程师高 7.1 个百分点，证明结果驱动训练的价值。
4. **工程师与目标智能体可协同进化**：目标智能体 SFT 后（59.2%），重训的目标专用工程师进一步将其提升至 64.2%（+5.0 点），说明 harness 编辑在智能体变强后仍然有效。
5. **编辑策略可跨模型泛化**：在 20 个未见目标模型上，平均提升 7.06 个百分点，63 个组合中 56 个提升、4 个持平、仅 3 个微小回退（≤2.0 点）。
6. **稀疏失败足以生成普适补丁**：仅用 10 个失败轨迹，Harness-R1 在 1,270 个 held-out 任务上提升 8.9 ± 1.5 个百分点，且所有 seed 为正；而 Qwen3.5-397B 和 DeepSeek-V4-Pro 的平均为负且跨 seed 波动大。
7. **生命周期贡献因环境而异**：pre-action 守卫对 WebShop 最重要（移除后 −3.9 点），post-feedback 恢复对 ALFWorld 最重要（移除后 −3.3 点）；固定规则无法自适应选择干预位置。

## 7. 优点

- **问题定义新颖且清晰**：将 harness 编辑从"一次性程序搜索"提升为"可通过在线 RL 学习的独立能力"，训练信号来自真实重跑结果而非文本合理性；
- **目标冻结设计严谨**：训练期间目标智能体完全冻结，隔离了 harness 编辑的贡献，因果归因清晰；
- **奖励设计合理**：以同批次任务重跑的实际成功率变化为奖励，有效避免生成"看似正确但实际无效"的补丁；
- **可执行补丁接口设计良好**：四个生命周期钩子覆盖了智能体执行的完整循环，支持上下文构建、决策前提示、动作守卫与反馈后恢复，既灵活又有约束（返回结构化效果，不直接操作环境）；
- **验证与回退机制**：补丁在安装前验证，无效/无操作补丁奖励为 0，降低了训练不稳定性；
- **泛化验证充分**：跨 20 个未见目标模型的正向迁移是强证据，说明学到的是可迁移的编辑策略而非任务过拟合；
- **消融与定性分析扎实**：生命周期消融揭示了各干预点的条件重要性，定性案例（含 GLM-5.2 的失败案例对比）增加了结论的可信度；
- **工程复现性**：提供了代码仓库、模型权重、完整超参数表和提示模板。

## 8. 不足与局限

- **同批次转导目标（transductive objective）**：奖励基于同批任务的前后对比，可能过拟合于失败挖掘所用任务；论文也承认未来需加入 held-out 性能项以显式优化对未见任务的鲁棒性。
- **单轮协同进化研究**：仅研究了一步"目标 SFT + 工程师重训"，未探索多轮交替进化的收敛性和复合增益。
- **初始化依赖强教师模型**：冷启动 SFT 依赖 GPT-5.5 生成的示例并经目标验证过滤，教师质量可能影响上限；未报告不同教师模型或不同 SFT 数据规模的敏感性。
- **统计显著性报告不足**：主结果未提供多次运行的方差或置信区间；消融显示标准差较小，但主表无法判断差异显著性。
- **未考虑推理效率成本**：补丁可能引入额外运行时开销（如多次提示注入），论文未报告补丁对延迟/成本的影响，也未在奖励中加入效率项。
- **部分组合存在回退**：跨目标泛化中有 3 个小幅回退（≤2.0 点），个别指标（如 WebShop Score）在协同进化后略有下降，说明方法并非无条件的帕累托改进。
- **对极弱目标模型效果有限**：从附录可见，Llama-3.2-1B 和 Gemma-3-1B 等极小模型提升幅度很小（1.2 点左右），因为它本身的基线能力太低，补丁空间受限。
- **测试集时间语义**：论文使用 2026 年发布的前沿模型作为对比基线，这些模型的 API/权重在评估时是否对评估集存在数据污染风险未加讨论。
