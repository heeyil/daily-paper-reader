## 摘要
长时程推理需要一种智能体运行时，当证据支持当前方法时能够持续执行，当测量揭示失败、隐藏约束或目标设定错误时能够转向。我们提出Argus，一种持久化、自我演化的运行时，其中Manager、Planner、Engineer和Reviewer在持久项目状态上执行有界任务。Argus将稳定的用户意图与操作目标、约束和验证标准分离，并仅在角色拥有的审查以及（若可用）任务原生验证之后，才接纳记忆、技能、程序、验证器、路由决策和已拒绝路径。模型权重保持不变；自我演化通过持久运行时状态和控制策略实现，在操作者拥有的升级点之间自主执行。在七个GPT-5.5基准竞技场中，Argus在SWE-Bench Pro上达到约78%的准确率，而直接使用Copilot为59%，同时使用1.41倍的聚合标记数。经过验证门控的自我演化后，成熟的SWE-Bench waves每任务使用的解决输入标记数减少21%，活跃工作流时间减少15%，同时记录34次验证器恢复和22次严格审查循环救援。Argus在AARRI-Bench上达到76.8%，在数学数据合成上领先28.0个百分点，并在GPU内核和语言模型训练结果上具有竞争力。除基准测试外，一个优化的RWKV6内核已被合并到上游；一项多日数学活动保留了被证伪的路线和基于证明的前沿更新；六个论文管线完成了254个任务，包含16次阶段回滚。这些结果表明，一个固定权重、自我演化的框架能够修订、恢复和积累经过验证的方法，同时为未来的监督学习和强化学习生成结构化轨迹。

## Abstract
Long-horizon reasoning requires an agentic runtime that can persist when evidence supports its current approach and pivot when measurements reveal failure, hidden constraints, or a misspecified objective. We present Argus, a persistent, self-evolving runtime in which Manager, Planner, Engineer, and Reviewer execute bounded missions over durable project state. Argus separates stable user intent from operational objectives, constraints, and verification criteria, and admits memories, skills, procedures, verifiers, routing decisions, and rejected routes only after role-owned review and, when available, task-native verification. Model weights remain fixed; self-evolution occurs through persistent runtime state and control policy, with autonomous execution between operator-owned escalation points. Across seven GPT-5.5 benchmark arenas, Argus achieves about 78% on SWE-Bench Pro versus 59% for Direct Copilot while using 1.41 times the aggregate tokens. After verification-gated self-evolution, mature SWE-Bench waves use 21% fewer solve-input tokens and 15% less active workflow time per task than startup waves, while recording 34 verifier recoveries and 22 strict review-loop rescues. Argus also reaches 76.8% on AARRI-Bench and a 28.0-point gap on mathematical data synthesis, with competitive GPU-kernel and language-model-training results. Beyond benchmarks, an optimized RWKV6 kernel was merged upstream; a multi-day mathematics campaign retained falsified routes and proof-backed frontier updates; and six paper pipelines completed 254 missions with 16 stage rollbacks. These results show that a fixed-weight, self-evolving harness can revise, recover, and accumulate verified approaches while producing structured trajectories for future supervised and reinforcement learning.

### 二、论文提出的方法论：核心思想、关键技术细节、流程说明

#### 1. 高层设计：持久化有界任务 + 四角色分权

- **核心抽象**：长存对象是“战役”（campaign），而非 provider 的 session 转译；工作被切分为**有界任务（bounded missions）**，每个任务必须显式终止（done/blocked/paused），并在持久项目状态上推进。
- **四角色职责分工**：
  | 角色 | 职责 | 权威输出 |
  |---|---|---|
  | Manager | 锚定目标、生命周期与路径；负责阶段推进/回滚/目标修订 | 战役划分与阶段转换 |
  | Planner | 将当前研究状态分解为有界任务与依赖关系 | 任务规范、计划状态、阶段清单 |
  | Engineer | 执行一轮改动：修码、调用工具、运行实验 | 执行结果、测量、交接、review 决策自选 |
  | Reviewer | 独立审查产物与执行记录（当需要或主动要求时） | done / continue / blocked + 下一步建议 + 状态修订 |
- **三平面分离**：控制平面（调度与授权）、执行平面（实际工作与任务内审查）、记录平面（只记载事件、不做科学完成判定），避免权限混同。

#### 2. 合约模型与转向裁决

- **报告级工作合约**： \\( K_t = (\iota, o_t, c_t, v_t) \\) —— 分别代表稳定用户意图、当前操作目标、已知约束、验证标准； \\( X_t \\) 记录用户可见的澄清/优先级/未决问题。
- **转向的裁决算子**： \\( (X_{t+1}, K_{t+1}) = \text{ManagerAdmit}(X_t, K_t, K'_t, e_t, r_t, u_t) \\) ，其中 \\( K'_t \\) 为拟定合约， \\( e_t \\) 为证据， \\( r_t \\) 为记录在案的评审结论， \\( u_t \\) 为授权决策。这是**分析性投影**而非单一原子 API，覆盖 GoalContract 修订、运行者提问、Planner 重规划、Manager 阶段过渡等分布式表面。
- **更新门控**：只有验证通过且经授权角色提交的更新才能进入持久状态——记忆、技能、验证器、路由、被拒路径均适用。角色可修订/归档/淘汰旧状态。

#### 3. 运行时自演化（核心机制）

- 公式化为： \\( H_{t+1} = U(H_t, \tau_t, E_t, K_{t+1}),\quad \theta_{t+1} = \theta_t \\) —— 模型权重不变，状态演化。
- \\( H_t = \{\text{Memory}, \text{Skills}, \text{Tools}, \text{Verifiers}, \text{Routing}\} \\)，各子面有明确 owner（Memory/Skills 由 Reviewer 提交，Routing 由 Manager 提交，Tools 由系统配置等）。
- 演化四步闭环：执行轨迹产出候选 → 责任角色依据产物与任务原生证据核验 → 授权者提交/修订/驳回 → 后续任务在起始上下文或执行策略中检索保留状态。
- 非单调性明确承认：状态可能失效、任务分布可能变难、某些任务可能不产生任何可重用更新。

#### 4. 闭环算法（Reviewed mission loop）

- 要点：Manager 提交战役 → Planner 领取任务 → Engineer 执行 → 低风险有界工作可用 Engineer 自审（review=skip），否则必须独立 Reviewer 裁决 → Reviewer 返回 continue 则继续修订，done/blocked 则结束任务轮 → 变更合约需重取用户或 Manager 授权 → 持久化结果、轨迹与更新状态。
- 关键工程细节：跨会话连续性依靠共享 `CHECKPOINT.md`；中断后从战役身份恢复，而非从模型转译重建；资源预算在模型调用和外部作业边界集中记账。

#### 5. 过程理论支撑

- **过程数据优势**（Proposition 1）：过程记录 \\( P \\) 包含最终产物 \\( Y \\) 不具备的信息（失败的实验、被拒分支、审查反馈、状态更新），因此对任意下游决策， \\( R(P) \le R(Y) \\) ，可严格小于。
- **压缩理论**：原始轨迹对有限上下文过多，需“决策有用的压缩” \\( \psi_b^\star \\) ——即具有完整事件磁带（tape）和有界已审查状态（checkpoint）的双层设计之理由。
- **可复用性（compounding）**：以折扣反事实收益 \\( G_L(\Delta H_t) \\) 衡量状态更新是否真正降低后续任务风险；强调“复合智能”是可证伪的反事实主张，不是宣传语。

- **优点**：指标均为任务原生单位、由外部/官方验证器裁决，避免了主观评分；对比基线清晰（Direct Copilot、人类最优、论文最优，以及同设备同协议）。
- **客观局限性**：
  - **SWE 纵向分析是观察性的**而非受控消融：无“冻结状态重放”对照，无法单独归因于记忆、技能、验证或路由；任务构成与难度也随时间变化。
  - **Reviewer 路由是自适应的非随机**，论文明确承认缺少随机路由以估计因果效应。
  - 数学战役的工作效率标签为整轮粗粒度归因（按任务用途分类），非段级标注。
  - 六篇论文的实验环境单一、日历时间重叠、自动化 review 快照模型生成，且日志系统跨项目演进。
  - **无外部盲评**：数学定理未经外部同行评审，论文完成不等同于录用；ACE-2 止步于 mapped synthesis，未做 routed timing/功率、DRC/LVS、流片或硅验证。

#### 公平性评价
- 论文整体偏向**展示性证据**，每个场景都有真实外部验证器把关；而“转向的安全性”（用户导向修订）没有公开展开的受控研究，仅为内部分析定性动机，是明显空白。


### 六、论文的主要结论与发现

1. **固定权重模型可以在运行时状态层面实现自我演化**：模型参数不变，但持久化记忆/技能/验证器/路由改变后续任务起点，验证门控使失败与成功路径都可复用。
2. **有验证的转向优于无转向**：SWE-Bench Pro 上 Argus 比 Direct Copilot 高约 19 个百分点（78% vs 59%），token 开销仅 1.41 倍，证明规划+审查+执行的开销换取精度是划算的。
3. **自演化产生可观测的效率提升**：成熟窗口（W19–22）比起始窗口（W1–6）每任务节省 21% 输入 tokens 与 15% 活跃时间；但轨迹非单调（W13–18 token 更低但时间更慢；W23–24 困难波回弹）。
4. **Reviewer 是有效的选择性纠错器**：466 个任务调用独立 Reviewer，43 个被要求修订，34 个最终通过官方验证器（79.1% 恢复率），22 个完成严格 review loop（51.2%）；35 个任务被判定 blocked 而非虚假完成。
5. **整体能力跨度广**：同一运行时在软件、GPU、训练、研究任务与数据合成领域均有竞争力（76.8% AARRI-Bench；28.0 数学差距；nanochat BPB 优于人类最优）。
6. **在外部验证器场景中，约束“是什么就说什么”**：ACE-2 的证书主动列出其不能证明的事项（未流片、未做 DRC/LVS、仅 2 tokens），证明了验证门控使人诚实；MOF 材料

MOF 材料生成场景中，Argus 利用外部 MOFChecker 验证器对候选材料进行结构合法性校验，替换了已发表方法中的内部启发式检查；这一过程严格遵循“未经验证不得入库”的门控规则，说明验证器外部化是避免“自我说服”的关键机制。

### 七、主要贡献与领域启示

1. **运行时层而非模型层的自演化框架**：Argus 将“学习”从权重更新迁移到持久状态更新，使得固定权重模型也能在长时程任务中积累可复用知识。这对计算受限场景和禁止微调的部署环境具有直接意义。
2. **将“转向”从异常变为可审计的正常操作**：通过合约模型、验证门控与角色分权，Argus 把“修改目标”从不可验证的黑盒决策转化为有证据、有授权、有记录的显式事件。这是对现有智能体“目标固定、执行优化”范式的重要补充。
3. **统一了“执行”与“验证”的职责边界**：四角色分权与三平面分离使得同一系统既能高效完成低风险任务（跳过独立审查），又能在高风险变更处强制引入独立审查，从而在效率与可靠性之间获得弹性权衡。
4. **提供了大规模、多领域的实证证据**：相比单个 benchmark 上的对比，论文在软件工程、GPU 内核、模型训练、科学研究、材料与芯片验证等七个异构场景中展示了同一运行时架构的复用性，具有较强的生态学效度。
5. **提出了可独立复用的过程理论**：过程记录“严格不劣于”最终产物、决策有用压缩、反事实复合收益等命题，为后续长时程智能体研究提供了理论语言，也便于其他团队将其作为可验证的假设来测试。

### 八、主要争议、风险与开放问题

1. **“验证转向”是否真正解决了目标漂移问题，还是只解决了“记录”问题？** 论文将转向的成功归因于验证门控与角色授权，但并未证明 Manager 对合约修订的“证据充分性”判断本身不会出错。若 Manager 本身被误导，则再严格的审计也只能记录错误，而非阻止错误。
2. **自演化状态的长期稳定性未经过长周期检验**：论文观察窗口最长为数百小时，状态更新在不同任务分布下的累积效应、反馈回路失控风险（例如 Reviewer 过度信任已入库技能）仍缺乏纵向消融。
3. **“复合智能”的度量尚不完善**：论文给出折扣反事实收益的形式化定义，但实际实验中并未逐项计算该指标，而以任务级别的 token/时间开销近似。这使“自演化真的提升了能力”的核心论断仍以间接证据为主。
4. **模型能力依赖明显**：主结果建立在 GPT-5.5 这一强基座之上，且 GLM-5.2 的在途实验提示模型能力会影响 Argus 的上限。弱模型 + Argus 是否仍能获得相当增益，论文没有回答。
5. **安全与对齐问题着墨较少**：四角色分权中 Manager 拥有最高修订权，但论文未讨论当用户意图本身有害或 Manager 被越权操控时的应对机制；审计记录也不等同于安全控制。

### 九、总结性评价

Argus 是一篇以系统工程为主的智能体运行时论文，其核心价值不在于提出某种新的神经网络结构，而在于将“验证”、“授权”与“状态演化”三个概念在长时程推理中可操作化。论文用大量异构 benchmark 和真实外部验证器证明：在固定权重模型下，通过持久化状态与严格门控，确实可以构建出能够长期坚持、也能被证据驱动地转向的自主智能体。其方法与结论对自主科学发现、自动化软件修复、长时程研究助手等方向具有直接参考价值；但在“转向安全性”的受控验证、状态增长的长期稳定性、以及弱模型泛化等方面仍留有未竟问题。整体上，这是一项工作量大、证据丰富、理论意识强的贡献，其意义更多在于提供了一个可复现、可扩展的运行时架构模板，而非某个单一 benchmark 上的最优数字。
